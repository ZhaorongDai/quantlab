<interfaces>
`quantlab/utils/timer.py`:
- `Timer(task_name: str)` is a context manager. `__enter__` logs INFO `Starting {task_name}`. `__exit__` logs INFO `{task_name} consumed time: {secs:.2f}s` and returns None, so exceptions still propagate unchanged. A variable assigned inside the `with` block stays in scope after it.
- The existing house style is `with Timer(f"{self.__class__.__name__}: cal"):` (quantlab/base/factor.py, quantlab/dataset/stock.py).

`class_name` property: `BaseModel.class_name` (quantlab/base/model.py) and `BaseBacktester.class_name` (quantlab/base/backtest.py) both return `self.__class__.__name__`, and both files already use `self.class_name` in every message. The new timer names use `self.class_name`, with no leading space.

Neither file imports Timer today. Their `quantlab.utils` import blocks are alphabetical:
- model.py: `...atomic`, `...jsonable`, `...metrics import regression_panel_metrics`; Timer goes directly after metrics.
- backtest.py: `...atomic`, `...backtest_report`, `...fingerprint`, `...jsonable import to_jsonable`; Timer goes directly after jsonable.

Import-contract check: tests/test_backtest_contracts.py forbids only config-factory imports in the backtest layer and lower layers importing the backtest layer. quantlab/utils/timer.py imports only `time` and `loguru`, so the new import is allowed and creates no cycle.
