# Quick 260915-p91: Point-in-time rule-based universe filter Summary

## Deviations from Plan

### 1. [Rule 2 — missing critical functionality] The contracted RuntimeError could not actually fire

- **Found during:** Task 1.
- **Issue:** The interface contract says `get_features()` before `cal()`/`read()` raises `RuntimeError` from `_mask_panel`. It cannot: `get_features()` funnels through `_get_xarray_dataset()`, which reads `data_backend.data` and raises a bare `AttributeError: 'XrBackend' object has no attribute 'data'` *before* `_mask_panel` is ever reached.
- **Fix:** Added a `_get_xarray_dataset()` override calling a shared `_assert_computed()`. `_mask_panel` keeps its own guard for direct callers. One override instead of two (`get_features`/`get_labels` both funnel through it).
- **Files:** quantlab/factor/universe_filter.py. **Commit:** f4bf997.

### 2. [Rule 1 — test bug] `datetime64` membership test could never pass

- **Found during:** Task 3.
- **Issue:** `expected_fill in set(sold.tolist())` — `.tolist()` on a `datetime64[ns]` array yields integer nanoseconds, so a `np.datetime64` is never a member. The *behaviour* was correct all along: the sell fired at exactly `bars[R2_ROW + 1]`.
- **Fix:** Compare as datetime64 throughout (`(sold == expected_fill).any()`, boolean-mask the early window).
- **Files:** tests/test_universe_filtered_factor.py. **Commit:** 0ae8e8d.

### 3. [Rule 1 — test asserted a non-invariant] Post-run config equality

- **Found during:** Task 3.
- **Issue:** The test asserted `rebuilt.get_config() == saved` after a run. `run()` re-dates factors for warm-up and `config.json` is written afterwards; a rebuild re-derives factor dates from the *model* dates via `BaseModel._reset_factors_config`. The two necessarily disagree once a run has happened.
- **Evidence (measured, not assumed):** a scratchpad probe ran the **unwrapped** `tests.backtest_fixtures` backtester and rebuilt it — saved factor `2024-02-05..2024-03-11` vs rebuilt `2024-01-01..2024-02-09`, saved dataset start `2024-01-31` vs rebuilt `2023-12-27`, `configs equal after a RUN? False`, differing key `['model']`. Identical divergence with no wrapper involved. This is why `tests/test_backtest_rebuild.py` asserts config equality only on a backtester that was never run.
- **Fix:** Compare configs with the re-derived `start_date`/`end_date` normalised away, documented with the measurement. The inner factor's identity is still asserted un-normalised, and the claim that matters — the re-run writes an identical `weights.zarr` and equal equity — is asserted exactly and separately.
- **Files:** tests/test_universe_filtered_factor.py. **Commit:** 0ae8e8d.
