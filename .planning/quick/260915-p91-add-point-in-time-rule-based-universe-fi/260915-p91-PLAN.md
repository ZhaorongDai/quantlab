<objective>
Add a point-in-time, rule-based stock-universe filter, implemented as a Factor wrapper class. `UniverseFilteredFactor` wraps any KunQuant factor or label and is itself a `FactorKunQuant`. Wrapped objects behave the same everywhere factor objects are used today: model collect/train, the backtester's re-dating and feature recompute, and `config.json` rebuild. Neither the model layer nor the backtester is edited.

Purpose: the US-equity Alpha101 -> 5-day Return -> XGBoostRegressor -> `USEquityCrossectionSelectStockVectorBt` run on ~7,700 Tiingo `us_all` symbols returned +886,077,331% in 244 days, with `best_iteration=0`. The cause was warrants, rights, units, test tickers and penny stocks (`AACIW`, `AAC-WS`, `AACBR`, `AACBU`, `ZWZZT` 0.007 -> 10.05). About 50 of the 57 forced liquidations were such instruments. Filtering the universe with the same point-in-time rules a live trader would use removes them from both the cross-sections and the trade list.

Output: `quantlab/factor/universe_filter.py`, a small generic `from_config` dispatch in `quantlab/utils/module.py`, `tests/universe_fixtures.py`, `tests/test_universe_filtered_factor.py`, `example/universe.md`, and an index row in `example/README.md`.

Locked semantics (user-locked in the planning context; referenced below as LS-1..LS-5; do not revisit):
- LS-1 Universe mask, point-in-time. A symbol is in the universe at t iff:
  - (a) the ticker is common stock (a static rule);
  - (b) RAW `close[t] >= min_price` (default 5);
  - (c) the trailing `window`-bar (default 20) mean of RAW `close*volume` ending at t is `>= min_dollar_volume` (default 1,000,000). An incomplete window means out.

  Use RAW close and volume, never adjusted. `anomaly_flag` is not used. The mask is 1.0 in and NaN out, on (timestamp, symbol).
- LS-2 Cross-sectional ops see only in-universe symbols; time-series ops see the full history. Every `CrossSectionalOp` input v becomes `Div(v, universe_mask)`, with the mask as an extra graph Input, fed in batch (`runGraph`) and stream (`StreamContext`) modes.
- LS-3 After computing, factor outputs AND labels are set to NaN where the mask at t is NaN. Labels come from UNFILTERED prices; only the mask at the label's own timestamp t matters, never the universe state at t+h. Then drop ONLY the symbols excluded by the static ticker rule (warrants, units, rights, test tickers), in every window. User decision 2026-09-15, superseding the original whole-window-NaN drop: symbols NaN for the whole window only because of the price or dollar-volume thresholds are KEPT as NaN columns.
  - Why: whole-window-NaN dropping made the symbol axis depend on the date window, and `DLModel._align_prediction_symbols` raises when a trained symbol is missing from a later window. The ticker rule is date-independent, so a symbol it removes is in no window's axis and can never have been trained on.
  - Kept NaN columns are neutral for ML heads that drop NaN-label rows: `XGBoostRegressor._to_rows` keeps only rows where `np.isfinite(y_rows).all(axis=1)` (quantlab/ml_model/xgb.py:225).
  - They are NOT neutral in DL-head TRAINING, and this is accepted, not fixed here. `DLModel._fit` runs `_preprocess` over the LABEL tensors as well as the feature tensors (quantlab/base/model.py:1069), and `MLPRegressor._preprocess` is `torch.nan_to_num(nan=0.0)` (quantlab/dl_model/mlp.py:185). Every masked cell, including a whole kept NaN column, therefore becomes a zero-target, zero-feature sample the network trains on, which skews the loss. This is pre-existing `DLModel` behaviour for ANY NaN (pre-listing gaps and delisted tails already do it); the wrapper only increases how many such cells there are. Fixing it would mean changing the model layer, which this task may not touch.
  - Prediction and selection are unaffected for both head types: all-NaN features make `predict_panel` return NaN (quantlab/base/model.py:567), so such symbols are never selected.
- LS-4 The backtester is unchanged and `price_dataset` stays unfiltered. A holding that leaves the universe gets NaN features, so `predict_panel` gives a NaN prediction. It is ineligible at the next rebalance bar and sold at the next real open. Document it: with `rebalance_periods=5` the sale is up to 4 bars late; with `rebalance_periods=1` it is the next day.
- LS-5 Accepted cost: a time-series op over a cross-sectional op (e.g. `correlation(rank(x), rank(y), 10)`) is NaN for up to that window after a symbol (re)enters the universe. This is consistent with live trading; document it.
</objective>

Methods:
- `_get_factor_names()`: returns `self.factor._get_factor_names()`.
- `_reset_dataset_config()`: calls `self.factor._reset_dataset_config()`. It then moves `config.dataset.config.start_date` EARLIER to `start_date - (LOOKBACK_DAYS_PER_BAR * window + LOOKBACK_PAD_DAYS)` calendar days, if that is earlier than what the inner set. It never narrows; format `%Y-%m-%d`. Why: the backtester's warm-up counts only `config.window` bars, and without this the first `window-1` bars of a window (or warm-up) would be out of universe for lack of dollar-volume history.
- `_get_factor_func()`:
  - Takes a FRESH `self.factor._get_factor_func()` (each call builds a new Builder graph; never cache or reuse ops, because the rewrite mutates `op.inputs`).
  - Runs the prototype's `apply_universe_mask` over its `.ops`, as a module-private function `_mask_cross_sectional_inputs(ops) -> tuple[list[OpBase], bool]`. Inside a `Builder()` context it creates one `Input(MASK_INPUT)`, and one `Div(inp, mask)` per distinct input (cached), placed in front of every `isinstance(op, CrossSectionalOp)` input. It returns `Function.topo_sort_ops(ops + builder.ops)`.
  - Sets `self._uses_mask` and returns `Function(rewritten_ops)`.
  - When no cross-sectional op exists, the ops are returned unchanged and `_uses_mask=False`. KunQuant prunes unconsumed inputs, so a mask input must never be declared or fed then.
  - Verified at planning: KunQuant 0.1.11 `ops/CompOp.py` has no `CompositiveOp` that decomposes into a cross-sectional op, `DiffWithWeightedSum` is itself a `GenericCrossSectionalOp`, and `TsRank` is time-series, so a pre-decompose rewrite is complete. A planner probe confirmed that rewriting `.ops` of an already-constructed `Function` compiles and runs.
- `compute_universe_mask(self, panel: xr.Dataset) -> xr.DataArray` (public):
  - Raises `ValueError` naming the missing column if `PRICE_COLUMN` or `VOLUME_COLUMN` is absent.
  - Sorts by timestamp and transposes to (timestamp, symbol) float64.
  - `dollar = close * volume`; `avg = dollar.rolling(timestamp=window, min_periods=window).mean()`. Any NaN inside the window gives NaN, which means out.
  - `in_u = (close >= min_price) & (avg >= min_dollar_volume)`. NaN comparisons are False.
  - If `exclude_non_common`, AND with a per-symbol common-ticker vector.
  - Returns `xr.where(in_u, 1.0, np.nan)`.
