# Quick 260906-13w: Chunked Zarr Ingestion and Universe-Mask Reporting Summary

**The full `us_all` Zarr conversion is no longer refused on a 16 GiB machine: `--to-zarr` densifies and appends one time window at a time onto a symbol axis pinned once over the whole range, guarded per-chunk (largest yearly window 0.35 GiB against a 4.00 GiB budget, versus the 7.19 GiB whole-range total), resumable at window granularity — plus a `UniverseMask` that names every index member the market data does not cover.**

## Accomplishments

- **The OOM is gone, and the guard that reported it is intact.** `BaseDataset.from_raw_data_chunked()` densifies one window at a time and appends along `timestamp`. Against the live roster the largest yearly window is **0.35 GiB** (15,424 pinned symbols x 253 trading days x 12 variables) versus the **7.19 GiB** whole-range total and the unchanged **4.00 GiB** budget. `assert_dense_panel_fits()` and `MAX_DENSE_PANEL_BYTES` were not weakened by a byte — `assert_chunked_panel_fits()` is a sibling.
  - POINTER: the second half of this accomplishment restates D-05 and was REVERSED 2026-09-12 by phase 03.6 SC-3 — the guard that reported the OOM is no longer intact; all three members were deleted. The FIRST half is unchanged and still true: the chunked densify-and-append path still bounds peak RAM by window. See the single D-05 amendment block at the end of `260906-13w-PLAN.md`'s `<objective>`.
- **The symbol axis is pinned once, and the pinning is now enforced three ways.** Resolved whole-range before any window exists (following `base/constituent.py:_densify`'s all-time-union rule), asserted element-for-element against every window inside the loop, and fingerprinted in the ledger so a roster refresh between two runs raises instead of appending onto a different axis.
- **Two silent-corruption paths in raw Zarr were found by experiment and closed.** `to_zarr(mode="a", append_dim=...)` **overwrites** a mismatched non-append coordinate with no error (a window with its own symbol axis would silently re-attribute every previously written row), and it **casts** an appended float64 NaN into an int64 variable to `0` — fabricating an observation where data was missing. `XrBackend.append()` now raises on both, and integer variables are promoted to float64 before the append so the second refusal is unreachable in normal operation.
- **Chunk boundaries come from the observed axis, sizing from the calendar, and the two cannot drift.** `plan_from_timestamps()` returns windows whose every edge is a real observed timestamp; `plan_calendar()` is sizing-only and says so in its first docstring line. Both group by one private `_period_key()` — `plan_calendar` walks a day-by-day range rather than using `pd.period_range` specifically so it routes through that single helper.
- **Resume is a two-record cross-check, not a guess.** The ledger sidecar lives *beside* the store (a `mode="w"` rewrite deletes the store directory) and is rewritten atomically. A resume refuses a fingerprint mismatch, a store with no ledger, and a store whose `timestamp` tail disagrees with the ledger's last recorded window — the state a crash between a successful `to_zarr` and the ledger write leaves behind.
- **The construction-time OOM trap is documented at the call site.** `ingest_us_equity.py` builds `ds_config` with `symbols=None`: a roster there makes the config setter run `_reset_symbols()` -> `read()` -> `FileNotFoundError` -> `from_raw_data()`, a full-range densification at `StockDataset(...)` construction time, before the chunked loop is ever entered. On a first run with no store that fires every single time.
- **Survivorship bias is now reportable, not just avoidable.** `UniverseMask.report()` logs the count **and** the complete, untruncated, unsampled list of in-window index members absent from the market panel. An empty report is an explicit `info` line — it is the falsification of the assumption that Tiingo serves delisted history, so it had to be reachable and quiet.

## Decisions Made

See `key-decisions` in the frontmatter. The three most load-bearing:

1. **Per-chunk sizing uses the pinned whole-range symbol count.** This is the one thing that was easy to get subtly wrong. Every window is materialised on the full pinned axis, so a 2025 window still allocates a column for a ticker that delisted in 2009. Calling `estimate_dense_panel()` scoped to a chunk would count only that chunk's listed symbols, understate the allocation, and reopen the OOM. `test_each_chunk_is_sized_on_the_pinned_whole_range_symbol_count` makes the difference observable: the fixture's 2025 roster is genuinely smaller than the whole-range one, and the guard is asserted to ignore that.
2. **Chunked writing is three responsibilities in three places, not one.** Incremental bytes onto the medium belong to `XrBackend` (every xarray-backed dataset gets it free); window/ledger arithmetic is a pure function of a timestamp axis and a file path, so it is a leaf module; the loop needs `config.zarr_file_path`, `_clean()` and `data_backend`, so it is `BaseDataset`'s. `StockDataset` is the only class overriding the seams today because it is the only one whose raw source can push a date filter down before materialisation — the ability to push down is per-source, the loop is not.
3. **`UniverseMask` reports one direction of the intersection and not the other.** An index member the market panel lacks is a coverage gap; a market symbol that is not a member is merely out of universe. Timestamps are a third case: the membership panel is on a calendar-day axis and market data on trading days, so the dropped weekend rows are expected by construction and reporting them would bury the symbol report under thousands of routine lines.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] `XrBackend.append` refuses a changed non-append coordinate instead of only documenting the requirement**

- **Found during:** Task 1 (before writing tests, while derisking zarr append semantics)
- **Issue:** The plan specified that `append`'s docstring "records that non-append dims and their coordinates must match exactly across calls, which is what `from_raw_data_chunked` guarantees by pinning the symbol axis." A direct experiment showed the failure mode is worse than a docstring can carry: `to_zarr(mode="a", append_dim="timestamp")` given a different `symbol` coordinate **silently overwrites the stored labels** and returns normally. Every previously written row is then attributed to the wrong symbols, and the store carries no evidence of it. A guarantee made only by the caller is one an unrelated future caller can break with no signal at all.
- **Fix:** `_assert_append_compatible()` compares every non-append coordinate against the store before the irreversible write and raises naming the dimension and both lengths. Only coordinates are read; the data variables stay lazy. The docstring still records the contract — the check makes it enforceable.
- **Files modified:** `dataset/backend.py`
- **Verification:** `tests/test_chunked_ingest.py::test_append_refuses_a_changed_symbol_axis`
- **Committed in:** `ffa5462` (Task 1 commit)

**2. [Rule 1 - Bug] Window dtype is a function of window density, and Zarr casts a float NaN into an integer store as 0**

- **Found during:** Task 1 (same derisking experiment)
- **Issue:** `set_index([...]).to_xarray()` yields `int64` for `volume` when a window is fully dense and `float64` when any cell is missing — so the dtype of a chunk depends on that chunk's own density, not on the schema. The store's dtype would therefore be fixed by whichever window happened to be written first, and appending a later float64 NaN into an int64 variable was measured to write **0**: a fabricated observation where the data was missing, silently, with no error. At full-market scale a fully-dense window is unlikely, but "unlikely" is not a correctness argument for a store that cannot be validated afterwards.
- **Fix:** two layers. `_pin_append_dtypes()` promotes integer data variables to float64 before every append, making the store dtype a property of the schema (and matching what `estimate_dense_panel` already assumes at 8 bytes per value); booleans are left alone. `_assert_append_compatible()` additionally refuses any dtype mismatch, so the corruption is unreachable even from a caller that bypasses the loop.
- **Files modified:** `base/data.py`, `dataset/backend.py`
- **Verification:** `tests/test_chunked_ingest.py::test_append_refuses_a_changed_dtype`; `test_chunked_store_matches_the_unchunked_store` proves the promotion does not change any value.
- **Committed in:** `ffa5462` (Task 1 commit)

**3. [Rule 2 - Missing Critical] `UniverseMask.apply()` refuses a disjoint pair of panels instead of returning an empty panel**

- **Found during:** Task 3
- **Issue:** The plan specified `apply()` selects onto the overlapping timestamps and intersected symbols. With two panels from different eras that overlap is empty, and the method would have returned a well-formed, entirely empty `xr.Dataset` — which a downstream backtest reads as "no positions held" rather than as the misconfiguration it is.
- **Fix:** `apply()` raises naming both counts when either intersection is empty. `report()` deliberately still works on a disjoint pair, so the diagnosis is available before the raise.
- **Files modified:** `dataset/masking.py`
- **Verification:** `tests/test_universe_mask.py::test_a_disjoint_timestamp_axis_is_refused_rather_than_returning_empty`
- **Committed in:** `ce89b03` (Task 3 commit)

**4. [Rule 1 - Bug] A test class modelled the default-seam case incoherently and recursed infinitely**

- **Found during:** Task 1 (RED -> GREEN transition)
- **Issue:** `test_default_windowed_seam_warns_that_chunking_bounds_only_the_write` originally built its subject by subclassing `StockDataset` and resetting both seams to `BaseDataset`'s defaults. That is an incoherent combination, not a realistic one: `StockDataset._raw_data_to_xr()` is defined in terms of the window seam while `BaseDataset._raw_data_to_xr_window()` is defined in terms of `_raw_data_to_xr()`, so the pair recurses. The implementation was correct; the test's model of "a class that has not overridden the seam" was not.
- **Fix:** the test now uses a minimal `BaseDataset` subclass implementing only the one abstract member — which is the actual shape of a dataset kind that inherits both defaults — and additionally asserts the resulting store is complete, so the default is proven correct rather than merely warned about. This is a fix to a test written in this same plan, not a weakening of any pre-existing assertion.
- **Files modified:** `tests/test_chunked_ingest.py`
- **Verification:** `uv run pytest tests/test_chunked_ingest.py -q` green.
- **Committed in:** `ffa5462` (Task 1 commit)
