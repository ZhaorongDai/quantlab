<settled_decisions>
The brief posed four open questions. They are SETTLED here; do not re-open them, and do
not plan or implement anything that contradicts them.

**D-1 -- Both paths ship, behind one router.** `widen_symbol_axis` stays the single
public entry and gains no strategy parameter. Two private strategies sit behind it. The
evidence is the brief's timing table: chunked is 1.2x / 4.0x / 3.6x the whole-store wall
clock on 0.2 / 34.6 / 137.3 MiB stores, so "always chunk" taxes every routine widen for
nothing. The repo's one-path rule forbids two live NAMES for one thing; one name with
two size-selected strategies is not that.

**D-2 -- The block size comes from the budget, floored onto the store's own chunk
grid.** `TimeChunkPlanner` is rejected: its granularities are calendar periods and a
period's row count is a function of frequency and density (a month of 1-minute bars is
~390x a month of daily bars), so it cannot bound bytes -- which is the whole constraint.
Rule:

```
row_bytes  = bytes of ONE append-dim row across the WIDENED panel
raw        = MAX_WIDEN_BYTES // row_bytes            (0 when row_bytes is 0)
block_rows = max(APPEND_DIM_CHUNK,
                 (raw // APPEND_DIM_CHUNK) * APPEND_DIM_CHUNK)
```

**D-3 -- The swap ordering is re-verified against the loop.** The loop lives inside the
`try:` whose `finally` closes `stored`; both `os.replace` calls stay outside it, in the
shipped order. The `rmtree(widening)` cleanup wraps the whole loop, not one write.

**D-4 -- `widen_data_vars` is OUT of scope.** Its filler cannot use the `append_dim`
trick (extending the append dim would extend every already-full stored variable too), so
a bounded version needs `region=` writes against a pre-created full-shape array -- a
different write primitive. It is filed as a todo carrying its own measured cost figure,
not dropped.

**D-5 -- The budget is `XrBackend.MAX_WIDEN_BYTES = 4 * 1024**3`.** Same figure as
`UniverseCatalog.MAX_DENSE_PANEL_BYTES` (same machine, same measured ceiling), separate
constant because this module has no import path to the acquisition layer and must not
grow one. Every measured scenario in the brief routes correctly at this value.

**D-6 -- The report is asymmetric.** Chunked branch: `logger.warning`, loud, naming the
figures and the wall-clock cost. Whole-store branch: one `logger.info` line naming the
estimate and the budget. A warning on every routine widen is noise; the brief's
requirement is that the SWITCH not be silent.
</settled_decisions>
