<objective>
Close RV-01: the `FactorPolars` construction-time name probe silently truncates its dataset's
date window, dropping the factor's lookback with nothing raised.

Fix: thread the store path into `DataBackend.head()` so it opens the store itself, and drop the
`read()` call from the probe. The probe stops going through `BaseDataset.read()` →
`_filter()` → in-place `filter_by_date`, so there is no narrowing left to survive
`XrBackend.read`'s cache.

Purpose: `Momentum` and `Alpha158SpotKline` in one `DLConfig` currently produce a panel whose
`momentum_5` column is ~80% NaN, with no error anywhere. Phase 4 is the next phase and consumes
exactly that panel.

Output: a path-threaded `head()` on both backends, a probe that never filters, and the first
test in this repo whose `DatasetConfig` carries dates.
</objective>

<decisions>

## D-1 — `head()` takes the path; `read()` is untouched

`head(path, n)` on the `DataBackend` ABC, path first, mirroring `read(path, **kwargs)`.
`BaseDataset.head(n)` keeps its signature and threads `self.config.zarr_file_path` through,
exactly as `read()` does.

Rejected on the record: **adding a `filter` parameter to `read()` and clearing `self.data`
afterwards.** Three reasons, all of which the path-threading version avoids by construction:

1. Clearing `self.data` destroys a caller's already-read data. `dataset/masking.py:89-90` does
   `market_dataset.read().get_xarray_dataset()`; anyone who reads a dataset and then builds a
   `FactorPolars` over that same object would have it wiped by the probe — the same class of
   shared-state side effect as RV-01 itself.
2. `filter=False` does not compose with the cache. `XrBackend.read`'s early-return means a
   dataset already read WITH filtering returns the filtered data anyway, so the flag does
   nothing unless `overwrite=True` rides along — which then forces a full re-open per probe and
   still clobbers the caller.
3. It widens `read()`'s public surface for an internal need, contradicting its own meaning
   ("instantiate the specified date range").

And the clear-after was *load-bearing*, not optional: `cal()` (`base/factor_polars.py:143`)
re-reads the same dataset object, so without the clear the cache early-return hands it the
probe's narrowed data — RV-01 recurring. Correctness that depends on one side effect cancelling
another is the thing being removed here.

## D-2 — `xr.open_dataset`, never `xr.open_zarr`

`XrBackend.read` (`dataset/backend.py:21`) already opens this same store with
`xr.open_dataset(path, **kwargs)`. Two different openers for one store in one class is a
divergence waiting to bite; `_assert_append_compatible`'s `open_zarr` is a separate,
append-specific concern and stays as it is.

## D-3 — RV-02 is NOT closed here and stays filed

**Decision: this fix does not address RV-02, and deliberately keeps its error identical.**

`head()` carrying `read()`'s explicit `Path(path).exists()` → `FileNotFoundError(f"File {path}
does not exist.")` guard is a choice, not an accident: without it a missing zarr directory
surfaces as an obscure xarray engine-guess error, or (on `PlBackend`) as a *deferred* failure at
`.collect()` time. RV-02's own severity note calls the current behaviour "loud and correctly
named"; that stays true.

One case does change, and it is named rather than discovered later: a dataset whose data exists
only IN MEMORY (`_reset_symbols()`'s `from_raw_data()` fallback, store never written) was
previously probeable, because `XrBackend.read`'s cache early-return served it. After this fix it
raises. That narrowing is accepted deliberately — a construction that succeeds or fails
depending on whether some earlier caller happened to populate a cache is the same hidden
coupling RV-01 is. Unreachable from any shipped factory or fixture today: `_reset_symbols()` only
runs when `config.symbols is not None`, and no `FactorPolars` construction path in the repo pins
symbols against an absent store.

Closing RV-02 properly means deciding whether name derivation may be DEFERRED (a lazy probe on
first `get_factor_names()`), which re-opens D-05's "names are known from construction onward"
contract and the test that locks it. That is a design call for the user, not a side effect of a
mutation fix. Task 1 records the decision as a tested property rather than only as prose.
