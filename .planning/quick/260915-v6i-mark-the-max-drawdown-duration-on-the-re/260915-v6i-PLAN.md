<design_decisions>
**D-1: the span is computed in the ENGINE layer, as a new NON-ABSTRACT hook.**
`BaseBacktester._drawdown_span(simulation) -> dict | None` returns `None`;
`VectorBtBacktester` overrides it and reads `simulation.native.drawdowns`. This mirrors
`_engine_stats` exactly — same argument, same "read `native`, return plain values"
shape — and honours the documented rule that `native` is read only by the engine that
produced it.

*Rejected:* a new `SimulationResult` field filled inside `_simulate`. It would put a
presentation-only value into the engine-agnostic simulation contract, and `_simulate` is
already the longest method in the engine. *Non-abstract by fact 8:* an abstract hook
would turn the contracts test red and force every future engine to implement a report
detail it may not have.

**D-2: units are TRADING DAYS (bar counts), stated as such.** The span length is
`end_idx - start_idx` — exactly what `vbt max_duration` returns and exactly the number
`metrics.json` carries. The user-visible English text says "trading days" explicitly, so
a reader who measures the time axis (which spans more CALENDAR days) is not misled. No
calendar timedelta is printed as the duration anywhere.

**D-3: the markers sit at `start_idx` and `end_idx`, not at `peak_idx`.** That is the
pair `vbt`'s own duration measures; marking from the peak would draw a span one bar
wider than the number beside it.

**D-4: the visible text says "deepest drawdown", not "max drawdown duration".** The
table row `Max Drawdown Duration` is the LONGEST drawdown's duration and can belong to a
different episode (fact 5). Naming the marked record "deepest" everywhere makes the two
numbers impossible to confuse, and one note states the relationship outright.

**D-5: two separate named traces**, `deepest_drawdown_start` and
`deepest_drawdown_end`. Distinct hover text per endpoint is the whole point (the end
marker must be able to say "never recovered"), and each carries its own `name`, which
the persisted-report parser requires.

**D-6: no blanket `try/except` around the hook.** The guards are explicit (no records,
no finite depth, index out of range). A vectorbt shape change that broke
`drawdowns` would already have failed `_engine_stats`, which runs well before the
report, so the report is not the place that discovers it.

**D-7: nothing is added to `metrics.json`.** Metric values, engine arithmetic and the
run-directory file set are untouched.
</design_decisions>
