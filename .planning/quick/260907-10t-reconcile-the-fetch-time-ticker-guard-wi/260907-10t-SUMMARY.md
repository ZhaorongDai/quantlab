# Quick Task 260907-10t: Reconcile the Fetch-Time Ticker Guard with the Roster Builder Summary

Two separately-deliberate decisions — `us_all` deliberately RETAINS its 1,124
warrant / unit / right / when-issued lines (260906-eme), and
`Acquisition._validate_symbols` admits only ONE suffix segment (03.2-03) — were
never pinned against each other, so `download()`'s whole-roster pre-flight
raised on `NXG-R-W` and killed a multi-hour full-market job before one request
was issued. Both ends now bind ONE compiled pattern in `enums/data.py`, the
roster builder drops malformed entries at build time, and
"everything the builder persists is fetchable" is an asserted invariant over the
FULL builder output of both rosters rather than an assumption.

**The plan's prediction about mutation 2 was wrong, and this is recorded rather
than smoothed over.** The plan asserted the reconciliation test would redden
under *both* named mutations. It reddens under mutation 1 (removing the build
filter) but **not** under mutation 2 (narrowing the pattern).

The reason is structural, and it is the design working rather than a hole:
because both ends bind the **same compiled object**, the builder drops exactly
what the guard would refuse, so "builder output is fetchable" is true under
*any* pattern. That is the whole benefit of sharing one object instead of
keeping two copies equal by a test. Making the reconciliation test catch the
narrowing would require re-introducing a second pattern for it to disagree with
— i.e. undoing the fix.

The pattern's *value* is pinned separately and that mutation reddens **six tests
across two modules**. The test docstring now states this measured result
instead of the plan's prediction; leaving the false claim in place would have
repeated the exact failure this task fixed (a provenance comment asserting
something untrue).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The fixture symbol `DELISTED1` is unfetchable and had always been**

- **Found during:** Task 2, before writing the filter — a probe of the shared
  `mock_universe_fetchers` roster against the new pattern returned
  `nasdaq_all n= 3 UNFETCHABLE: ['DELISTED1']` /
  `us_all n= 17 UNFETCHABLE: ['DELISTED1']`.
- **Issue:** `tests/conftest.py`'s roster CSV carries `DELISTED1` — nine
  characters with no delimiter. No real US ticker has that shape: the longest
  delimiter-free symbol in the live 14,485-symbol `us_all` roster is **seven**
  (`ALLPDCL`, `ALLYPRA`). `_validate_symbols` therefore refused it, and had
  refused it under the *pre-fix* pattern too. The unconditional build-time
  filter correctly drops it, which broke five tests:
  `test_nasdaq_fetcher_filters_exchange_assettype_currency`,
  `test_us_equity_fetcher_filters_nyse_nasdaq_amex_and_excludes_others`,
  `test_nasdaq_roster_exchange_filter_and_symbol_set_are_unchanged` (D-02's
  exact-symbol-set lock), `test_get_symbols_in_range_keeps_post_2006_delistings`
  and `test_each_chunk_is_sized_on_the_pinned_whole_range_symbol_count`.
- **Fix:** renamed the fixture literal to `DLIST1` (6 chars) across
  `tests/conftest.py`, `tests/test_universe.py` and
  `tests/test_constituent_panel.py`, with the constraint recorded as a comment
  at the fixture row so a future >7-char fixture symbol is not reintroduced.
- **Why not the alternative:** keeping `DELISTED1` and relaxing the assertions
  would have deleted the meaning of D-02's exact-set lock *and* made three
  delisting tests pass for the wrong reason — `test_universe.py:292`
  (`assert "DELISTED1" not in symbols`) would have gone green because the
  symbol no longer existed anywhere, not because the date filter worked. That
  is this project's recorded failure mode, ten times over.
- **Turned into a permanent guard:** the Task-3 reconciliation test now runs
  against the shared conftest roster as well as the measured payload, so the
  fixture vocabulary itself is pinned and this class of fixture drift fails
  loudly next time.
- **Files modified:** `tests/conftest.py`, `tests/test_universe.py`,
  `tests/test_constituent_panel.py`
- **Commit:** `0526974`

**2. [Rule 3 - Blocking] Dead `import re` in `base/acquisition.py`**

- **Found during:** Task 1. Removing the standalone `re.compile` left `re`
