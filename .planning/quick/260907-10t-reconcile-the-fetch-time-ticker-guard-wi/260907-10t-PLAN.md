### The three ambiguous symbols -- the call, and its evidence

The planning brief left `NSPR-WSB`, `OXY-WSW` and `UA-C-W` to be decided here.
Evidence is the symbol FAMILY each belongs to in the live table:

```
NSPR: ['NSPR', 'NSPR-WS', 'NSPR-WSB']
OXY:  ['OXY',  'OXY-WS',  'OXY-WS-W', 'OXY-WSW']
UA:   ['UA',   'UA-C',    'UA-C-W']
```

- **`UA-C-W` is LEGITIMATE** -- it goes with the retained multi-suffix set, not
  the malformed set. `UA-C` is one of the docstring's own named verified
  surviving class shares, so `UA-C-W` is that class-C share's when-issued line.
  Its shape `2-1-1` is byte-identical to `DB-R-W`. The brief listed it as
  malformed; the family evidence says otherwise, so it is admitted, and it is
  a fixture literal in Task 1 precisely so this call is re-checkable.
- **`OXY-WSW` is MALFORMED (dropped)** -- the table carries BOTH `OXY-WS-W`
  and `OXY-WSW`. The properly-delimited form of the same warrant is already in
  the roster, so dropping the un-delimited variant loses no security at all.
- **`NSPR-WSB` is MALFORMED (dropped)** -- and this one has a real, stated
  cost: unlike OXY there is no `NSPR-WS-B`, so dropping it loses one microcap
  warrant series. Accepted deliberately: admitting it requires widening every
  suffix segment from `{1,2}` to `{1,3}`, i.e. weakening the bound for all
  14,485 symbols on the evidence of 2 outliers (one of them redundant),
  against 77 symbols that follow the delimiter convention. Hard constraint 3
  says a widening must be argued for rather than assumed; a 50% loosening of
  the segment bound to save one redundant and one microcap warrant does not
  clear that bar. **Recorded as a named, measured, carried-forward finding**
  in the same idiom 260906-eme used for the retained warrants.

Verified against the live table -- the chosen pattern
`^[A-Z0-9]{1,7}(?:[.-][A-Z0-9]{1,2}){0,2}$` rejects exactly and only:

```
us_all     (6): CAPTW(EXP20260807), DTV_1, ETP-, NSPR-WSB, NXT(EXP20091224), OXY-WSW
nasdaq_all (7): -P-HIZ, ASRV 8.45 06-30-28, CAPTW(EXP20260807), CHNG 6,
                DTV_1, NSPR-WSB, NXT(EXP20091224)
```

### Hard constraint 2 -- provenance, VERIFIED not assumed

The brief required establishing the truth rather than trusting the comment.
**The comment is false.** `base/acquisition.py:34` is a standalone
`re.compile` of the same literal, and `grep -n "_validate_symbols\|_TICKER_PATTERN"
base/acquisition.py` returns only lines 34, 622, 650, 654 -- there is **no
local import anywhere in the method**, contradicting both the module comment
("Imported from `acquisition/universe.py` rather than re-declared", "The import
is deferred to `_validate_symbols`") and the docstring ("The pattern IS
`acquisition/universe.py`'s `_WELL_FORMED_TICKER`"). Two copies of one literal,
already free to diverge; widening one alone would leave the comment asserting
something false in a second way.

So the plan's approach follows from that: **share one compiled object.** Not
two copies kept equal by a test -- identity, so a re-declaration is impossible
rather than merely discouraged.

### Where the shared pattern may live -- forced by an existing test

Neither module may import the other:

- `base/acquisition.py` importing `acquisition.universe` inverts the layering
  (its own comment, still correct on this point).
- `acquisition/universe.py` importing `base.acquisition` **breaks a live
  test**: `tests/test_volume_guard.py:739` reads universe.py's source and
  asserts the literal string `"base.acquisition"` does not appear, because the
  volume guard's "refuse before any client exists" property is structural.

`enums/data.py` is the shared lower module -- already imported by both
(`base/acquisition.py` takes `RAW_HIVE_KEYS`/`Vendor`; `acquisition/universe.py`
takes `UniverseCategory`) -- and it is already the established home for exactly
this idiom: its own header reads "Locked literal token sets shared by
base/config.py, config/__init__.py, and base/acquisition.py", and D-19 put
`RAW_HIVE_KEYS` there so "the writer and the reader cannot drift". Same reason,
same place.

### Hard constraint 3 -- the two patterns do NOT both widen

Only the fetch-side pattern widens. `acquisition/universe.py:_WELL_FORMED_TICKER`
stays exactly as it is, because it does a different job on a different input:
it validates **Wikipedia-scraped change-log cells** for the S&P 500 / Nasdaq-100
membership fetchers, where its documented targets are "an interior delimiter,
an embedded space, lowercase, an over-long cell", and an interior delimiter
specifically means "two cells were merged, i.e. a parser regression".

A three-segment cell is that exact regression signal on that input. And the
input vocabulary cannot need the widening: index constituents are common stock,
and **both constituent categories have 0 pattern failures across 1,151 symbols**
(measured above). Widening it would delete a real guard to buy nothing. The two
patterns are therefore deliberately different, and Task 3 pins that difference
with its reason so a later reader cannot "align" them.
