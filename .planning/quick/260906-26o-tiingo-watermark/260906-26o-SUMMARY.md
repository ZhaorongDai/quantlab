# Quick Task 260906-26o: Tiingo Range-Aware Watermarks + Quota Abort Summary

**Watermarks now record the covered date range instead of only its end, so widening `--start-date` re-fetches instead of silently shipping inconsistent per-symbol history; quota exhaustion is classified as a global, recoverable condition that stops dispatch rather than burning ~10,000 symbols as fast-failing requests.**

## Accomplishments

- **D-03 fixed.** `_read_coverage()` / `_coverage_status()` / `_covers()` replace the end-date-only skip predicate. A symbol is covered only when its `last_date` matches AND its recorded covered start is known and no later than the requested start. The regression test asserts the widened start is what actually reaches the vendor, not merely that a call happened.
- **D-04 honoured without guessing.** A legacy sidecar reads back with `start_date=None`, and no code path fills it from `config.start_date` or any other fallback. `stamp_watermarks(start_date)` takes the value from its caller, fills only absent starts, never overwrites a recorded one, and issues zero network requests. A dedicated test pins `start_date is None` so a future "helpful" default turns the suite red.
- **D-01 preserved.** Same-window and narrowed-window re-runs still issue zero vendor calls; the 4,621 downloaded symbols are not re-fetched by default.
- **D-05 fixed.** `_is_quota_error()` classifies on 429 status *or* the durable `"request allocation"` token, walking `exc.args[0].response` because `RestClientError` genuinely has no `.response`. A `threading.Event` checked as `_attempt`'s first statement stops vendor requests for every already-queued task. The quota condition is excluded from `_failures.json`, and the run reports completed/remaining counts and that watermarks are preserved.
- **D-06 delivered.** A bounded resume loop that recomputes `pending` from disk each pass, driven by three `config.kwargs` knobs via the existing `_knob` idiom, off by default, with an overridable `_sleep()` seam.
- **The falsified paid-tier claim was corrected** in the `ConcurrentTiingoAcquisition` docstring, rather than left to mislead the next reader.

## Decisions Made

- **The un-stamped legacy default is skip-and-report**, with `legacy_watermarks="refetch"` as the opt-in escape hatch. Assuming a start is forbidden (D-04) and re-fetching by default violates D-01; what made the original failure dangerous was the *silence*, not the skip, so the fix is to make the skip loud and name its cure. Argued in the plan's `<decision_record>` and restated in `_coverage_status`'s docstring so the reasoning is met before the branch.
- **403 stays out of the quota status set.** Tiingo returns 403 for plan-restricted single tickers; treating it as global would let one restricted ticker abort a 15k-symbol run. A 403 carrying the allocation wording is still caught textually, so the stricter set costs nothing.
- **The result generator is drained, not abandoned.** Breaking out mid-iteration leaves joblib worker teardown to GC; draining is deterministic and nearly free once every remaining task is a no-op. The tqdm description switches to `"QUOTA EXHAUSTED -- draining, not fetching"` so a racing bar cannot read as success.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `refresh()` would have been forced into an endless re-fetch by a widened `--start-date`**

- **Found during:** Task 1
- **Issue:** The plan specifies `_covers(symbol)` and says to swap `_run`'s pending computation onto it for both entry points. But `refresh()` requests `[watermark_last_date, end_date]` per symbol and never `config.start_date`. Judging refresh against a widened `config.start_date` would therefore mark every symbol pending on *every* run, while the re-fetch it triggered could not close the gap and the carried-forward covered start would not move — an endless, silent quota burn, i.e. a new instance of the exact class of defect this task exists to remove.
- **Fix:** `_covers(symbol, from_watermark=False)`. When `from_watermark` is true the predicate short-circuits to the end-date-only rule, preserving `refresh()`'s exact pre-existing semantics. Widening the covered range is `download()`'s job, and the reasoning is documented on `_coverage_status`.
- **Files modified:** `acquisition/tiingo.py`
- **Verification:** `tests/test_tiingo_acquisition.py#test_concurrent_refresh_is_not_forced_to_re_fetch_by_a_widened_start`
- **Committed in:** `b832e5b`

**2. [Rule 2 - Missing functionality] `--dry-run` could not answer the question Task 3's checkpoint asks it**

- **Found during:** Task 1
- **Issue:** Task 3's `<how-to-verify>` steps 2 and 3 instruct the user to run `--dry-run` and read the covered/skipped, legacy, and re-fetch counts. Task 1's action listed only the stamping and policy flags as glue, and `--dry-run` exited before ever classifying a watermark — so as written, the checkpoint's own verification steps would have printed nothing about coverage, and step 3's alternative (a real run with `--start-date 2010-01-01`) would have started re-downloading 4,638 symbols.
- **Fix:** `ConcurrentTiingoAcquisition.coverage_report()` — a read-only method sharing `_partition_by_coverage` with the real run, so the dry run and the run it predicts cannot disagree — plus `_print_coverage()` glue in the dry-run block. It issues zero price requests. Because `TiingoAcquisition.__init__` demands the credential at construction (a pre-existing, tested property that was deliberately not weakened), the report is skipped with an explanatory line when `TIINGO_API_KEY` is absent, preserving the documented "`--dry-run` needs no API key" behaviour.
- **Files modified:** `acquisition/tiingo.py`, `ingest_us_equity.py`
- **Verification:** `tests/test_tiingo_acquisition.py#test_coverage_report_counts_without_issuing_a_single_vendor_call`; `uv run python ingest_us_equity.py --help` exits 0
- **Committed in:** `b832e5b`
