<docstring_template>
## The convention, once

Follows `base/factor.py::config`, the existing in-repo precedent. This exact
template was written out as a prototype module at planning time and run through
the gate: **0 failures**, covering all seven shapes below.

### Shape 1 — class

```python
class DataBackend(ABC):
    """数据存储后端的抽象基类，把"数据存在哪里"与"数据是什么"解耦。

    子类各自实现一种存储介质（Zarr、Parquet），上层的 Dataset / Factor
    只持有一个 DataBackend 实例，因此更换存储介质不需要改动上层代码。
    """
```

A class gets a summary plus, where it earns one, a short rationale paragraph.
Classes need no `Args:` — constructor parameters are documented on `__init__`.

### Shape 2 — `__init__`

```python
    def __init__(self, path: str, overwrite: bool = False):
        """初始化后端并记住目标存储路径，但不在构造时读取任何数据。

        Args:
            path (str): 存储根目录路径。
            overwrite (bool): 为 True 时允许写入覆盖同路径已有数据，默认 False。
        """
```

No `Returns:` — `__init__` returns nothing. Note the summary says what
construction does and does NOT do; it does not narrate the two assignments.

### Shape 3 — plain function with args and a return

```python
    def read(self, path: str, **kwargs) -> Self:
        """从磁盘读取数据到内存，返回自身以便链式调用。

        Args:
            path (str): 存储路径。
            **kwargs (object): 透传给底层存储引擎的读取参数。

        Returns:
            Self: 后端自身。
        """
```

`**kwargs` and `*args` ARE parameters and get entries, written with their stars.

### Shape 4 — `@property`

```python
    @property
    def data(self) -> xr.Dataset:
        """已读入内存的数据集；未读取前访问会报错，避免静默返回空值。

        Returns:
            xr.Dataset: 当前后端持有的数据集。
        """
```

A getter has no parameters, so it gets **no `Args:` section**. It does return a
value, so `Returns:` is required. A setter takes one parameter and returns
nothing: `Args:` only, no `Returns:`.

### Shape 5 — generator

```python
    def _batches(self, symbols: list[str], size: int) -> Iterator[list[str]]:
        """把标的列表切成固定大小的批次，避免单次请求超出供应商上限。

        Args:
            symbols (list[str]): 待切分的标的列表。
            size (int): 每批标的数量。

        Yields:
            list[str]: 一个批次的标的列表。
        """
```

`Yields:` documents the *yielded element* type, not the `Iterator[...]` wrapper.

### Shape 6 — ABC abstract method

```python
    @abstractmethod
    def get_xarray_dataset(self, indexes: list[str]) -> xr.Dataset:
        """把后端数据转换为规范形状的 xarray 数据集，供上层各层统一消费。

        Args:
            indexes (list[str]): 作为坐标轴的维度名，流水线固定传
                ``["timestamp", "symbol"]``。

        Returns:
            xr.Dataset: 以 indexes 为坐标的数据集。
        """
        ...
```

**The structural edit to be careful with.** `base/backend.py` writes these as
one-liners — `def get_xarray_dataset(self, indexes: list[str]) -> xr.Dataset: ...`
— with the body on the signature line. Adding a docstring means breaking that
into three lines and keeping the trailing `...` as the body. Dropping the `...`
leaves a function whose body is only a docstring; that still parses and still
works as an abstract method, but it changes the file's shape gratuitously. Keep
the `...`. This is the single most mechanical-error-prone shape in the plan.

### Shape 7 — augmenting an EXISTING docstring (decision 2)

```python
    def head(self, path: str, n: int) -> pl.LazyFrame:
        """有界读取：最多返回存储中的 n 行，用于在不加载全量数据的前提下探查结构。

        A BOUNDED read: at most `n` rows of the store at `path`.

        The bounded twin of `get_lazyframe()`. The returned lazyframe carries
        the same column names and the same dtypes `get_lazyframe()` would
        return -- real dtypes matter, because callers run real expressions
        over this probe to learn what those expressions produce.

        Args:
            path (str): 存储路径。
            n (int): 最多读取的行数。

        Returns:
            pl.LazyFrame: 至多 n 行的探查结果。
        """
```

**Layout, decided here because the brief left it ambiguous:** Chinese summary
first → existing English prose, verbatim, as the extended description →
`Args:`/`Returns:`/`Raises:` last. This is standard Google layout (summary,
extended description, sections) and it means the preserved prose is never
interleaved with anything.

Three rules for this shape:

1. **Not one word of the existing English is edited, reordered or re-wrapped.**
   Copy it through untouched. This is where `base/acquisition.py` and
   `acquisition/alpaca.py` record measured facts and rejected alternatives.
2. **Never add a second `Args:` or `Returns:`.** Where the docstring already has
   one (there are 8 such docstrings, listed in `<planning_measurements>`),
   augment it in place: add the missing type in parens, add a Chinese gloss
   alongside the English. Two `Args:` blocks is malformed Google style and the
   gate rejects it.
3. The Chinese summary is a summary — 1 to 2 lines. It does not attempt to
   translate the English body.

### Type derivation (DOC-05)

In priority order:

1. **The parameter is annotated** → copy the annotation verbatim into the
   parens. `list[str]` stays `list[str]`; do not simplify it to `list`, do not
   expand `Self`.
2. **Unannotated, but the type is determined by the code** → derive and write
   it. A default value gives it (`overwrite=False` → `bool`). The context
   manager protocol gives it (`utils/timer.py::__exit__`'s three parameters are
   `type[BaseException] | None`, `BaseException | None`, `TracebackType | None`).
   The body gives it (`utils/module.py::get_cls_from_path` returns the result of
   an attribute lookup on an imported module — that is `type`).
3. **Unannotated and genuinely undeterminable** → write the loosest type you can
   defend from the code, and put the real constraint in the Chinese description.
   `config (dict): 由 to_dict() 序列化出的配置字典，必须含 name 键。` is honest;
   `config (DatasetConfig)` when the code only ever subscripts it is a guess.
   `Any` is an acceptable answer when the description carries the duck-typing
   contract. **Never name a class you cannot point to in the code.**

**Do not touch the signature.** Adding, removing or changing a type annotation
is out of scope and is a behaviour change (it alters what `inspect.signature`,
`typing.get_type_hints` and every source-scanning test see). Types go in the
docstring only.
</docstring_template>

## `tests/test_docstring_convention.py`

Built and validated at planning time: the rule set below produces exactly **890
failures** on the current tree and **0** on the seven-shape prototype.

**Discovery.** `Path(repo_root).rglob("*.py")`, excluding any path with a
dot-prefixed part (`.venv`, `.git`, `.planning`, `.gsd`), anything under
`tests/`, and any `test_*.py` or `conftest.py`. Measured to yield exactly the
same **61 files** as `git ls-files '*.py'` minus tests — so no subprocess call
is needed and the test works in a bare checkout.

**Units.** Every `FunctionDef`, `AsyncFunctionDef` and `ClassDef` reached by
`ast.walk`, **except** those whose direct parent is a function (nested closures;
there are exactly 2, and a closure is an implementation detail of its enclosing
function, which is itself gated).

**Rules.** For each unit:

| Rule | Condition |
|---|---|
| `MISSING` | `ast.get_docstring(node)` is falsy |
| `SUMMARY-NOT-CHINESE` | the first blank-line-delimited paragraph contains fewer than 4 CJK characters (`[一-鿿]`) |
| `DUP-<section>` | `Args`/`Returns`/`Raises`/`Yields` appears more than once as a bare `^\s*Name:\s*$` header |
| `NO-ARGS` | the unit is a function with at least one parameter other than `self`/`cls` (counting `*args`/`**kwargs`) and has no `Args:` section |
| `ARGS-MISSING` | the `Args:` section does not name every such parameter |
| `ARGS-UNTYPED` | a named parameter's entry carries no `(type)` in parentheses |
| `NO-RETURNS` | the function is non-generator and either annotated with a return type other than `None`, or contains a `return <expr>` — and has no `Returns:` section |
| `NO-YIELDS` | the function contains `yield`/`yield from` and has neither `Yields:` nor `Returns:` |

Classes are exempt from the `Args`/`Returns`/`Yields` rules — a class documents
its construction on `__init__`.

**The ratchet.** A module-level `_CONVERSION_ALLOWLIST: frozenset[str]` of
not-yet-converted module paths. Two tests:

1. `test_every_non_test_unit_carries_a_google_style_chinese_docstring` — collects
   failures across all discovered modules, drops those whose file is in the
   allowlist, and asserts the remainder is empty. Its failure message lists
   `path:lineno:name — RULE`, capped at 40 lines, and states the total.
2. `test_the_conversion_allowlist_only_shrinks` — asserts (a) every allowlist
   entry names a file that exists and is discovered by the walker, so a rename
   cannot leave a stale exemption behind, and (b) every allowlist entry still
   has at least one failure, so a file that has been converted CANNOT stay
   exempt. This is what makes the ratchet monotone: a converted file is forced
   out of the allowlist, and once out it can never go back in without this test
   or test 1 going red.

**A `if __name__ == "__main__":` block** prints the full report grouped by file
with a `REMAINING: N` total line. This is the countable entry point each task's
`<verify>` reads, and it is why the gate is one file with two entry points
rather than a script plus a test that drift apart.

**Suite counts, exactly:** 425 today → **427** from T1 through T12 (two tests
added) → **426** after T13 retires test 2 with the allowlist.

## How the gate could pass for the wrong reason

Analysed against the rule set above. Task-specific instances are named in each
task's `<gate_evasion>`.

- **`"""中文"""` and nothing else.** Caught for any function with a parameter
  (`NO-ARGS`) or a return value (`NO-RETURNS`) — which is 586 of the 591 units.
  It survives only on a no-parameter, no-return method. The 4-CJK-character floor
  rejects the degenerate `"""中文"""` (2 chars) and `"""值"""` (1 char); a
  4-character Chinese summary of a no-arg mutator is a real summary.
- **Filler glosses.** `x (int): 参数` satisfies every mechanical rule. There is no
  regex that reliably distinguishes a lazy gloss from a terse-but-correct one,
  so the gate does not try. Instead every task's `<done>` requires the executor
  to have re-read its own batch for the CLAUDE.md WHY-over-WHAT rule, and the
  bare fillers `参数`, `返回值`, `无`, `待补充`, `TODO`, `见上` are forbidden as a
  complete description. **This is the gate's known limit and it is stated so
  nobody mistakes a green gate for a good docstring.**
- **A restated-code summary.** `设置 x 的值` above `self.x = x` passes everything.
  Same mitigation: it is a review obligation in `<done>`, not a gate rule.
- **A type copied wrong.** `path (int)` on a `path: str` parameter passes — the
  gate checks that parens exist, not that the type is right. Mitigated by rule 1
  of type derivation (copy the annotation verbatim, do not retype it from
  memory), which makes the correct action also the cheapest one.
- **Widening the allowlist.** Blocked by ratchet test 2: an allowlist entry for a
  file with zero failures is itself a failure.
