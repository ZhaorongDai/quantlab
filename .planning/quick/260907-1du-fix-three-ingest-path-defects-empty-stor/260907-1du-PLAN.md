<design_decisions>

## Defect 1 — chosen fix: a pre-probe of the stored symbol axis. NARROW.

`_reset_symbols()`'s fallback fires on `FileNotFoundError` from `read()`. An empty store does not raise there — `read()` succeeds and then `_filter()` -> `filter_by_symbol` -> `.sel({"symbol": [...]})` raises `ValueError` from *inside* `read()`, so no `except` clause on `read()` can ever see it. The condition must therefore be tested BEFORE `read()` is called.

`BaseDataset._stored_symbol_axis(store_path)` (base/data.py:437) already answers exactly this question, coordinate-only and lazily, and is already used against this same store by `_reconcile_new_listings`. It returns `None` for an absent store or an absent coordinate, and `[]` for a present-but-empty one. Both are falsy, and both correctly mean "no usable symbol axis here".

**`read()` is not touched.** Its `Path(path).exists()` guard and its exact `FileNotFoundError` message on both backends stay byte-identical (locked by `tests/test_backend_head.py::test_head_raises_immediately_on_an_absent_store`, quick task 260906-w3t). The inner `try/except FileNotFoundError` around `read()` stays too — it is still reachable if the store is removed between the probe and the read.

Measured live at planning time (`scratchpad/probe3.py`):
- baseline: `BASELINE RED: ValueError could not convert string to float: np.str_('AAPL')`
- with the pre-probe: `FIXED: symbols = ('AAPL',)` and `AFTER SAVE dims: {'timestamp': 2, 'symbol': 1} symbol dtype: StringDType()` — the empty store is correctly replaced by `save()`'s `mode="w"` write.

## Defect 2 — chosen fix: a ONE-SHOT pending-panel handoff. Does NOT reopen D-05/RV-02.

The duplicate is: the construction-time fallback materialises the whole panel, and the caller then asks for the same panel again microseconds later. **The fix hands the constructor's panel to the first `from_raw_data()` call and then forgets it.**

What this does NOT change, stated explicitly because RV-02 exists to prevent exactly this drift:
- Name/symbol derivation still happens EAGERLY, at construction time, from a full raw materialisation. D-05's construction-time-names contract is untouched.
- `from_raw_data()`'s signature is unchanged — `from_raw_data(self) -> Self`, no new parameter.
- With `symbols=None` (the `ingest_us_equity.py` chunked path) `_reset_symbols()` never fires, no marker is ever set, and behaviour is byte-identical to today.
- When the store is POPULATED, `_reset_symbols()` takes the `read()` branch and sets no marker, so the caller's `from_raw_data()` converts exactly as it does today. The skip only ever applies to a panel the constructor itself just built.

**Rejected alternatives, and why:**
- *Deferring name derivation / making `_reset_symbols()` cheap via `_raw_axes_in_range()`* — this is precisely the D-05 reopening the planning brief forbids doing as a side effect, and it would also leave the backend unpopulated after construction, a real behaviour change.
- *A general `from_raw_data()` result cache keyed on a config fingerprint* — needs a subclass-aware fingerprint of everything `_raw_data_to_xr()` reads (raw root, vendor, frequency), which is new unverified surface, and it turns a bug fix into a caching policy that can go stale.
- *A conditional at the two ingest call sites* — the construction-time conversion only happens when the store is absent/empty, so the caller cannot statically know whether to skip; and the logic would be duplicated across `ingest_alpaca.py` and `ingest_tiingo.py`.

The marker is guarded on THREE facts, all cheap: (a) it exists, (b) the backend still holds the very object the constructor produced (identity, not equality), and (c) the config's `(start_date, end_date)` still match what the constructor converted. It is cleared on read whether or not it is used, so it is valid for exactly one call. Named narrowing: a caller who mutates `config.raw_data_dir_path` in place between construction and the first `from_raw_data()` gets the constructor's panel. Nothing in this repo does that, and it is stated in the docstring rather than left implicit.

## Defect 3 — chosen fix: a structural-null mask. HOW IT TELLS THE TWO APART.

The dense `[timestamp, symbol]` panel is a cartesian product (D-06), so a symbol that did not trade in a given minute is NaN in EVERY variable at that cell. That is the design, not an anomaly.

- **structural mask** = logical AND over the caller's `required_columns` of `isnull()`. True where the bar does not exist at all.
- **unexpected nulls for a column** = `isnull() & ~structural_mask` — nulls in cells where a bar DOES exist.

This is exactly the discrimination hard constraint 2 demands:
- `trade_count` null only where the bar is absent -> 0 unexpected -> silent.
- `vwap` null everywhere while bars exist -> unexpected == the observed-cell count -> WARNS, and the count it reports is now the count that actually matters.

Verified live (`scratchpad/probe4.py`): `structural cells: 1`; `trade_count raw nulls: 1 unexpected: 0`; `vwap raw nulls: 4 unexpected: 3`; `close raw nulls: 1 unexpected: 0`.

Two deliberate widenings, both closing blind spots rather than opening them:
- REQUIRED columns are now null-checked too (via the same mask), so `open` missing on a bar where `close` exists finally warns. Today it is silent — measured.
- The mask is built from the `required_columns` ARGUMENT, not the module constant, because `dataset/spot.py:SpotKlineDataset._clean()` passes Title-Case `("Open","High","Low","Close","Volume")`. A hardcoded mask would raise `KeyError` on every Binance ingest.

A column whose dims differ from the mask's falls back to the plain null count rather than broadcasting into a meaningless larger array.
</design_decisions>
