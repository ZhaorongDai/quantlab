<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Local script &lt;-&gt; Tiingo REST API | `TiingoClient` sends the API key over HTTPS to a third-party service; the key itself must never live in files that cross the local-repo &lt;-&gt; public-GitHub boundary |
| Committed source &lt;-&gt; public GitHub repo (`origin` = github.com/ZhaorongDai/quantlab.git) | Anything committed here is already public; this is the boundary the leaked key crossed |
| `QUANTLAB_DATA_DIR` / `QUANTLAB_NASDAQ_STOCKS_PARQUET` / `QUANTLAB_CHECKPOINT_PATH` env vars &lt;-&gt; filesystem writes/reads | Developer-controlled input that determines where the pipeline reads/writes data and checkpoints |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01-01 | Information Disclosure | `scripts/download_stock_data_from_tiingo.py` | mitigate | Remove the hardcoded key literal; read exclusively from `TIINGO_API_KEY` env var (Task 1). Closes the "new commits can never re-leak this specific pattern" risk; does not retroactively scrub the already-public key (handled separately in 01-05 via user key rotation, since that key is already compromised regardless of this fix). |
| T-01-01-02 | Information Disclosure | any other `.py` file in the repo | mitigate | Executor should `grep -rn` for other hardcoded-secret-shaped literals (`api_key\s*=\s*['"][A-Za-z0-9]{16,}`, `token\s*=`, `secret\s*=`) across the repo while making this change, as a sanity check; INTEGRATIONS.md's audit found none besides the Tiingo key, but this task's fix is the natural checkpoint to double-check. |
| T-01-01-03 | Tampering | `QUANTLAB_DATA_DIR` / `QUANTLAB_NASDAQ_STOCKS_PARQUET` / `QUANTLAB_CHECKPOINT_PATH` env vars | accept | Single-user local research tool with no untrusted/multi-tenant input; these env vars are developer-controlled, same trust level as running arbitrary local Python already implies. |
</threat_model>
