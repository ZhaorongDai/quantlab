## Warnings

### WR-01: 声称「段末未平仓数逐段相加等于 whole 的 Total Open Trades」，这个说法不成立

**File:** `quantlab/base/backtest.py:1488-1493`、`example/backtest.md:355-356`
**Issue:** 新写的 docstring 说：段内 `closed_trade_count` 逐段相加等于 `whole["Total Closed Trades"]`，「段末未平仓数同理——两边对得上账，这是刻意维持的性质」。`example/backtest.md:356` 也写了「段末未平仓数同理」。但 `open_trade_count` 的定义是**每段末尾**仍未平仓的持仓（第 1517-1521 行对每个 `end` 各数一次）。举例：样本内段末持有、到样本外才平仓的持仓，会计入 `in_sample.open_trade_count`；而 `whole["Total Open Trades"]` 只数整个窗口最后一根 bar 上仍未平仓的持仓。所以一般来说 `in_sample.open_trade_count + out_of_sample.open_trade_count != whole["Total Open Trades"]`。现有测试 `test_slice_order_counts_partition_the_whole_run` 锁住的其实是另一件事：只有最后那段样本外（它的末尾就是窗口末尾）的 open 数等于整段的 open 数。它没有锁「相加相等」，注释里也写明了这一点。文档和测试的说法互相矛盾。更要命的是，这条错误声明被写成「刻意维持的性质」，下一个读到它的人如果据此加上相加断言，测试会变红，他可能会反过来去「修」源码。
**Fix:** 两处都改成准确的表述，例如：
```text
段内 closed_trade_count 逐段相加等于 whole["Total Closed Trades"]（段不重叠且铺满窗口）；
open_trade_count 是各段末尾的快照，只有末尾与窗口末尾重合的那一段等于 whole["Total Open Trades"]，
各段相加不等于整段。
```

### IN-02: `_delta` 声称 "must never raise"，但 `math.isfinite` 对超大 int 或 Fraction 会抛 OverflowError

**File:** `quantlab/utils/backtest_report.py:592-599`
**Issue:** `numbers.Real` 包括 Python `int` 和 `fractions.Fraction`。`math.isfinite(10**400)` 会先转成 float，实测抛出 `OverflowError: int too large to convert to float`。真实指标里几乎不会出现这样的值，但这个函数是在暂存目录里运行的，文档又明确承诺「绝不抛异常」，而实现只靠类型判断来兑现这个承诺。
**Fix:**
```python
    for value in (later, earlier):
        if isinstance(value, bool) or not isinstance(value, numbers.Real):
            return None
        try:
            if not math.isfinite(value):
                return None
        except (OverflowError, TypeError, ValueError):
            return None
    try:
        return later - earlier
    except Exception:
        return None
```

### IN-03: 有限的 np.float32 差值同样绕过 `.6g` 格式化，deferred-items.md 说「delta 列不受影响」只对了一半

**File:** `quantlab/utils/backtest_report.py:565-566`、`.planning/phases/03.8-.../deferred-items.md`
**Issue:** `np.float32(0.3) - np.float32(0.1)` 的结果仍然是 `np.float32`，不是 `float` 的子类，会走 `_cell` 的 `str(value)` 分支，渲染成 `0.20000002`。`_delta` 的 `math.isfinite` 只保证 NaN/inf 会显示成破折号，管不到有限值的格式化。这和已记录的 deferred 项是同一个根因，这里不重复报告；需要改的是 deferred-items.md 里「delta 列不受影响」这句话，它应该只针对非有限值。
**Fix:** 修 deferred 项时（`_cell` 的浮点分支改为判断 `numbers.Real`，并排除 bool 和 int），差值列会一起修好；同时更正 deferred-items.md 里的那句话。

### IN-04: 差值列对「量」类指标的差值会被段长度混淆

**File:** `quantlab/utils/backtest_report.py:633-638`
**Issue:** `order_count`、`fees_paid`、`traded_notional`、`closed_trade_count`、`turnover.sum` 都是随段长度累加的量。样本内和样本外的 bar 数通常相差很大（在 `run_cv` 拼接曲线里，样本内只有每折开头的几根 bar），它们的差值主要反映长度差，不是表现差。D-01 已经明确选择「按类型全部做差」，表头也只写了算式，所以这不算缺陷。但读者很容易把 `order_count` 的差值误读成交易活跃度的变化。
**Fix:** 可选：在 `_report_notes` 里加一条说明，指出差值列对计数和求和类指标会受两段长度不同的影响（note 文本不要含 `<>&"'`）。

### IN-05: 整年都没有有限收益时，热力图会直接少掉那一年的行，而且看不出来

**File:** `quantlab/utils/backtest_report.py:441`
**Issue:** `years` 只取 `dropna()` 之后还剩下的年份。如果中间某一年的收益全是 NaN，这一年就不会出现在 y 轴上。y 轴是 category 轴，2021 会直接接在 2019 后面，读者看不出中间缺了一年。这和「没覆盖的月份留空，不伪造」的原则不一致。现实中净值连续时基本不会发生。
**Fix:** 用 `range(years[0], years[-1] + 1)` 生成连续的年份行，缺失的年份整行填 None。
