  <behavior>
    Fed through `write_backtest_report(metrics=...)` as RAW objects (never pre-converted):
    - Two finite floats in both slice blocks -> the cell renders their difference.
      `{"in_sample": {"m": 1.0}, "out_of_sample": {"m": 3.5}}` -> delta cell `2.5`.
    - Two ints -> their integer difference.
    - A `bool` pair (`True` / `False`) -> a dash, NOT `1`.
    - Either operand `float("nan")` or `float("inf")` or `np.float64("nan")` -> a dash.
    - A `pd.Timedelta` pair -> a dash. A `pd.Timestamp` pair -> a dash. `pd.NaT` -> a dash.
    - A `str` pair -> a dash (and nothing raises; `str - str` would raise TypeError).
    - A key present only in `whole` (both slice operands absent) -> a dash, nothing raises.
    - `in_sample=None` (block present, value None) -> the column still appears and every
      delta cell is a dash; the page is still written.
    - A mapping carrying only `{"whole": ...}` -> the table has THREE header cells
      (`metric`, `whole`) and no delta column at all.
    - Mixed types across the two blocks (float vs Timedelta) -> a dash.
  </behavior>

  <action>
Add the delta column to the report leaf. Everything dispatches on TYPE; no metric name
appears anywhere in this code.

**Imports:** add stdlib `numbers` to the first import group beside `html` and `math`
(`math` is already imported at line 67). Do NOT add `numpy` — the module docstring at
line 62 declares "stdlib, pandas, xarray and plotly only", and while
`test_the_module_is_a_leaf` only scans for `quantlab` imports, adding numpy would make
that docstring a lie. `numbers.Real` is chosen over `(int, float)` precisely so numpy
scalars are admitted without importing numpy: `isinstance(np.int64(5), int)` is False
while `isinstance(np.int64(5), numbers.Real)` is True. `np.bool_` needs no special case —
it is not a `numbers.Real`.

**New module constant** `DELTA_HEADER = "out_of_sample - in_sample"`, with a `#:` comment
recording that it deliberately states the ARITHMETIC rather than passing judgement: the
table cannot know whether a larger number is better for a metric it has never seen, so it
states the operation and lets the reader judge. This wording is what makes D-01's decision
to difference ratio metrics defensible.

**New helper** `_delta(later, earlier) -> object` returning `later - earlier` when BOTH
operands are finite real non-booleans, and `None` otherwise. Order of checks per operand,
and the order is load-bearing: test `isinstance(value, bool)` FIRST and return None (bool
is an int subclass, so `True - False == 1` would render as a plausible number); then
require `isinstance(value, numbers.Real)`; then require `math.isfinite(value)`. Return
`None` rather than a dash string — the caller renders it through `_cell`, which already
turns None into `DASH`. Give it a docstring stating: that it dispatches on type and never
on metric name (a rule keyed to `Sharpe Ratio` would be dead the day the metric set is
replaced); why `bool` is tested first; why `numbers.Real` rather than `(int, float)`; and
that it must never raise, because it runs inside the run's staging directory where an
exception costs the entire run.

**No `try/except` anywhere in this change.** The module's discipline is explicit
interception — guard, `.get`, early return — as modelled by `_add_drawdown_span` (lines
301-336), whose docstring states the reason. The predicate returning None on every
non-qualifying operand is what makes it total; `str - str` and `None - float` both raise
TypeError and are both excluded before any arithmetic happens.

**Wiring in `_metrics_section`:** after `columns` is built, compute
`show_delta = "in_sample" in present and "out_of_sample" in present`. Gate on `present`
MEMBERSHIP, not on truthiness: `present` is `[name for name in _BLOCKS if name in metrics]`
(line 460), so a block whose value is None is still "present" and yields `{}` — which is
correct, because a None `in_sample` should give None operands and a dashed delta. Gating on
truthiness instead would silently drop the column for exactly that case. Read both operands
with `.get` on BOTH levels — `columns.get("out_of_sample", {}).get(key)` — because
`columns` only holds the blocks in `present`.

When `show_delta`, append one `<td>` to the row's `cells` string and one `<th>` to
`headers`, using the same `"".join(...)` idiom already there. The delta cell must be a
plain `<td>...</td>` inside the same contiguous run of cells, because the test parser
`_cells` matches `((?:<td>[^<]*</td>)+)`. Keep `rows.append`'s exact six leading spaces.
Render the delta through `_escape(_cell(delta))` like every other cell — the header goes
through `_escape` too, even though it is a constant with no special characters.
