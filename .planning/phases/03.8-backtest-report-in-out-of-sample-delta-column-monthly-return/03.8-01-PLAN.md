<objective>
Switch the backtest's trade statistics to the POSITION view, totally and in one
vocabulary, and give the whole-window block the execution-activity count it loses
by doing so.

Purpose: the lot-level (vectorbt `exittrades`) view books every partial trim of a
holding as its own closed trade. Under equal-weight target-percent rebalancing only
a *winner* ever needs trimming, so the win rate is systematically overstated —
measured at ~6.5 points on two independent real runs (57.27% vs 50.74% / 50.81%).
The user chose the better number over the pair (D-02).

Output: `metrics.json` and `report.html` carry one trade vocabulary; `whole` gains
`order_count`; the nested `positions` block is gone; two docstrings, one report note
and one doc section that describe the retired design are rewritten in the same
change.

**This is the phase tracer.** It is the only deliverable that runs through every
layer this phase touches — engine (`_simulate`, `_engine_stats`) to base
(`_compute_metrics`, `_period_record_stats`) to the persisted `metrics.json` and the
rendered `report.html` — and it is verified end to end on a real `run()` before
plans 02 and 03 expand the report sideways. It also lands the metrics table's final
key set first, which is what lets plan 02's delta census assert an exact key set
instead of being written key-set-agnostic (see `<ordering_decision>`).
</objective>

<ordering_decision>
