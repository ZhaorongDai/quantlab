### 1. `quantlab/utils/backtest_report.py` — the generic metric-table walker (delta column)

**Analog:** itself, `_metrics_section` at lines 449-491. Exact current shape:

```python
def _metrics_section(metrics: dict | None) -> str:
    if not metrics:
        return ""
    present = [name for name in _BLOCKS if name in metrics]
    if not present:
        return ""

    columns = {
        name: _flatten(metrics[name]) if isinstance(metrics.get(name), dict) else {}
        for name in present
    }
    rows: list[str] = []
    seen: list[str] = []
    for column in columns.values():
        for key in column:
            if key not in seen:
                seen.append(key)
    for key in seen:
        cells = "".join(
            f"<td>{_escape(_cell(columns[name].get(key)))}</td>" for name in present
        )
        rows.append(f"      <tr><th>{_escape(key)}</th>{cells}</tr>")
    if not rows:
        return ""

    headers = "".join(f"<th>{_escape(name)}</th>" for name in present)
    return (
        "  <h2>Metrics</h2>\n"
        '  <table class="metrics">\n'
        f"    <thead><tr><th>metric</th>{headers}</tr></thead>\n"
        "    <tbody>\n"
        + "\n".join(rows)
        + "\n    </tbody>\n"
        "  </table>\n"
    )
```

Load-bearing facts a plan must copy rather than re-derive:

- **A missing key is already handled**, and this is the whole answer to Pitfall 3:
  `columns[name].get(key)` — a `.get`, never `[...]`. A block that is `None` becomes
  `{}` (line 465), so its column is all-`None`. The delta operands must be read the
  same way: `columns.get("in_sample", {}).get(key)`. Note `present` only contains
  blocks **present in the mapping**, so `columns["in_sample"]` can raise `KeyError`
  if the block is absent entirely — use `.get` on `columns` too.
- **The delta cell is appended to `cells`, and one `<th>` is appended to `headers`.**
  Both are built by the same `"".join(...)` idiom; keep it.
- **`rows.append` uses exactly six leading spaces** (`f"      <tr>..."`), and
  `_cells` in the test parses `r"<tr><th>([^<]+)</th>((?:<td>[^<]*</td>)+)</tr>"` —
  the delta cell must be a plain `<td>...</td>` in that same run of cells, or every
  existing `_cells`-based test silently changes arity. Expect to update the existing
  arity assertions: `test_an_unknown_metric_key_renders_and_raises_nothing` asserts
  `== ["1.5", "—", "2.5"]` (line 202) and
  `test_a_null_block_is_a_column_of_dashes_rather_than_being_dropped` asserts
  `[row[1] for row in cells.values()] == ["—", "—"]` (line 245). Both go red on a
  4th column — by design, they are the arity lock.

**Type-dispatch pattern to mirror** — `_cell`, lines 429-446. Note `bool` is tested
BEFORE `int`, which is the exact ordering the new `_delta` predicate needs:

```python
def _cell(value: object) -> str:
    if value is None:
        return DASH
    if isinstance(value, bool):
        return "true" if value else "false"
    if isinstance(value, int):
        return str(value)
    if isinstance(value, float):
        return DASH if not math.isfinite(value) else f"{value:.6g}"
    text = str(value)
    return text if text.strip() else DASH
```

`math` is already imported (line 67); `DASH = "—"` is the module constant (line 79).
Rendering the delta through `_cell` means `None` → dash for free — the new helper
should return `None` and let `_cell` do the rendering, not format a dash itself.

**Import discipline:** the module's imports are lines 66-73 (`html`, `math`,
`pathlib.Path`, `pandas`, `plotly.graph_objects`, `xarray`, `make_subplots`). Adding
stdlib `numbers` belongs in the first group with `html` / `math`. Adding `numpy`
would contradict the docstring's own declaration at line 62 ("stdlib, pandas,
xarray and plotly only").

### 2. `quantlab/utils/backtest_report.py` — the monthly series, figure, and page (heatmap)

**Analog:** `_add_monthly_returns`, lines 351-376. This is the source-of-truth for
how the series is derived — the heatmap must consume the identical five lines
(extract them into a shared `_monthly_series(returns)` rather than duplicating):

```python
def _add_monthly_returns(fig, returns: xr.DataArray | None) -> None:
    """Per-calendar-month compounded return of `returns`, as bars.

    Grouped with `index.to_period("M")` rather than a resample alias: the
    monthly alias was renamed (`M` -> `ME`) across pandas versions while
    `to_period` reads the same in both. ...
    """
    if returns is None:
        return
    series = returns.to_pandas().dropna()
    if series.empty:
        return
    index = pd.DatetimeIndex(series.index)
    monthly = (1.0 + series).groupby(index.to_period("M")).prod() - 1.0
    fig.add_trace(
        go.Bar(
            x=[period.to_timestamp() for period in monthly.index],
            y=monthly.values,
            name="monthly_return",
            hovertemplate="%{x|%Y-%m}<br>%{y:.2%}<extra></extra>",
        ),
        row=3,
        col=1,
    )
```

Four things to copy verbatim: the `returns is None` early return, the `.dropna()`
(without it an all-NaN month becomes a fabricated `0.0`), the `series.empty` early
return, and `index.to_period("M")`. Also copy the `name=` + `hovertemplate=` habit —
**every trace on the page carries a `name`**, locked by
`test_every_trace_carries_a_name` (line 311) and required by the persisted-report
parsers.

**How the single figure is currently emitted and embedded** — `write_backtest_report`
lines 222-225, the exact insertion surface for a second div:

```python
    div = fig.to_html(full_html=False, include_plotlyjs="cdn")
    Path(path).write_text(
        _document(title, summary, metrics, div, notes), encoding="utf-8"
    )
```

and `_document`, lines 523-551, whose body is a single f-string concatenation with
`div` inserted verbatim:

```python
    return (
        "<!DOCTYPE html>\n"
        '<html lang="en">\n'
        "<head>\n"
        '  <meta charset="utf-8">\n'
        f"  <title>{_escape(title)}</title>\n"
        f"  <style>{_STYLE}  </style>\n"
        "</head>\n"
        "<body>\n"
        f"  <h1>{_escape(title)}</h1>\n"

        f"{div}\n"
        f"{_metrics_section(metrics)}"
        f"{_notes_section(notes)}"
        "</body>\n"

```

The second div goes between `f"{div}\n"` and `f"{_metrics_section(metrics)}"` —
picture, picture, numbers, notes. `_document`'s docstring states the rule that
governs it: "`div` is plotly's own fragment and is inserted verbatim -- plotly owns
its escaping. Everything else on the page comes from the run and is escaped." The
second div is plotly's too, so it is likewise inserted raw; anything else added
(a `<h2>` caption) must go through `_escape`, matching `_summary_section` /
`_notes_section`, both of which escape every interpolated value.

Second figure must use `include_plotlyjs=False` — the first div's `"cdn"` already
loads plotly.js, and `test_the_report_is_one_self_contained_file_loading_plotly_from_the_cdn`
(line ~148-155) asserts both `[p.name for p in tmp_path.iterdir()] == ["report.html"]`
and `"cdn.plot.ly" in ...`.

**Do not add a 4th subplot row.** The existing figure is built at lines 164-170 with
`shared_xaxes=True`; a 4th row ties the three datetime axes to a categorical one
(RESEARCH Pitfall 6).

**Defensive discipline the new chart must follow** (the `.get`-everything /
drop-bad-input idiom, since an exception here deletes the entire run). The canonical
in-module example is `_add_drawdown_span`, lines 301-336 — explicit interception, no
`try/except`:

```python
    if not span:

    ...
    bars = span.get("bars")
    depth = span.get("depth")
    length = "an unknown number of" if bars is None else str(bars)
    depth_text = "" if depth is None else f"<br>depth {float(depth):.2%}"
    ...
```

### 5. `tests/test_backtest_report.py` — parsers and fixtures

**Analog:** the three parsers already in the file.

```python
def _cells(html: str) -> dict[str, list[str]]:
    """Every metric row as `name -> [cell, ...]`, parsed back off the page."""
    rows = re.findall(r"<tr><th>([^<]+)</th>((?:<td>[^<]*</td>)+)</tr>", html)
    return {name: re.findall(r"<td>([^<]*)</td>", cells) for name, cells in rows}


def _traces(html: str) -> dict[str, dict]:
    """The trace list plotly embeds, by name -- the run-level locks' parser."""
    start = html.index("[", html.index("Plotly.newPlot("))
    traces, _ = json.JSONDecoder().raw_decode(html, start)
    return {trace["name"]: trace for trace in traces}


def _layout(html: str) -> dict:
    """The layout object plotly embeds: the JSON value after the trace array."""
    start = html.index("[", html.index("Plotly.newPlot("))
    _, end = json.JSONDecoder().raw_decode(html, start)
    layout, _ = json.JSONDecoder().raw_decode(html, html.index("{", end))
    return layout
```

`_traces` / `_layout` both anchor on the **first** `Plotly.newPlot(`. That is why
adding a second div leaves `test_the_figure_draws_exactly_these_five_traces` (line
392) and `test_the_layout_gives_every_axis_title_room_to_render` (line 411) green —
and why the heatmap is invisible to every current lock. A second-div parser modelled
on `_traces` (`html.index("Plotly.newPlot(", first + 1)`) is mandatory, or the chart
ships untested.

**Fixture pattern to copy** — lines 30-61. `_write(tmp_path, **kwargs)` defaults the
mandatory arguments and returns the page text; `_value()` / `_returns()` build tiny
xarray inputs on `pd.bdate_range("2024-01-01", periods=12)`. Note `_returns` puts all
12 bars **inside one calendar month** — a heatmap test spanning years needs its own
multi-month fixture built the same way, not a change to `_returns` (which
`test_the_figure_draws_exactly_these_five_traces` depends on).

**Naming/docstring convention:** test names are full sentences
(`test_a_key_present_in_no_block_produces_no_row`), and each non-obvious test carries
a docstring saying what would break. Match it.

**Delta-column tests must feed RAW types** (RESEARCH Pitfall 1): the report receives
the un-`to_jsonable`d mapping, so a lock must pass `pd.Timedelta`, `pd.NaT`,
`pd.Timestamp` and `float("nan")` straight into `_write(tmp_path, metrics=...)`.
`test_unrenderable_values_become_a_dash_never_nan_or_none` (line 248) is the shape to
copy.

## Shared Patterns

### Defensive rendering (applies to every edit in `backtest_report.py`)
**Source:** `_add_drawdown_span` (lines 301-336), `_metrics_section` (line 476),
`_add_monthly_returns` (lines 360-364).
**Rule:** `.get` for every key, explicit early `return` / `continue` guards, no
`try/except`. The report is written inside the run's staging directory; an exception
deletes the whole run. Stated in the module docstring lines 30-34 and again in
`_add_drawdown_span`'s docstring.

### HTML escaping
**Source:** `_escape` (lines 407-409) — `html.escape(str(value))`.
**Apply to:** every interpolated label, metric name, cell value and note. Plotly
divs are the sole exception and are inserted verbatim by design.

### Genericity (no metric name in the leaf)
**Source:** module docstring lines 25-34; `_flatten` (lines 412-426).
**Locked by:** `test_a_mapping_with_every_shipped_key_deleted_still_renders` (line
220), `test_an_unseen_nested_sub_dict_is_flattened_to_dotted_paths` (line 205).
**Apply to:** the delta column — dispatch on type, never on key.

### Leaf import set
**Source:** lines 66-73; `test_the_module_is_a_leaf` (line 158) scans for lines
starting `from quantlab` / `import quantlab`.
**Apply to:** the heatmap and delta helpers — stdlib `numbers` is fine, `numpy` is
not (docstring line 62 would become false).

### Engine-only vectorbt
**Source:** `engine_vectorbt.py` module docstring lines 3-5.
**Locked by:** `tests/test_backtest_contracts.py:330 test_vectorbt_is_imported_only_by_the_engine`.
**Apply to:** item 3 only; the report leaf and the base class must not gain a
vectorbt import.

### Run-directory file set is an exact set
**Sources of the assertion:** `tests/test_backtest_persistence.py:97`,
`tests/test_backtest_run.py:123`, `tests/test_backtest_run_cv.py:601`,
`tests/test_universe_filtered_factor.py:936`.
