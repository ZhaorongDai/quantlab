## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Added `pythonpath = ["."]` pytest config so `dataset` package resolves under pytest**
- **Found during:** Task 2, RED phase (writing `tests/test_backend_overwrite.py`)
- **Issue:** `from dataset.backend import XrBackend` in the new test file raised `ModuleNotFoundError: No module named 'dataset'` when run via `uv run pytest`, even though `uv run python -c "import dataset"` worked fine. Root cause: `tests/` has no `__init__.py`, so pytest's default sys.path insertion algorithm adds the `tests/` directory itself to `sys.path`, not the repo root — meaning top-level packages like `dataset/`, `base/`, `enums/` were never importable from any test module.
- **Fix:** Added `[tool.pytest.ini_options]\npythonpath = ["."]` to `pyproject.toml` (built into pytest >= 7.0, no extra plugin needed). This is a foundational fix required for every later Phase 2 plan's test files (which will also need to import from `dataset`, `base`, `factor`, etc.), not just this plan's own test.
- **Files modified:** `pyproject.toml`
- **Verification:** `uv run pytest tests/test_backend_overwrite.py -v` now collects and imports `dataset.backend` successfully; re-ran full `uv run pytest tests/ -v` afterward, 3 passed.
- **Committed in:** `9cf3de6` (Task 2 RED commit, since it was required for the RED test itself to even collect)
