<objective>
Build the new, properly encapsulated Tiingo acquisition component CONTEXT.md D-10 requires: a class-based `Acquisition(ABC)` + concrete `TiingoAcquisition`, mirroring the codebase's established `Dataset`/`FactorKunQuant` ABC+concrete lifecycle pattern -- explicitly NOT modeled on `get_binance_instruments.py`/`cal.py` (flat scripts) or `scripts/download_stock_data_from_tiingo.py` (throwaway style, though its Tiingo API call shape IS the reference for WHAT to call). <interfaces>
base/data.py's config-setter idiom to mirror (already read in full during research):
- `config` property returns `self._config`.
- `config` setter: assigns `self._config = config`; sets `self._config.name = self.import_path`;
  defaults `self._config.start_date`/`.end_date` from `enums.constant.Date.START_DATE`/`.END_DATE`
  when `None`.

`Acquisition`'s `config` setter follows the identical shape, operating on `AcquisitionConfig`
(defined in `base/config.py` by 02-02) instead of `DatasetConfig`. `enums.constant.Date`
supplies the same `START_DATE`/`END_DATE` sentinels already used by `Dataset`.

`AcquisitionConfig` (from `base/config.py`, landed by 02-02) has fields in this order:
`market: Market`, `frequency: Frequency`, `raw_data_dir_path: str`, `watermark_path: str`,
`symbols: tuple[str, ...]`, `start_date: str | None = None`, `end_date: str | None = None`,
`kwargs: dict | None = None`, `name: str | None = None`. It has NO credential field -- read
`TIINGO_API_KEY` from `os.environ` only inside `TiingoAcquisition.__init__`.

Reference Tiingo call shape from `scripts/download_stock_data_from_tiingo.py` (WHAT to call,
not HOW to structure it -- see D-10): construct `TiingoClient({"session": True, "api_key":
os.environ["TIINGO_API_KEY"]})`; call `client.get_ticker_price(stock, fmt="json",
startDate=start_date, endDate=end_date, frequency="daily")`; wrap the JSON list-of-dicts result
in `pl.DataFrame(...)`; cast `date` to `pl.Datetime` and rename it to `timestamp`; add a
`symbol` literal column via `pl.lit(stock).alias("symbol")`.

`StockDataset._to_kunquant()` (`dataset/stock.py`) unconditionally does
`data.drop_vars(["open","high","low","close","volume"])` then renames `adjOpen`->`open` etc.
-- if those `adj*` columns are absent from the fetched JSON this fails downstream, not at
acquisition time (02-RESEARCH.md Pitfall 3). Always pass an explicit `columns=` listing every
field needed; never rely on the client's undocumented default.

`tests/conftest.py` (landed by 02-01) provides `tiingo_json_response` and `mock_tiingo_client`
fixtures -- use `mock_tiingo_client` in every test in this plan; it already sets
`TIINGO_API_KEY` via `monkeypatch.setenv` and patches `acquisition.tiingo.TiingoClient`, and
exposes a `.calls` list on the returned `FakeTiingoClient` class recording every
`get_ticker_price(...)` call's kwargs.
