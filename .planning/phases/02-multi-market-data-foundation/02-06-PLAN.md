<interfaces>
`base/data.py:Dataset(ABC)` requires three abstract methods to be implemented by any
subclass: `_to_kunquant(self, data: xr.Dataset, data_columns: tuple[str, ...]) -> tuple[dict,
np.ndarray, np.ndarray]`, `_raw_data_to_xr(self) -> xr.Dataset`, `_to_nautilus(self, data:
xr.Dataset, venue: str, n_jobs: int) -> tuple[list[list], list[Instrument]]`. A test-only
`FakeDataset` only needs `_raw_data_to_xr()` to return a real, small, valid `[timestamp,
symbol]`-indexed `xr.Dataset` (hand-built directly, no file I/O needed since this is testing
the abstraction, not real ingestion); `_to_kunquant`/`_to_nautilus` can `raise
NotImplementedError` since the lifecycle under test (`from_raw_data`/`save`/`read`) never
calls them.

`DatasetConfig` (from `base/config.py`, landed by `02-02`) requires `market`/`frequency` as
Literal-typed fields, but Python does not enforce `Literal` values at runtime -- passing a
novel string like `market="fake_market"` for this test is valid Python and is the correct way
to prove genuine novelty (a real third market/frequency is out of this phase's scope per
CONTEXT.md's domain boundary; this test only needs to prove the CONTRACT holds for an
arbitrary new value, not register a fourth real market in the `Market` Literal).
</interfaces>
