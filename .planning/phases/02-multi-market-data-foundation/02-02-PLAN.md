<objective>
Add first-class `market`/`frequency` fields to `DatasetConfig` (CONTEXT.md D-01) and retrofit every config factory in `config/__init__.py` to derive its storage paths from the `data/{market}/{frequency}/{name}.zarr` convention (D-02), replacing today's hardcoded, non-uniform path segments (`spot/monthly/klines` vs `spot/klines.zarr`). Add the new `stock_kline_config()` factory (D-09, currently missing entirely) and a companion `stock_acquisition_config()` factory returning the new `AcquisitionConfig` dataclass that Wave 3's `TiingoAcquisition` component will consume. This is the shared contract both the Tiingo (Wave 3-4) and Binance (Wave 3) vertical slices build on — it must land once, centrally, so both slices see identical `market`/`frequency` semantics and neither duplicates path-derivation logic.

Purpose: Closes ROADMAP Phase 2 Success Criterion 4's config half — "adding a new market or frequency only requires a new Dataset subclass + config, no factor/model/backtest changes" — by making market/frequency structural, not implicit in path strings.
Output: `DatasetConfig.market`/`.frequency` (required), `AcquisitionConfig` (new), 4 retrofitted + 2 new factory functions in `config/__init__.py`, `test.py` updated to still construct a valid `DatasetConfig`.
</objective>

Current `base/config.py:DatasetConfig` (base/config.py lines 9-22):
```
raw_data_dir_path: str
zarr_file_path: str
catalog_path: str
start_date: str | None = None
end_date: str | None = None
symbols: tuple | None = None
kwargs: dict | None = None
name: str | None = None
```
Required fields (no default) must come before fields with defaults in a dataclass — `market`/
`frequency` must be inserted alongside `raw_data_dir_path`/`zarr_file_path`/`catalog_path`
(before `start_date`), not appended at the end, or Python raises
`TypeError: non-default argument 'market' follows default argument`.

Current `config/__init__.py:spot_kline_config()` hardcodes `"downloads" / "spot" / "monthly" /
"klines"` and `"data" / "spot" / "klines.zarr"` — two different, inconsistent path shapes for
the same source. `_data_root()` (already exists, reads `QUANTLAB_DATA_DIR`) is the base every
new helper must build on top of, not replace.

`test.py` (lines 14-20) hand-builds:
```
dscfg = DatasetConfig(
    raw_data_dir_path=str(_data_root / "scripts" / "downloads" / "nasdaq_data"),
    zarr_file_path=str(_data_root / "scripts" / "downloads" / "nasdaq_data" / "stock.zarr"),
    catalog_path="none",
)
```
This will raise `TypeError` the moment `market`/`frequency` become required fields — add
`market="us_equity", frequency="1d"` to this call. Do not otherwise restructure `test.py`
(CLEAN-02/QUAL-02 cleanup of this file is explicitly Phase 7 scope, not this phase's).

`cal.py`, `train_model.py`, and `backtest/test_strategy.py` never construct `DatasetConfig`
directly — they only call `alpha101_config()`, `alpha158_config()`, and `spot_label_config()`
(all of which internally call `spot_kline_config(symbols=symbols)` with no `market`/`frequency`
override), so once `spot_kline_config()`'s new `market`/`frequency` parameters have defaults
(`"crypto_spot"`/`"1d"`), these three files' existing call sites keep working with zero edits.
`test_nt.ipynb` similarly calls `spot_kline_config(symbols=("BTCUSDT",), start_date='2025-01-01')`
with no `market`/`frequency` override — same reasoning applies. This plan does not modify any
of these four files; Task 2's smoke-check acceptance criterion exists solely to prove that
reasoning holds by static analysis (ast.parse-based syntax check), not to change their content.
