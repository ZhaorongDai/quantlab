# Phase 03.7 Plan 02: Config Rebuild and Read-Cache Refresh Summary

**Dataset and factor loaders now build `cls.config_cls(**config)` on a deep copy, so Polars factors and constituent datasets rebuild from their persisted JSON config instead of raising the two D-26 TypeErrors. `Factor.read(overwrite=True)` re-opens the factor store so a re-dated window takes effect. All ten behaviors are regression-locked, and four mutations were observed red.**

## Accomplishments
- The four intermediate classes each declare a plain `config_cls` class attribute: `MarketDataset -> DatasetConfig`, `IndexConstituentDataset -> ConstituentDatasetConfig`, `FactorKunQuant -> FactorConfig` and `FactorPolars -> PolarsFactorConfig`. `BaseDataset` and `Factor` have no abstract member added, so the tests that subclass them directly still instantiate.
- `quantlab/utils/module.py` no longer hardcodes a config class. `_config_cls_of(cls)` returns the declared class or raises `TypeError` naming `cls.__qualname__`. All three loaders deep-copy their input as the first statement. `load_model_from_config` still calls `load_factor_from_config` through the module global, so the monkeypatched loader tests in `tests/test_model_hierarchy.py` keep working.
- `Factor.read(self, overwrite: bool = False)` forwards `overwrite` to `XrBackend.read` and then calls `_auto_filter()`. Its docstring says the default is the cached read, and that `overwrite=True` is required after mutating `config.start_date`/`end_date`, which is the backtester's D-14 path.
- `tests/test_config_roundtrip.py` (7 tests) and `tests/test_read_cache_refresh.py` (3 tests) lock every behavior. Both construct configs directly, never through `quantlab/config` factories (D-32).

## Decisions Made
- `config_cls` is a plain class attribute on the intermediate classes, following RESEARCH. It is not abstract, because six test modules subclass `BaseDataset`/`Factor` directly.
- A class with no `config_cls` is refused with a `TypeError` that names it, and there is no fallback config class. Guessing a default config class is exactly how the D-26 bug worked. The refusal also keeps an arbitrary importable callable from being instantiated with a config dict (T-03.7-07).
- The refusal test resolves the nested dataset to the real `StockDataset` and returns the bare class only for the factor path. The factor refusal therefore comes from `load_factor_from_config`'s own check, not from the nested dataset load.
