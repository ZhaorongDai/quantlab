# Phase 03.7: Cross-sectional backtester (BaseBacktester + USEquityCrossectionSelectStockVectorBt) - Research

**Researched:** 2026-09-14
**Domain:** vectorbt portfolio simulation, model-layer inference plumbing, config round-trip reproducibility
**Confidence:** HIGH for engine behaviour and the live-code facts (probed/read this session). MEDIUM for design recommendations under Claude's Discretion.

## Summary

The engine mechanics D-05/D-07 rely on hold up on vectorbt 1.1.0 / pandas 3.0.5, re-probed this session. `Portfolio.from_orders(size=weights.shift(1), size_type="targetpercent", price=adjOpen, close=adjClose, direction="both", group_by=True, cash_sharing=True, call_seq="auto")` fills a bar-t signal at the bar-(t+1) open. A NaN size means "hold". Long-to-short flips work. Sizes are fractional. A 3000-symbol x 750-bar long-short run simulates in about 3.9 s. The probes surfaced three engine facts CONTEXT does not state:
1. The NaN-price freeze is **group-wide**: once a held symbol's price is NaN, *no* symbol rebalances again, not just the delisted one.
2. On a rebalance bar, an unselected symbol must get weight `0.0`, not NaN. NaN means "keep", and it silently blocks the rest of the rebalance.
3. A grouped `Portfolio` **cannot be sliced by time** (confirmed by both the docs and a probe), so D-22's "full `stats()` set for the in-sample/out-of-sample slices" has to be built from sliced returns plus slice-filtered order and trade records.

On the model and config side, the D-26 `TypeError`s reproduce verbatim. Four things in the live code will bite a naive implementation:
- **`XrBackend.read()` caches.** Once a dataset or factor has been read, widening `config.start_date` (D-14/D-15 warm-up) has **no effect** unless `read(overwrite=True)` is used. Probe: 6 bars, still 6 after widening, 10 with `overwrite=True`.
- **Fold dates are not ISO dates on real data.** `train_cv` fold dates come from `np.datetime_as_string` and render as `'2026-08-07T00:00:00.000000000'` on the real `datetime64[ns]` stores.
- **`DLModel._predict` returns whatever the head's `forward` returns.** For `RNNRegressor`/`RNNClassifier` that is a *tuple*, not a `[T,S,L]` tensor.
- **xgboost predicts finite values for all-NaN feature rows.** `predict_panel` must mask those rows to NaN, or not-yet-listed symbols become selectable.

The real local store `us_all.zarr` holds only 21 daily bars (2026-08-07..2026-09-04, 7700 symbols), so every phase test must be synthetic. The suite is already partly red before this phase: `tests/test_factor_hierarchy.py` fails to collect, and 56 tests fail in unrelated files. The phase gate therefore has to be "no new failures", not "all green".

**Primary recommendation:** Build the phase in three waves:
- **Wave 1:** the model and config foundations (`config_cls` rebuild fix, `predict_panel`, `cv_folds.json`, backend cache invalidation for re-dated reads).
- **Wave 2:** the pure-function core (TopN selector → weights, rebalance schedule, warm-up / in-sample date math, fingerprint, turnover, metrics serialization), each unit-tested on synthetic panels.
- **Wave 3:** `BaseBacktester`/`VectorBtBacktester`/`USEquityCrossectionSelectStockVectorBt`, then `run`/`run_cv`, persistence, report, the config loader, and the `vecbt` cleanup plus docs.

## User Constraints (from CONTEXT.md)

### Locked Decisions

### Class structure and placement
- **D-01:** The engine varies by **inheritance**; market and selection logic vary by **composition**. This avoids a market × style × engine class explosion.
  - Hierarchy: `BaseBacktester` (`quantlab/base/backtest.py`) → `VectorBtBacktester` (engine layer) → `USEquityCrossectionSelectStockVectorBt` (thin named subclass that combines the US-equity market spec with a cross-sectional TopN selector).
  - Concrete classes live in a new package `quantlab/backtest/` (exact module names are Claude's discretion). Future siblings `USEquityTimeseriesVectorBt` and `USEquityCrossectionEventDrivenBt` must be addable without changing the base class.
- **D-02:** The only user-facing methods are `run()` (model backtest) and `run_cv()` (model-CV backtest). `run()` executes the pipeline template in the base class, in this order:
  1. prepare the model (train or load);
  2. align factor dates, then predict;
  3. generate signals;
  4. simulate;
  5. benchmark (optional, see D-08);
  6. metrics;
  7. report and persist.

  Abstractable steps are template/abstract methods on the base. The engine-specific ones (`_simulate`, `_simulate_benchmark`) and the signal-generation step (`_generate_signals`) are abstract.
- **D-03:** **The signal-generation output contract is target weights.** It is an `xr.Dataset` with a `weight` variable on dims `(timestamp, symbol)`, whose values are:
  - NaN on bars that are not rebalance bars;
  - on rebalance bars, `sum(|w|) ≤ 1` (gross ≤ 100%).

  This is the same "target holding % per symbol" contract Phase 5's optimizer will produce, so an optimizer can replace the TopN selector without backtester changes. Weights are persisted (D-24) so a future event-driven engine can reuse them. — **Reversibility:** costly — it becomes the Phase 5 → backtest interface and a persisted on-disk artifact; changing it later touches the selector, every engine, and stored runs.

### Price data, execution, universe
- **D-04:** Prices come from `dataset.read().get_xarray_dataset()`, with column names chosen by **class attributes on the backtester**, never hardcoded inside methods. For US equity: the fill price is `adjOpen` and the valuation price is `adjClose` (both split/dividend adjusted; Tiingo EOD columns `quantlab/enums/data.py:TiingoColumns.EOD`). Unadjusted `open`/`close` are never used for P&L. The user asked for this directly: "复权价能不能直接 get_xarray_dataset() 然后根据类定义的列名取数据".
- **D-05:** **Execution timing: a signal formed at the close of bar t fills at the open of bar t+1.**
  - vectorbt shape: `Portfolio.from_orders(close=adjClose, price=adjOpen, size=weights.shift(1 bar), size_type="targetpercent", direction="both", group_by=True, cash_sharing=True, call_seq="auto")`.
  - Verified in a vectorbt 1.1.0 / pandas 3.0.5 probe: a signal on bar 0 filled at bar 1's open, and a long→short flip worked with `direction="both"`.
- **D-06:** **The universe is every symbol in the price dataset.** There is no index-membership masking this phase.
- **D-07:** **Delisting rule: when a held symbol's price turns NaN, forward-fill its last price and force-liquidate it at the next rebalance.** Record each forced liquidation (symbol, bar, price).
  - Why this is required, verified by probe: vectorbt keeps a NaN-priced position at its last value and **silently skips every later rebalance**. A target-100%/0% rebalance never executed and raised no error; forward-filling prices restored the rebalance.
- **D-08:** **Benchmark:** `BacktestConfig.benchmark_dataset` is an optional single-symbol dataset (it may be an index), at the same frequency, default `None`. Locally there is no directly-downloaded index price data (only `data/data/us_equity/1d/us_all.zarr` and `stock_alpaca.zarr`), so **benchmark comparison is NOT implemented this phase.** The user said: "只有指数集是直接下载的指数价格（如果现在还没有，先不做 benchmark 对比）". Keep the config slot and the base hook so it can be added later; when the benchmark is `None`, reports omit it.

### Stock selection and weights
- **D-09:** Direction is a config choice, `long_only` or `long_short`.
  - `long_only`: the top_n names by score, equal weight, summing to 100%.
  - `long_short`: top_n longs sum to +50% and bottom top_n shorts sum to −50%, equal weight within each book. Gross exposure is 100%, net 0.
  - This follows the project key decision "持仓模型采用多空、不加杠杆（净/毛敞口 ≤100%）" (`.planning/PROJECT.md` Key Decisions).
- **D-10:** Pick count is a fixed `top_n` (no quantile mode).
- **D-11:** The score comes from the config `score_label` (a label name). By default it is the model's first label (index 0). An unknown label name raises.
- **D-12:** Eligibility on a rebalance bar excludes symbols whose prediction is NaN, or that have no `adjOpen` on the fill bar (t+1). If fewer than top_n remain, select what is available, split the book weight equally among them, and log a warning.

### Model preparation and date alignment
- **D-13:** `BacktestConfig.model_mode` is `"train"` or `"load"`.
  - `train` uses the **model's own config dates** (`train_start`/`train_end`/`test_start`/`test_end`) and does NOT override them. The backtest window only drives prediction and in/out-of-sample classification.
  - `load` requires a checkpoint path.
- **D-14:** **Date alignment works by mutating the factor configs directly** (`factor.config.start_date` / `end_date`, which existing `Factor._reset_dataset_config` pushes into the dataset config). Do not build a parallel slicing or fetch path. The user said: "对于涉及读取指定日期数据或计算因子，可以直接改因子类的配置文件". Prediction computes **features only** (not labels), via D-29.
- **D-15:** Warm-up is **automatic from the factors' `config.window`**:
  - take the maximum window, in bars;
  - convert it to a start date using the price dataset's own trading calendar (its timestamp axis), not calendar-day arithmetic;
  - set the factors' start date that much earlier, predict, then slice the predictions back to the backtest window.

  Note: `Factor._reset_dataset_config` already subtracts `window` **calendar days** from the dataset start (`quantlab/base/factor.py`). That existing behaviour is an extra buffer, not a bar-accurate warm-up, and must not be relied on.
- **D-16:** `run_cv()` reads **`cv_folds.json` in the `train_cv` project directory** (written by D-30). For each fold it:
  - loads that fold's checkpoint;
  - backtests **only that fold's test segment**;
  - reports per-fold results.

  It also produces a stitched out-of-sample equity curve across folds. `BaseModel._cv_folds` yields contiguous, non-overlapping test segments, so stitching is valid; assert it rather than assume. — **Reversibility:** costly — `cv_folds.json` becomes an on-disk format that CV backtests of old training runs depend on.
- **D-17:** **In-sample detection.** The effective training window is `[train_start, train_end + label horizon]`, where the label horizon is the maximum `n_forward_periods` across the model's labels, in bars. The label on `train_end` uses the next n bars of prices, so those bars count as in-sample too.
  - If the backtest window overlaps this range: `logger.warning`, continue, and report in-sample and out-of-sample results separately.
  - Split by **slicing the single continuous simulation's returns/equity**, not by running separate simulations. Separate runs would reset capital and change the path.
  - In `run_cv`, apply this per fold using that fold's dates.

### Rebalancing and execution details
- **D-18:** The rebalance anchor is the first bar of the backtest window. After it, rebalance every `rebalance_periods` bars (a bar count, frequency-agnostic) and hold positions unchanged in between.
- **D-19:** Defaults, all configurable: `fees=0.0005` (5bp), `slippage=0.0005` (5bp), `init_cash=1_000_000`.
- **D-20:** Fractional shares are allowed.
- **D-21:** There are no borrow/short financing costs this phase. Docs and report must state that short-side returns are optimistic.

- **D-23:** Charts are a **plotly interactive HTML** with an equity curve and a drawdown curve, in-sample bars shaded (plotly 5.24 is already a dependency).
- **D-24:** Each run gets its own directory `output_dir/{class}_{timestamp}/` holding:

  - target weights (xarray/Zarr, per the project's inter-module format constraint);
  - equity and returns series;
  - forced-liquidation records;
  - metrics JSON;
  - the HTML report;
  - the data fingerprint (D-27).

Add a `load_backtester_from_config(config: dict)` (or equivalent) alongside `quantlab/utils/module.py:load_model_from_config`. ## Project Constraints (from CLAUDE.md)

- **xarray/Zarr between modules, no DataFrame as a layer transport.** The weights contract is an `xr.Dataset` persisted as Zarr. pandas is allowed only *inside* the vectorbt engine boundary (vectorbt needs DataFrames). Convert at the `_simulate` boundary and return xarray/plain results.
- **Model training consumes xarray directly.** `predict_panel` takes and returns `xr.Dataset`.
- **Backtest stack: vectorbt first.** NautilusTrader stays a reserved extension. Do not revive the deleted `backtest/test_strategy.py` prototype.
- **Credentials via env vars only.** Nothing in this phase needs one; wandb stays off by default (D-28).
- **Config-driven reproducibility** (CFG-01): the backtest config JSON must rebuild the run (D-25).
- **Module contracts:** the optimizer contract is "target holding % per symbol", which is the D-03 weights.
- **`uv` for packages.** No new dependency is needed: vectorbt, plotly and zarr are already declared in `pyproject.toml`.
- **Backend only**, no web frontend. The plotly HTML is a file artifact.
- **Package layout convention:** empty `__init__.py`; import by full dotted path (`from quantlab.backtest.xxx import ...`).
- **macOS OpenMP:** `tests/conftest.py` sets `OMP_NUM_THREADS=1` on darwin before any import. Any example or script mixing torch (pulled in by `quantlab.base.model`) and xgboost must set it too.
- **GSD workflow enforcement:** edits go through `/gsd-execute-phase`.
- **User memory rules (treated as constraints):**
  - Class-based, layered components, never flat scripts.
  - Do not model new pipeline code on `scripts/` throwaways.
  - Never `git stash`.
  - No config factories (D-32).
  - Date alignment happens through factor config (D-14).
  - Time-series vs cross-sectional normalization is a design choice, never a bug to "align".
  - Dataset hooks stay overridable (future unstructured data).

### Anti-Patterns to Avoid

- **NaN weights for unselected symbols on a rebalance bar.** NaN means "no order". The old position is kept and blocks the buys (Pitfall 3).
- **Slicing the Portfolio by time for in-sample/out-of-sample.** Unsupported (Pitfall 5).
- **`dataclasses.asdict` on `BacktestConfig` holding dataset/model objects.** It deep-copies the objects, including loaded panels (Pitfall 8). Build `get_config()` by hand like `BaseModel.get_config`.
- **Computing warm-up with `pd.DateOffset(days=window)`.** D-15 forbids it; use the price calendar index.
- **Importing `quantlab.backtest` from `base/`, `model`, `factor` or `dataset`.** Layering is one-directional. `quantlab/base/backtest.py` may import `quantlab.base.model`, but nothing below may import the backtester.
- **Routing any construction through `quantlab/config/__init__.py` factories** (D-32).

## Common Pitfalls

### Pitfall 1: Re-dating a dataset/factor after a read has no effect (XrBackend read cache)
**What goes wrong:** `run()` with `model_mode="train"` calls `collect()` (reads data narrowed to the model's dates). D-14 then widens `factor.config.start_date` for warm-up and calls `cal()`/`read()`. The cached, already-narrowed panel comes back. Warm-up silently shrinks, or the prediction window is empty.
**Why it happens:** `XrBackend.read` returns early when data is already loaded, and `BaseDataset.read()` then narrows in place [VERIFIED: `quantlab/dataset/backend.py:19-21` — `def read(self, path: str, overwrite: bool = False, **kwargs) -> Self:` / `if not overwrite and hasattr(self, "data"):` / `return self`; `quantlab/base/data.py:288-291` — `self.data_backend.read(self.config.zarr_file_path, **kwargs)` then `self._filter()`]. `FactorKunQuant.cal()` reaches the dataset through `to_kunquant` → `self.read()` with no `overwrite` [VERIFIED: `quantlab/base/data.py:1128-1132`]. `Factor.read()` takes no kwargs [VERIFIED: `quantlab/base/factor.py:110-113`].
**Probe evidence (this session):** a 10-bar store read with `start_date="2024-01-05"` → `first read: 6`; after setting `start_date="2024-01-01"`, `read()` → `6`; `read(overwrite=True)` → `10`.
**How to avoid:** after mutating dates (D-14), force a fresh read for every factor's dataset (`factor.config.dataset.read(overwrite=True)`). For `factor_data_strategy="read"`, also re-read the factor store. That needs a small additive `overwrite: bool = False` parameter on `Factor.read()`, or an explicit backend reset. This is the existing read path with its existing flag, not a parallel fetch path (D-14). The same applies to the backtester's own price dataset when it shares an object with a factor.
**Warning signs:** the prediction panel has fewer timestamps than `window + backtest bars`, or leading NaN rows inside the window.

### Pitfall 2: NaN price freezes the WHOLE group, not only the delisted symbol
**What goes wrong:** once a held symbol's price is NaN, every later rebalance of *every* symbol is silently skipped.
**Probe evidence:** B held, B price NaN from bar 3, rebalance to A=100%/B=0 → orders only on 2024-01-02; A never re-bought (P4). With `ffill()` on both open and close, B sells at its last price 22.0 and A buys (P4b). A symbol with **leading** NaN prices that was never held does *not* freeze the group, and fills normally once listed (P10a–c).
**How to avoid:** ffill both `price` and `close` before simulating (D-07). Detect forced liquidations from the **raw** (un-ffilled) price: held position ≠ 0 and raw fill price NaN at the rebalance fill bar → record `(symbol, bar, ffilled price)`. Selection must use the raw `adjOpen[t+1]` for eligibility (D-12). Otherwise an ffilled delisted symbol looks tradable.
**Warning signs:** the order count stops growing mid-backtest; equity becomes a straight buy-and-hold line.

### Pitfall 3: NaN weight on a rebalance bar means "keep", and blocks the rebalance
**Probe evidence (P4c):** rebalance row `[1.0, NaN]` for A/B → no orders at all; B kept, A not bought (no free cash with `allow_partial=True`, which is the default) [VERIFIED: probe `vbt.settings.portfolio` → `'allow_partial': True`].
**How to avoid:** the selector writes `0.0` for every unselected symbol on rebalance bars and NaN only on non-rebalance bars (exactly D-03). Add an assertion in `_simulate`: rebalance rows contain no NaN.

### Pitfall 4: Fees and slippage semantics on `targetpercent`
**Probe evidence (P5, fees=10bp, slippage=1%):** buy A at open 11 filled at `11.11` (×1.01); sell B at open 25 filled at `24.75` (×0.99); `Fees` = size × slipped price × 0.001 (0.505 on 45.45 × 11.11). Target sizing accounts for fees (B bought 23.29, not 23.81).
**Valuation price:** the default `val_price` is `inf` = "current order price" [VERIFIED: probe → `'val_price': inf`; installed docstring `vectorbt/portfolio/base.py:1713` — "Any `np.inf` element is replaced by the current order price."]. Target percentages are therefore computed on group value marked at the t+1 **open**. Document this in the backtester docstring.

### Pitfall 5: A grouped Portfolio cannot be time-sliced → in-sample/out-of-sample "full stats" must be assembled
**Evidence:** `pf.loc[a:b]` and `pf.iloc[2:7]` → `IndexingError: Columns only: This object already contains one column of data` (probe). The docs say: "Changing index (time axis) is not supported." [CITED: https://vectorbt.dev/api/portfolio/base/].
**How to avoid:** for each slice, compute:
- (a) `rets.loc[s:e].vbt.returns(freq, year_freq).stats()`;
- (b) slice-filtered order-record metrics: fees, turnover, order count;
- (c) slice-filtered trade-record metrics (by `Exit Timestamp` for closed trades; open trades flagged);
- (d) start/end value from `pf.value()`.

Report the whole run with `pf.stats()`. Document that slice metrics are the returns-based set plus record-based counts. This is an implementation reading of D-22 (Open Question 2); D-34 later confirmed it exactly as stated here.

### Pitfall 6: `stats()` defaults that are wrong for this project
- `year_freq` defaults to `365 days` [VERIFIED: probe → `year_freq setting: 365 days`]. For daily US equity, annualize with `252 days` [ASSUMED: 252 trading-day convention]. Pass `settings=dict(year_freq=...)` to `pf.stats()` and `year_freq=` to the returns accessor. Minute bars need a different value, so put `year_freq` on the market spec or config.
- `pf.stats()` includes `benchmark_return` (buy-and-hold of the traded columns' `close`) and warns about `alpha`/`beta` [VERIFIED: probe row `Benchmark Return [%] 50.406504` plus `UserWarning: Metric 'alpha' requires benchmark_rets to be set`]. D-08 says to omit the benchmark when `None`, so pass an explicit `metrics=` list excluding `"benchmark_return"`. The full key list is [VERIFIED: probe `vbt.Portfolio.metrics.keys()` → `['start', 'end', 'period', 'start_value', 'end_value', 'total_return', 'benchmark_return', 'max_gross_exposure', 'total_fees_paid', 'max_dd', 'max_dd_duration', 'total_trades', 'total_closed_trades', 'total_open_trades', 'open_trade_pnl', 'win_rate', 'best_trade', 'worst_trade', 'avg_winning_trade', 'avg_losing_trade', 'avg_winning_trade_duration', 'avg_losing_trade_duration', 'profit_factor', 'expectancy', 'sharpe_ratio', 'calmar_ratio', 'omega_ratio', 'sortino_ratio']`].
- `freq` must be set: pass `freq=` from the price dataset's bar interval (`BaseDataset.time_interval` is the mode of diffs [VERIFIED: `quantlab/base/data.py:219-229`]).

### Pitfall 7: xgboost gives finite predictions for rows with no data
**Probe evidence:** a 5-round booster predicts `[1.703115 1.703115]` for two all-NaN rows. DL heads `nan_to_num` their inputs to 0 [VERIFIED: `quantlab/dl_model/rnn.py:368-370` `data = torch.nan_to_num(data, nan=0.0)`], so they also predict on empty rows.
**How to avoid:** `predict_panel` sets predictions to NaN wherever **all** features are NaN (not listed / delisted), so D-12 eligibility excludes them. Recommendation, not a locked decision [ASSUMED]; a stricter "any feature NaN" mask would drop most rows for 100+-factor sets.

### Pitfall 8: `dataclasses.asdict` deep-copies object-valued fields
**Probe evidence:** `asdict(PolarsFactorConfig(window=1, dataset=h))` called `__deepcopy__` once, and the output value was not `h`. `BaseFactorConfig.to_dict` is `asdict(self)` [VERIFIED: `quantlab/base/config.py:95-96` `def to_dict(self):` / `return asdict(self)`], and `Factor.get_config` calls it before replacing `dataset` [VERIFIED: `quantlab/base/factor.py:181-185`]. A `BacktestConfig` holding a model and datasets would deep-copy loaded panels and a booster on every `get_config()`.
**How to avoid:** `BaseBacktester.get_config()` builds the dict field by field. Scalars go through `dataclasses.fields`; `price_dataset.get_config()`, `model.get_config()` and `benchmark_dataset.get_config() if not None` are called explicitly. Do not call `asdict` on the whole config.

### Pitfall 9: Loaders mutate the caller's dict
`load_factor_from_config` assigns `config["dataset"] = <object>` and `load_model_from_config` assigns `config["factors"] = [objects]` into the dict it was given [VERIFIED: `quantlab/utils/module.py:53` `config["dataset"] = load_dataset_from_config(config["dataset"])`; `:69-70`]. A round-trip test that reuses the saved dict, or a backtester loader that then serializes it, gets objects inside JSON. Copy first (`copy.deepcopy(config)` at the top of `load_backtester_from_config`).

### Pitfall 10: Serializing dates and metrics to JSON
- Fold dates on real data are nanosecond strings. `np.datetime_as_string` on the stores' `datetime64[ns]` gives `'2026-08-07T00:00:00.000000000'`, which `datetime.date.fromisoformat` rejects (probe). `pd.Timestamp(np.str_)` raises `TypeError: Expected str, got numpy.str_`; `pd.Timestamp(str(s))` works (probe). The real store's timestamp dtype is `datetime64[ns]` [VERIFIED: probe on `us_all.zarr`]. `run_cv` must parse fold dates with `pd.Timestamp(str(x))`. If fold dates are pushed into a dataset config through the `BaseDataset.config` setter, its ISO normalization would raise [VERIFIED: `quantlab/base/data.py:272-281` `datetime.date.fromisoformat(str(value)).isoformat()`].
- `stats()` returns `NaN`, `inf` (`Profit Factor inf`), `Timestamp`, `Timedelta`/`NaT` and numpy scalars (probe). `json.dump` emits non-standard `NaN`/`Infinity` and fails on Timestamp/Timedelta. ### Data fingerprint (D-27)

```python
def fingerprint(ds: xr.Dataset, variables: list[str]) -> dict:
    ds = ds.sortby(["timestamp", "symbol"])
    h = hashlib.sha256()
    h.update(np.ascontiguousarray(ds["timestamp"].values.astype("datetime64[ns]").astype("int64")).tobytes())
    h.update("\x00".join(map(str, ds["symbol"].values.tolist())).encode())
    for v in sorted(variables):
        a = np.asarray(ds[v].transpose("timestamp", "symbol").values, dtype=np.float64)
        a = np.where(np.isnan(a), np.nan, a)          # canonical NaN bit pattern
        a = a + 0.0                                    # -0.0 -> 0.0
        h.update(v.encode()); h.update(np.ascontiguousarray(a).tobytes())
    return {"algorithm": "sha256", "digest": h.hexdigest(), "variables": sorted(variables),
            "start": str(ds.timestamp.values[0]), "end": str(ds.timestamp.values[-1]),
            "n_timestamps": int(ds.sizes["timestamp"]), "n_symbols": int(ds.sizes["symbol"])}
```
