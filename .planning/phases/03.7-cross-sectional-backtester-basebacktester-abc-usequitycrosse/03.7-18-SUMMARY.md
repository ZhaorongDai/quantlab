# Phase 03.7 Plan 18: XGBoost W&B feature importance (G-03.7-9 addition) Summary

**`XGBoostRegressor` now writes `importance_{weight,gain,total_gain}/{factor}` for every declared factor into the W&B summary after training. Values come from a nameless Booster's `get_score`, with `f{i}` mapped to `get_factor_names()[i]` and never-split factors set to 0.0. Nothing reaches `recorder.log`, no `feature_names` are used, and prediction and checkpoint code are untouched.**

## Accomplishments

- `XGBoostRegressor._fit_model` calls the new `_record_feature_importance()` after `xgb.train` and after the best_iteration/best_score block. It only does this when `self._wandb_recorder is not None`.
- `_record_feature_importance` handles each type in the module constant `_IMPORTANCE_TYPES = ("weight", "gain", "total_gain")`:
  - It starts every factor at 0.0 and parses each `get_score` key as `f<int>`, filling in `float(score)` for that factor.
  - A key that does not parse, or whose index is out of range, raises a ValueError naming the key and the factors.
  - It writes one `summary.update` per type.
- Under early stopping, `self.model` is already the truncated Booster (`save_best=True`), so the recorded importance describes the checkpoint on disk. Test X checks this against `joblib.load` of that checkpoint.
- The class docstring's `wandb` section lists the keys, the index mapping, the zero-fill, the multi-output aggregation, and that order is checked by `BaseModel.load()`.
- `example/model.md` changes, in Chinese:
  - The XGB head's W&B table row now lists the importance keys.
  - A dated G-03.7-9 paragraph opens the `## ML / 树模型：XGBoostRegressor` section and points to the `load()` section for variable order.
