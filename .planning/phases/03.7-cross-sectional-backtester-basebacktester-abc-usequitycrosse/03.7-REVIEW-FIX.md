**Commit:** 8780ee2

**Applied fix:**
- **Training window:** `_training_window` now finds the training segment with the same pandas `DatetimeIndex.slice_indexer` that the model layer's `data.sel(timestamp=slice(train_start, train_end))` uses. Endpoints are passed through unchanged (`_slice_bound`), so `"2024-01-02"` covers the whole session, `"…T13:00"` stops at 13:00, and the manifest's nanosecond strings match exactly. The window end is the last training bar plus the horizon.
- **Endpoint labels:** `training_window`, `in_sample_range` and `out_of_sample_ranges` now use bar labels (`_bar_label`). A midnight bar is written as its ISO date, so daily output is unchanged. Any other bar is written as a full ISO timestamp.
- **Exact comparisons:** these now compare exact timestamps (`_label_ns`) instead of days: `_split_window`, `_in_ranges`, the open-trade count in `_period_record_stats`, and the engine's `_period_returns_stats` (which now slices with `Timestamp` rather than string `.loc`).
- **run_cv:** passes the manifest's raw train bounds (`fold["_train_bounds"]`) instead of the `_iso_date`-truncated ones.
- **Docs:** the false claim at `example/backtest.md` "…这是偏保守的方向" is struck through and annotated with a dated correction, per D-18. It is not deleted.

**Regression tests:** in `tests/test_backtest_metrics.py`:
- `test_intraday_training_window_ends_horizon_bars_into_the_next_session`: includes a positive control showing the model layer's slice ends at 16:00.
- `test_training_window_honours_a_time_of_day_train_end`: covers the ISO, fold-style-ns, Timestamp and datetime64 spellings.
- `test_slice_statistics_compare_exact_bar_timestamps_not_days`: a 24h market with a midnight bar; checks the mask, the sliced return, and the open/closed trade counts.

**Mutation proof:** against fd15968, 6/6 of the new test cases fail.

**Behaviour choice:**
- **Chosen:** bar-label endpoints (date for midnight bars, full ISO otherwise), with exact comparison everywhere.
- **Rejected:** always persisting full ISO timestamps, as the review suggested. That would change every daily `metrics.json` and documented output (`2024-05-20` -> `2024-05-20T00:00:00`) for no correctness gain.
- **Left alone:** test-segment selection and contiguity in `run_cv` remain day-based. That is IN-05, out of scope.

### CR-02: `MarketSpec.year_freq` mis-annualizes every bar interval longer than one day

**Status:** fixed: requires human verification
**Files modified:** `quantlab/base/backtest.py`, `tests/test_backtest_engine.py`, `example/backtest.md`
**Commit:** f7459e7

**Applied fix:** bars per year now depends on the bar interval:

| Bar interval | Bars per year |
|---|---|
| Intraday | unchanged |
| Exactly one day | `trading_days_per_year` (252) |
| Longer than one day | `min(trading_days_per_year, CALENDAR_DAYS_PER_YEAR / days)`, with `CALENDAR_DAYS_PER_YEAR = 365.25` |

The new rule gives weekly (7D) 52.18, 30D 12.18, 31D 11.78, and 91D 4.01. The same number feeds Sharpe, Sortino, Calmar, annualized return and `turnover.annualized`. The doc formula is struck through and annotated.

**Regression test:** `tests/test_backtest_engine.py::test_us_equity_year_freq_multi_day_bars_are_calendar_spans`. It checks weekly, monthly and quarterly values, and that bars per year is continuous and non-increasing from one day up to a quarter.

**Mutation proof:** against the pre-fix code the test fails with `assert 36.0 == 52.178…`.

**Behaviour choice:** a bar longer than one day is treated as a **calendar span**. Weekly and monthly bars occur once per calendar period whether or not it contains holidays. The count is capped at 252 so a bar is never shorter than one trading day; this keeps the function continuous at one day and monotone.

Rejected alternatives:
- **The review's `round(days × 5/7)` trading days per bar:** gives weekly 50.4 and 31D 11.45, which treats holidays as if they deleted whole weekly or monthly bars.
- **Raising for intervals above one day:** the project is multi-frequency (D-18).

**Known cost, documented:** a series resampled "every N trading days" (mode interval 2–3D) would be annualized as calendar spans, about 40% more bars than a trading-day count. Nothing in the project currently produces such series.

The existing `test_model_without_train_dates_warns_and_records_null` now deletes the checkpoint record, because the record now takes precedence over `config.model`.

**Regression tests:** in `tests/test_backtest_dates.py`:
- `test_load_refuses_a_checkpoint_trained_on_other_variables`: [different-factor, different-label]; also asserts no features are computed first.
- `test_load_uses_the_checkpoints_train_dates_over_stale_config_dates`
- `test_load_without_a_checkpoint_config_json_warns_and_trusts_config_model`

**Mutation proof:** against f7459e7, 4/4 fail.

**Behaviour choices:**

Rejected: raising (it would block backtesting a model rebuilt by hand for backtesting), and warning while still trusting `config.model` (it would keep the misclassification).

### WR-02: `predict_panel` does not check the symbol universe matches training

**Files modified:** `quantlab/base/model.py`, `quantlab/utils/module.py`, `tests/test_model_predict_panel.py`, `example/model.md`
**Commit:** 554e69b

**Applied fix:**
- **Record:** `_save_model` writes a `trained_on` record into the checkpoint's `config.json`: `factor_names`, `label_names`, and the training panel's `symbols`. It also sets `_trained_symbols`.
- **Load:** `load()` reads the symbols back before `_read_checkpoint`, and `DLModel._read_checkpoint` sizes the net from them (falling back to the current panel when there is no record).
- **New hook:** `_align_prediction_symbols`, a non-abstract hook, so the hierarchy locks are unchanged. It is a no-op on `BaseModel` (ML heads predict row by row). On `DLModel` it:
  - raises `ValueError` naming any missing training symbol, which also catches a panel with the same count but different members;
  - warns about and drops symbols the model never saw;
  - selects the training symbols in their training order. **Correction (2026-09-15, G-03.7-8):** the selection is the training symbols' membership in symbol-sorted order, which is the layout the network actually trained on (`to_array` sorts the symbol axis, and `DLModel._fit` trains through it). "Training order" silently assumed that training order equals sorted order. G-03.7-8 disproved that: with an unsorted `trained_on.symbols` record, coords followed the record while values followed sorted order.
- **Loader:** `load_model_from_config` drops `trained_on`, the same way it drops `resolved_hyperparameters`.

**Regression tests:** in `tests/test_model_predict_panel.py`:
- `test_dl_checkpoint_records_its_symbols_and_predict_panel_aligns_onto_them`: a fresh instance loads without collecting; a wider reversed panel returns exactly the training symbols plus a warning.
- `test_dl_predict_panel_refuses_a_panel_missing_a_training_symbol`: [dropped-symbol, same-count-other-member]
- `test_checkpoint_config_json_with_the_training_record_rebuilds_the_model`

**Mutation proof:** against 8465f1a, 4/4 fail.

**Behaviour choice:**
- **Chosen:** for DL heads, a missing training symbol raises, and extra symbols are dropped with a warning. The backtester's reindex then gives those symbols NaN predictions, so they are never selectable (consistent with D-06/D-12).
- **Rejected:** raising on any difference (a store that gains new tickers would no longer be backtestable), and reindexing silently (missing symbols would be zero-filled and every RNN recurrence would shift).
- **Not enforced for ML heads:** they are row-wise, so symbol order and membership do not affect their predictions.

### WR-03: `cv_folds.json` checkpoint paths (and the backtest config's paths) resolve against the cwd

**Files modified:** `quantlab/base/model.py`, `quantlab/base/backtest.py`, `tests/test_backtest_run_cv.py`, `tests/test_model_cv_manifest.py`, `tests/test_backtest_rebuild.py`, `example/backtest.md`
**Commit:** 80ab83f

**Applied fix:**
- **Writing:** `_train_one_fold` writes absolute checkpoint paths, into both the returned dicts and the manifest.
- **Resolving:** `run_cv` resolves each fold through `_resolve_fold_checkpoint`:
  1. first `{cv_project_dir}/{experiment dir}/{file}`, taken from the last two path components, so a moved project still works and old relative manifests are readable;
  2. then an existing absolute recorded path;
  3. never the cwd.

  If neither location exists it raises `FileNotFoundError`. The resolved path is what gets recorded.
- **Config paths:** the `BaseBacktester.config` setter normalizes `checkpoint`, `cv_project_dir` and `output_dir` to absolute paths with `Path.absolute()`.

**Regression tests:**
- `tests/test_backtest_run_cv.py::test_run_cv_resolves_fold_checkpoints_inside_the_project_dir_not_the_cwd`, two cases:
  - `stale-absolute`: the project was moved.
  - `relative`: same-named decoy checkpoints sit under the cwd, and the old code silently loaded them.
- `tests/test_model_cv_manifest.py::test_manifest_checkpoints_are_absolute_with_a_relative_save_dir`
- `tests/test_backtest_rebuild.py::test_backtest_config_path_fields_are_stored_absolute`

**Mutation proof:** against 554e69b, 4/4 fail.

**Behaviour choice:**
- **Project-directory layout takes precedence over the recorded absolute path.** `train_cv` always writes into its project directory, so the layout invariant holds. This lets a moved project resolve itself and never reads a stale location.
- **`Path.absolute()` rather than `resolve()`,** so symlinked roots such as macOS `/var` -> `/private/var` are kept as the user wrote them.
- **Rejected:** storing paths relative to `cv_project_dir` inside the manifest. That would change the meaning of the persisted D-36 v1 format.

### WR-08: A failed persist leaves a run directory that looks like a completed run

**Files modified:** `quantlab/base/backtest.py`, `tests/test_backtest_persistence.py`, `tests/test_backtest_run_cv.py`, `example/backtest.md`
**Commit:** 7c8f737

**Applied fix:** `_persist_run_dir(write)` replaces `_new_run_dir`, and both `_report_and_persist` and `_persist_cv` use it. It:
1. refuses an existing final directory;
2. writes everything into a hidden sibling `.{name}.partial`;

4. on any `BaseException`, including `KeyboardInterrupt`, removes its own staging directory and re-raises.

**Regression tests:**

The existing `test_existing_run_directory_is_never_overwritten` still passes.

**Mutation proof:** against 0a675a8, 2/2 fail (the half-written directory remains).

**Behaviour choice:**
- **Chosen:** stage the directory and rename it into place.
- **Rejected:** a `_SUCCESS` marker. Every consumer and the loader would have to learn to check for it, and a human browsing the folder would still see the broken directory.
- **Removal is limited:** the staging directory is removed with `shutil.rmtree`. It is a fresh directory this process created, so it cannot be a reparse point.
