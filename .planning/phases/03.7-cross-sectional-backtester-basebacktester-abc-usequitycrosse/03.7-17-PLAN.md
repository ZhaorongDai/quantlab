<objective>
Close the model-level part of UAT gap G-03.7-9. `BaseModel.load()` never reads trained_on.factor_names or
trained_on.label_names, so `load()` + `predict_panel` outside the backtester silently feeds permuted inputs, and
labels permuted outputs, for both XGBoost and DL heads.

Purpose: three causes (`.planning/debug/model-load-skips-variable-order-check.md`):
- (1) load() lacks the check.
- (2) Neither head validates variable identity itself.
- (3) The only check sits in the backtester and compares the wrong record. It reads the factor config field
  instead of trained_on, with a measured false positive and false negative.

Per user decision there is one model-level check keyed on trained_on, and the backtester delegates to it. This
plan alone owns the variable-order guarantee for every head, ML (XGBoost) and DL alike. The user clarified on
2026-09-15 that XGBoost feature_names is not an order guarantee: plan 03.7-18 only writes XGBoost feature
importance to W&B and adds no name validation, so nothing here relies on it.

Output: `_assert_trained_variables` in the model layer, backtester delegation, a new test module, extended
backtester tests, and dated doc paragraphs.
</objective>

<flagged_assumptions>
- **Warning dedup.** The backtester must run the check before the DL-only feature collection (:574 requires
  refusal before any collection). load() then runs the check again, because direct callers must be protected.
  Without dedup, the legacy and no-record warnings would print twice per backtester load, which is the kind of
  warning noise G-03.7-7 exists to remove. Rule: comparisons and raises run on every call. Only an
  exact-duplicate WARNING message from the same model instance is suppressed, tracked in a per-instance set of
  already-emitted messages. Every message includes the checkpoint path and the recorded names, so a different
  checkpoint or an edited sidecar warns again.
- **Model-level no-record warning wording must not contain the substring `has no config.json`.** That substring
  belongs to the backtester's own dates-oriented warning, which :650 counts as exactly one. The backtester
  message keeps the substring and the path, and is narrowed to say only that the training DATES cannot be
  checked, because the model now owns the variable warning.
- **At most one legacy warning and at most one no-record warning per call, not one per variable kind.** Each
  names the kinds it applies to.
- **A sidecar that exists but is not a JSON object raises** ValueError naming the file. Corruption is not the
  same as absence. `_read_trained_symbols` goes through the same parser.
- **Labels are compared too** (output channel order), as the gap requires.
</flagged_assumptions>
