(1) `quantlab/utils/jsonable.py`. A leaf module: stdlib, numpy and pandas only. It exposes `to_jsonable(value)`:
- dict becomes a dict with str keys and recursed values; list or tuple becomes a list.
- bool and numpy bool become bool; numpy integer becomes int.
- float or numpy floating becomes float, with NaN, +inf and -inf mapped to None.
- pandas Timestamp, numpy datetime64, datetime.datetime and datetime.date become ISO-8601 strings; NaT becomes None.
- pandas Timedelta, numpy timedelta64 and datetime.timedelta become str; NaT becomes None.
- pathlib.Path becomes str; enum.Enum becomes its value, recursed.
- str, int and None pass through unchanged; any other object becomes str(value).
The reason (RESEARCH Pitfall 10): vectorbt stats carry NaN, inf, Timestamp and Timedelta, and plain json.dump either emits non-standard NaN tokens or raises.

(4) `quantlab/base/backtest.py`, a new module.

Imports: stdlib (abc, dataclasses, datetime, pathlib), numpy, pandas, xarray and the loguru logger, plus:
- `from quantlab.base.model import BaseModel`
- `from quantlab.dataset.backend import XrBackend`
- `from quantlab.enums.constant import Date`
- `from quantlab.utils.atomic import write_json_atomically`

It must not import vectorbt (the engine layer owns that) and must not import anything under `quantlab/backtest/`.

Define `MarketSpec`, a frozen dataclass:
- Fields `fill_price_column: str`, `valuation_price_column: str`, `trading_days_per_year: int`, `session_minutes_per_day: int`.
- `year_freq(self, bar_interval) -> pd.Timedelta`. For an interval of one day or more, bars per year = trading_days_per_year x (one day / interval). For an intraday interval, bars per year = trading_days_per_year x session_minutes_per_day / (interval in minutes).
- Return `pd.Timedelta(bar_interval) * bars_per_year`. vectorbt annualizes with year_freq / freq, so daily bars give 252 and 1-minute bars give 252 x 390 (RESEARCH Pitfall 6).

Define `SimulationResult`, a dataclass:
- `value: xr.DataArray` and `returns: xr.DataArray`, both on dim `timestamp`.
- `orders: xr.Dataset` on dim `order`, with variables `timestamp`, `symbol`, `size`, `price`, `fees`, `side`.
- `liquidations: list[dict]`, `bar_interval: np.timedelta64`.
- `native: object | None = None`: the engine's own result object, read only by the engine that produced it.

Define `BacktestResult`, a dataclass with `run_dir: Path`, `predictions: xr.Dataset`, `weights: xr.Dataset`, `simulation: SimulationResult`, `metrics: dict`.

Define `BaseBacktester(ABC)`. Its Chinese class docstring explains D-01 (engine varies by inheritance, market and selection by composition) and D-02 (the public entry points are template methods on this class, and subclasses never override them). Members:
- Abstract property `config_cls`, and class attribute `MARKET: MarketSpec | None = None`.
- `__init__(self, config)`: `self.config = config`.
- `config` property and setter:
  - The FIRST statement is the `isinstance(config, self.config_cls)` check, raising TypeError with the message `f"{self.class_name} requires a {self.config_cls.__name__}, got {type(config).__name__}"` (BaseModel style).
  - Then raise TypeError if `self.MARKET is None` (naming the class) or if `config.model` is not a BaseModel.
  - Then raise ValueError for: `model_mode` not in ("train", "load"); model_mode "load" with checkpoint None; `rebalance_periods < 1`; `fees < 0`, `slippage < 0` or `init_cash <= 0`; `pd.Timestamp(start_date) > pd.Timestamp(end_date)`.
  - Then a non-None `benchmark_dataset` raises NotImplementedError. The message states that benchmark comparison is excluded from phase 03.7 by D-08 until directly-downloaded index price data exists, and that the config slot is kept.
  - Only then assign `self._config`, set `self._config.name = self.import_path`, and call `self._validate_config()`. That hook is non-abstract and does nothing by default.
- Properties `class_name` and `import_path`, copied from BaseModel.
- `get_config(self) -> dict`: `cfg = self.config.to_dict()`, `cfg["price_dataset"] = self.config.price_dataset.get_config()`, `cfg["model"] = self.config.model.get_config()`, and `cfg["benchmark_dataset"]` is None when unset, otherwise its get_config().
- `run(self) -> BacktestResult`, the D-02 template, in this order:
  1. `self._prepare_model()`.
  2. `calendar = self._price_calendar(end_date)`.
  3. `predictions = self._align_and_predict(start_date, end_date, calendar)`.
  4. `prices = self._load_prices(start_date, end_date)`. A window with zero price bars raises ValueError naming both dates.
  5. Reindex predictions onto `prices.timestamp` and `prices.symbol`. Missing symbols become NaN and therefore ineligible (D-06, RESEARCH Pitfall 14).
  6. `weights = self._generate_signals(predictions, prices)`, then `self._assert_weights_contract(weights, prices)`.
  7. `simulation = self._simulate(weights, prices)`.
  8. `benchmark = self._simulate_benchmark(start_date, end_date)`.
  9. `metrics = self._compute_metrics(simulation, benchmark)`.
  10. `run_dir = self._report_and_persist(predictions, weights, simulation, metrics)`.
  11. Return `BacktestResult`.
- `_prepare_model(self)`: model_mode "load" calls `self.config.model.load(self.config.checkpoint)`. Mode "train" calls `model.collect()` then `model.train()`. Training uses the model's own train/test dates, which are never overwritten (D-13).
- `_price_calendar(self, end_date) -> np.ndarray`:
  - Write ISO `YYYY-MM-DD` strings directly into `price_dataset.config.start_date` (`Date.START_DATE`) and `.end_date`. The dataset setter's ISO normalization only runs on whole-config assignment, so always write ISO strings.
  - Call `price_dataset.read(overwrite=True)`. Without it the XrBackend read cache returns an earlier, narrower read (RESEARCH Pitfall 1).
  - Return the sorted `timestamp` values of `price_dataset.get_xarray_dataset()`.
- `_warmup_start(self, calendar, start_date) -> str` (D-15):
  - `window = max(int(f.config.window) for f in model.config.factors)`, or 0 when there are no factors.
  - `idx = np.searchsorted(calendar, np.datetime64(pd.Timestamp(start_date)), side="left")`.
  - When `idx - window < 0`, logger.warning names the shortfall in bars, and index 0 is used.
  - Return `pd.Timestamp(calendar[max(idx - window, 0)]).strftime("%Y-%m-%d")`.
  - Bars are counted on the price calendar, never with a calendar-day offset. Factor._reset_dataset_config's own calendar-day subtraction remains as an extra buffer and is not relied on.
- `_align_and_predict(self, start_date, end_date, calendar) -> xr.Dataset` (D-14):
  - `warmup = self._warmup_start(calendar, start_date)`.
  - For each factor in `model.config.factors`: set `factor.config.start_date = warmup` and `factor.config.end_date = end_date`, call `factor._reset_dataset_config()`, then call `factor.config.dataset.read(overwrite=True)` (Pitfall 1).
  - `features = model._collect_all_features()`: features only, never labels.
  - Return `model.predict_panel(features).sel(timestamp=slice(start_date, end_date))`. xarray partial-string slicing includes the whole end day.
- `_load_prices(self, start_date, end_date) -> xr.Dataset`:
  - Set the price dataset's dates to the window and call `read(overwrite=True)`.
  - The columns named by `self.MARKET.fill_price_column` and `self.MARKET.valuation_price_column` must exist; otherwise raise ValueError naming the missing column and the store path.
  - Return `ds[[fill, valuation]].load().copy(deep=True)`, so a later re-date of a dataset object shared with a factor cannot change it.
- `_assert_weights_contract(self, weights, prices)` (D-03) checks all of the following, and any breach raises ValueError naming the first offending timestamp:
  - `"weight"` is in `weights.data_vars`, and its dims are `("timestamp", "symbol")`.
  - The timestamp and symbol coords equal those of `prices`.
  - Every row is either all-NaN or all-finite.
  - Every finite row has `abs(w).sum() <= 1 + 1e-9`.
- Abstract hooks, each with a one-line Chinese contract docstring in BaseModel hook style:
  - `_generate_signals(self, predictions, prices) -> xr.Dataset`
  - `_simulate(self, weights, prices) -> SimulationResult`
  - `_simulate_benchmark(self, start_date, end_date) -> SimulationResult | None`
  - `_engine_stats(self, simulation) -> dict`
- `_compute_metrics(self, simulation, benchmark) -> dict` returns `{"whole": self._engine_stats(simulation)}`. It adds a `"benchmark"` key only when benchmark is not None.
- `_run_dir_name(self) -> str` returns `f"{self.class_name}_{datetime.now().strftime('%Y%m%d_%H%M%S_%f')}"`. The microseconds stop two runs in the same second from colliding; D-24 names the directory {class}_{timestamp}.
- `_report_and_persist(self, predictions, weights, simulation, metrics) -> Path` (D-24):
  - `run_dir = Path(self.config.output_dir) / self._run_dir_name()`. If it exists, raise `RuntimeError(f"{run_dir} already exists")`; runs are never overwritten, following the `_save_model` precedent. Otherwise `mkdir(parents=True)`.
  - `write_json_atomically(run_dir / "config.json", to_jsonable(self.get_config()), indent=2)`.
  - `XrBackend().to_internal(weights).write(str(run_dir / "weights.zarr"))`.
  - `xr.Dataset({"value": simulation.value, "returns": simulation.returns})` written the same way to `equity.zarr`.
  - `write_json_atomically(run_dir / "metrics.json", to_jsonable(metrics), indent=2)`.

(5) `quantlab/backtest/selection.py`, with Chinese docstrings:
- `rebalance_mask(n_bars: int, rebalance_periods: int) -> np.ndarray` returns a bool array.
  - It is True at indices 0, p, 2p and so on (D-18: the anchor is the first window bar, then every p bars).
  - Index n_bars - 1 is forced False, because the last bar's signal has no t+1 fill bar inside the window (RESEARCH Pitfall 13).
  - rebalance_periods < 1 raises ValueError.
- `resolve_score_label(score_label: str | None, label_names: list[str]) -> str`. None returns `label_names[0]` (D-11). An unknown name raises ValueError listing the known label names, and an empty label list raises ValueError.
- `CrossSectionTopNSelector`, a frozen dataclass with `direction: Literal["long_only", "long_short"]` and `top_n: int`. `__post_init__` raises ValueError for an unknown direction or top_n < 1.
- `select(self, scores: xr.DataArray, next_fill_price: xr.DataArray, rebalance: np.ndarray) -> xr.Dataset`:
  - The output starts all-NaN, so non-rebalance bars stay NaN (D-03).
  - Each True row first becomes 0.0 for every symbol. A NaN on a rebalance bar would mean "hold" and silently block the rebalance (RESEARCH Pitfall 3).
  - Eligible means finite score AND finite next_fill_price (D-12).
  - Rank eligible symbols with `np.argsort(-score, kind="stable")`, so ties resolve by symbol-axis order (reproducibility, D-25).
  - long_only: k = min(top_n, n_eligible), and the top k symbols get 1/k (D-09).
  - long_short: k = min(top_n, n_eligible // 2). The top k get +0.5/k and the bottom k get -0.5/k, so the two books never share a symbol (D-09).
  - When k < top_n, logger.warning names the timestamp, k and top_n (D-12). When k == 0 the row stays all 0.0 (flat).
  - Return `xr.Dataset({"weight": (("timestamp", "symbol"), array)})` using the scores' coords.

(6) `quantlab/backtest/engine_vectorbt.py`. It is deliberately not named after the library (RESEARCH Pitfall 12). `VectorBtBacktester(BaseBacktester)` stays abstract: config_cls and _generate_signals come from the concrete class.

Its Chinese class docstring states three things:
- A signal at the bar-t close fills at the bar t+1 open (D-05).
- Target percentages are computed on group value marked at the order price, vectorbt's val_price default (RESEARCH Pitfall 4).
- No borrow or short-financing cost is modelled, so short-side returns are optimistic (D-21).

Class attribute `STATS_METRICS` is the tuple of vectorbt Portfolio metric names from RESEARCH Pitfall 6 minus benchmark_return: start, end, period, start_value, end_value, total_return, max_gross_exposure, total_fees_paid, max_dd, max_dd_duration, total_trades, total_closed_trades, total_open_trades, open_trade_pnl, win_rate, best_trade, worst_trade, avg_winning_trade, avg_losing_trade, avg_winning_trade_duration, avg_losing_trade_duration, profit_factor, expectancy, sharpe_ratio, calmar_ratio, omega_ratio, sortino_ratio.

`_simulate(weights, prices)` uses pandas only inside this method; xarray is the format between modules.
- The bar interval is the mode of the price timestamp diffs, mirroring BaseDataset.time_interval. Fewer than two bars raises ValueError.
- `w` is the weight array transposed to (timestamp, symbol), then `.to_pandas()`.
- The fill and valuation frames come from the MARKET columns via `.to_pandas().ffill()` (D-07). A NaN-priced held position freezes every later rebalance of the whole group (RESEARCH Pitfall 2).
- Call `vbt.Portfolio.from_orders(close=valuation, price=fill, size=w.shift(1), size_type="targetpercent", direction="both", group_by=True, cash_sharing=True, call_seq="auto", fees=cfg.fees, slippage=cfg.slippage, init_cash=cfg.init_cash, freq=pd.Timedelta(bar_interval))` (D-05, D-19). Fractional sizes are vectorbt's default (D-20).
- `value = pf.value()` and `returns = pf.returns()` become `xr.DataArray`s on dim `timestamp`.
- Orders come from `pf.orders.records_readable`, mapped from Timestamp/Column/Size/Price/Fees/Side to timestamp/symbol/size/price/fees/side as an `xr.Dataset` on dim `order`.
- `liquidations` is an empty list, and `native=pf`.

`_simulate_benchmark(start_date, end_date)` returns None; the base setter already rejects a non-None benchmark_dataset (D-08).

`_engine_stats(simulation)` returns `simulation.native.stats(metrics=list(self.STATS_METRICS), settings=dict(year_freq=self.MARKET.year_freq(simulation.bar_interval)), silence_warnings=True).to_dict()`.
