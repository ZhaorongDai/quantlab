# Phase 03.7 Plan 06: Model Preparation and Date Alignment Summary

**The backtester's first two template steps are now correct in every mode:**
- warm-up is counted in bars on the price calendar and clamped with a warning;
- re-dated factor reads go through `_refresh_factor_reads`, which refreshes the dataset always and the factor store under "read";
- predictions align to every price symbol by label;
- load mode checks the file first and collects the panel for DL heads before `load()`.

## Accomplishments
- `BaseBacktester._iso_date(value)` returns `pd.Timestamp(str(value)).strftime("%Y-%m-%d")`. It replaces the tracer's `_iso`, and `run()` and `_warmup_start` both route through it.
- `_refresh_factor_reads(factor)` always calls `factor.config.dataset.read(overwrite=True)`. Under `factor_data_strategy == "read"` it also calls `factor.read(overwrite=True)`. `_align_and_predict` calls it for each factor right after `_reset_dataset_config()`, in place of the old inline dataset read. Its Chinese docstring explains the cache: `XrBackend.read` returns early once it holds data, and `_filter`/`_auto_filter` then narrow that data in place.
- `_warmup_start` still counts bars with `np.searchsorted`. Its clamp warning now names the requested bars, the available bars, the shortfall and the clamped start date.
- `_prepare_model` in load mode:
  1. checks `Path(checkpoint).exists()` and raises `FileNotFoundError` naming the path;
  2. for a `DLModel` only, calls `model.data_backend.to_internal(model._collect_all_features())`;
  3. calls `model.load`.

  Train mode is unchanged: `collect()` then `train()`, on the model's own dates.
- The construction-time `load`/checkpoint check has a comment marking it as the one-line condition 03.7-10 relaxes.
- `tests/test_backtest_dates.py` holds the 12 locks and a test-local `TinyLinearDLHead`, which does a real SGD step for one epoch.

## Carried findings from earlier plans

1. **(a) Plan 01 M7, zero-bar warm-up escaped. Addressed.** The warm-up test uses `n=5, window=5`, and its window starts on a Monday. Five calendar days before a Monday reach back only 3 bars, so `Factor._reset_dataset_config`'s buffer alone cannot cover the lookback. M3 goes red.
   **(b) Plan 01 M8, missing reindex escaped. Addressed.** The D-06 test narrows the factor dataset with `symbols=` so it excludes `FFF`. Predictions therefore carry a different symbol set from prices, and M4 goes red.
2. **Plan 03 hazard, same-shape panels pairing by position. Addressed.** `test_predictions_align_to_price_symbols_by_label_not_position` writes the price store in reverse symbol order. `predict_panel` always returns symbols sorted, so predictions and prices have the same shape but different orders. The test checks each prediction value and the chosen names by symbol label. Removing the reindex (M4) and relabelling by position (M4b) both go red.

## Decisions Made
- `_iso` was renamed to `_iso_date` rather than kept next to it. `_iso` had only the two callers in `run()`, and two names for one normalization rule is the ambiguity a later reader resolves wrongly.
- The construction-time message already says load mode needs a checkpoint path, so it was left as is. A comment above the condition records that `run_cv` reads `cv_project_dir` instead and that 03.7-10 changes only that one line.
- The date-strategy tests put the backtest window (bars 25..45) before the model's own start (bar 35). With the window inside the model's range, the stale cache would still hold the needed bars, and the refresh mutations would stay green.
- The factor-date test uses two factors with windows 3 and 7. That locks both halves of "every factor" and "the maximum window": M6 (smallest window) goes red.
