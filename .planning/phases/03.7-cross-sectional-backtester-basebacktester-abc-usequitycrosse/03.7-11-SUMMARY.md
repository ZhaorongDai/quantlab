# Phase 03.7 Plan 11: Backtester Rebuild from config.json Summary

**`load_backtester_from_config` turns a backtest run's `config.json` back into a runnable backtester.** It first refuses any class that is not a `BaseBacktester`. It then rebuilds the price dataset, the model with its factors, labels and checkpoint reference, an optional benchmark, and every scalar parameter. The stored `data_fingerprint` becomes `expected_fingerprint`. Nine locks cover it. They prove that re-runs reproduce identical weights and equity for load mode, train mode and run_cv, and that a changed store gets a warning. All 6 mutations went red.

## Accomplishments

- **The loader (`quantlab/utils/module.py`).** `load_backtester_from_config(config)` runs these steps in order:
  1. Deep-copy the input.
  2. Pop `data_fingerprint`.
  3. Import `BaseBacktester` locally.
  4. Resolve `config["name"]`. If it is not a type or not a `BaseBacktester` subclass, raise `TypeError` naming the dotted path. Nothing has been built yet at this point.
  5. Rebuild `price_dataset` with `load_dataset_from_config` and `model` with `load_model_from_config`. Rebuild `benchmark_dataset` only when it is not None.
  6. Construct `cls(_config_cls_of(cls)(**config))`.
  7. Set `expected_fingerprint`.

  The docstring states the trust stance: a config JSON is trusted local input, like a checkpoint.
- **Round trip (D-25, D-26).** A JSON-normalized `get_config()` rebuilds with the same backtester class, `CrossSectionBacktestConfig` and `MLConfig`, and gives back an equal `get_config()`.
- **Identical re-runs (D-25).** Each test runs once, reads `config.json`, rebuilds and runs again. The two run directories hold identical `weights.zarr` (`xr.testing.assert_identical`) and exactly equal equity `value` arrays.
  - **Load mode:** whole-window `Total Return [%]` is also equal, and no fingerprint warning appears.
  - **Train mode:** the rebuilt run trains its own model, so two `.joblib` files exist. The test waits 1.1 s because `BaseModel.train` names project directories to the second.
  - **run_cv:** a real `train_cv` run with 8 folds; the stitched weights and equity are identical.
- **Changed data (D-27).** One `adjClose` cell inside the window is rewritten in place. The rebuilt run warns with `data fingerprint mismatch for 'price_dataset'` and still returns a result. An unchanged store re-runs with no warning (load-mode test).

## Issues Encountered

- **Rebuilt factor dates.** The `BaseModel` config setter pushes the model's own `start_date`/`end_date` onto every factor and label. A run mutates factor dates to its warm-up window, and the rebuilt model resets them, so a rebuilt `get_config()` equals the original's only for configs taken before a run. That does not affect re-runs, since `run()` re-dates factors itself. The round-trip lock therefore compares pre-run configs.
