# Phase 03.7 Plan 07: cv_folds.json Manifest and Stale Backtest Hook Deletion Summary

**`train_cv` now leaves `{project}/cv_folds.json` = `{"format_version": 1, "folds": to_jsonable(results)}`, written atomically after both branches, so `run_cv` (03.7-10) can replay exactly the folds a training run used. The stale in-model backtest hooks (D-37) are gone and a signature/`hasattr` lock keeps them out.**

## Decisions Made
- The manifest is written after the summary-run block, right before `return`, so it follows both branches and covers the zero-fold case too.
- Only a `to_jsonable` copy is dumped. The strict-JSON test also asserts that the returned list still holds the NaN, which shows the conversion never mutates `results`.
- The deletion lock checks both `hasattr` and `__dataclass_fields__` on each config class, plus the exact `_fit` parameter list. A `backtest_data` reintroduced as a real dataclass field would also go red.
