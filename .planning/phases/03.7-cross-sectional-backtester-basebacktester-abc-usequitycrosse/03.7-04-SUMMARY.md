## Accomplishments
- `VectorBtBacktester._simulate` first checks that every weight row is all-NaN or all-finite, before any pandas conversion. A mixed row raises `ValueError` naming its timestamp. The base contract check only runs inside `run()`, so a direct caller could skip it.
- After the vectorbt run, `_forced_liquidations` turns each finite signal row t (with t+1 in the window) into records. A record is written for every symbol whose holding at t is nonzero and whose raw fill price at t+1 is NaN. Each record holds `symbol`, `signal_timestamp`, `fill_timestamp` and the ffilled `price`, and one info line is logged per record.
- `_signed_order_sizes` derives cumulative (timestamp, symbol) positions from order records. It refuses orders off the price axis and unknown sides.
- The class docstring (Chinese) now covers:
  - D-07: why both price frames are forward-filled (the whole group freezes, RESEARCH Pitfall 2);
  - the liquidation rule and the record fields;
  - the Pitfall 3 refusal.
- `tests/test_backtest_engine.py` holds the 19 tests named in the plan. It also holds a test-local `EqualWeightEveryone(VectorBtBacktester)` that declares only `config_cls`, `MARKET` and `_generate_signals`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `_signed_order_sizes` signature takes the price axes**
- **Found during:** Task 1
- **Issue:** The plan writes `_signed_order_sizes(orders) -> xr.DataArray` returning a (timestamp, symbol) panel. Order records only carry the bars and symbols that traded, so the helper cannot build the full panel Task 2 indexes by bar t.
- **Fix:** It is a staticmethod `_signed_order_sizes(orders, timestamps, symbols)`. The acceptance grep `def _signed_order_sizes` still prints 1.
- **Files modified:** quantlab/backtest/engine_vectorbt.py
- **Verification:** A scratchpad probe returned the expected cumulative positions for a flip and zeros for an empty order set. Mutation M8 turns the liquidation test red.
- **Committed in:** e936081

**2. [Rule 2 - Missing Critical] Helper refuses off-axis orders and unknown sides**
- **Found during:** Task 1
- **Issue:** An order timestamp not on the price axis, or a side other than Buy/Sell, would be silently misplaced or mis-signed. Either would corrupt the D-07 holding test.
- **Fix:** Both cases raise `ValueError`.
- **Files modified:** quantlab/backtest/engine_vectorbt.py
- **Verification:** All 19 tests pass. The guards are inert on vectorbt's own records.
- **Committed in:** e936081

- **The benchmark test's warning arm cannot fail on its own.** `_engine_stats` passes `silence_warnings=True`, and its explicit metrics list requests no alpha/beta, so no `benchmark_rets` warning can appear either way. That test's key arm is what M6 turns red. The warning arm is kept as a plan-required tripwire, and this note records that it carries no independent weight.
- **Engine tests emit the zarr "Consolidated metadata" warning.** It comes from the fixture store write, and there is no code impact.
- **A late-listing symbol is ineligible only on its first bar.** If a symbol lists on bar t+1 exactly, its raw fill price is finite and it is eligible. A symbol that turns NaN again after listing, and was held, is recorded like any delisting. This is consistent with D-07, and no test contradicts it.
