# Phase 03.7 Plan 05: predict_panel Head Adapters Summary

**`predict_panel` now serves every shipped head. MLPRegressor flattens to its `[T, S*F]` inference input, RNNRegressor returns the direct-prediction channels, and RNNClassifier returns per-label P(up). Eleven contract tests lock label order, coords, NaN masking and the error cases, and the stale `RNNClassifier._vecbt` is deleted.**

## Accomplishments
- `tests/test_model_predict_panel.py` locks the D-29 contract on an ML stub, a generic DL head, XGBoostRegressor, MLPRegressor, RNNRegressor and RNNClassifier:
  - output follows the declared label order (labels declared reverse-alphabetically);
  - output coords are sorted and each value sits at the coordinate that produced it (input given with both axes reversed);
  - a row whose features are all NaN predicts NaN, and a partially-NaN row does not;
  - a missing factor, an uninitialized model and an unadapted tuple head each fail naming the problem.
- `MLPRegressor._predict_panel_array` flattens `[T, S, F]` in `_train_one_batch`'s C order, calls the unchanged public `predict()`, and reshapes `[T, S*L]` back to `[T, S, L]`.
- `RNNRegressor._predict_panel_array` returns `all_direct_preds`, so label 0 is `base_models[0]`'s direct prediction, not the aux-combined `primary_pred_final` (D-33).
- `RNNClassifier._predict_panel_array` pairs direct logit channels `[2i, 2i+1]` and returns the class-1 softmax. Its Chinese docstring says each label variable holds a probability, not a return. A channel count other than 2 x labels raises `ValueError` naming the head.
- `RNNClassifier._vecbt` and its now-unused `pandas` import are gone (D-37). `test_rnn_classifier_vecbt_is_deleted` replaces the old raises-lock, and the superseded module-docstring bullet in `tests/test_dl_models.py` is annotated rather than deleted.

## MLP finding (D-33 premise)

D-33 lists MLP among the generic heads that keep the plain `[T, S, L]` path. The code says otherwise:
- `MLPRegressor._init_model` builds `nn.Linear(num_symbols * num_features, ...)`;
- the training loop flattens every bar to `[T, S*F]`;
- `test_mlp_regressor_trains_two_epochs_and_predicts` documents that `predict()` takes the flat matrix.

The generic path failed exactly as predicted: `RuntimeError: mat1 and mat2 shapes cannot be multiplied (90x2 and 6x16)`. The adapter satisfies D-29 without touching MLP's public `predict()` or its module.

## Decisions Made
- MLP gets an adapter, not a changed `predict()`. The flat contract is the head's public inference API, already locked by `tests/test_dl_models.py`.
- The RNNClassifier channel-count check raises rather than trusting the reshape. A mismatched module would otherwise pair logits from two different labels and still produce valid-looking probabilities.
- The RNN tests compute expected values from `model.model(...)` directly, under `eval()` and `no_grad`. They never read the expected values through `predict_panel` or the adapter.
