# Phase 03.7: Cross-sectional backtester (BaseBacktester + USEquityCrossectionSelectStockVectorBt) - Context

**Gathered:** 2026-09-14
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase delivers a **backtester layer** that turns a trained return model into a tradable, reproducible backtest. It builds:

1. **`BaseBacktester`**, an abstract base class in `quantlab/base/backtest.py`, plus a `BacktestConfig` dataclass. The base class owns the pipeline template and the only two public entry points: `run()` for a model backtest and `run_cv()` for a model-CV backtest.
2. **One concrete backtester, `USEquityCrossectionSelectStockVectorBt`**: a simple, fast vectorbt backtest of a US-equity cross-sectional stock-selection strategy. On each rebalance it selects n stocks from the price universe using model predictions and holds them unchanged until the next rebalance.
3. **Two model-layer additions** the backtester needs:
   - `BaseModel.predict_panel(features) -> xr.Dataset`;
   - `train_cv` persisting a `cv_folds.json` manifest.
4. **Config round-trip reproducibility**:
   - a backtest's output config JSON rebuilds the whole backtester (datasets, factors, labels, model, parameters) and re-runs the identical backtest;
   - fix the existing factor/dataset rebuild gap, so Polars factors and constituent datasets rebuild too;
   - record a data fingerprint.
5. **Delete `quantlab/vecbt/bt.py`** (REQUIREMENTS CLEAN-02).

The backtest price data, the stock-selection signal and the (optional) benchmark all share one bar frequency (e.g. all daily or all minute).

**Relation to the roadmap:** this front-loads the vectorbt part of BT-01 (Phase 6) and establishes the target-weights contract Phase 5's optimizer will emit. Phase 6 still owns the single-config end-to-end data→…→backtest pipeline and the NautilusTrader path (BT-02).

**Not in this phase:**
- `USEquityTimeseriesVectorBt` and `USEquityCrossectionEventDrivenBt` (names are reserved by the hierarchy only);
- benchmark comparison, until directly downloaded index price data exists;
- borrow costs;
- any portfolio optimizer beyond equal-weight TopN;
- index-membership universes.

</domain>

<decisions>
## Implementation Decisions

### Class structure and placement
- **D-01:** The engine varies by **inheritance**; market and selection logic vary by **composition**. This avoids a market × style × engine class explosion.
  - Hierarchy: `BaseBacktester` (`quantlab/base/backtest.py`) → `VectorBtBacktester` (engine layer) → `USEquityCrossectionSelectStockVectorBt` (thin named subclass that combines the US-equity market spec with a cross-sectional TopN selector).
  - Concrete classes live in a new package `quantlab/backtest/` (exact module names are Claude's discretion). Future siblings `USEquityTimeseriesVectorBt` and `USEquityCrossectionEventDrivenBt` must be addable without changing the base class.
- **D-02:** The only user-facing methods are `run()` (model backtest) and `run_cv()` (model-CV backtest). `run()` executes the pipeline template in the base class, in this order:
  1. prepare the model (train or load);
  2. align factor dates, then predict;
  3. generate signals;
  4. simulate;
  5. benchmark (optional, see D-08);
  6. metrics;
  7. report and persist.

  Abstractable steps are template/abstract methods on the base. The engine-specific ones (`_simulate`, `_simulate_benchmark`) and the signal-generation step (`_generate_signals`) are abstract.
- **D-03:** **The signal-generation output contract is target weights.** It is an `xr.Dataset` with a `weight` variable on dims `(timestamp, symbol)`, whose values are:
  - NaN on bars that are not rebalance bars;
  - on rebalance bars, `sum(|w|) ≤ 1` (gross ≤ 100%).

  This is the same "target holding % per symbol" contract Phase 5's optimizer will produce, so an optimizer can replace the TopN selector without backtester changes. Weights are persisted (D-24) so a future event-driven engine can reuse them. — **Reversibility:** costly — it becomes the Phase 5 → backtest interface and a persisted on-disk artifact; changing it later touches the selector, every engine, and stored runs.

### Price data, execution, universe
- **D-04:** Prices come from `dataset.read().get_xarray_dataset()`, with column names chosen by **class attributes on the backtester**, never hardcoded inside methods. For US equity: the fill price is `adjOpen` and the valuation price is `adjClose` (both split/dividend adjusted; Tiingo EOD columns `quantlab/enums/data.py:TiingoColumns.EOD`). Unadjusted `open`/`close` are never used for P&L. The user asked for this directly: "复权价能不能直接 get_xarray_dataset() 然后根据类定义的列名取数据".
- **D-05:** **Execution timing: a signal formed at the close of bar t fills at the open of bar t+1.**
  - vectorbt shape: `Portfolio.from_orders(close=adjClose, price=adjOpen, size=weights.shift(1 bar), size_type="targetpercent", direction="both", group_by=True, cash_sharing=True, call_seq="auto")`.
  - Verified in a vectorbt 1.1.0 / pandas 3.0.5 probe: a signal on bar 0 filled at bar 1's open, and a long→short flip worked with `direction="both"`.
- **D-06:** **The universe is every symbol in the price dataset.** There is no index-membership masking this phase.
- **D-07:** **Delisting rule: when a held symbol's price turns NaN, forward-fill its last price and force-liquidate it at the next rebalance.** Record each forced liquidation (symbol, bar, price).
  - Why this is required, verified by probe: vectorbt keeps a NaN-priced position at its last value and **silently skips every later rebalance**. A target-100%/0% rebalance never executed and raised no error; forward-filling prices restored the rebalance.
- **D-08:** **Benchmark:** `BacktestConfig.benchmark_dataset` is an optional single-symbol dataset (it may be an index), at the same frequency, default `None`. Locally there is no directly-downloaded index price data (only `data/data/us_equity/1d/us_all.zarr` and `stock_alpaca.zarr`), so **benchmark comparison is NOT implemented this phase.** The user said: "只有指数集是直接下载的指数价格（如果现在还没有，先不做 benchmark 对比）". Keep the config slot and the base hook so it can be added later; when the benchmark is `None`, reports omit it.

### Stock selection and weights
- **D-09:** Direction is a config choice, `long_only` or `long_short`.
  - `long_only`: the top_n names by score, equal weight, summing to 100%.
  - `long_short`: top_n longs sum to +50% and bottom top_n shorts sum to −50%, equal weight within each book. Gross exposure is 100%, net 0.
  - This follows the project key decision "持仓模型采用多空、不加杠杆（净/毛敞口 ≤100%）" (`.planning/PROJECT.md` Key Decisions).
- **D-10:** Pick count is a fixed `top_n` (no quantile mode).
- **D-11:** The score comes from the config `score_label` (a label name). By default it is the model's first label (index 0). An unknown label name raises.
- **D-12:** Eligibility on a rebalance bar excludes symbols whose prediction is NaN, or that have no `adjOpen` on the fill bar (t+1). If fewer than top_n remain, select what is available, split the book weight equally among them, and log a warning.

### Model preparation and date alignment
- **D-13:** `BacktestConfig.model_mode` is `"train"` or `"load"`.
  - `train` uses the **model's own config dates** (`train_start`/`train_end`/`test_start`/`test_end`) and does NOT override them. The backtest window only drives prediction and in/out-of-sample classification.
  - `load` requires a checkpoint path.
- **D-14:** **Date alignment works by mutating the factor configs directly** (`factor.config.start_date` / `end_date`, which existing `Factor._reset_dataset_config` pushes into the dataset config). Do not build a parallel slicing or fetch path. The user said: "对于涉及读取指定日期数据或计算因子，可以直接改因子类的配置文件". Prediction computes **features only** (not labels), via D-29.
- **D-15:** Warm-up is **automatic from the factors' `config.window`**:
  - take the maximum window, in bars;
  - convert it to a start date using the price dataset's own trading calendar (its timestamp axis), not calendar-day arithmetic;
  - set the factors' start date that much earlier, predict, then slice the predictions back to the backtest window.

  Note: `Factor._reset_dataset_config` already subtracts `window` **calendar days** from the dataset start (`quantlab/base/factor.py`). That existing behaviour is an extra buffer, not a bar-accurate warm-up, and must not be relied on.
- **D-16:** `run_cv()` reads **`cv_folds.json` in the `train_cv` project directory** (written by D-30). For each fold it:
  - loads that fold's checkpoint;
  - backtests **only that fold's test segment**;
  - reports per-fold results.

  It also produces a stitched out-of-sample equity curve across folds. `BaseModel._cv_folds` yields contiguous, non-overlapping test segments, so stitching is valid; assert it rather than assume. — **Reversibility:** costly — `cv_folds.json` becomes an on-disk format that CV backtests of old training runs depend on.
- **D-17:** **In-sample detection.** The effective training window is `[train_start, train_end + label horizon]`, where the label horizon is the maximum `n_forward_periods` across the model's labels, in bars. The label on `train_end` uses the next n bars of prices, so those bars count as in-sample too.
  - If the backtest window overlaps this range: `logger.warning`, continue, and report in-sample and out-of-sample results separately.
  - Split by **slicing the single continuous simulation's returns/equity**, not by running separate simulations. Separate runs would reset capital and change the path.
  - In `run_cv`, apply this per fold using that fold's dates.

### Rebalancing and execution details
- **D-18:** The rebalance anchor is the first bar of the backtest window. After it, rebalance every `rebalance_periods` bars (a bar count, frequency-agnostic) and hold positions unchanged in between.
- **D-19:** Defaults, all configurable: `fees=0.0005` (5bp), `slippage=0.0005` (5bp), `init_cash=1_000_000`.
- **D-20:** Fractional shares are allowed.
- **D-21:** There are no borrow/short financing costs this phase. Docs and report must state that short-side returns are optimistic.

### Output, reporting, reproducibility
- **D-22:** Metrics are **vectorbt `stats()` full set + turnover**, computed for the whole backtest, the in-sample slice and the out-of-sample slice (D-17).
- **D-23:** Charts are a **plotly interactive HTML** with an equity curve and a drawdown curve, in-sample bars shaded (plotly 5.24 is already a dependency).
- **D-24:** Each run gets its own directory `output_dir/{class}_{timestamp}/` holding:
  - the complete backtest config JSON;
  - target weights (xarray/Zarr, per the project's inter-module format constraint);
  - equity and returns series;
  - forced-liquidation records;
  - metrics JSON;
  - the HTML report;
  - the data fingerprint (D-27).
- **D-25:** **A backtest config must fully rebuild and re-run the backtest.** Loading the persisted config JSON reconstructs the datasets, factors, labels, model class (+ checkpoint reference when `model_mode="load"`) and every parameter, and `run()` reproduces the same backtest. Add a `load_backtester_from_config(config: dict)` (or equivalent) alongside `quantlab/utils/module.py:load_model_from_config`. The user said: "回测要输出 config，未来使用回测器可以直接加载这个 config，它将加载需要的数据和类，并且重新跑这个回测。所有参数都需要一致，以确保回测可复现…回测器也是从一个回测器的 config 直接构建所有需要的东西". — **Reversibility:** costly — the JSON is a persisted, user-facing format; renaming or moving fields breaks re-runs of stored backtests.
- **D-26:** **Fix the existing config-rebuild gap in this phase.** Factor and dataset classes declare a `config_cls` (mirroring `BaseModel.config_cls`), and `load_factor_from_config` / `load_dataset_from_config` build `cls.config_cls(**config)`.
  - Verified broken today: a `PolarsFactorConfig` dict → `TypeError: FactorConfig.__init__() missing 2 required keyword-only arguments: 'mode' and 'data_columns'`; a `ConstituentDatasetConfig` dict → `TypeError: DatasetConfig.__init__() got an unexpected keyword argument 'cache_dir'`.
  - Verified working today: `Alpha101Stock` (KunQuant) + `Return` label + `XGBoostRegressor` round-trips (`get_config` → JSON → `load_model_from_config` → `get_config`) with an identical config.
  - Lock the fix with round-trip regression tests for a KunQuant factor, a Polars factor, and the backtester config.
- **D-27:** **Data fingerprint.** For each dataset used within the backtest window (including warm-up), record the time range, the symbol count, and a checksum of the price/data columns actually used. Store it in the run output. A rebuild-from-config re-run recomputes it and compares: on mismatch, `logger.warning` and continue. Motivation: datasets get appended, and Tiingo re-bases adjusted prices retroactively after new dividends.
- **D-28:** wandb is an optional switch `use_wandb`, default `False`. When on, log metrics and the equity chart to a separate backtest run.

### Model-layer additions
- **D-29:** `BaseModel.predict_panel(features: xr.Dataset) -> xr.Dataset` takes a `(timestamp, symbol)` feature panel. It returns predictions with one variable per label name on the same dims, so the xarray→array→predict→xarray plumbing lives in the model layer, shared by DL and ML, not in the backtester. It must handle `DLModel` tensor output and `MLModel` numpy output.
- **D-30:** `train_cv` writes `cv_folds.json` into its project directory. Each fold entry holds `fold`, `train_start`, `train_end`, `test_start`, `test_end`, `experiment_name`, `checkpoint`, plus the fold's test metrics when present — the same dicts `train_cv` already returns. The returned value is unchanged.

### Cleanup
- **D-31:** Delete `quantlab/vecbt/bt.py` (REQUIREMENTS CLEAN-02) and remove or redirect every reference (the `quantlab/vecbt/` package, docs, scripts such as `test.py`/`train_model.py` if they import it).

### Claude's Discretion
- Exact module and file names under `quantlab/backtest/`, the shape of the result dataclasses, and whether the US-equity market spec and TopN selector are small classes or dataclasses.
- Turnover formula, as long as it is defined in the docstring and reported consistently.
- Checksum algorithm for the data fingerprint.
- Format of the forced-liquidation records and plot styling.
- Test fixtures: synthetic in-memory panels in the style of the model-layer tests' `FakePanel`; no network, no real data.

### Established Patterns
- Config objects are dataclasses with `to_dict()`. A domain object's `config` setter mutates the config on assignment (fills dates, pushes them down, sets `name = import_path`), and `get_config()` nests child configs.
- Model-layer docstrings in `quantlab/base/model.py` are in Chinese; test docstrings are in English and explain what each test locks and why it would go red.
- Tests are synthetic, CPU-only and offline (`FakePanel` stand-ins, `WANDB_MODE=disabled`), run with `uv run pytest`. Factor constructors read their dataset store eagerly, so tests must not construct real `Factor`s against missing stores.
- Superseded wording is kept and annotated rather than deleted (the D-18 convention seen across 03.x docs).
- Layering is one-directional: `base` → `dataset`/`factor`/`label` → `dl_model`/`ml_model` → backtest. The new `quantlab/backtest/` sits at the top and must not be imported by lower layers.
