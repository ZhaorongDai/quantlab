**Verified blocking discovery (supersedes 03-RESEARCH.md's claim that the crypto batch path "already works"):** `my_ops/preprocess.py` defines `WindowedZScore.decompose(self)` and `WindowedRobustStandardization.decompose(self)`, but the installed KunQuant 0.1.11 declares the contract as `CompositiveOp.decompose(self, options: dict)` (`KunQuant/Op.py:292`) and invokes it as `op.decompose(options)` (`KunQuant/passes/Decompose.py:15`). ROADMAP Phase 3 Success Criterion 1 ("User can compute the Alpha158 factor set in batch mode ... and get back an `xarray.Dataset`") is therefore FALSE today. This plan makes it true.

1. `KunQuant/Op.py:292` — `class CompositiveOp(OpBase): @abstractmethod def decompose(self, options: dict) -> List[OpBase]`. Every KunQuant-shipped subclass in `KunQuant/ops/CompOp.py` matches this two-argument shape. The call site is `KunQuant/passes/Decompose.py:15` — `decomposed = op.decompose(options)`.

2. `my_ops/preprocess.py` currently declares `def decompose(self) -> list[OpBase]:` (line 11, `WindowedZScore`) and `def decompose(self) -> List[OpBase]:` (line 34, `WindowedRobustStandardization`). Neither body reads `options`; adding the parameter and ignoring it is sufficient and is a strict superset of current behaviour.

3. With the signature corrected, `Alpha158SpotKline(...).cal().get_features()` returns an `xr.Dataset` with `{'timestamp': 40, 'symbol': 8}` and variables `['KMID', 'STD5', 'VOLUME0']` — measured, not assumed. KunQuant native compilation cost is ~1.5 s per compiled graph; the whole `.cal()` after compilation is <10 ms.

4. Cost control for compiled-graph tests: pass an explicit `factor_names` list into `FactorConfig` so only those `Output(...)` nodes are reachable and the compiled graph stays tiny. Both concrete classes filter on it — `Alpha101SpotKline._get_factor_func()` does `if alpha.__name__ in factor_names`, `Alpha158SpotKline._get_func_stream()` does `if k in factor_names`. Passing `factor_names` explicitly also bypasses the `config`-setter's `_get_factor_names()` call entirely.

5. Verified-valid factor names: Alpha158 → `KMID`, `VOLUME0`, `STD5` (169 names total; `KMID` is names[0]). Alpha101 → `alpha001` (82 alphas total).

6. Verified-minimal `data_columns` per factor subset: `["open", "close", "volume"]` is sufficient for `["KMID", "VOLUME0", "STD5"]`; `["close"]` is sufficient for `["alpha001"]`. `data_columns` names are the POST-rename KunQuant names — `SpotKlineDataset._to_kunquant()` (`dataset/spot.py:117-139`) renames `Quote asset volume→amount`, `Open→open`, `High→high`, `Low→low`, `Close→close`, `Volume→volume` before building the input dict.

7. `SpotKlineDataset`'s on-disk Zarr columns are Binance Title-Case: `Open`, `High`, `Low`, `Close`, `Volume`, `Quote asset volume` (see the `_RAW_REQUIRED_COLUMNS` note in `dataset/spot.py`). `StockDataset`'s are lowercase raw `open/high/low/close/volume` PLUS `adjOpen/adjHigh/adjLow/adjClose/adjVolume` — `StockDataset._to_kunquant()` (`dataset/stock.py:48-70`) drops the raw five and renames the adj five onto them, so a `stock_zarr` fixture missing either group will raise.

8. `base/data.py:Dataset.config` setter calls `_reset_symbols()` (which calls `self.read()`) whenever `DatasetConfig.symbols is not None`. Fixtures must therefore write the Zarr store to disk BEFORE constructing any `DatasetConfig` that carries a non-None `symbols` value.

The four scaffolds created here inherit that rule — none of them may import `base.factor_polars`, `factor.momentum`, or `Alpha158Stock` at module level in this plan.
