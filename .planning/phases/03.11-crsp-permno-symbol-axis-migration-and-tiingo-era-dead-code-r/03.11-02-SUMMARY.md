## Decisions Made

1. **文本轴用 `str()` 而不是 `astype()`。** 计划给的配方是统一 `pd.Index(list(labels)).astype(stored_index.dtype)`。实测（pandas 3.0.5）`pd.Index([10107]).astype(object).tolist()` 返回 python int `10107`，**不是** `'10107'`——也就是说在 int→object 方向这条配方会回到它本来要消灭的静默 miss。所以按 dtype KIND 分流：文本轴（`O`/`U`/`S`/`T`）用 `str()`，其余走 `astype`。字符串 store 上的行为与修改前逐字相同。
2. **`symbol_encoding` fixture 保持两个 arm。** 它服务的 ~33 个测试全部用 ticker 标签，而 ticker 没有 int64 拼写；把 fixture 指向三元组不会增加覆盖，只会让 `symbol_coord` 在这些测试里抛 `ValueError`。第三个 arm 由 PERMNO 形态的 suite 用同名 `parametrize` 覆盖 fixture 显式接入（id 仍落在 `[int64]`）。为此新增 `SYMBOL_COORD_STRING_ENCODINGS`，并把「模型」与「可承载任意标签的子集」这条分界写成测试，免得后来者把窄的改宽。
3. **不可转标签的 `ValueError` 直接冒泡**（计划给的二选一）。`normalize_to_axis_dtype` 已经点名被拒的值与目标 dtype，再包一层只会把同样的信息挪远一帧。已在 `widen_symbol_axis` docstring 注明选了哪条。
4. **`stored_symbol_encoding` 按 `dtype.kind == "i"` 判定**，且该函数体内不出现具体 dtype 字面量——遵循它自己 docstring 的 never-by-a-width-literal 规则，int32 store 同样是整数编码。
