### 523 → 520 的解释（逐个可数，不是「大概」）

少的三列**全部**来自 2024 窗口内发生的**真实改名**。在 ticker 轴上一次窗口内改名把一个证券劈成两列（各带一个洞），PERMNO 轴上它就是一列：

| PERMNO | 改名 | 生效日 |
|---|---|---|
| 12449 | `FLT` → `CPAY` | 2024-03-25 |
| 17700 | `CDAY` → `DAY` | 2024-02-01 |
| 67598 | `PEAK` → `DOC` | 2024-03-04 |

523 − 3 = 520，**逐字对上**。做法是从新写出的 `.crsp_tickers.json` 里筛出「2024 窗口内有多于一条区间」的 PERMNO（109 个），再剔掉其中 ticker 未变的（区间因 `shareclass` / 类型列变化而切分，名字相同）——剩下的恰好就是上面这三个。反方向也核过：旧 store 的轴是 `StringDType`、长度 523。

### 为什么 NaN 数从 1520 掉到 764 而断言仍然成立

因为**断言挂在不变量上，不在计数上**。`adj_close_nan == adj_volume_nan == structural_gaps` 说的是「后修复面板里没有一个多余的 NaN」，与格子总数无关。格子少了（252 × 520 = 131,040，而不是 131,796），而且合并掉的那三对列互相补上了对方的洞，所以空格总数跟着变小是**预期**的。这正是计划把这四条写成不变量形式的原因：换轴之后它们仍然是正确的验收，而一条 `== 1520` 的断言在这里会红得毫无信息。
