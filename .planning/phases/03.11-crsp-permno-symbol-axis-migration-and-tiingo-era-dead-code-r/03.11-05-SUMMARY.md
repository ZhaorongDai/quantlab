## Decisions Made

1. **`_rename_permno_to_symbol` 是一个 helper 而不是两行重复。** 两个 CRSP 类同形，且这次改动的全部含义就是「这是一次 rename，不是 cast、不是再派生」——helper 的 docstring 是这句话唯一的落点。它一度叫 `_as_symbol_intervals`，因为撞上计划的字面验收条件 `grep -c "symbol_intervals" quantlab/dataset/constituent.py == 0` 而改名；改完发现新名字本来也更准确。
2. **`test_crsp_constituent.py` 的五个 symbol-interval 测试改写而不是删除。** 它们测的机器（ticker 区间解析）被本 plan 删掉了，但它们保护的**事实**没有消失，只是换了说法：FB/META 从「两行区间」变成「一行区间」，BRK.B 从「要渲染出 `.B` 后缀」变成「份额类别就是标识符本身」，GOOG 交接从「一条连续成员」变成「两个证券两条区间」。第四条尤其值得留：ticker 轴会把 13407 在 2000–2012 那段**丢掉并报告为 unlabelled**，PERMNO 轴把它全部保留——这是准入口径变宽的成分股侧孪生，与 03.11-03 的 `admitted_without_ticker` 对应。
3. **成员资格断言经 `_label()` 解析轴标签，对 dtype 不可知。** dtype 与顺序只在它们自己那两条测试里被声称。若成员资格断言直接写 `sel(symbol=13407)`，那两类断言就会互相背书：轴退回字符串时它们会一起红，而红的原因分不清是成员算错了还是轴退化了。
4. **`coords` 用 `np.asarray(symbols)`，不硬写 `dtype=np.int64`。** Wikipedia 的 control arm 走同一条 `_densify`，硬写 dtype 会让它当场崩掉。计划已经预见并点名了这一条。
5. **`masking.py` 的 `symbols` 用 `sort_symbol_axis` 而不是裸 `Index.sort_values()`。** int64 上两者同序，但字符串轴的既有字典序语义也要有个**说得出口的来源**；两种轴走同一个来源，这条契约就只表达一次。
6. **`tests/test_ingest_wrds_crsp.py` 新增的那条红不修。** 见 Deviation 2。
