## WR-04 路线裁定的证据（本 plan 独立复核）

`grep -rn "CrspTickerLookup" quantlab scripts` 实测：两个生产构造点（`quantlab/dataset/masking.py:115`、`quantlab/base/backtest.py:198`，都经 `beside_store`），**两处都不读 `product_end`**；`grep -rn "product_end" quantlab/ scripts/` 的 70 处命中里，其余全部属于 `CrspQueries.product_end` / `CrspReference.product_end` / 写侧的 `vintage_product_end` 键，与这个 `@property` 无关。唯一引用是 `tests/test_crsp_ticker_sidecar.py` 的那条测试。REVIEW 的「no production caller」成立。

即便如此仍选择 **(b) 抽共享 helper 而不删**，三条证据：

1. `vintage_product_end` 是写侧**刻意记录**的字段（`quantlab/dataset/crsp.py:1320-1336` 写明了理由：同一个 PERMNO 在更新的 CRSP vintage 下可能带更晚的 interval，所以「哪些名字」只有连同「按哪个 vintage 读的」才答得完整），并被写侧 schema 断言锁死为旁车三个必需键之一（`tests/test_crsp_ticker_sidecar.py:143-159`）。一个被写入、被 schema 锁住、被文档描述、却没有带类型读者的字段，是待接的需求，不是死重量。
2. 模块 docstring 把「派生值放在 `@property` 后面（`product_end`）」列为它刻意与 `CrspReference` 对齐的**四条**之一。删掉会破坏一条写下来的设计对称性 —— 那属于设计变更，不是 CLAUDE.md「不写兼容层」所许可的那种删除。
3. 缺陷本身是「唯一一处」为假；抽 helper 让它为真，并挡住**任何未来的第三个 payload 读者**再开同一个口子。删除只让今天的两个读者变成一个，挡不住第三个。
