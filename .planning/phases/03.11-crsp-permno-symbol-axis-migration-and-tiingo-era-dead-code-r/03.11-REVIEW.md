### Warnings

#### WR-01: `RecursionError` escapes `label()`'s "never raises" contract — and `as_of()`'s "every refusal is shaped" one

**File:** `quantlab/dataset/crsp_tickers.py:118-131` (the `payload` property's
`except (OSError, ValueError)`), reached through `:271` (`label`'s `unusable`
tuple) and `:217` (`as_of`).

**Issue:** The five-exception tuple in `label()` is not exhaustive. A sidecar
whose JSON is deeply nested makes `json.loads` raise **`RecursionError`**, which
inherits from `RuntimeError` — so it is caught by neither `payload`'s
`(OSError, ValueError)` nor `label`'s
`(FileNotFoundError, ValueError, KeyError, AttributeError, TypeError)`. It walks
straight out of the display path.

Reproduced against the shipped code (sidecar bytes `"[" * 20000 + "]" * 20000`):

```
deep_nest: label RAISED RecursionError: maximum recursion depth exceeded
           while decoding a JSON array from a unicode string
```

Every other hostile payload I probed is correctly contained — a directory in the
sidecar's place (`IsADirectoryError` ⊂ `OSError`), a permission error, a
truncated file, invalid UTF-8 (`UnicodeDecodeError` ⊂ `ValueError`), a >4300-digit
JSON integer (Python 3.11 int-digit limit, `ValueError`), literal `null`, a
top-level list, a string where a span list belongs, `None` span values. This is
the single remaining hole, and the module docstring at `:19-27` is now the thing
that makes it a defect: it asserts "All THREE ways the sidecar can fail RAISE,
and each refusal is **shaped**". An unshaped `RecursionError` out of `as_of()` is
exactly the bare-exception outcome plan 12 set out to eliminate. A contract that
advertises "never raises" and has one escape hatch left is worse than one that
never claimed it — the three bare `label()` call sites
(`quantlab/dataset/masking.py:262`, `quantlab/backtest/engine_vectorbt.py:303`,
`quantlab/base/model.py:1315` via `symbol_labeller`) are all unguarded on the
strength of that claim, and `engine_vectorbt.py:303` sits mid-simulation.

Likelihood is low — the file is machine-written, so pathological nesting implies
hand-editing or deliberate corruption rather than a truncated write — which is
why this is a Warning and not a Critical.

**Fix:** One word, and put it in `payload` rather than in `label`'s tuple, so
both entry points are covered and `as_of`'s refusal stays shaped:

```python
            try:
                self._payload = json.loads(
                    self.sidecar_path.read_text(encoding="utf-8")
                )
            except (OSError, ValueError, RecursionError) as exc:   # <-- add
                raise ValueError(
                    f"{type(self).__name__}: the ticker sidecar "
                    ...
                ) from exc
```

Verified on a patched copy: `label([13407], day)` → `['13407']`, and `as_of`
raises the shaped `ValueError` naming the class, the path and the rebuild.
(Building the message after a `RecursionError` is safe in CPython, which restores
stack headroom once the exception unwinds.) Worth a fourth
`MALFORMED_SIDECARS`-style regression, since this one is not structural damage
and would not be caught by the existing parametrisation.

#### WR-02: the three "backstop" exception types can now only swallow genuine bugs — the exact outcome the docstring says the explicit tuple exists to prevent

**File:** `quantlab/dataset/crsp_tickers.py:271` (definition), `:274` and `:293`
(both `except unusable:` sites); the claim it contradicts is at `:267-269`.

**Issue:** The docstring states the design rule explicitly:

> ``except Exception`` is deliberately NOT used: the tuple is spelled out so a
> genuine programming bug in this module still reaches the caller instead of
> being swallowed by a display path.

But the tuple is
`(FileNotFoundError, ValueError, KeyError, AttributeError, TypeError)`, and after
the *same commit's* structural guards landed, the last three are unreachable from
data damage:

- `_intervals()` now raises only `FileNotFoundError` / `ValueError` (its own
  `_malformed`, or `payload`'s two refusals).
- `as_of()` now raises only `ValueError` (`_malformed`) — every previously
  unguarded index (`span["start"]`, `span["end"]`, `span["ticker"]`,
  `list.get`) is preflighted at `:220-237`.
- `day` and `permnos` come from the caller, not the sidecar; `int(value)` has its
  own narrow guard at `:285`.

So `KeyError`, `AttributeError` and `TypeError` have exactly one remaining source:
a programming error inside this module. The tuple therefore swallows precisely the
class of failure its own rationale says it was narrowed to surface. Demonstrated
by injecting each typo into a subclass and calling `label()` over a **valid**
sidecar:

```
typo in as_of (span["tikcer"] -> KeyError)  swallowed -> ['13407']
typo in _intervals (self.paylaod -> AttributeError) swallowed -> ['13407']
```

Both return a plausible-looking fallback. A future refactor that breaks `as_of`
will not fail `tests/test_crsp_ticker_sidecar.py`'s happy-path tests through
`label()` — it will silently print digits, and the reviewer's own stated safety
net is what hides it.

**Fix:** Narrow the tuple to what the guards can actually produce, and lift it to
a module constant so the two `except` sites and any future display entry point
share one spelling:

```python
#: What an unusable sidecar raises. Both entry points now funnel every
#: structural defect through `_malformed` (ValueError) or `payload`
#: (FileNotFoundError/ValueError), so these two are exhaustive -- and a
#: KeyError/AttributeError/TypeError can now only be a bug in this module,
#: which must reach the caller.
_UNUSABLE = (FileNotFoundError, ValueError)
```

If the backstops are kept deliberately (defence-in-depth against a future
un-preflighted index), then the docstring at `:267-269` must be corrected to say
so, because as written it is false. Do not leave both.

#### WR-03: a corrupt sidecar now degrades with **zero** diagnostic, and the degraded output is indistinguishable from the supported no-sidecar state

**File:** `quantlab/dataset/crsp_tickers.py:272-275` and `:291-294`.

**Issue:** Both `except unusable:` arms discard the exception entirely — no
`logger`, no counter, no once-per-instance note. The operator's only signal that
an audit sidecar is broken is that tickers stopped appearing in the forced-
liquidation log / `liquidations.json` / `UniverseMask.report()` /
`predict_panel`'s WR-02 warnings. But "PERMNO digits instead of tickers" is also
the **normal, documented, fully supported** output for a Tiingo/Alpaca store or a
CRSP store built before 03.11-09 (`:254-258`). The two states are byte-identical
on the console, so the one that needs a rebuild is invisible.

That cuts against the codebase's own stated posture — `quantlab/base/config.py:142`
and `:176` both annotate the filter report with "**never applied silently**", and
the roster rescue at `crsp.py` emits a `logger.warning` for exactly this reason.
An *audit* sidecar that fails silently is the case where silence costs most.

The module's leaf constraint does not block the fix: `:39-42` forbids
*project-internal* module-scope imports, and `loguru` is third-party — it is
already imported by `masking.py`, `engine_vectorbt.py` and `base/model.py`, which
are this module's only consumers.

**Fix:** One warning per instance, so a batch of 500 liquidations does not spam:

```python
    def _degrade(self, exc: BaseException) -> None:
        """Note an unusable sidecar ONCE, then fall back to the digits.

        Never raises (that is the whole contract), but never silent either:
        digits-instead-of-tickers is also the normal output for a store with no
        sidecar at all, so without this line the two are indistinguishable and
        the broken one never gets rebuilt.
        """
        if not self._degraded:
            self._degraded = True
            logger.warning(
                f"{type(self).__name__}: falling back to PERMNO digits -- "
                f"{exc}"
            )
```

with `self._degraded = False` in `__init__` and `except unusable as exc:
self._degrade(exc)` at both sites. Lock it with an assertion on
`warning_messages` in the existing
`test_label_falls_back_when_the_sidecar_parses_but_is_shaped_wrong`
parametrisation.

#### WR-04: `product_end` bypasses the shape check `_intervals()`'s docstring claims to own, and still raises the bare `AttributeError` this plan set out to delete

**File:** `quantlab/dataset/crsp_tickers.py:192` (`product_end`), against the
claim at `:158-159` (`_intervals`).

**Issue:** `_intervals()` documents itself as "**The one place** the payload's
top-level shape is checked". It is not. `product_end` calls
`self.payload.get("vintage_product_end")` directly, so on a non-object payload it
produces exactly the failure mode `tests/test_crsp_ticker_sidecar.py:
test_as_of_refuses_a_structurally_broken_sidecar_with_a_shaped_error` was written
to abolish:

```
product_end on `[]` payload: AttributeError: 'list' object has no attribute 'get'
```

`[]` is one of the three payloads in this plan's own `MALFORMED_SIDECARS`, so the
plan reproduced the input and fixed two of the three public methods that consume
it. The module docstring at `:19-27` now asserts a shaped refusal for
structural damage without qualifying which entry points it covers.

Mitigating: `CrspTickerLookup.product_end` has **no production caller** — the only
reference in the repo is
`tests/test_crsp_ticker_sidecar.py:test_product_end_is_parsed_from_the_recorded_vintage`.
That is why this is a Warning and not higher; it is also an argument that the
method is currently dead weight on the public surface.

**Fix:** Route it through the same check (one line), which also gives it the
shaped message for free:

```python
    @property
    def product_end(self) -> date | None:
        payload = self.payload
        if not isinstance(payload, dict):
            raise self._malformed(
                f"its top level is a {type(payload).__name__}, not a JSON object"
            )
        recorded = payload.get("vintage_product_end")
```

(Or extract the top-level check out of `_intervals` into a `_object_payload()`
helper that both call, and make the docstring's "one place" claim true.)
Alternatively, if `product_end` is genuinely unused, delete it — the project's
"no backward compat" rule (CLAUDE.md) permits that outright.

**File:** `tests/test_crsp_identity.py:1098-1101`
(`test_the_equity_store_over_the_same_raw_tier_drops_qqq`).

smaller version of the exact "delete-and-leave" failure plan 13's own
