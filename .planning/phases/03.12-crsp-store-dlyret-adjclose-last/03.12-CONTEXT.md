### 增量保存的正确性是本 phase 的交付内容

操作者补充裁定（2026-09-22）：**不做读取时计算，做保存 zarr 时计算，并且增量保存也要正确。**

换锚到 `.first()` 后，chunked ingest 与 append 是同一个问题的两副面孔：
`adjClose_t = close_A · G_t / G_A`，而 `G = cum_prod(1 + dlyret)` 从累乘起点开始；
**第二个 chunk / append 的新段里没有锚行**，`G_A` 与累乘起点都不在手上。
这恰恰是既有 chunk 级锚点防护（`crsp.py:496 / :517 / :525-534`）存在的理由——
原研究把它们列进了删除清单（因为方案 C 让问题消失），**现在这个理由可能重新成立**。

因此：

- 本 phase 必须交付一个**可执行的边界续算机制**，不得推后
- 验收必须能证明：**先全量建 A+B，与先建 A 再 append B，得到逐位相同的 store**
  （这条是 D-03「逐位不变」作废后的替代验收不变量之一）
- 候选机制（按 PERMNO 分块 / 跨度无关的 per-PERMNO sidecar / 从 `adjClose·close` 反解）
  由增补研究给出推荐与失效边界

⚠️ 若选 sidecar 方案，必须论证它与本 phase 正在删除的 window-anchored sidecar
**在失效条件上的区别**：前者是 PERMNO 首行的函数，只向前 append 时永不移动；
后者是转换窗口的函数。若该区别在某些情况下不成立（raw tier 往前扩、
或某个 PERMNO 的首个可用行因数据修订而改变），需给出检测手段。

### 新增的开放问题（需补研究）

## 起因

03.11 的 UAT 过程中，操作者追问「现在是前复权还是后复权」，由此引出对复权锚点设计的重审。

现状（`quantlab/dataset/crsp.py:607-632`）：

```
adjClose_t = close_A × G_t / G_A        G = cum_prod(1 + dlyret).over("permno")
锚点 A = 每个 PERMNO 在【转换窗口内】最后一个可用行（`.last()`）
```

锚在最后一天 ⇒ **前复权**：最新日的 `adjClose` 等于真实 `close`，历史价格按 `G_t/G_A` 缩放。

**核心缺陷：锚点是转换窗口的函数。** 同一只股票，`2000-2024` 与 `2000-2025` 两个 store 的
历史 `adjClose` 数值不同。由此长出一整套机械：

| 代码 | 存在理由 |
|---|---|
| `crsp.py:380` anchor sidecar（`ADJUSTMENT_RECORD_*`） | 记录 store 按哪个窗口锚建的 |
| `_assert_anchor_unchanged`（`crsp.py:1463-1520`） | 拒绝跨锚点写入 |
| `_adjustment_record()` 的 `start_date`/`end_date` 字段（`crsp.py:1446-1461`） | 锚由窗口标识 |
| `crsp.py:13-25` 顶部长注释 | 解释锚为何必须窗口级、不能 chunk 级 |
| `crsp.py:496` / `:517` / `:525-534` | chunk 级锚点防护 |
| 「Convert into a NEW store」而非 append | 一列两锚点会在接缝造出虚假收益 |
| D-12 指纹失效 + `backtest.py:1145-1188` warning | 重建换锚，既有 backtest run 全部不可重放 |

**这整套税，只为「锚点会移动」而存在。**

## 决策

### D-01 采用方案 C（锚点下沉到读侧），不采用方案 B（换成后复权）

讨论中出现三个方案：

| 方案 | 做法 | 时序不变 | 截面可比 | 锚点机械 |
|---|---|---|---|---|
| A 现状（前复权） | store 存 adjClose，锚在最后一天 | ✗ | ✓ | 全套保留 |
| B 后复权 | 同上，锚改到第一天 | ✓ | ✗ | 全套保留，只是拒绝规则反向 |
| **C 锚点下沉读侧** | store 只存 raw + `dlyret`；adjClose 由读侧按锚点派生 | ✓ | ✓ | **整套删除** |

**选 C。** 理由：

1. **C ⊇ B。** C 传 `anchor="listing"` 精确等于 B 的输出；反之不成立（B 把锚烧进 store，
   换锚只能重建）。
2. **B 只是把税换个姿势背。** B 若锚在「窗口内首日」，改 `start_date` 照样移动锚点，
   一行机械都删不掉。
3. **C 使 store 无条件不变。** `close`/`open`/`high`/`low`/`volume`/`dlyret`/`dlycumfacshr`
   全是逐行 vendor 事实，与任何窗口无关 ⇒ append 合法、指纹稳定、dataset 层锚点机械消失。
   可变性被推到读侧，成为一个**显式函数参数**，而非「上次转换时 end_date 填了什么」的隐性后果。

**工程量对比：C = B + 一个契约层。** B 已经要做的脏活（原始层取数路径）C 全都要做；
C 多出的是「把 adjClose 从 store 列变成派生物」。

### D-02 采用解法 ii（每 PERMNO 前缀标量表）

「锚下沉到原始层」**不是一次单行查找**。陷阱：`crsp.py:590-594` 的 `_G` 是**从窗口第一行
开始累乘**的。锚一旦在窗口外，窗口内的 `_G` 与 `G_A` 不在同一基准，相除无意义。
**收益链本身必须从上市日开始累乘。**

三条解法：

| | 做法 | 成本 |
|---|---|---|
| i 拓宽派生窗口 | 原始层读取从 `config.start_date` 改成每个 PERMNO 的上市日，算完 `_G` 再切回窗口 | 改动最小，但 5 年窗口可能变成 60 年的读，隐性放大难估 |
| **ii 前缀标量表** | 每 PERMNO 存一个「上市日→窗口起点」的累计收益标量 `C`，则 `G_t^{global} = G_t^{window} × C` | 扫描只要 3 列，产物是每 PERMNO 一个标量 |
| iii vintage 级全量 G 表 | 一次算好 `(permno, date, G)` 落进 `_reference/` | 一次性成本后归零，但 CRSP 全历史日频 ~1 亿行 |

**选 ii。** 扫描窄（比 i 省一个数量级 I/O）；产物小；落盘位置现成
（`_reference/` + `CrspReference.manifest()` 的 vintage 戳，`crsp_reference.py:261-329`，
与 03.10-04 的参考表写入器同一套路，不发明新机制）。

### D-03 默认锚 = `"last"`，下游逐位不变

03.12 是一次**纯架构改动**：store 变不可变、锚点机械整套删除、append 合法、指纹稳定，
而**所有现有因子/模型/回测输出逐位相同**。

后复权从「必须现在决定的迁移」降级为「随时可传的一个参数」。

支持的锚：

| 锚 | 改 `start_date` | 改 `end_date` | 语义 |
|---|---|---|---|
| `"last"`（默认） | 变 | 变 | 当前前复权，零回归 |
| `"first"` | 变 | 不变 | 窗口内后复权 |
| `"listing"` | 不变 | 不变 | 真后复权（= 方案 B） |
| 固定日历日 | 不变 | 不变 | 以某日为基准的指数 |

### D-05 `_assert_anchor_usable` 保留，不在删除清单内

`crsp.py:665-740` 守的是 CR-01 / CR-02：

- CR-01：CRSP 的无价格哨兵是数字 `0.0`，能通过 `is_not_null()`，一旦成为锚会让
  `adjClose = 0.0 × G_t / G_A` 在该证券**整段历史**上恒为 0
- CR-02：只按 `close` 选锚再去读那行的 `dlycumfacshr`，会读到 NULL，
  整段退市历史的 `adjVolume` 变 NaN 而原始 `volume` 满格

这与窗口无关，锚改到 `.first()` 之后依然必要。锚点谓词必须继续是**三条同时满足且来自同一行**：

```python
close.is_not_null() & (close > 0.0) & dlycumfacshr.is_not_null()
```

且 `close` 必须复刻 `crsp.py:575-589` 的哨兵派生（`dlyprcflg ∈ _NO_PRICE_FLAGS` 或
`dlyprc == 0.0` → `None`，再取 `abs()`），**不能直接用 `dlyprc > 0`**。

### D-06 落盘形状

```
_reference/adjustment_anchor.parquet
  permno | anchor_date | close_A | cumfacshr_A | cum_to_<start>
```

前四列是 **vintage 的函数**（窗口无关，算一次永久有效）；
`cum_to_<start>` 是 `(vintage, start_date)` 的函数，按需补算并缓存。

这使 `_adjustment_record()`（`crsp.py:1446`）的 `start_date`/`end_date` 两字段可以删除
——**锚只由 vintage 标识**，这是删掉 `_assert_anchor_unchanged` 整套机械的前提。

### D-07 三种复权因子必须分开

CRSP 同时具备，不可合一：

| 因子 | 源 | 用途 |
|---|---|---|
| 总收益（含分红） | `cum_prod(1 + dlyret)` | 因子研究默认 |
| 仅拆股 | `dlycumfacpr` | 价格形态 / 技术指标 |
| 成交量 | `dlycumfacshr` | 与价格因子**不是同一个数** |

把后两者混读正是 CR-02 的成因。
