## Critical Issues

### CR-01: `.first()` 锚让 `adj*` 的水平失去截面可比性，而截面因子直接读它，零覆盖

**File:**
`quantlab/dataset/crsp/__init__.py:622-634`（选锚归约）、`:652-654` + `:1404`（`adjVolume = dlyvol × dlycumfacshr / _cumfacshr_anchor`）、`:645-649`（`adjClose = close_A × G_t / G_A`）
**消费方:** `quantlab/factor/alpha101.py:83-87`、`quantlab/factor/alpha158.py:108-112`

**Issue:**

CRSP 的 `dlycumfacshr` 是以**数据末端为 1.0** 归一的（fixture 实证：AAPL 拆股前 4.0 / 拆股后 1.0；
QQQ 1999 = 2.0 / 2025 = 1.0）。在旧的 `.last()` 锚下，仍在交易的标的 `cumfacshr_A = 1.0`、
`close_A` = 窗口末日的原始收盘，于是面板末端的 `adjClose` 就是**真实美元**、`adjVolume` 就是
**当期股数口径**，跨标的可比。换成 `.first()` 之后，每只标的被自己锚日的因子除，
比例因标的而异。

我在盘上这份 store（`data/data/us_equity/1d/wrds_crsp_sp500_1d.zarr`，252 × 520）上
按新锚**实算**了这个比例（每只标的取它最后一个可用日）：

| 量 | min | p50 | p95 | max | 恰好 == 1.0 的标的占比 |
|---|---|---|---|---|---|
| `adjClose / close` | 1.00 | **1.017** | 1.062 | **50** | **17.5%** |
| `adjVolume / volume` | **0.02** | 1.00 | 1.00 | 1.00 | 96.7% |

`.last()` 锚下这两列在每只标的的末日上都**恰好是 1.0**（I-1 的对偶）。现在 82.5% 的标的
带着一个非 1 的、**各不相同**的刻度。而且这个离散度**随窗口长度单调增长**：p50 的 1.017
基本就是一年的股息率（总收益链 vs 价格链），文档里规划的窗口是 **1999–2025**，
25 年下来仅股息一项就是 1.6× 上下，再叠上拆股（本窗口已经有 50×）。

为什么这是正确性问题而不是口味问题：KunQuant 的 `Rank` 在
`.venv/.../KunQuant/Op.py:562` 上逐字写着 *"the cross sectional rank among different
stocks"*，而 `predefined/Alpha101.py:145` 就是
`-1 * rank(covariance(rank(d.close), rank(d.volume), 5))`，`:153` 是
`correlation(rank(d.high), rank(d.volume), 3)`。也就是说 `Rank(adjVolume)` 现在排的是
**「成交量 ÷ 该标的自己的历史拆股因子」**，`Rank(adjClose)` 排的是
**「价格 × 该标的自己的累计总收益倍数」**。这不是「时序 vs 截面是设计选择」
（`project_factor_normalization_axis`）的那种选择 —— 那条说的是**归一化轴**的选择，
这里是**输入量本身**在标的之间被乘上了一组互不相同、与经济含义无关的常数。

**本 phase 的四条不变量一条都抓不到它：** I-1 是单行、I-2 是同一 store 的两次构建、
I-3/I-4 都写在 `for symbol in ...` 里逐标的比较（`tests/test_crsp_first_anchor.py:503`、`:553`）。
I-4 的措辞「只换刻度，不换经济含义」在**逐标的**意义上为真，在**截面**意义上为假。
D-04 护栏（`git diff -- quantlab/factor/` 为空）保证的恰恰是**没有人看过这一侧**。

**已验证不受影响的一侧（写在这里避免过度扩大）：** 回测是安全的。
`quantlab/backtest/engine_vectorbt.py:136-149` 用 `size_type="targetpercent"`、
没有 `size_granularity`、`fees`/`slippage` 都是比例，所以每标的一个常数缩放不改变
P&L —— 「回测用例全绿」不能拿来支持因子侧的安全。

**Fix:**

三条路，**需要人裁决**，不要由 fixer 自己挑：

1. （最小）加一条**截面**不变量并如实记录取舍，例如：

```python
# tests/test_crsp_first_anchor.py
def test_the_cross_sectional_level_scale_is_not_uniform_under_the_first_anchor():
    """I-6（characterization）：换锚之后 adjClose/close 在标的之间不再恒为 1。

    实测（252x520 shipped store）：p50 1.017、max 50、恰好 1.0 的只有 17.5%。
    截面 Rank(adjClose) / Rank(adjVolume) 因此读到的是被每标的常数缩放过的量。
    """
```
   并在 `_derivation()` 的 KNOWN LIMITATIONS 里补第三条：**截面水平不可比**，
   点名 `quantlab/factor/alpha101.py` 与 KunQuant `Rank` 是它的读者。

2. 让因子侧读**原始** `close`/`volume` 做截面比较（`quantlab/factor/universe_filter.py:161`
   已经为掩码走了这条路：「掩码读的**原始**列名（LS-1）。绝不是 `adjClose` / `adjVolume`」——
   同一条判例在 alpha101 上没有被应用）。

3. 恢复 `.last()` 锚，用别的机制解决 append 不可变性（本 phase 换锚的动机）。

无论选哪条，**在真实 store 重建之前**决定：重建之后因子库必须一并重算（文档 checklist
第 3 步），那一步就是这个语义变化落到实验结果上的时刻。

### WR-02: `test_the_anchor_is_the_FIRST_usable_row` 在 `.last()` 锚下同样全绿

**File:** `tests/test_crsp_dataset.py:1095-1150`

**Issue:** fixture 是三行：`2020-03-01` 无价、`03-02` close 100.0 / ret 0.01、`03-03` close 102.0 / ret 0.02。
在**旧** `.last()` 锚下：anchor = `03-03`，`close_A = 102`，`G = [1.0, 1.01, 1.0302]`，`G_A = 1.0302`，于是

- `adjClose(03-02) = 102 × 1.01 / 1.0302 = 100.0` ✅（用例断言 100.0）
- `adjClose(03-03) = 102.0` ✅（用例断言 102.0）
- `adjClose(03-01) = NaN` ✅（用例断言 NaN）

三条断言**逐位相同**，所以这条被改名成 `..._FIRST_usable_row`、docstring 宣称

which is where the anchor rule now has to do its work」的用例，**把 `.first()` 改回
`.last()` 它不会红**。这恰恰是 plan 01 的执行者在 `tests/test_crsp_first_anchor.py` 里
诊断出来并用一次 4:1 拆股修掉的缺陷（见 01-SUMMARY Deviation 1），但没有回头修这一条 ——
于是用例名本身又成了一句关于覆盖面的假陈述，正是它的 docstring 反对的那种东西。

**Fix:** 复用同一个修法 —— 在 `03-03` 落一次拆股（`dlyprc="25.5"`、`dlyfacprc="4.0"`、

### WR-03: I-2 的「增量性」自检无法区分 append 与整库重写

**File:** `tests/test_crsp_first_anchor.py:683-690`

**Issue:** 唯一的增量性证据是

```python
ledger = json.loads(Path(str(extended_config.zarr_file_path) + ".chunks.json").read_text(...))
assert len(ledger["windows"]) >= 2, ledger
```

`granularity="year"`、窗口 `[2019-11-01, 2020-09-30]` 本来就跨两个年份，所以**一次整库重写**
也会留下 2 个窗口，这条断言照样绿。更要命的是：既然锚只是 `start_date` 的函数，
一次整库重写产出的面板与全量构建**完全相同**，`xr.testing.assert_identical` 也绿。
也就是说这条用例证明了「两次运行得到同一个答案」，但**没有**证明它想证明的那件事
——「run 1 写到盘上的值在 run 2 之后仍然是原来那些字节」（docstring `:598-601` 的原话）。
它替代的是一条真正的跨运行闸门，这个替代是有落差的。

**Fix:** 在 run 2 之前把 run 1 的面板读出来存住，run 2 之后对**重叠区**再做一次
`assert_identical`；或者断言 run 2 之后 `ledger["windows"][0]` 与 run 1 结束时读到的
第一条窗口记录逐字相同（并断言 run 2 的 `ConversionResult.windows_written == 1`）。

### WR-04: 从未执行的真实数据门用**面板**重建锚行，而生产在**过滤之前**选锚

**File:** `tests/test_crsp_rebuild_measurements.py:test_the_real_store_reproduces_its_adjusted_columns`（新增，从未运行）
**对照:** `quantlab/dataset/crsp/__init__.py:622-636`（选锚）vs `:665`（`derived = self._apply_security_filter(derived)`）

**Issue:** 生产的顺序是「选锚 → `_assert_anchor_usable` → 算 `adj*` → **再**跑证券过滤」。
`_apply_security_filter` 的裁决是**逐行**的，它自己的 docstring（`:948-950`）写着
*"The verdict is PER ROW ... so a security that stopped being common stock keeps exactly
the era in which it was (D-17)"*。因此一只早期不是普通股、后来变成普通股的 PERMNO，
它的**生产锚行不在面板里**。

新门是从**面板**（过滤后 + 稠密化后）重算 `usable` 谓词并取 `indices[0]`，然后断言
那一行 `adjClose == close`。两者不是同一行时，这条门会**因为一个与锚无关的原因变红**；
反过来，在过滤没删早期行的数据上它绿，也没有验证到生产的谓词。
这是本 phase 唯一一条会碰真实 store 的门，而它**一次都没有被执行过**（操作者选 B，
重建推迟），所以这个不匹配目前是未被观测的。

**Fix:** 要么在断言里排除「面板首个可用行 ≠ 生产锚行」的情形并把这类 PERMNO 单独点名
（像 `anchorless` 那样打印出来），要么直接从 `CrspStockDataset._derivation()` 取
`_close_anchor` 与 `_cumfacshr_anchor` 做对照（不再用面板反推）。至少在 docstring 里
写明这个前提：**本门假定证券过滤没有删掉任何 PERMNO 的锚行**。

### WR-05: 删掉唯一有牙的断言之后，`try/except ValueError` 成了条件空转

**File:** `tests/test_crsp_dataset.py:1555-1559`

### WR-07: 退化守卫只看 `_G_anchor`，不看 `_cumfacshr_anchor` —— WINDOWS #30 同类的第二个实例

### IN-05: I-3 / I-4 在旧锚下恒绿，它们不是锚方向的回归门

**File:** `tests/test_crsp_first_anchor.py:476-576`

对照序列 `_adjclose_anchored_last()` 是 `.last()` 锚的 numpy 复刻。如果生产改回 `.last()`，
`current` 与 `control` 逐位相同 ⇒ I-3 的 `ratio ≡ 1.0`（`max == min` 成立）、
I-4 的 `current_steps == control_steps`（逐位相等）——**两条都绿**。这是它们的设计
（它们证明的是「换锚不改经济含义」），但模块 docstring 把四条不变量并列成「carry that
claim」，容易让下一个读者以为方向被四条一起守着。实际上把 `.first()` 改回 `.last()`
只有 I-1 和 6 条硬编码水平期望会红。
**Fix:** 在模块 docstring 里加一句：I-3/I-4 是**对称**不变量，锚方向的回归门是 I-1
与 `tests/test_crsp_dataset.py` / `test_crsp_tracer.py` / `test_crsp_identity.py` 里的水平期望。

另：`_adjclose_anchored_last()` 用的是**面板**的 `close`/`ret`（过滤之后），而生产的 `_G`
是在过滤之前算的。当前 fixture 不删行所以等价；与 WR-04 是同一个前提，值得在
docstring 里写出来。
