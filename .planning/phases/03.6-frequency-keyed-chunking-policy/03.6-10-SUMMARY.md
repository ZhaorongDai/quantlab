The plan asks this explicitly. Arm 1's `pytest.raises(ValueError)` aborts at the `OSError` before reaching its sidecar assertion, so it was measured directly on the unfixed tree:

The orphan was not a stub — it was a **complete widened store** (`close`, `symbol`, `timestamp`, `zarr.json`), left on disk with nothing to reclaim it, while the real store stayed stuck on its original two-symbol axis. `widen_symbol_axis`'s own `except BaseException: shutil.rmtree(widening)` does not cover this, because the failing `os.replace` sits outside that `try`.

## The deviation from the review's snippet, and why

`03.6-REVIEW.md`'s WR-03 proposes refusing on `superseded.exists() and target.exists()` **unconditionally**. Taken literally that regresses behaviour in the name of fixing it: an EMPTY `.superseded.tmp` holds nothing, `os.replace` onto an empty directory **succeeds** on POSIX, and a widen against that state completes today. An unconditional refusal would turn a working widen into an error.

The shipped guard therefore splits on `any(superseded.iterdir())`:

- **non-empty → refuse**, with a message naming the residue path, both producers (a widen crashed between its two renames; a SIGKILLed `on_new_listing="rebuild"` whose aside uses the same string and is never reclaimed because the rollback runs only on an exception or a cancel), the fact that the closing rename would otherwise fail only after the whole rewrite was paid for, and the manual remedy;
- **empty → self-heal** with `shutil.rmtree(..., ignore_errors=True)`, mirroring the module's own `.widening.tmp` handling one line below.

That reasoning is written into the docstring's new guard entry so the deviation is visible rather than looking like a misreading. Arm 2 (`..._self_healed_like_the_widening_one`) is green **before and after** and exists solely to catch this regression direction.

## Decisions Made

- **Emptiness split over the review's unconditional refusal** (see above). Recorded in the docstring.
- **Single definition over renaming.** `03.6-REVIEW.md` offers both branches. Renaming was declined: it changes an on-disk artefact name for no safety the new guard does not provide, it would require editing `tests/test_chunked_ingest.py` (plan `03.6-08`'s file this round, whose `:2174-2175` assert the literal `.superseded.tmp`), and — the decisive one — it would make an existing `.superseded.tmp` residue on a real operator's disk **invisible to the very code meant to notice it**. The reasoning is written into the annotation.
- **Arm 3 asserts structure, not identity.** `is` between the two class attributes is deliberately not asserted: CPython's interning of a non-identifier string literal is an implementation detail and would be a flake waiting to happen. Equality is a separate, weaker check.
- **The new module does not request the `symbol_encoding` fixture.** That fixture is parametrized, and requesting it would collect 6 tests where the plan's gates demand exactly 3. The arms are about directory-level crash states, not coordinate encodings, so realism is not lost.
