## Table values and landing `day`

### What value does `1d` take?

| Option | Description | Selected |
|--------|-------------|----------|
| `year` | Today's behaviour; 356 MiB/window; coarser than `RAW_HIVE_KEYS["1d"]`'s month shard | ✓ |
| `month` | Aligns one window to one raw shard (30 MiB), but changes today's behaviour and ~12x the appends | |

**Notes:** Sizes computed from `MAX_DENSE_PANEL_BYTES`'s own measurement basis (15,424 symbols x

### `day`'s ledger write amplification

| Option | Description | Selected |
|--------|-------------|----------|
| Accept as a known cost | Minute full-history backfill is v2 (DATA-V2-02); ledger churn is noise beside the Zarr writes | ✓ |
| Record as a deferred todo | Accept now, open a todo for an append-style ledger | |
| Fix the ledger this phase | Scope creep — atomic whole-file rewrite is `ChunkLedger`'s safety guarantee | |

**Notes:** `ChunkLedger.record()` → `_flush()` rewrites the entire JSON per window
(`chunking.py:257-276, 386`). A ten-year `1m` conversion at `day` is ~2,500 windows → O(n²) bytes
written plus ~2,500 Zarr appends instead of ~10.
