### WR-01: `widen_and_append` 不转发 `append_dim_size`，新恢复的 grid 不变量在 `widen`/`update()` 路径上仍然为假

**File:** `quantlab/dataset/backend.py:837-942`（`widen_and_append`）、`:618-619`（`_widen_whole_store`）、`:189-196`（`append` docstring 的断言）、`quantlab/base/data.py:1286-1291`（`_reconcile_new_listings` 的 widen 分支）

**Issue:** `03.6-05` 把 `append_dim_size` 从 `from_raw_data_chunked` 一路穿到 `_append_encoding`，让**创建写**的格网成为 store 总 extent 的属性。但 store 创建之后格网并非「不可再改」——`widen_symbol_axis` 走的是 `mode="w"` 整店重写，`_widen_whole_store` 用的是 `self._append_encoding(append_dim, data=widened)`，`widened` 的 append 维长度是**重写当时**的 extent，不是最终 extent。而 `widen_and_append` 虽然通过 `**kwargs` 收下了 `append_dim_size`，只把它转发给收尾的 `append()`，两个 widen 调用一个都没拿到。

实测复现（`APPEND_DIM_CHUNK=4`，store 最终 9 行）：

```
after creating write : {'close': (4, 2)}        # min(4, 9) = 4，正确
after widen_and_append: {'close': (3, 3)}        # 被重钉成 min(4, 当时的 3 行)
expected per the stated invariant: (4, 3)
```

可达性不是理论上的：`_reconcile_new_listings` 的 `widen` 分支（`base/data.py:1286`）在循环**之前**直接调 `widen_symbol_axis`，同样不带总 extent；而 `update()` 的三选一里，「新增 symbol 在 store 自己的 extent 内没有 raw 行」这个**最常见**的情形正是解析成 `widen`。于是一个 extent 尚不足 `APPEND_DIM_CHUNK` 的 store（日频约两年以内）在一次 `update()` 里被 widen 并继续 append，最终格网就比不变量声称的更小，且 Zarr 不可回改。

连带两处文本被证伪：

- `backend.py:189-192`：「Against an EXISTING store the value is accepted and ignored: **the grid was pinned irreversibly by the creating write** and there is nothing left to decide」——同一个类的 `widen_symbol_axis` 就能改它。
- `backend.py:51-58`：「so **both paths** land on `min(APPEND_DIM_CHUNK, total_len)`」——第三条路径（widen 重写）不在其中，而这段话正是本次 gap-closure 写下的。

新增的四条 grid 测试参数化了 `year/month/day`、crash+resume、rebuild，**没有一条覆盖 `on_new_listing="widen"`**，所以这个缺口对绿灯是不可见的。

**Fix:** 让重写路径也能被告知总 extent，并补上缺的那条测试臂：

```python
# quantlab/dataset/backend.py
def widen_symbol_axis(self, path, symbols, dim="symbol", append_dim="timestamp",
                      fill_values=None, *, append_dim_size: Optional[int] = None) -> Self:
    ...
        strategy(stored, widening, requested, dim=dim, append_dim=append_dim,
                 fills=fills, block_rows=block_rows,
                 append_dim_size=append_dim_size)

def _widen_whole_store(self, stored, widening, requested, *, dim, append_dim,
                       fills, block_rows, append_dim_size=None) -> None:
    widened = stored.reindex({dim: requested}, fill_value=fills).load()
    encoding = self._append_encoding(append_dim, data=widened,
                                     append_dim_size=append_dim_size)
    widened.to_zarr(str(widening), mode="w", encoding=encoding)
```

`widen_and_append` 把 `kwargs.get("append_dim_size")` 透给两个 widen；`_reconcile_new_listings` 的 widen 分支传 `append_dim_size=len(timestamps)`（该值在调用点已在手上）。`_widen_chunked` 同理（首块写入处）。测试侧加第五条臂：

### WR-06: `_widen_block_rows` 用类名硬取常量，而它的协作者用 `self.` —— grid 恒等式与字节上界在子类下会静默解耦

**File:** `quantlab/dataset/backend.py:474-526`（尤其 `:524-525`）

**Issue:** 该方法是 `@staticmethod`，内部写死：

```python
chunk = XrBackend.APPEND_DIM_CHUNK
raw = XrBackend.MAX_WIDEN_BYTES // row_bytes if row_bytes > 0 else 0
```

而同一条路径上的协作者全部走实例查找：`widen_symbol_axis:376` 用 `estimate["widened_bytes"] > self.MAX_WIDEN_BYTES` 决定是否分块，`_report_widen_strategy` 用 `self.MAX_WIDEN_BYTES` 打日志，`_append_encoding:999` 用 `self.APPEND_DIM_CHUNK` 定格网。

于是一个覆写了这两个常量的子类（或实例级 patch）会得到两种互不相容的行为：

- 覆写 `MAX_WIDEN_BYTES`（比如调低到 1 GiB 以适配更小的机器）：**路由**按 1 GiB 判定要走分块，**块大小**却仍按基类的 4 GiB 算 —— 分块重写每块最多仍吃 4 GiB，子类要的内存上界一条都没兑现。
- 覆写 `APPEND_DIM_CHUNK`：块大小的下界用基类值、`_append_encoding` 用子类值，`min(CHUNK, 首块长) ≡ min(CHUNK, total)` 这个 docstring 里以「identically」措辞给出的恒等式随之破掉——而这正是本阶段刚刚恢复的那条不变量在 widen 侧的全部保障。

`_widen_block_rows` 的 docstring 花了两大段论证「两条路径靠不同路线落在同一格网上是有意的形状」（本次复审确认该论证在**常量一致**的前提下成立），但代码本身没有把那个前提固定住。现有测试用 `monkeypatch.setattr(XrBackend, ...)` 改的是类属性，两边恰好同时生效，所以这个解耦对绿灯不可见。

**Fix:** 改成 `@classmethod`（或普通方法），让两个常量走同一条查找链：

```python
    @classmethod
    def _widen_block_rows(cls, row_bytes: int) -> int:
        chunk = cls.APPEND_DIM_CHUNK
        raw = cls.MAX_WIDEN_BYTES // row_bytes if row_bytes > 0 else 0
        return max(chunk, (raw // chunk) * chunk)
```

调用点 `self._widen_block_rows(...)` 不变。并在 docstring 里把「两条路线落在同一格网」这句话的前提写出来：它成立**当且仅当**本方法与 `_append_encoding` 读到同一个 `APPEND_DIM_CHUNK`。
