### CR-01: 窄区间 update/widen 会不可逆地把已完成 store 的 chunk grid 改小

**Files modified:** `quantlab/dataset/backend.py`, `tests/test_chunked_ingest.py`
**Commit:** `8c7ff94`
**Status:** fixed

**Applied fix** — the approved single-point shape, verbatim:

```python
# quantlab/dataset/backend.py  _append_encoding
if dim == append_dim and append_dim_size is not None:
    # The stated extent is a LOWER bound, never a ceiling on
    # what the panel in hand already proves the store holds.
    # It exists to RAISE the grid when the caller holds only a
    # window of a larger store; a caller whose window is
    # narrower than the store must not be able to re-pin the
    # grid downward, because `mode="w"` makes that
    # irreversible.
    size = max(int(panel.sizes[dim]), int(append_dim_size))
else:
    size = int(panel.sizes[dim])
```

The `max(min(self.APPEND_DIM_CHUNK, size), 1)` line below is UNCHANGED, so
`APPEND_DIM_CHUNK` remains the ceiling and a range longer than it is unaffected. On the
chunked branch `_widen_block_rows`'s `max(APPEND_DIM_CHUNK, ...)` floor already protects the
first block, so the new `max()` cannot pull the grid the other way — confirmed by
`test_the_chunk_grid_survives_a_block_by_block_widen` staying green.

**Docstring** — `_append_encoding`'s opening claim ("`append_dim_size` is the store's TOTAL
extent along `append_dim`") was the exact statement CR-01 falsified at the only production call
site. It is restated as a lower bound, with the effective extent named explicitly
(`max(panel.sizes[append_dim], append_dim_size)`). The superseded wording is **preserved in
place** per this phase's D-18 convention, in the same shape commit `ed9d77a` used for its three
corrections: a bolded lede naming what was wrong, `SUPERSEDED by ...`, the original quoted
verbatim, then why the falsity was load-bearing (the `from_raw_data_chunked` →
`_raw_axes_in_range()` → `config.start_date`/`config.end_date` chain, the measured
`(4, 2)` → `(2, 3)`, and Zarr's write-time grid fixing making it irreversible). Nothing was
deleted. One incidental wording edit was made and then reverted so the diff touches only text
that was actually wrong.

**Regression test** — `tests/test_chunked_ingest.py::test_a_narrow_stated_extent_cannot_shrink_an_existing_stores_grid`,
placed beside the five sibling grid arms. It builds a COMPLETE 12-row store at
`APPEND_DIM_CHUNK = 4`, asserts the store starts on `min(APPEND_DIM_CHUNK, 12) == 4` (so a
broken setup cannot pass vacuously), then widens with `append_dim_size=2` and asserts the grid
is still `(4, 3)`. Its docstring records the RED conditions and states why the direction was
uncovered: all five existing arms state an extent at or ABOVE the store's own length
(`_incomplete_store` states 9 while holding 3), so they pin only the "raise the grid" half.
