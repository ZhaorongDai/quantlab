rolled-back rebuild. On an already-complete store the two rules coincide and nothing
degrades, which is precisely why the existing widen tests are all green.

Purpose: the trade this phase made -- the library offers the ladder, the caller owns the cost

raw-tier IO as the accepted costs of a finer rung. An irreversible on-disk grid is not on
that list, and after this plan it does not happen on any path.

Output: `append_dim_size` threaded into the four rewrite sites that still lack it, the FIFTH
parameterised `widen` test arm plus three companion arms, and the three false unconditional

Reasoned against the live tree at plan time, not restated from plan 05. Each conclusion is
what the tasks implement.

**(1) `_reconcile_new_listings` does NOT have `timestamps` in scope.** The gap report says
the value "is already in hand at that call site", which is true of the CALLER and false of
the METHOD. Verified at plan time: the signature is

`from_raw_data_chunked`, bound at `symbols, timestamps = self._raw_axes_in_range()` and
passed nowhere. **Resolution: `_reconcile_new_listings` gains its own keyword-only
`append_dim_size`, and `from_raw_data_chunked` passes `len(timestamps)` at the call site
(`:662-664`).** A fix that only edited the widen branch would not compile.

**(2) The two widen strategies must keep ONE signature.** `_widen_whole_store`'s docstring
states the contract explicitly -- "The two strategies carry ONE signature so the router
selects between them by name and calls them identically; a router that had to remember which
arguments each strategy wanted is a router with two call sites to drift apart" -- and the
router calls `strategy(stored, widening, requested, dim=..., append_dim=..., fills=...,
block_rows=...)` with a fixed keyword set. **Resolution: BOTH strategies gain the parameter,
in the same position, with the same default, even though only `_widen_whole_store` is on the
measured path.** A verify command below compares the two parameter lists element for element.

**(3) `_widen_chunked` is NOT already correct, and its docstring's argument is why the gap
survived.** The floor makes `min(APPEND_DIM_CHUNK, first_block_len)` equal
`min(APPEND_DIM_CHUNK, total_len)` only when `total_len` is the store's FINAL extent. On an
incomplete store (`total = 3`, `chunk = 4`, `block_rows = 4`) the single block is 3 rows and
the first block writes `min(4, 3) = 3`, where the stated extent wants `min(4, 9) = 4`.
**Resolution: `_widen_chunked` forwards the keyword into its first block's
`_append_encoding` AND keeps its floor.** The floor and the keyword are complementary, not
alternatives -- the floor bounds BYTES (`MAX_WIDEN_BYTES`), which no append-dim length can
express. Task 3 rewrites the docstring paragraph that currently presents them as
alternatives.

**(4) `widen_and_append`'s signature must NOT grow the parameter.** It already receives
`append_dim_size` inside `**kwargs` (passed by `from_raw_data_chunked`) and forwards
`**kwargs` verbatim to all three of its `self.append(...)` exits. **Resolution: read it with
`kwargs.get("append_dim_size")` -- GET, never POP -- and pass it EXPLICITLY to
`widen_symbol_axis` and `widen_data_vars`.** A `pop` would starve the closing `append()` and
silently reintroduce the ORIGINAL first-window defect on the creating write, which is a
strictly worse outcome than the gap being fixed. Plan `03.6-05` deliberately left this
signature alone and its own verify asserted the absence; keeping it absent also keeps the
`Factor.update()` call path byte-identical.

**(5) The keyword must be inert at its default, on all four new sites.** `_append_encoding`
already substitutes only `if dim == append_dim and append_dim_size is not None`, so a `None`
travelling through the new parameters produces byte-identical output. Every existing caller
of `widen_symbol_axis` and `widen_data_vars` -- including `Factor.update()`'s only route --
passes nothing. **Resolution: default `None` everywhere; the three sibling suites plus
`test_widening_fixture_realism.py` running UNEDITED is the evidence.**

**(6) The crash in the new test fixture is load-bearing, not decoration.** The verifier's own
fairness note: widening an already-COMPLETE store re-pins to the same value and degrades
nothing, which is why `test_widen_keeps_history_and_backfills_the_new_listing_with_nan` is
green today and would stay green through the defect. **Resolution: the widen arm MUST widen
an incomplete store.** `_FailsOnSecondWindow` is what makes the extent-at-rewrite rule and
the stated-extent rule give different answers; removing it removes the whole discrimination.

**(7) `_chunk_grid` is the ONE read idiom in the module and stays that way.** Plan
`03.6-05` deliberately factored `zarr.open_group(path, mode="r")[name].chunks` into a single
module-level helper (`tests/test_chunked_ingest.py:162`) precisely so five call sites could
not drift on how the grid is read. **Resolution: every new arm calls `_chunk_grid(...)`. No
new test opens a zarr group or reads `.chunks` directly.**
