<objective>
Close WR-03, the second of the two robustness defects the developer pulled into scope this round
(`03.6-REVIEW.md` `### WR-03`; listed as `advisory` with
`evidence_status: not independently reproduced` in `03.6-VERIFICATION.md`).

The defect: `XrBackend.widen_symbol_axis`'s crash guard handles only
`superseded.exists() AND NOT target.exists()`. The fourth state -- BOTH present -- has no guard at
all, and the closing swap is `os.replace(target, superseded)`, which on POSIX raises `ENOTEMPTY`
when `superseded` is a non-empty directory. So the method estimates the widen, routes the strategy,
materialises and writes the ENTIRE `.widening.tmp` sidecar, and only then fails -- the whole rewrite
paid for and thrown away, with an error that mentions neither the residue nor what to do about it,
and an orphaned sidecar left on disk.

The residue is reachable by two routes, and the second is the interesting one:
`BaseDataset.SUPERSEDED_SUFFIX` and `XrBackend.SUPERSEDED_SUFFIX` are the SAME string appended to
the SAME store path. A SIGKILLed `on_new_listing="rebuild"` leaves `<store>.superseded.tmp` behind
(`_restore_rebuild_asides` only runs on an exception or a cancel, and SIGKILL reaches neither), and
from then on EVERY widen against that store pays the full rewrite before failing.

Because the review did not reproduce this independently, Task 1 is a failing-first reproduction
that constructs the residue state and goes red before any production line moves. If the residue
proves unconstructible, Task 1 says so in writing and the plan halts rather than shipping a fix for
a condition nobody can produce.

Wave 2, blocked on BOTH wave-1 plans, and for file reasons that are worth stating the way the
ROADMAP's own 03.6 wave notes do: this plan edits `quantlab/dataset/backend.py`, which plan
`03.6-08` rewrites text in (its `widen_and_append` and `_widen_block_rows` / `_widen_chunked`
docstrings), and `quantlab/base/data.py`, which plan `03.6-09` changes
`_restore_rebuild_asides` in. Neither collision is semantic -- this plan's edits sit in
`widen_symbol_axis` and on the `SUPERSEDED_SUFFIX` constant -- but both are the same file, and two
plans editing one file in one wave is the hazard the wave assignment exists to prevent.

Purpose: `widen_symbol_axis`'s docstring promises "Guards fire before any write". WR-03 is the one
state where that promise is not kept, and the state it misses is exactly the one where the residue
directory may hold the only complete copy of a store.

Output: a reproduction that is red today, a residue guard that refuses before any write while
self-healing the harmless empty case, one definition of the shared suffix, and a D-18 annotation on
the constant that made the collision possible.
</objective>
