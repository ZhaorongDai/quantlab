### `quantlab/base/chunking.py` — the constant table (D-01, D-02, D-09)

**Analog A (shape + `#:` rationale + deliberate tick omission):** `quantlab/acquisition/universe.py:2077`

```python
    #: Rows a single symbol-day yields at each `enums.data.Frequency` token.
    #:
    #: `1d` is one bar per trading day by definition. `1m` is **390** -- the
    #: regular 09:30-16:00 ET session, 6.5 hours x 60 minutes. This is an
    #: ASSUMPTION, not a measurement: ...
    #:
    #: `tick` is deliberately ABSENT: see `estimate_acquisition_volume`'s
    #: `rows_per_symbol_day`. A number here would be a guess, and a guess here
    #: is what makes a guard confidently wrong in the one regime it exists for.
    BARS_PER_DAY_BY_FREQUENCY: dict[str, int] = {"1d": 1, "1m": 390}
```

Copy: the `#:` block ending in an explicit paragraph saying WHY `tick` is absent, the
`dict[str, int]`-style bare-`str` annotation, the one-line literal. Note this one is a CLASS
attribute; D-01 deliberately makes the new table MODULE-level.

**Analog B (module-level, bare-`str`-keyed, prose block above):** `quantlab/enums/data.py:135`

```python
RAW_HIVE_KEYS: dict[str, tuple[str, ...]] = {
    "1d": ("month",),
    "1m": ("date",),
    "tick": ("data_type", "date", "symbol"),
}
```

The `#`-comment (not `#:`) prose block above it is the module-level precedent for a long
rationale; `BARS_PER_DAY_BY_FREQUENCY` is the `#:` precedent. Planner picks one and says which.

**Analog C (the raise message style D-02 copies)** — `quantlab/base/chunking.py:57-62`:

```python
    def __init__(self, granularity: str = "year") -> None:
        if granularity not in self.GRANULARITIES:
            raise ValueError(
                f"TimeChunkPlanner: unknown granularity {granularity!r}; "
                f"accepted values are {list(self.GRANULARITIES)}."
            )
        self.granularity = granularity
```

Import-time form: a module-level `for`/`if` raising `ValueError` with this exact message
shape (`<name>: <what is wrong> {value!r}; accepted values are {list(...)}.`). **No in-repo
precedent exists for a module-level validation block** — CONTEXT D-02 confirms `quantlab/utils/file.py:30,35`
are the only `assert`s and both are in-function. This is a NEW idiom; give it a `#:`/`#`
rationale saying why it is not a bare `assert` (`python -O` strips asserts).

**LEAF constraint to preserve** — the module docstring (`chunking.py:13-21`) declares stdlib +
pandas/xarray + `quantlab.utils.atomic` and nothing else. The table must add no import.

## Shared Patterns

### Derived, never restated
**Source:** `quantlab/utils/cli.py:255-270` (`choices=list(TimeChunkPlanner.GRANULARITIES)`,
`choices=list(BaseDataset.NEW_LISTING_STRATEGIES)`)
**Apply to:** the new table, `_period_key`, and any test enumerating granularities. A value
added to `GRANULARITIES` must not need a second edit anywhere. D-10's trailing `raise` is the
enforcement arm of this same rule.

### An estimator answers; the asserting sibling raised
**Source:** `quantlab/acquisition/universe.py:1851` `estimate_chunked_panel` vs `:1986`
`assert_chunked_panel_fits`
**Apply to:** `universe.py` and all three shells. This phase keeps the first half and deletes
the second. Every deleted `assert_*_fits(...)` call becomes the `estimate_*(...)` it already
wrapped, with the verdict (`chunk["fits"]`) rendered instead of raised.

### Injected `print_fn`, input dict returned
**Source:** `quantlab/utils/cli.py:801` `print_chunk_report`, `:876` `print_volume_estimate`,
and `print_conversion_result`
**Apply to:** every rendering change under D-13. `print_fn` stays the LAST keyword parameter;
the input dict is returned so the call site composes; values are read off the report, never
recomputed inside the renderer.

### Message shape for a refusal
**Source:** `quantlab/base/chunking.py:57-62` (terse, `{value!r}` + legal set) and
`quantlab/acquisition/registry.py:553-566` (long-form: what, why, which phase fixes it)
**Apply to:** D-02's import-time `ValueError` (terse form) and D-03's absent-frequency
refusal (long form).

### Base-declares / `MarketDataset`-narrows
**Source:** `quantlab/base/data.py:437` + `:1374-1383` (docstring) + `:1387`
(`config: DatasetConfig`) + `:1424` (`@abstractmethod` re-declaration)
**Apply to:** D-05's hook. The class docstring must gain a paragraph naming the new member,
exactly as the existing "A SIXTH member is owned here for a different reason" paragraph does.

### The base layer never imports the acquisition package
**Source:** 03.5 D-04, restated by CONTEXT D-01
**Apply to:** `quantlab/base/chunking.py` and `quantlab/base/data.py`. This is why the table
cannot live on `UniverseCatalog`, and it is also why `quantlab/utils/cli.py` reads
`MAX_DENSE_PANEL_BYTES` through a call-time import rather than a module-scope one.
