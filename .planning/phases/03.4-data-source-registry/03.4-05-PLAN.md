<objective>
Turn the acquisition loop's progress into event objects through a pluggable reporter, and add a
cancel token checked at batch boundaries so a cancelled multi-hour backfill stays resumable — with
the result object and the failure manifest kept in agreement on every exit path.

Purpose: D-12 moved writes in-process, and the loop lives here, so cancellation is something the
console cannot add from outside — under the old subprocess contract cancelling was `kill`. Today
`_run_once` renders a tqdm bar to stderr and logs through loguru; neither is consumable by an
in-process caller, and tqdm's cursor control fights a Textual screen. This plan closes SC-5's second
half.

Output: `quantlab/base/progress.py`, a reporter- and cancel-aware `Acquisition`, a widened
registry-level `run()`, and the D-16/D-17/D-18/D-19 proofs.
</objective>

<flagged_assumptions>

  both the write and the result assembly, so `set(result.failures) == set(manifest)` holds on every
  exit path rather than only on the uncancelled ones.
</flagged_assumptions>
