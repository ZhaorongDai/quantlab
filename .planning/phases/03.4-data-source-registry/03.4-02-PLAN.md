<objective>
TRACER: prove the whole registry story end to end on one path, then pin it.

One descriptor is defined beside its vendor class and registers itself, a cold subprocess import of
the registry alone enumerates both vendors, credential status is readable with no credential
present, and `ingest_tiingo.py` reaches Tiingo through the registry — naming no vendor class — via a
programmatic `run()` that returns a result object while `_failures.json` still lands on disk.

Purpose: this is the thinnest path that touches every layer the phase modifies (registry → vendor
module → `Acquisition` base → repo-root entry point). Proving it end to end here means an
architectural dead end surfaces after one commit rather than after the inspector, the reporter, the
cancel token and three shells have all been built on top of it.

Output: `quantlab/acquisition/registry.py`, the two descriptors, `AcquisitionResult` +
`Acquisition.last_result`, `ingest_tiingo.py` as a thin shell, and the D-01..D-07 test suite.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired `pluralization` over this phase's scope. The genuine delta is
not the words it matched on but the one underneath them: **a vendor used to be a singular, implicit
fact — each ingest script named exactly one acquisition class at every call site — and this phase
introduces a set of them behind one enumeration.**

- **Noun that is now primary:** `SourceDescriptor` — "an acquirable data source", keyed by `vendor`,
  carrying a capability LIST.
- **Decision:** `promote`. The general representation becomes primary: callers enumerate and resolve
  descriptors, and the vendor-specific `Acquisition` subclass is demoted to one field of a
  descriptor (`acquisition_cls`) rather than remaining a name typed at each call site. This is not
  add-alongside: after plan 06 no shell names a vendor class at all, so the singular form is
  removed rather than kept beside the plural one.
- **Rationale:** the demoted representation still exists and is still required — it is how a download
  actually happens — but it is now reached only through the promoted one, which is what makes
  "adding a vendor is registering a descriptor, not editing five call sites" true.
- **Invariant test (suggested, and taken):** `tests/test_ingest_shells.py::no_shell_names_a_vendor_class`
  is exactly the invariant that goes red if a future phase reintroduces the singular assumption at a
  call site; `test_one_descriptor_per_vendor_rejects_a_duplicate` is the identity-model half.
</assumption_delta_decision>
