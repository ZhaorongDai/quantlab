## Gaps Summary

**一个 gap，一个根因，六个站点。**

03.4-08 把清单语义从「最近一次 run 的快照」变成「跨 run 累积的耐久记录」；
REVIEW CR-01（`c0e392f`）又把 `AcquisitionResult.failures` 从这个累积记录里拆了出来，
**主动作废**了 `set(result.failures) == set(manifest)`。代码这两步都做对了，且都被能红的
测试锁住了。问题在于随后的文档清扫**又一次只覆盖了一部分实例**：

- `c0e392f` 改了 `example/acquisition.md`、`example/registry.md`、`03.4-VALIDATION.md`
  和三处 docstring，**漏了** `.planning/ROADMAP.md:326` 与 `.planning/STATE.md:204`；
- 03.4-08 / `e2833b4` 改了 `_merge_unattempted_failures` 的 docstring 与
  `example/acquisition.md` 的「常见坑 5」，**漏了** `_write_failure_manifest` 自己的
  docstring、`example/acquisition.md` 的核心概念段（181-182）与走查段（560）、
  以及 `example/pageledger.md:137`。

于是现在：

- `.planning/ROADMAP.md` —— `quantlab-console` 要照着写断言的契约文件 —— 说一条
  **可执行地为假**的等式 "does hold on every exit path"。同一仓库里
  `test_a_disjoint_rerun_does_not_inherit_earlier_failures` 正绿着，而它断言的恰恰是
  `result.failures == {}` 同时清单持有 `{'AMZN': ...}`。
- `_write_failure_manifest` 的 docstring 说「清单永远描述最近一次 run，空的就是上次跑
  干净了」；隔三个方法的 `_merge_unattempted_failures` docstring 说「忙 store 上大多数
  清单条目是折回来的而非本轮观测到的」。**前者正是后者以及那个新增耐久性测试的失败消息
  所引用的权威**（"An empty manifest is, per `_write_failure_manifest`'s own docstring,
  a statement that the last run was clean"）—— 引用链的根现在是一句假话。
- `example/acquisition.md` 同一文件内，第 182 行与第 773 行互相打架，中间隔着 591 行。

这是本阶段第三次出现同一形状：**一次基于单一字面量 / 单次 grep 的文档清扫，
覆盖大部分实例、漏掉少数，留下一句陈述与它自己的反面并排站着。**
plan 09 的 prohibition 2 逐字禁止了这件事（"a partial fix that corrects one clause and
leaves the other is the same defect in a smaller font"），plan 09 的 must-have 7 要求
ROADMAP「记录这个关系实际是什么」。两条都不成立。

**这不改变阶段目标的达成。** 登记表是真的、可枚举、无凭证可用、有仓内消费者，六条
成功标准全部行为性通过。这是一次文档与代码之间的契约漂移，修复是几处有界的文本编辑 ——
但因为漂移发生在跨仓库契约文件（ROADMAP）和被其他 docstring 引用的权威 docstring 上，
不能作为 advisory 放过。

**给闭环计划的一句提醒：** 不要再用单一字面量 grep 做验收。按语义关键词多变体扫描
（`最近一次 run` / `永远描述` / `上次跑干净` / `LATEST run` / `last run was clean` /
`set(result.failures) == set`），并把扫描本身写成一个能红的 verify 命令。
