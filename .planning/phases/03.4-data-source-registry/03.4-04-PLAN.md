<objective>
Extract coverage judgement into a credential-free `CoverageLedger` that `Acquisition` composes and
delegates to, then build the read-only `SourceInspector` on top of that same object.

Purpose: SC-3 and SC-4 together. `TiingoAcquisition(config)` raises without `TIINGO_API_KEY` at
construction, which is why `ingest_us_equity.py` today SKIPS its own coverage report on an
unconfigured machine — for a computation that is nothing but local file reads. The inspector removes
that absurdity. D-09 makes it binding that the inspector does not re-implement the coverage rule:
the four-state classification plus the orthogonal no-data count is not reproducible by
re-derivation, and two implementations that agree today are exactly how an operator ends up trusting
the wrong one.

Output: `quantlab/base/coverage.py`, `Acquisition` delegating, `quantlab/acquisition/inspector.py`,
and the SC-3/SC-4 proofs.
</objective>

See `03.4-01-PLAN.md` → "Artifacts this phase produces". This plan creates `CoverageLedger` and its
eleven members, `CoverageLedger.for_config()`, `Acquisition._coverage`, `SourceInspector` and its

<flagged_assumptions>
- **D-09 (unclassified).** The probe found no edge shape for "the inspector must not re-implement
  coverage judgement". Planner assumption: "shared" is proved by IDENTITY, not by equal results —
  the D-09 test asserts both callers reach the same function object AND that a mutation to that one
  function changes both answers. Equality of returned dicts alone would pass for two implementations
  that happen to agree.
- **D-10 (unclassified).** Planner assumption: "lazy" is proved by type and by non-collection — the
  returned object is a `pl.LazyFrame` and the test asserts on `.explain()` without calling
  `.collect()` for the pruning proof. The developer's D-10 override (a lazy object technically
  permits asking for a whole tier) is closed from the other side by D-11's required arguments, not
  by narrowing the return type.
- **Extraction shape.** RESEARCH offered two options for the `_data_type` blocker. This plan takes
  Option A (`CoverageLedger` composed by both, `data_type` passed IN) because it needs zero change
  to either vendor class and makes the inspector's independence structural. Option B
  (`resolve_data_type` classmethod) would touch `AlpacaAcquisition.RAW_COLUMNS`/`RAW_SCHEMA`, which
  read `self._data_type`, and risk the resolved-once-used-for-both invariant that class's docstring
  defends.
- **Module placement.** `quantlab/base/coverage.py` rather than a module under `quantlab/acquisition/`,
  because the inspector must be able to import it without importing anything under
  `quantlab/acquisition/` or `quantlab/base/acquisition.py`.
</flagged_assumptions>
