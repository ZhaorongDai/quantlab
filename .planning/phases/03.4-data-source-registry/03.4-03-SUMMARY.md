# Phase 03.4 Plan 03: Atomic JSON Sidecars Summary

**One stdlib-only `write_json_atomically` helper now writes every JSON sidecar in the repository — both resume ledgers and both acquisition sidecars — with each caller's on-disk bytes unchanged, making SC-5's "a cancelled run leaves watermarks resumable" true against a real batch-boundary interruption.**

## Performance

- **Duration:** 13 min
- **Started:** 2026-09-08T23:59:23Z
- **Completed:** 2026-09-09T00:12:35Z
- **Tasks:** 2 (both TDD, 4 commits)
- **Files modified:** 5 (1 created, 4 modified)

## Accomplishments

- **Extracted the atomic-write body that existed twice into one place.** `ChunkLedger._flush` wrote it, `PageLedger._flush` copied it verbatim, and the plan would have made it four copies. `quantlab/utils/atomic.py:write_json_atomically` is now the only `NamedTemporaryFile` in `quantlab/` — verified repo-wide, not just in the two ledgers.
- **Made both acquisition sidecar writers atomic without changing a byte of their output.** `_write_watermark` stays compact, `_write_failure_manifest` stays `indent=2, sort_keys=True`, and both are asserted against `json.dumps` output rather than by eye.
- **Proved the property that motivated the phase.** Under the old plain `open(path, "w")`, an interruption truncated a good watermark to empty before `json.dump` wrote a byte — the RED for Task 2 was exactly that (`assert b'' == b'{"last_date": ...}'`). The resumed run now reads the previous complete value.
- **Pinned D-20's no-lock decision as code.** An AST scan over every module under `quantlab/` with a non-vacuity floor, catching both a forbidden import and a hand-rolled `.lock` literal.
- **Mutation-verified all ten locks.** Every test that ships was proven to turn red against a broken mechanism, not merely read.

## Files Created/Modified

Module docstring carries the rationale, the provenance (extracted, not copied a third time) and the explicit statement that no lock is taken.

- `quantlab/base/acquisition.py` — `_write_watermark` and `_write_failure_manifest` each reduced to one delegating call; both docstrings gained a sentence naming why atomicity matters *here* (D-17 cancels at a batch boundary, which is when this file is written); a `#:` comment at `_write_watermark` records D-20's blast-radius bound and the prohibition against tightening `_read_sidecar`.
- `tests/test_atomic_sidecars.py` — grew from 2 Wave-0 self-tests to 10. The two Wave-0 tests were left untouched and both still pass.

## Decisions Made

1. **The helper lives under `utils/`, and both LEAF docstrings were amended rather than left standing.** The plan flagged this: `pageledger.py` and `chunking.py` both claimed "ZERO project-internal imports", and importing `utils.atomic` makes the letter of that claim false while preserving its spirit. Both docstrings now name `quantlab.utils.atomic` as the single stdlib-only leaf they import, and state explicitly *why* it cannot close a cycle (it imports nothing from this project at all). The unit-testability and no-cycle reasons were kept intact.

2. **Formatting stays at the call site.** `indent=2` is passed by each ledger, `sort_keys=True` by the manifest, nothing by the watermark. A helper that imposed one house format would have made every pre-existing file on disk differ from every new one — a repudiation-shaped change hidden inside a durability fix. Mutation-verified in both directions.

3. **`_read_sidecar` is deliberately NOT tightened.** The prohibition the plan names is now enforced by a mutation-verified test (`test_a_half_written_watermark_sidecar_reads_back_as_absent`, which the Wave-0 plan wrote precisely so it could be re-asserted unchanged) and recorded as a `#:` comment at the site a future reader would be tempted to "finish the job" from.

4. **Literal `os.replace` / `NamedTemporaryFile` strings removed from the ledger docstrings.** The acceptance criterion is "neither file contains them any more"; a prose mention in a docstring trips a literal check. Reworded to "renamed over the destination" with a pointer to `quantlab.utils.atomic.write_json_atomically` for the mechanism. See Deviations.

5. **RED evidence via a faithful pytest→TAP rendering.** `gsd check tdd-red-evidence` parses node-`--test` TAP; pytest emits none. A pure transformation script turns the real `pytest -v` result lines into `ok`/`not ok` plus `# tests/# pass/# fail` counters — nothing invented, every line derived from a real run. Both cycles returned `RED_EVIDENCE_OK`.

## Mutation Verification

Wave 2's executor found three acceptance criteria that would have shipped green while proving nothing. The same standard was applied here: **every** lock was proven by breaking the mechanism it guards and observing the intended test go red.

| Mutation applied | Test that turned red |
|---|---|
| Drop `dir=` (stage the temp file in the system temp dir) | `test_the_temp_file_is_created_in_the_destination_directory` |

| Revert `_write_watermark` to plain `open()` + `json.dump` | `test_an_interrupted_watermark_write_leaves_the_previous_value_readable` |
| Give the watermark `indent=2` (silent format drift) | `test_watermark_write_is_atomic_and_keeps_its_compact_shape` |

**Finding worth recording:** `test_write_json_atomically_leaves_no_temp_file` survives the plain-`open()` mutation — a naive writer leaks no temp file either, so that test alone does not prove atomicity. It is non-vacuous only against the `copyfile` mutation (the temp file survives). The property it actually guards is *no leaked staging file*, and `test_a_failed_write_...` plus the interrupted-watermark test are what guard atomicity. Both classes of mutation were run; neither test is load-bearing alone. The tree was restored and `diff`-verified clean after every mutation.

**2. [Rule 2 - Missing Critical] The no-lock test needed a second arm and a non-vacuity floor**

- **Found during:** Task 2 (writing `test_no_lock_is_introduced_anywhere_in_quantlab`)
- **Issue:** The plan specified an import scan plus a `.lock`-path check. Written as an import-only AST scan it would miss a lockfile hand-rolled as `open(p.with_suffix(".lock"), "x")`, which needs no import at all. Separately, an AST walk whose file list silently came back empty (wrong root, a rename) would pass vacuously — the exact failure mode STATE.md records for the Wave-2 enumeration-order test.
- **Fix:** Added the `.lock` string-literal arm (mutation-verified independently) and an explicit `len(sources) > 20` non-vacuity floor with a message, plus an assertion that the package root resolves.
- **Files modified:** `tests/test_atomic_sidecars.py`
- **Verification:** Both arms mutation-verified separately (`fcntl` import → red; `".lock"` literal → red).
- **Committed in:** `71b42f4` (Task 2 RED commit)

**3. [Rule 3 - Blocking] Task-1 RED would have been a collection error, taking the Wave-0 tests with it**

- **Found during:** Task 1 (RED phase)
- **Issue:** A module-scope `from quantlab.utils.atomic import ...` against a not-yet-existing module fails the whole file at collection, which is `INVALID_RED` (a load failure, not an attributable test failure) and would also have reported the two passing Wave-0 self-tests as failures.
- **Fix:** RED used per-test local imports, giving four individually-named failing tests and two still-passing Wave-0 tests; the imports were hoisted to module scope in GREEN where they belong.
- **Files modified:** `tests/test_atomic_sidecars.py`

- **Committed in:** `c6c4580` (RED) / `6fd987e` (hoist)
