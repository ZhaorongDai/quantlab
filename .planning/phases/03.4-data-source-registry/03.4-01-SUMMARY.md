## Decisions Made

- **`-k`-matches-nothing is asserted by exit code 5, not by grepping `no tests ran`.** pytest 9.1.1 emits `no tests collected (N deselected)`. Exit 5 is version-stable. Plans 02–07 must use the exit-code form.
- **`isolated_registry` fails loudly, not silently.** No `try/except`, no `importorskip`. A skipped isolation fixture is indistinguishable from one that isolated.
- **`no_credentials` names its three env vars as literals.** Sourcing them from `CREDENTIAL_ENV_VARS` would make the proof circular; the two lists are instead pinned against each other from the outside, in `test_vendor_credential_env_names_are_module_level_constants_not_client_attributes`.
- **The three D-15 shells are `ingest_tiingo.py`, `ingest_alpaca.py`, `ingest_us_equity.py`.** `ingest_binance_spot.py` serves crypto spot, reaches no us-equity vendor, and is out of scope.
- **Helpers were copied rather than cross-imported.** `tests/` is not a package (no `tests/__init__.py`; `pyproject.toml` sets only `pythonpath = ["."]`), so a cross-test import would couple one file's collection to another's import-time state.

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plan's watermark-root path expression is off by one**
- **Found during:** Task 2 (`test_the_acquisition_config_fixture_serves_both_vendors_with_a_terminated_raw_root`)
- **Issue:** The plan specified asserting `Path(cfg.watermark_path).parent == Path(cfg.raw_data_dir_path).parent.parent / "_watermarks"`. Against the actual fixture (`tests/conftest.py:1104`), `raw_data_dir_path` is `{downloads}/{vendor}` and `watermark_path` is `{downloads}/_watermarks/{vendor}`, so the correct relation is `raw_root.parent / "_watermarks"` — one level up, not two. Written as specified, the assertion fails.
- **Fix:** Asserted the correct sibling relation, plus the property that actually matters stated negatively (`raw_root not in watermark_root.parents`), so a future layout change that preserves the invariant still passes.
- **Files modified:** `tests/test_source_registry.py`
- **Verification:** `uv run pytest tests/test_source_registry.py -q` → 3 passed

**2. [Rule 3 - Blocking] Two acceptance criteria grep for a string pytest 9.1.1 never emits**
- **Found during:** Task 2, recurring in Task 3
- **Issue:** Task 2 and Task 3 each require `uv run pytest ... -k "<later-plan selectors>" -q 2>&1 | grep -q "no tests ran"` to succeed. On pytest 9.1.1 a selector matching nothing prints `12 deselected in 0.15s` (and `no tests collected (N deselected)` under `--collect-only`). The literal `no tests ran` is never produced, so the criterion could not pass no matter how correct the implementation was.
- **Fix:** Verified the criterion's *intent* — zero tests selected — with two forms that work on this pytest: the run exits **5**, and `--collect-only -q` prints `no tests collected`. Both were checked for the Task 2 and Task 3 selector sets and for all 28 later-plan selectors at once. The finding is recorded in STATE.md as a decision, because plans 02–07 carry the same broken command shape.

- **Committed in:** n/a — no code change; recorded in STATE.md and here
