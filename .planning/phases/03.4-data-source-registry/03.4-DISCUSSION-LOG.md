## Descriptor key and field set

### Q1 — Descriptor granularity

| Option | Description | Selected |
|--------|-------------|----------|
| `(vendor, market, frequency)` triple | Every row directly runnable; ~4-5 rows today; console renders flat, no invalid combos. Cost: vendor-level facts repeat, or need a vendor-level parent. | |
| One row per vendor, capability list inside | 2 rows today; vendor facts stated once, matching where the class attributes already live. Cost: console expands the cross-product itself, and `market × frequency` is not a full cross-product. | ✓ |
| Two tiers: vendor descriptor + capability rows | Both problems separated. Cost: one more layer than the single-tuple idiom the ROADMAP names. | |

**Notes:** The stated cost of the chosen option became Q2.

### Q2 — Capability list shape

| Option | Description | Selected |
|--------|-------------|----------|
| Tuple of explicit capability rows | Each element a full runnable `(market, frequency, data_type)`. Flat, directly iterable. | |
| Nested `market → frequency → data_types` dict | Compact, mirrors reality. Cost: three-level loop to enumerate. | |
| Capability as a small dataclass | Named fields, extensible (asset class, earliest date, entitlement). Matches the repo's dataclass-config habit. Cost: heavier than bare tuples; `UniverseCatalog` uses bare class tuples. | ✓ |

**Notes:** Constraint surfaced during the question — `Frequency` has only `1d`/`1m`/`tick`, but
Alpaca's `tick` splits further into `quotes`/`trades` via `TICK_DATA_TYPES` and `ENDPOINT_MAP`, so
capabilities need one level more than `(market, frequency)`.

### Q3 — How the descriptor points at its acquisition class

| Option | Description | Selected |
|--------|-------------|----------|
| Direct class reference | Same form as `MEMBERSHIP_FETCHERS`; type-checked. Cost: importing the registry imports every vendor SDK. | ✓ |
| Dotted path string + lazy resolution | Uses the existing `get_cls_from_path` idiom; enumeration imports no SDK. Cost: typos surface at runtime. | |
| Both: class reference + lazy module import | Lightweight index table for listing. Cost: two definitions to keep consistent. | |

**Notes:** Verified before asking — `quantlab/acquisition/tiingo.py:4` is
`from tiingo import TiingoClient` at module level, so the import cost is real. Accepted because
both `tiingo` and `requests` are already hard quantlab dependencies.

### Q4 — Who decides "credential configured"

| Option | Description | Selected |
|--------|-------------|----------|
| Descriptor declares names, registry judges | Shared `is_configured` reading `os.environ`; console needs no acquisition object. Cost: name appears twice, needs a consistency test. | ✓ |
| Descriptor is the single truth, `__init__` reads it | One definition. Cost: acquisition layer depends back on the registry; circular-import risk. | |
| Leave `__init__` alone, add a consistency test only | Smallest change. Cost: two truths remain, drift merely goes red. | |

## Where descriptors live

### Q1 — Descriptor form

| Option | Description | Selected |
|--------|-------------|----------|
| Class attributes on the Acquisition subclass | `DATA_SOURCES = (TiingoAcquisition, AlpacaAcquisition)`, literally the `MEMBERSHIP_FETCHERS` form. Cost: already-large classes grow; one class cannot hold two descriptors. | |
| Independent dataclass instances | Separates "who I am" from "how I download"; one class can carry several descriptors later. Cost: tuple holds instances, not classes. | ✓ |
| Class attributes + registry-collected view | Both benefits. Cost: field set defined in two places. | |

**Notes:** Raised in the question — the `Acquisition` subclasses already carry `RAW_SCHEMA`,
`QUOTA_STATUS_CODES`, `LEGACY_WATERMARK_POLICIES`, `FIELD_MAP`, `TIMEFRAME_MAP`, `ENDPOINT_MAP`,
`RAW_COLUMNS_BY_DATA_TYPE`, `SESSION_TIME_ZONE`.

### Q2 — What "registering" means

| Option | Description | Selected |
|--------|-------------|----------|
| Hand-maintained class-level tuple | Identical to `MEMBERSHIP_FETCHERS`; deterministic order; trivially mockable. Cost: forgetting to register is silent. | |
| Decorator auto-registration | Defining a source registers it; cannot be forgotten. Cost: contents depend on import graph; order non-deterministic; test isolation harder; no precedent in repo. | ✓ |
| Tuple + exhaustiveness test | Deterministic order, and forgetting goes red. | |

**Notes:** The chosen option's costs were stated before selection and were accepted.

### Q3 — Guaranteeing enumeration completeness

| Option | Description | Selected |
|--------|-------------|----------|
| Package `__init__` imports all vendor modules | Simple and deterministic. Cost: first non-empty `__init__.py` in the repo; importing the package pulls every SDK. | ✓ |
| Registry module imports them itself | `__init__.py` stays empty. Cost: circular-import risk; decorator and registry must split into two modules. | |
| `pkgutil` scan of the package directory | New files work with no edit. Cost: implicit; poor errors; would sweep in `universe.py`. | |

## Read-side API shape

### Q1 — Where the read surface lives

| Option | Description | Selected |
|--------|-------------|----------|
| New read-only inspector class | Needs no credentials, constructs no acquisition. Cost: `coverage_report` already lives on `Acquisition` and shares `_partition_by_coverage`. | ✓ |
| Extend `Acquisition`, make the credential check lazy | Zero-cost sharing. Cost: turns a fail-fast safety behaviour into fail-late, against a pinned test. | |
| Hang it on the registry | One entry point for the console. Cost: registry becomes catalogue + query engine. | |

**Notes:** Verified before asking — `tests/test_tiingo_acquisition.py:65` pins that
`TiingoAcquisition(config)` raises `RuntimeError` matching `TIINGO_API_KEY` when the env var is
absent. This made the constraint concrete rather than hypothetical.

### Q2 — What the row-level read returns

| Option | Description | Selected |
|--------|-------------|----------|
| Forced pagination, materialised page | "Ask for a whole tier" becomes unrepresentable. Cost: in-process analysis gets no lazy object. | |
| LazyFrame / lazy object | Most flexible; matches `PlBackend.get_lazyframe`. Cost: "don't ask for the whole tier" becomes a convention, not a guarantee. | ✓ |
| Two methods: `page()` and `scan()` | Both real use cases served. Cost: two entry points to explain. | |

**Notes:** Flagged at the time as being in tension with the ROADMAP's "any surface that can be
asked for a whole tier at once is the wrong surface". Rather than reversing the choice, the risk
was closed from the other side in Q3.

### Q3 — Whether filters are mandatory

## CLI rework extent

### Q1 — What happens to the three scripts

| Option | Description | Selected |
|--------|-------------|----------|
| Descriptor carries a CLI entry field, scripts kept | Small change; registry gains an in-repo consumer; console reads the command from the descriptor. | |
| Merge into one `ingest.py --source` | Uniform exported command. Cost: same-vendor targeted vs bulk needs another flag; arg sets differ widely; existing patch-based tests must be rewritten. | ✓ (later superseded) |
| Add `[project.scripts]` first | Real console entry points. Cost: largest change; packaging was just touched by 260907-sm2. | |

**Notes:** Surfaced during the question — `ingest_tiingo.py` and `ingest_us_equity.py` are the
**same vendor**, differing by targeted vs bulk-backfill intent; and `pyproject.toml` has no
`[project.scripts]`.

### Q2 — Mid-area user redirection

**User's input (free text):** *"可以直接使用 tui，tui 做成之后 cli 可以抛弃"*

**Conflict raised before proceeding:** the ROADMAP's locked 2026-09-07 boundary contract makes the
CLI the console's *write mechanism* — subprocess invocation is what keeps a multi-hour backfill
from taking the console down, and what makes "the exported command IS what the console runs" true
by construction. Two readings were distinguished: humans stop using the CLI (compatible with the
contract) vs the CLI is removed outright (breaks it).

| Option | Description | Selected |
|--------|-------------|----------|
| Humans stop using it, kept as machine interface | Locked contract intact. | |
| Truly removed, writes go in-process | Overturns the locked contract; long-task isolation moves to the console repo. | ✓ |
| Undecided; build to the contract this phase | Defer the question until the console exists. | |

### Q3 — Follow-up: *"能不能不走 cli 的入口？"*

Answered directly rather than by another question: yes, technically — but two things follow. (1)
The registry would lose its only in-repo consumer, which is precisely what the ROADMAP's in-scope
"retire the hardcoded vendor dispatch" item exists to prevent ("so the registry has a first
consumer IN THIS REPO and cannot rot into a console-only side table"). (2) Long-task isolation
moves wholly to the console repo. A thin-shell compromise was recommended.

| Option | Description | Selected |
|--------|-------------|----------|
| Programmatic entry + scripts reduced to thin shells | Satisfies the in-repo-consumer requirement, keeps a no-TUI fallback, and "abandon the CLI" becomes "stop evolving it". | ✓ |
| Programmatic entry only, delete the scripts | No CLI at all. Cost: ROADMAP in-scope item becomes a deletion; registry has zero in-repo call sites. | |
| Programmatic entry only, scripts untouched | Smallest change. Cost: hardcoded dispatch and registry coexist as two truths. | |

**Notes:** This supersedes Q1's "merge into one `ingest.py --source`".

## Progress and cancellation

### Q1 — How progress is delivered

| Option | Description | Selected |
|--------|-------------|----------|
| Optional callback, tqdm still the default | Small change; both callers served. Cost: exceptions in the callback pollute the acquisition. | |
| Generator driven by the caller | Cancellation is `break`, for free. Cost: control flow inverted; `_run` restructured. | |
| Event object + pluggable reporter | Matches the repo's layering habit; most extensible. Cost: a new abstraction for two implementations. | ✓ |

**Notes:** Verified before asking — `download()`/`refresh()` return `Self`; progress is
`tqdm(..., desc=f"{self.VENDOR} …")` at `base/acquisition.py:1327` plus loguru. Neither is
consumable in-process, and tqdm's cursor control fights a Textual screen.

### Q2 — Cancellation mechanism

| Option | Description | Selected |
|--------|-------------|----------|
| Separate cancel token, checked at batch boundaries | Reporting and control stay separate; completed batches land and advance the watermark; run stays resumable. | ✓ |
| Reporter return value as the signal | No new concept. Cost: a log-only reporter that forgets `return True` silently stops an acquisition. | |
| Defer to a later phase | Cost: the gap is created by the in-process decision, and the console cannot close it from outside — the loop is in quantlab. | |

## Result and partial-failure shape

| Option | Description | Selected |
|--------|-------------|----------|
| Result object **and** `_failures.json` as today | Caller gets the outcome without reading disk; manifest survives a crash. Cost: two outputs to keep consistent. | ✓ |
| Result object only | One truth. Cost: a crash loses everything, and `_failures.json` is resume input today. | |
| Keep `return Self`, query afterwards via the inspector | Zero change; cleanest read/write split. Cost: caller must issue a second query to learn what just happened. | |

| Option | Description | Selected |
