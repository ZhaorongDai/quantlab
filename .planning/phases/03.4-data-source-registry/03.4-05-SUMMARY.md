# Phase 03.4 Plan 05: Progress Reporter and Batch-Boundary Cancellation Summary

**A `quantlab/base/progress.py` leaf carrying `ProgressEvent` + a `ProgressReporter` ABC (tqdm/callback/null) and a `CancelToken`, wired through `Acquisition.attach()` and `registry.run()`, with the cancel checked at `_attempt_batch`'s first statement and the on-disk manifest merged on the cancel path so the result object and `_failures.json` agree on every exit path.**

## Accomplishments

- **Progress became event objects without the shell run losing its bar.** `_run_once` no longer constructs a `tqdm`; it emits `run_started` / `batch_completed` / `quota_exhausted` / `cancelled` / `run_finished`, and `TqdmProgressReporter` renders exactly what the inline block did — same `total`, same `f"{VENDOR} {start}..{end}"` description, same `unit="batch"`, same quota description switch. That is asserted through the CONSTRUCTOR kwargs, never by capturing stderr, whose width depends on the terminal.
- **A reporter cannot end a run, in either of the two ways it could.** It cannot stop one deliberately (cancellation is a separate token; `emit` returns `None` and the caller ignores it) and it cannot stop one accidentally (`_emit` wraps every call in `try/except` + a scrubbed warning, and the joblib result generator is still drained to completion).
- **Cancellation lands where the guarantee actually lives.** `_should_stop()` — the OR of the quota abort and the cancel token — is `_attempt_batch`'s FIRST statement, keeping the 3-element `(symbols, "skipped", None)` return that two existing tests destructure. The `cancel_leaves_a_resumable_store` fixture is deliberately sized (12 batches, `max_workers=8`) so joblib's `pre_dispatch` of `2 * n_jobs` queues every batch and the input-generator `break` can never fire — RESEARCH Pitfall 2 built into the fixture rather than asserted in prose. Mutation M5 confirms it: moving the check to the generator alone turns the test red.
- **A cancel is never mistaken for the vendor running out of allocation.** `_run` breaks on the cancelled flag BEFORE the quota branch: no `_sleep`, no wait, no resume, no allocation-exhausted message. The test sets `wait_for_quota=True` so "never slept" means something.
- **The two D-18 outputs agree on the cancel path too, which they did not before.** `_write_failure_manifest` overwrites and `_run`'s `failures` starts empty, so a run cancelled before reaching last run's failures would have written `{}` — and that method's own docstring calls an empty manifest a statement that the last run was clean. `_merge_unattempted_failures` folds those entries back BEFORE both the write and the result assembly.
- **13 new tests, and every lock mutation-verified.** 14 mutations run; each intended test observed turning red. One mutation was invalid and was redone (see Issues), and one pre-existing coverage gap was surfaced rather than hidden (see below).

## Decisions Made

- **Module placement diverges from RESEARCH deliberately.** `quantlab/base/progress.py`, not `quantlab/acquisition/progress.py`: `base/acquisition.py` imports the default reporter and the layering runs `base` → concrete packages. Recorded in the module docstring, per the plan's `<flagged_assumptions>`.
- **`progress=False` resolves to `NullProgressReporter`.** The replaced code built a `tqdm(disable=True)`. Both render nothing; not building the object is the honest expression. The four constructor arguments are still asserted for the truthy branch, which is where "byte-compatible default" actually bites.
- **Cancel-path manifest policy: MERGE, not skip.** RESEARCH left the choice open. Merging keeps failures a cancelled run genuinely discovered AND preserves the previous run's un-retried ones, which is what makes `set(result.failures) == set(manifest)` true on every exit path rather than only the uncancelled ones.
- **The never-raises wrapper lives at the caller (`_emit`), not in the reporter.** The exception must be `_scrub`bed with the vendor's `CREDENTIAL_ENV_VARS`, and only the acquisition object knows those. Putting the `try/except` in `progress.py` would either log unscrubbed text or force a credential-ignorant leaf to learn about credentials.
- **`_run_once` reports `quota_aborted` and `cancelled` as two booleans, not one tri-state**, because `_run` must handle them differently: a quota abort may wait and resume, a cancel must not.

## Issues Encountered

**A pre-existing coverage gap, surfaced by M6 and reported rather than hidden.** When `_should_stop()` is mutated to consult ONLY the cancel token — i.e. `_attempt_batch`'s first statement stops honouring the vendor quota abort entirely — the whole of `tests/test_tiingo_quota.py` stays **green at 24 passed**.
