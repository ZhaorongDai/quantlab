<objective>
Close VERIFICATION gap 1: make the failure manifest durable on the exit path an operator actually
hits, and pin it with a test that can fail.

Purpose: `_merge_unattempted_failures` was written for exactly this bug class, documented at length
in its own docstring, and then wired into one of the five exits that need it — the `if cancelled:`
branch. `wait_for_quota` defaults to `False`, and quota exhaustion is the EXPECTED end of the
full-market `us_all` backfill this phase exists to serve (the 2026-09-06 incident burned ~10,000
symbols). On that default path the previous run's recorded 404s are overwritten with an empty
object, which `_write_failure_manifest`'s own docstring defines as a statement that the last run was
clean. The verifier reproduced this with an executing test: `quota_aborted: True`,
`cancelled: False`, and a manifest on disk that had just been emptied (D-18).

The phase could not see it, and that reason matters more than the bug. D-18 pinned the equality
between `result.failures` and the manifest as the consistency check, but `_run` assembles both sides
from the same `failures` dict at the same point, so the equality is an identity — it read True
directly on top of the destroyed manifest. The regression this plan adds therefore asserts on the
manifest's CONTENTS after a quota abort, and the validation contract records what the old check
actually is.

Output: one unconditional pre-write merge covering every exit of `_run`'s resume loop, a red-first
regression test in `tests/test_acquisition_progress.py`, three corrected docstrings, and a D-18
validation row that pins a property rather than a construction.
</objective>

<flagged_assumptions>
- **The by-construction relocation widens behaviour on two exits the verifier did not name.**
  `03.4-VERIFICATION.md` names the cancel exit (already merged) and the two quota exits. Moving the
  single call after the `while True:` loop also puts it on the `if not pending: break` exit and the
  `if not aborted: break` (normal completion) exit. Planner judgement: this is correct and is the
  point of choosing by-construction. `attempted = all_succeeded | set(failures)` is the set the run
  has news about; on any exit, an entry for a symbol outside that set is one this run cannot speak
  for. The one case where the widening preserves a STALE entry is a symbol that failed, was then
  hand-stamped by `ingest_us_equity.py --stamp-legacy-watermarks` (so it is covered without ever
  having succeeded), and is consequently never in `pending` again — its old reason lingers. That is
  a smaller harm than erasing a live 404, and `SourceInspector.failures()` is an advisory operator
  view, not a control input. Task 1 requires this to be stated in the SUMMARY and requires any
  resulting red test to be reported rather than suppressed.
