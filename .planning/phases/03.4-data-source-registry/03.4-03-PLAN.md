<objective>
Make watermark-sidecar and failure-manifest writes atomic, through ONE shared helper that the two
existing ledger copies also adopt.

Purpose: D-20's pre-planning check found that `Acquisition._write_watermark` and
`_write_failure_manifest` are plain `open(path, "w") + json.dump`, while `PageLedger._flush` and
`ChunkLedger._flush` thirty lines away are already temp-file + `fsync` + `os.replace`. Because
D-17's cancellation interrupts precisely at a batch boundary, SC-5's promise that a cancelled run
leaves the store and watermarks resumable is not actually true against a plain write. The developer
widened the phase scope to close this. Extracting one helper rather than adding a third inline copy
is the repo's own recorded lesson about drift between duplicated implementations.

Output: `quantlab/utils/atomic.py`, four call sites converted, and `tests/test_atomic_sidecars.py`
proving crash durability, formatting parity and that no lock was introduced.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent writers → sidecar directory | A thin-shell script and the console can overlap on one source (D-20 accepted residual risk) |
| process interruption → filesystem | A cancel or crash can land between any two bytes of a write |
| pre-existing on-disk files → reader | Sidecars written before this phase are still read by the same code |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03.4-03-01 | Tampering | concurrent writers corrupting a watermark sidecar | high | mitigate | Temp file in the destination directory + `fsync` + `os.replace`, so a reader sees one complete file or the other. Extracted once and shared by all four writers. |
