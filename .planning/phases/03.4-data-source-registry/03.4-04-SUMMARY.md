# Phase 03.4 Plan 04: CoverageLedger + SourceInspector Summary

**Coverage judgement lifted out of `Acquisition` into a credential-free `CoverageLedger` that both the real run and a new `SourceInspector` compose — so the inspector answers inventory, coverage, failure reasons and lazy row-level browsing on a machine with no credentials and zero vendor requests, and its coverage answer is provably the same function object the acquisition run uses, proved by mutation rather than by agreement.**

## Accomplishments

- **`quantlab/base/coverage.py` is a LEAF and that is the whole point.** It imports stdlib, `base/config.py` and `enums/data.py` and nothing else, which is what lets a reader reach coverage judgement without dragging in a class whose `__init__` demands `TIINGO_API_KEY`. Eleven members moved; `Acquisition` composes a ledger per access and every one of those eleven is now a single delegating call — and the *shape* of those bodies is AST-pinned, because a re-inlined implementation would keep all ~40 existing call sites green while quietly ending D-09.
- **The D-09 sharing is proved by mutation, and the run exposed which arm actually binds.** Monkeypatching `CoverageLedger.partition_by_coverage` moves both the inspector's and the real run's answers. The identity arm (`acquisition._coverage.partition_by_coverage.__func__ is CoverageLedger.partition_by_coverage`) does *not* catch a re-inlined `Acquisition._partition_by_coverage` — see "Mutation Verification" below, where that is recorded rather than papered over.
- **`ingest_us_equity.py`'s absurdity is now removable.** That script prints `coverage report: skipped (export TIINGO_API_KEY to see it)` for a computation that is nothing but `open()` and `json.load()`. `SourceInspector.coverage(config)` returns the identical dict with every credential deleted from the environment. ## Decisions Made

1. **Extraction Option A, as the plan specified.** `CoverageLedger` composed by both callers with `data_type` passed IN. Zero change to either vendor class, and it makes the inspector's independence structural rather than conventional. Option B (`resolve_data_type` classmethod) would have touched `AlpacaAcquisition.RAW_COLUMNS`/`RAW_SCHEMA`, which read `self._data_type`.

2. **`LEGACY_WATERMARK_POLICIES` / `DEFAULT_LEGACY_WATERMARK_POLICY` moved to `coverage.py` and bound onto `Acquisition`.** The plan required only `FAILURE_MANIFEST_NAME` to be declared once, and required the policies to be *passed in* as values (which they are). But `for_config` — the constructor the inspector uses — needs the same policy set the real run uses and cannot import `Acquisition` to get it, so leaving the literals on the class would have created a second free-to-diverge copy in the same commit that removed one. They stay reachable as `Acquisition.LEGACY_WATERMARK_POLICIES` (`ingest_us_equity.py` reads that for its argparse `choices`) and a subclass can still narrow them, because `_coverage` passes whatever the class declares into the ledger.

3. **`_coverage` is built per access, not cached in the config setter.** `AlpacaAcquisition._data_type` is an instance property reading a knob with NO default; evaluating it eagerly at config-assignment time would raise for a tick config whose knob is supplied afterwards, where today `_watermark_root` only evaluates it lazily. Per-access construction is a five-attribute object and preserves the current evaluation timing exactly. The reason is written at the property.

4. **`validate_symbols` extracted to a module-level function.** See Deviation 2 — `browse_raw` holds a `DatasetConfig`, not an `AcquisitionConfig`.

5. **`browse_zarr` raises `ValueError`, not `KeyError`.** The plan says "re-raise with a message naming the store, the requested symbols and how many symbols the store carries" without fixing the type. `ValueError` is this repo's house style for a legible refusal (`_scan_raw`, `_assert_vendor_root`, `validate_symbols`, `_tick_data_type` all raise it), and `KeyError.__str__` reprs its argument, which mangles a multi-line operator message into one quoted blob. The original `KeyError` is preserved in `__cause__` and the test asserts it is.

6. **`inventory`'s raw root descends into `data_type={quotes|trades}` for tick.** Mirrors `watermark_root` and `StockDataset._scan_root`. Reporting the vendor root instead would conflate the two data types — the same namespacing mistake as Pitfall 8, in its harmless disk-footprint costume.

7. **`browse_zarr` deliberately does NOT run `validate_symbols`.** There a symbol is a coordinate label matched against an index, never a path segment and never a query-string value, so neither trust boundary the pattern guards is crossed — and the index either carries the label or raises, which is *stricter* than the pattern. Stated in the method's own comment so it reads as a decision rather than an omission. `browse_raw` and `coverage` do validate, per T-03.4-04-01.

8. **The registry import-cost flag Wave 2 raised is resolved by not importing the registry at all.** `inspector.py` imports no registry and no vendor module, so it never pays the vendor-SDK cost. It *does* pay `nautilus_trader` (~1.7 s cold) through `quantlab/dataset/stock.py`, which is the price of reusing `_scan_raw` rather than writing a second parquet scan — a trade the module docstring states explicitly rather than leaving to be discovered. No lighter path was taken, and the reason is that the four bugs `_scan_raw` already fixes are worth more than a cold second.
