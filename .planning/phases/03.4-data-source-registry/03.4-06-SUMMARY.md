# Phase 03.4 Plan 06: Thin Ingest Shells Summary

**All three us-equity ingest entry points reduced to shells that name no vendor class — every constructor call, every config factory and all seven argparse defaults that used to read a vendor class constant now route through the descriptor `DataSourceRegistry.get()` returns — and `ingest_us_equity.py --dry-run` now prints a real inspector-computed coverage report on a machine with no credential configured, pinned by 12 tests of which 11 were mutation-verified.**

## Accomplishments

- **L-5 is closed, and it is proved DYNAMICALLY.** The constructor call was the obvious vendor binding; the argparse defaults were seven more, and they name the vendor at parser-definition time, so a registry landing would have left every one of them untouched while SC-6's letter was satisfied. All seven now read through `SOURCE.acquisition_cls`. The proof is not a source scan for that expression — it is that with a stub descriptor patched in, `_build_arg_parser()` comes back carrying the stub's absurd constants (`7717`, `("stub_quotes", "stub_trades")`, `"stub_warn"`). A source scan would pass equally well against a file that wrote the expression in a comment; this cannot.
- **SC-3's visible consequence landed inside this repository.** `ingest_us_equity.py` used to print `coverage report:   skipped (export TIINGO_API_KEY to see it)` for a computation that is nothing but `open()` and `json.load()`. That branch is gone, the report is unconditional through `SourceInspector`, and the module no longer reads a credential environment variable at all — `import os` went with the branch. Run for real on this machine with all three credentials unset: 13,729 symbols resolved, coverage report printed.
- **A gap 03.4-02 left open was found and closed.** `ingest_tiingo.py` was calling `stock_acquisition_config` directly. That produced a byte-identical config *only* because `"tiingo"` is that factory's incumbent default — the vendor was never routed through the descriptor, so `config_factory` was dead weight in the one script meant to demonstrate the registry, and a rename of the default would have silently redirected the shell's paths. All three shells now build their config the same way, which is what let the wiring lock assert uniformly instead of exempting one.
- **A structural lock that this refactor silently disarmed was caught and widened.** `tests/test_volume_guard.py:_is_acquisition_construction` matched only an `ast.Name` ending in `Acquisition`. After the migration no shell carries one, so the "a client constructed before the guard must be the zero-request stamping migration" arm returned an empty list for all three scripts and stopped asserting anything — while the one real pre-guard construction was still there. Widened to the `SOURCE.acquisition_cls` form, then mutation-verified in both directions.
- **Eleven mutations run, none survived.** Every lock shipped here was mutated against the mechanism it guards: hardcoded argparse choices, a bypassed config factory, a flipped roster mode, a roster-bearing dataset config, a reinstated credential branch, a dropped header line, a moved `apply_data_dir`, a re-imported vendor class, a renamed flag, and a `SOURCE` that bypasses `get()`. All turned the intended test red.

## Decisions Made

- **`ingest_tiingo.py` was modified although the plan named only two shells.** See Deviation 1 — the plan's own must-have truth demands `descriptor.config_factory` for *each* shell, and the alternative was a wiring lock that exempted one of the three.
- **The us_equity config-factory wiring is proved structurally, not dynamically.** That shell builds its acquisition config inside `__main__`, where roster resolution needs the universe table. The proof is the conjunction of three arms — `SOURCE` IS the object the registry returned (identity, checked in the loader), exactly one `SOURCE.config_factory(...)` call node exists, and `stock_acquisition_config` is not imported — which together leave no other route. Mutation M3 confirms it.
- **No new `all_three_shells_still_exist` test.** 03.4-01's `test_every_shell_file_exists_and_is_git_tracked` already asserts existence *and* git-tracking for all three, and 01-SUMMARY explicitly forbids replacing that self-test. Writing a second one would have been duplication dressed as coverage.
- **The dry-run negative asserts on `skipped (export`, not on `skipped`.** The correct `already covered:` line reads `(would be skipped)`. A bare-word negative would go red on right output, which is exactly how a gate gets weakened until it catches nothing.
- **The stub descriptor is built directly from `SourceDescriptor`, never through `register_source`.** No test here can leak a fake vendor into `DataSourceRegistry.SOURCES` — the failure mode `isolated_registry` exists to prevent, avoided by not needing the fixture at all. The stub-loaded shell modules are likewise kept out of `sys.modules`, so the real `ingest_*` modules other test files import are untouched.
