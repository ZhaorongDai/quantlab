## Critical Issues

### CR-01: 无条件合并把「别的 roster 的旧失败」灌进了本轮的 run 结果

**File:** `quantlab/base/acquisition.py:1483-1486`（合并 + 写入）、`quantlab/base/acquisition.py:1499-1507`（`AcquisitionResult` 组装）

**Issue:**

`_merge_unattempted_failures(failures, attempted=all_succeeded | set(failures))` 现在无条件执行，而 `attempted` 只包含**本轮真正有消息的符号**。凡是不在 `attempted` 里的旧条目一律被 `setdefault` 折回 `failures`——包括**本轮 `requested` 里根本没有的符号**。而 `failures` 这个 dict 随后同时喂给了磁盘清单**和** `AcquisitionResult.failures`。

`_merge_unattempted_failures` 的 docstring 只承认了一种放大后果：「一个因为水位已覆盖而没进 `pending` 的符号，其条目现在被保留」。实际放大的范围要大一档：**根本没进 `requested` 的符号**也被保留并被计入结果对象。03.4-08 自己新增的那个测试就是这个形状（run 2 请求 `NFLX/NVDA/TSLA`，断言 `AMZN` 存活），只是它没有回头检查结果对象。

实测（探针测试，run 1 三个符号里 `AMZN` 404；run 2 换成 `NFLX/NVDA` 且**全部成功**）：

```
RUN2 requested: ('NFLX', 'NVDA')
RUN2 failures : {'AMZN': 'RestClientError: 404 Client Error: Not Found ...'}
RUN2 quota_aborted: False  cancelled: False
```

即 `set(result.failures) - set(result.requested) == {'AMZN'}`。这违反 `AcquisitionResult` 自己的 docstring（“What ONE programmatic run did”），并且 `coverage` 字段只覆盖 `requested`，两个字段自此不再可对齐。

运维面上的直接后果，在 `ingest_us_equity.py:533-536`：

```
print(f"{len(result.succeeded)} symbol(s) succeeded, {len(result.failures)} failed")
```

一次 `--symbols AAPL` 的冒烟跑，在一个曾经全市场回填留下 400 个真实 404 的 store 上，会打印 `1 symbol(s) succeeded, 400 failed`。任何以 `result.failures` 为门禁的控制台 / CI 判据，从此在这个 store 上永远不会再变绿。

全量测试通过 —— 说明**没有任何测试在断言「本轮结果只描述本轮」**，这个回归是裸的。

**Fix:** 把「磁盘清单的耐久性」和「结果对象的本轮语义」拆成两个 dict，别让一个变量同时承担两种含义：

```python
        # 磁盘清单：耐久，吸收本轮没消息的旧条目
        manifest = dict(failures)
        self._merge_unattempted_failures(
            manifest, attempted=all_succeeded | set(failures)
        )
        self._write_failure_manifest(manifest)

        self.last_result = AcquisitionResult(
            vendor=self.VENDOR,
            requested=tuple(requested),
            succeeded=tuple(sorted(all_succeeded)),
            # 本轮自己的消息，不含从磁盘折回来的旧条目
            failures=dict(failures),
            ...
        )
```

这会打破 `set(result.failures) == set(_failures.json)` 这条等式 —— 但 03.4-08 自己已经在注释和文档里把这条等式降级为「回执，不是正确性检查」，正好可以顺势改成更强的两条断言：`set(result.failures) ⊆ set(requested)`，以及 `set(_failures.json) ⊇ set(result.failures)`。需要同步更新 `tests/test_acquisition_progress.py::test_result_and_manifest_agree`、`example/acquisition.md:196-200`、`example/registry.md:551-557`。

若坚持保留等式，退而求其次的最小修法是给 `_merge_unattempted_failures` 加一个 `scope=set(requested)` 参数，只把 scope 内的旧条目折回 `failures`，scope 外的条目**单独**并入写盘用的 dict —— 本质仍是上面的两 dict 拆分，只是藏在方法内部。

## Warnings

### WR-01: 被合并保留的条目没有任何清理路径，会永久淤积

**File:** `quantlab/base/acquisition.py:2044-2154`

**Issue:** 一条失败条目只有在「该符号重新进入 `pending` 并且成功」时才会被清除（`attempted` 排除 `all_succeeded`）。而 03.4-08 之后，**永久离开 roster 的符号**（退市后 `get_symbols_in_range` 随窗口移动不再返回它、或运维把它从 universe 里删了）再也不会进入任何一轮的 `requested`，其条目就永远留在清单里，只能手工删文件。docstring 只点名了 `--stamp-legacy-watermarks` 这一种情形，漏掉了 roster 变更这条更常见的路径。

连带影响：`example/acquisition.md:214-219` 的四态表把「抓取失败」定义为「边车文件无 + 清单条目有」，是互斥的。合并放大后，「边车有 + 清单条目也有」变成可达状态（手工 stamp 或跨 roster 遗留），表已经不完整。`quantlab/acquisition/inspector.py:309` 的 `"failures": len(self.failures(config))` 也因此会把陈旧条目算进运维面板的失败数。

**Fix:** 给条目加一个可判定的过期规则，或至少给运维一条命名的清理路径。最小可行：在 `_write_failure_manifest` 之外加一个 `prune_failures(symbols)` 显式方法（与 `stamp_watermarks` 同一种「用户显式提供、代码绝不猜」的形状），并在 `ingest_us_equity.py` 暴露成一个开关；同时把四态表改成「边车文件」与「清单条目」两个正交维度，而不是四行互斥列表。

### WR-02: 折回的条目会触发一句事实错误的 WARNING 日志

**File:** `quantlab/base/acquisition.py:2142-2148`

**Issue:** `_write_failure_manifest` 在 `if failures:` 分支里播报：

```
f"{len(failures)} symbol(s) failed and were skipped; first {len(sample)}: {sample}. "
f"Full manifest: {path}. They have no watermark, so the next run retries them."
```

合并之后 `failures` 里可能全部是**本轮根本没碰过**的旧条目。于是一次零失败的 run 会在 stderr 上打出 `1 symbol(s) failed and were skipped`（我在探针里实测到了这一行）。最后半句「They have no watermark, so the next run retries them」对于「已被手工 stamp」或「已离开 roster」的条目是假的 —— 下一轮不会重试它们。

**Fix:** 采纳 CR-01 的两 dict 拆分后，这句日志只对本轮的 `failures` 播报；折回的条目另起一句、用不同措辞，例如：

```python
        if failures:
            ...  # 本轮失败，措辞不变
        carried = set(manifest) - set(failures)
        if carried:
            logger.info(
                f"{len(carried)} earlier failure(s) were carried over untouched "
                f"-- this run had no news about them. Manifest: {path}."
            )
```

### WR-03: 清单的「读-改-写」不是原子的，并发 run 现在每条出口都会竞争

**File:** `quantlab/base/acquisition.py:1483-1486`、`quantlab/base/coverage.py:259-294`

**Issue:** `write_json_atomically` 保证的是**单次写入**的原子性，不是 read-modify-write 的原子性。`_merge_unattempted_failures` 先读盘、再改内存、最后覆盖写，中间没有任何锁。03.4-08 之前只有取消路径走这条 RMW，属于罕见；现在**每一条出口**都走，于是共享同一个 `watermark_path` 的两个进程（例如同时跑一个 `refresh` 和一个补窗口的 `download`，两者 vendor/frequency 相同）必然互相覆盖：后写者会复活先写者刚清掉的条目，或抹掉先写者刚记录的失败。

**Fix:** 至少把这个风险写进 `_write_failure_manifest` 的 docstring 与 `example/acquisition.md`，声明「同一 `watermark_path` 下不得并发跑两个 acquisition」；若要真正修，用 `quantlab/utils/atomic.py` 旁边加一个基于 `os.open(..., O_CREAT | O_EXCL)` 的 `{watermark_root}/_failures.lock` 文件锁，包住「读清单 → 合并 → 写清单」整段。

### WR-04: 新测试里的「从未被请求」守卫无法生效，是空守卫

**File:** `tests/test_acquisition_progress.py:943-948`

**Issue:** 测试用一个内嵌 `assert` 来「证明」`AMZN` 从未被请求：

```python
    def exhausted(self, ticker, **kwargs):
        assert ticker != permanent, (
            f"{permanent} was requested by the aborting run; ..."
        )
        raise quota
```

两个问题：

1. **它永远不可能触发。** run 2 的 config `symbols=("NFLX", "NVDA", "TSLA")`，`_run` 用的是 `symbols or self.config.symbols`，`AMZN` 不在其中，按构造就到不了 vendor。
2. **即便触发也不会红成它想要的样子。** `_attempt_batch`（`quantlab/base/acquisition.py:1918`）用 `except Exception` 全捕获，`AssertionError` 是 `Exception` 的子类，会被吞掉并降级成 `"failed"` 状态；这条精心写的诊断消息永远不会出现在测试输出里，取而代之的是后面 `after[permanent] == recorded_reason` 那条含义完全不同的失败。

docstring 里那句「"Never attempted" 由一个不触发的守卫证明」因此是不成立的 —— 它证明的是「按构造不可能」，不是「运行时被验证」。

**Fix:** 换成本文件已有的、真正有效的惯用法（`test_result_and_manifest_agree:854` 就在用）——断言 vendor 调用记录：

```python
    mock_tiingo_client.calls = []
    second.download()
    assert permanent not in {c["ticker"] for c in mock_tiingo_client.calls}, (
        f"{permanent} was requested by the aborting run; it must never be "
        f"attempted, or the run would have news about it"
    )
```

这条断言跑在测试线程上、不经过 `_attempt_batch` 的 `except Exception`，会如实红。

### WR-05: 「每一条出口都跑」不包含异常出口，`wait_for_quota` 场景下的 Ctrl-C 会丢掉整轮失败记录

**File:** `quantlab/base/acquisition.py:1470-1486`

**Issue:** 迁移后的注释宣称「so it runs on every way out of the resume loop」，并逐条列出五个 `break`。但它只覆盖 `break`，不覆盖**异常**。`_run_once` / `_partition_by_coverage` 抛出，或者最典型的——`wait_for_quota=True` 时 `self._sleep(wait_seconds)` 里挨了 `KeyboardInterrupt`（默认 3600s × 最多 3 次，运维手动打断是必然发生的事）——都会直接越过 `_merge_unattempted_failures` 和 `_write_failure_manifest`。此时上一轮的清单确实没被清空（这点是安全的），但**本轮已经发现的 404 全部丢失**，而崩溃后仍有记录正是这个文件存在的理由。

**Fix:** 把整个 `while True:` 包进 `try` / `finally`，让写盘落在 `finally` 里：

```python
        try:
            while True:
                ...
        finally:
            self._merge_unattempted_failures(
                failures, attempted=all_succeeded | set(failures)
            )
            self._write_failure_manifest(failures)
```

`AcquisitionResult` 的组装留在 `try` 之后不动（异常路径本来就没有结果可返回）。同时把注释里的「every way out」改成「every `break`, and via `finally` every exception too」，否则注释比代码承诺得多。
