# Phase 03.4: Code Review Report

**Reviewed:** 2026-09-08
**Depth:** standard
**Files Reviewed:** 30
**Status:** issues_found

## Summary

The registry, inspector, progress/cancel plumbing and atomic sidecar writer are unusually
well-reasoned, and the credential rule holds: nothing in the reviewed code returns, logs or
embeds a credential value, `scripts/download_stock_data_from_tiingo.py`'s historical leak is
gone, and both descriptors carry env var NAMES only. `_scrub` remains the single egress choke
point and `ProgressEvent.message` respects it. No injection, traversal or hardcoded-secret
vulnerability was found.

The defects that were found are concentrated where this phase added a NEW exit path to an
existing loop and did not re-audit the old ones:

- the cancel path got a failure-manifest merge; the quota-abort path — which is the DEFAULT
  path, since `wait_for_quota` is off — did not, and silently erases the previous run's
  failure reasons (CR-01);
- the reporter lifecycle is per-PASS while the resume loop is per-RUN, so a caller-supplied
  reporter is `close()`d and then written to again (WR-01);
- three documentation deliverables assert facts about `_failures.json` readers that the code
  in this same phase falsified (WR-06).

The test suite for this phase is genuinely adversarial (structural AST arms, socket bans,
identity-not-equality assertions, no skips/xfails), which is why the surviving defects are
all on paths the tests do not exercise: quota-abort + manifest, multi-pass reporters, and
non-symbol `KeyError`s out of `.sel()`.

## Critical Issues

### CR-01: The quota-abort exit path erases the previous run's failure manifest

**File:** `quantlab/base/acquisition.py:1429-1473` (merge at 1434, quota breaks at 1449/1456,
write at 1473)

**Issue:** `_merge_unattempted_failures` is wired ONLY into the `if cancelled:` branch.
Both quota-abort exits (`if not wait_for_quota: ... break` at 1449, and `if waits >= max_waits:
... break` at 1456) fall straight through to `self._write_failure_manifest(failures)` at 1473
with a `failures` dict that contains only what THIS run reached.

`_write_failure_manifest` overwrites, and `_run`'s `failures` starts empty on every call. So:

1. Run 1 backfills 15,000 symbols; 40 fail with a 404. `_failures.json` holds 40 entries.
2. Run 2 resumes, quota-aborts after 100 batches without ever dispatching those 40.
3. `_failures.json` is overwritten with `{}` — which `_write_failure_manifest`'s own docstring
   defines as "a meaningful statement that the last run was clean". That statement is false.

The 40 reasons are the ONLY record of why those symbols failed: watermarks record success, not
failure, and `SourceInspector.failures()` (the operator console's failure surface) reads
nothing else. This is exactly the failure mode `_merge_unattempted_failures`' docstring was
written to prevent — and its stated justification for the omission is wrong on the facts:

> "That was safe while every run either completed or quota-aborted, because such a run reaches
> (or explicitly declines to speak for) every symbol."

A quota-aborted run does NOT reach every symbol; it stops dispatching and returns `"skipped"`
for the remainder. `wait_for_quota` defaults to `False`, so this is the default behaviour of a
quota abort, not a corner case. It is also the exact scenario the phase's own history cites
(the 2026-09-06 Tiingo lockout).

Note the D-18 invariant `set(result.failures) == set(manifest)` still holds — both are built
from the same dict — so an invariant test cannot catch this. The manifest and the result are
consistently wrong together.

**Fix:** Move the merge out of the cancel branch so every exit path that did not attempt the
whole roster restores the entries it has no news about:

```python
            all_succeeded.update(succeeded)
            failures.update(pass_failures)
            if cancelled:
                logger.warning(...)   # keep the cancel-specific message here
                break
            if not aborted:
                break
            if not wait_for_quota:
                logger.warning(...)
                break
            if waits >= max_waits:
                logger.warning(...)
                break
            ...
        # ONE merge, covering cancel AND quota-abort AND max-waits: any exit that
        # left symbols unattempted must not speak for them.
        self._merge_unattempted_failures(
            failures, attempted=all_succeeded | set(failures)
        )
        self._write_failure_manifest(failures)
```

Add a test alongside `tests/test_acquisition_progress.py::test_result_and_manifest_agree` that
seeds a manifest, quota-aborts before reaching those symbols, and asserts the seeded entries
survive.

## Warnings

### WR-01: A caller-supplied reporter is `close()`d once per PASS, then written to again

**File:** `quantlab/base/acquisition.py:1638-1650` (`_run_once`'s `finally`), with the resume
loop at `1414-1471`

**Issue:** `_run_once` emits `run_finished` and calls `self._close_reporter()` in a `finally`.
`_run`'s resume loop can call `_run_once` up to `quota_max_waits + 1` times (default 4) for one
logical run. After pass 1, the reporter has been closed; pass 2 then emits `coverage`
(`_report_coverage`, line ~1420) and `run_started` into that same closed object, because
`_active_reporter` caches the resolved reporter and only `attach()` invalidates it.

This is invisible for `TqdmProgressReporter` (it rebuilds its bar on `run_started`) and for
`CallbackProgressReporter` (`close()` is the ABC's no-op), which is why the tests pass. It is
broken for the actual intended consumer: `registry.run()`'s docstring sells `reporter` as "the
console's two handles on a running acquisition", and a console reporter that owns a queue,
socket or file will be released mid-run and then written to. `ProgressReporter.close`'s own
docstring — "Release whatever `emit` acquired" — describes a run-scoped lifecycle, not a
pass-scoped one.

**Fix:** Keep `run_finished` per pass (it is a true statement about the pass) but move the
release to the run boundary:

```python
        finally:
            self._emit(ProgressEvent(kind="run_finished", ...))
            # NO _close_reporter() here -- `_run` owns the reporter's lifetime,
            # and its resume loop can call this method several times.
```

and in `_run`, wrap the `while True:` loop in `try/finally: self._close_reporter()`. Add a test
that runs two passes (quota abort + `wait_for_quota=True`) against a reporter recording
`close()` calls and asserts exactly one.

### WR-02: `browse_zarr` blames missing symbols for every `KeyError`, including ones from the time axis

**File:** `quantlab/acquisition/inspector.py:499-519`

**Issue:** `dataset.sel(symbol=listed, timestamp=slice(start_date, end_date))` can raise
`KeyError` for reasons other than an unknown symbol. Verified against the installed xarray:

```
>>> ds  # dims ('t', 'symbol'), no `timestamp`
>>> ds.sel(symbol=["AAPL"], timestamp=slice("a","b"))
KeyError: "'timestamp' is not a valid dimension or coordinate for Dataset with dimensions ..."
```

The handler unconditionally computes `missing = [s for s in listed if s not in known]`, which
is `[]` in that case, and raises:

> `...browse_zarr: the Zarr store at '/...' does not carry [] (requested ['AAPL']). The store
> carries 2 symbol(s).`

That message is self-contradictory and points the operator at a symbol problem that does not
exist, while hiding the real one (a store written with a different time dimension name — a
plausible outcome of a half-migrated or third-party store, which is exactly when someone
reaches for the read-only inspector).

**Fix:** Only re-raise as the symbol message when symbols are actually the cause:

```python
        except KeyError as exc:
            known = (
                {str(v) for v in dataset["symbol"].values}
                if "symbol" in dataset.coords
                else set()
            )
            missing = sorted(s for s in listed if s not in known)
            carried = int(dataset.sizes.get("symbol", 0))
            dataset.close()
            if not missing:
                # Not a symbol problem -- do not invent one.
                raise
            raise ValueError(...) from exc
```

### WR-03: `validate_symbols` uses `re.match` against a `$`-anchored pattern, so a trailing newline passes

**File:** `quantlab/base/coverage.py:595`

**Issue:** `_TICKER_PATTERN.match(text)` with `TRADEABLE_TICKER_PATTERN = re.compile(r"^[A-Z0-9]{1,7}(?:[.-][A-Z0-9]{1,2}){0,2}$")`. In Python, `$` also matches immediately before a
trailing newline. Verified:

```
>>> TRADEABLE_TICKER_PATTERN.match("AAPL\n")   # -> match
>>> TRADEABLE_TICKER_PATTERN.match("AAPL\nX")  # -> None
```

`"AAPL\n"` therefore passes the one control this function exists to be, and then becomes both a
filesystem path segment (`{watermark_root}/AAPL\n.json`, `symbol=AAPL\n/` under the raw root —
a second, permanently-diverged coverage record for the same ticker) and an element of the
comma-joined `symbols=` query value, where a bare LF is a request-smuggling primitive against
any non-`requests` transport a future vendor uses. It is not a traversal, but it is a hole in a
control whose docstring claims to close both trust boundaries, and this function was rewritten
and relocated by this phase.

**Fix:** `if not _TICKER_PATTERN.fullmatch(text):` (or change the pattern's `$` to `\Z`).
`fullmatch` is the safer edit because it stays correct if the anchors are ever dropped. Add
`"AAPL\n"` to the rejection cases in `tests/test_source_inspector.py::test_the_inspector_rejects_a_traversal_symbol`.

### WR-04: `ProgressEvent` is `frozen=True` but its `detail` dict is mutable, so the stated isolation guarantee is false

**File:** `quantlab/base/progress.py:108` (`detail: dict = field(default_factory=dict)`), claim
at `quantlab/base/progress.py:98-99`

**Issue:** The docstring states: "Frozen, so a reporter cannot mutate an event another reporter
is about to receive." `frozen=True` prevents attribute REBINDING only. `detail` is the field
that actually carries the payload (`coverage` counts, `batch_completed` status), and any
reporter can do `event.detail["pending"] = 0` or `event.detail.clear()` in place. With a
`CallbackProgressReporter` fan-out to several console subscribers, the first subscriber can
corrupt what the rest see — the precise scenario the sentence promises is impossible. The same
field also makes `ProgressEvent` unhashable at runtime despite `frozen=True` generating
`__hash__`.

**Fix:** Freeze the payload too, or downgrade the claim. Preferred:

```python
from types import MappingProxyType

    detail: Mapping = field(default_factory=lambda: MappingProxyType({}))

    def __post_init__(self):
        object.__setattr__(self, "detail", MappingProxyType(dict(self.detail)))
```

and keep `symbols` a tuple as it already is. If a mapping proxy is too heavy, at minimum amend
the docstring to say only the field bindings are frozen and that `detail` must be treated as
read-only by convention.

### WR-05: `ingest_us_equity.py` restates Tiingo's batch size as a literal while `ingest_tiingo.py` reads it off the descriptor

**File:** `ingest_us_equity.py:147` (`TIINGO_BATCH_SIZE = 1`), used at `ingest_us_equity.py:495`

**Issue:** `ingest_tiingo.py` passes
`batch_size=SOURCE.acquisition_cls.DEFAULT_BATCH_SIZE` to the volume guard and comments:

> "Read off the descriptor's acquisition class rather than restated here, so the guard and the
> fetcher cannot disagree about the batch size."

`ingest_us_equity.py` — the shell that runs the multi-hour 15.4k-symbol job the request ceiling
actually binds — hardcodes `TIINGO_BATCH_SIZE = 1` instead. If `TiingoAcquisition.DEFAULT_BATCH_SIZE`
ever moves (or a `batch_size` knob is added to this shell), the guard prices a fetch nobody is
about to issue, understating the request count by exactly that factor. Both files argue the
same reasoning; only one of them follows it. `test_every_argparse_default_that_named_a_vendor_class_now_reads_the_descriptor`
does not cover it because this is a module constant, not an argparse default.

**Fix:** Delete the constant and use the descriptor, matching the sibling shell:

```python
            batch_size=SOURCE.acquisition_cls.DEFAULT_BATCH_SIZE,
```

and extend the shells test to assert no shell defines a literal batch-size constant.

### WR-06: Two documentation deliverables assert that nothing under `quantlab/` reads `_failures.json`; this phase made that false

**File:** `example/acquisition.md:184-185`, `example/registry.md:656-658`

**Issue:** Both say, in Chinese, "there is no code under `quantlab/` that reads this file". As
of 03.4-05 there are TWO readers, and `quantlab/base/coverage.py:read_failure_manifest`'s own
docstring says so explicitly ("the manifest now has TWO readers"):

- `quantlab/acquisition/inspector.py:188` — `SourceInspector.failures`
- `quantlab/base/acquisition.py:2027` — `Acquisition._merge_unattempted_failures`

`example/acquisition.md` then contradicts itself in the next sentence ("the only in-repo reader
is `SourceInspector.failures()`") and describes the cancel-path merge two sentences later
without noticing that the merge IS a read. `example/registry.md`'s pitfall 11 has the same
shape. The true statement — the one both files are reaching for — is that the manifest is not
RESUME input; resume is driven by watermark-sidecar presence.

**Fix:** In both files, replace the "no code reads it" clause with the accurate one, e.g.

> **它不是续跑输入。** 续跑完全由水位边车的**存在与否**驱动,清单从不参与那个判断。
> 仓库内有两个读者,都走唯一那个容错读取器 `CoverageLedger.read_failure_manifest`:
> `SourceInspector.failures()`(运维视图)和 `Acquisition._merge_unattempted_failures`
> (取消路径写清单前的合并)。

### WR-07: `registry.run()` declares a non-optional return type but returns `Optional`

**File:** `quantlab/acquisition/registry.py:309` (`-> AcquisitionResult:`), `:356`
(`return acquisition.last_result`)

**Issue:** `Acquisition.last_result` is declared `AcquisitionResult | None` and is `None` until
`_run` completes. `run()` promises `AcquisitionResult`. Today the only two `download()`/`refresh()`
implementations always set it, so the annotation is a claim the type system cannot check and a
third vendor (or an overridden `download()`) breaks it into an `AttributeError` at the call
site — `ingest_alpaca.py`, `ingest_tiingo.py` and `ingest_us_equity.py` all immediately do
`len(result.succeeded)` with no guard.

**Fix:** Make the contract explicit rather than assumed:

```python
    result = acquisition.last_result
    if result is None:
        raise RuntimeError(
            f"{type(acquisition).__name__}.{'refresh' if refresh else 'download'}() "
            f"returned without setting `last_result`. Every entry point must route "
            f"through `Acquisition._run`, which is what builds the result from the "
            f"same accumulated failures the manifest receives (D-18)."
        )
    return result
```

## Info

### IN-01: `EVENT_KINDS`' comment claims exhaustiveness for a kind that is never emitted

**File:** `quantlab/base/progress.py:58-71`

**Issue:** The comment reads "Every `ProgressEvent.kind` the acquisition loop emits ... exhaustive
as of 03.4-05", but `batch_failed` is emitted nowhere (`grep` finds it only in the tuple and in
the `ProgressEvent` docstring, which honestly calls it "reserved"). `example/registry.md` gets
this right ("保留未用"); the source comment does not. A console author reading the tuple will
write a `batch_failed` handler that never fires. Note `_run_once` already destructures
`_batch_message` and discards it at the exact point such an event would be emitted.

**Fix:** Either emit it (`if batch_status == "failed": self._emit(ProgressEvent(kind="batch_failed", ..., message=_batch_message))` — the message is already `_scrub`bed) or amend the comment to
"every kind this module DEFINES; `batch_failed` is reserved and currently unemitted."

### IN-02: Unused descriptor fields and an API surface with no in-repo production caller

**File:** `quantlab/acquisition/registry.py:84`, `:86`, `:132`, `:134`, `:184`, `:287`

**Issue:** `Capability.earliest_available` and `Capability.entitlement` are never set on either
descriptor and never read anywhere in `quantlab/`, `tests/` or the shells.
`SourceDescriptor.universe_categories`, `SourceDescriptor.supports()`, `credential_status()`
and `DataSourceRegistry.all()` are set/exercised only by tests, never by production code. This
is deliberate (ROADMAP D-12 targets the out-of-repo console) and is documented as advisory, so
it is recorded rather than objected to — but `earliest_available`/`entitlement` are the two
that have no consumer at ALL, not even a descriptor that populates them, and are therefore
indistinguishable from speculative generality.

**Fix:** Either populate `earliest_available` on the four Alpaca capabilities and the Tiingo one
(the values are public vendor facts) so the field is at least a live declaration, or drop the
two fields until the console asks for them — `Capability` is documented as extensible by adding
optional fields, so removing them costs nothing later.

### IN-03: `write_json_atomically` changes file permissions and does not fsync the destination directory

**File:** `quantlab/utils/atomic.py:69-90`

**Issue:** Two side effects of the extraction that the docstring's "byte-identical output"
claim does not cover:

1. `tempfile.NamedTemporaryFile` creates with mode `0600`. The replaced `open(path, "w")`
   created with the umask default (typically `0644`). Every rewritten watermark, ledger and
   manifest silently loses group/other read — benign on a single-user laptop, surprising on a
   shared workstation or in a container running as a different UID for reads.
2. `os.fsync(handle.fileno())` makes the DATA durable; the parent directory entry created by
   `os.replace` is not fsynced. The stated contract ("either the previous valid file or the new
   one") still holds, so this is not a defect — but the docstring's power-loss reasoning is
   incomplete as written.

**Fix:** After `os.replace`, add `os.chmod(destination, 0o644 & ~current_umask)` — or simpler,
`os.chmod(handle.name, 0o666 & ~umask)` before the replace — and note the directory-fsync
omission explicitly in the docstring so the next reader does not assume it is there.

### IN-05: Documentation embeds a developer-specific absolute path in copy-pasteable commands

### IN-06: `AcquisitionResult.coverage` always classifies as a download, even for a refresh

**File:** `quantlab/base/acquisition.py:1481` (`coverage=self.coverage_report(requested)`),
`:1707-1731` (`coverage_report` hardcodes `from_watermark=False`)

**Issue:** `refresh()` partitions with `from_watermark=True`, which short-circuits to the
end-date rule alone. The result object it returns reports a partition computed with
`from_watermark=False`, so a refresh's `result.coverage` can show `widened` / `legacy` counts
for symbols the run deliberately did not treat that way. A console rendering
`result.coverage` after a refresh shows a classification the run never used.

**Fix:** Thread the mode through: `coverage=self.coverage_report(requested, from_watermark=from_watermark)`,
adding the keyword to `coverage_report` with a `False` default so existing callers
(`SourceInspector.coverage`, the dry run) are unchanged.

### IN-07: `quota_aborted` can be reported `True` for a run that finished cleanly on a later pass

**File:** `quantlab/base/acquisition.py:1414-1424`, `:1480`

**Issue:** `aborted` is assigned from `_run_once` but the `if not pending: break` at the top of
a subsequent pass exits without reassigning it. A pass-1 quota abort that nonetheless completed
every remaining symbol leaves `pending` empty on pass 2, breaks there, and reports
`quota_aborted=True` on a run that succeeded in full.

**Fix:** Reset `aborted = False` (and `cancelled = False`) at the top of each loop iteration,
before the `pending` computation.

### IN-08: Cross-module reach into a private method, and a doubled `exists()` check

**File:** `quantlab/acquisition/inspector.py:446` (`reader._scan_raw(...)`), `:251` and `:295`

**Issue:** (a) `browse_raw` calls `StockDataset._scan_raw`, a single-underscore private, from
another package. The docstring argues at length that reusing it is correct — that argument is
accepted — but the coupling is unmarked on the `StockDataset` side, so `_scan_raw` reads as
freely refactorable. (b) `_raw_inventory` calls `root.exists()` at line 251 and again at 295 for
the returned dict; a root created or removed between them yields `shards > 0` alongside
`"exists": False`.

**Fix:** (a) Promote `_scan_raw` to `scan_raw` with a `_scan_raw` alias, or add a comment on
`StockDataset._scan_raw` naming `SourceInspector.browse_raw` as an out-of-package consumer.
(b) Hoist `root_exists = root.exists()` once and use it in both places.

### IN-09: Re-importing a vendor module raises at import time

**File:** `quantlab/acquisition/registry.py:253-261`

**Issue:** `register_source` raises `ValueError` on a duplicate vendor, and registration happens
at module-body execution. `importlib.reload(quantlab.acquisition.tiingo)` — used by
auto-reloaders, some notebook workflows, and coverage tooling — therefore fails with
"vendor 'tiingo' is already registered". Refusing a genuine second descriptor is correct
(D-01); crashing on a reload of the same one is not the case the rule is defending against.

**Fix:** Make re-registration of the IDENTICAL descriptor idempotent while keeping the
collision refusal:

```python
    for existing in DataSourceRegistry.SOURCES:
        if existing.vendor == descriptor.vendor:
            if existing == descriptor:
                return existing  # module reload: same descriptor, not a collision
            raise ValueError(...)
```

(`SourceDescriptor` is a frozen dataclass, so `==` is field-wise; a reloaded module produces a
NEW `acquisition_cls` object, so this needs `existing.vendor == descriptor.vendor and
existing.display_name == descriptor.display_name and existing.capabilities == descriptor.capabilities`
or an explicit reload guard. Choose whichever, but decide it deliberately rather than leaving
reload broken by accident.)
