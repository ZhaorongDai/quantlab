### Locked Decisions

Copied verbatim from `.planning/phases/03.4-data-source-registry/03.4-CONTEXT.md`. **D-01..D-20 are
the requirement IDs for this phase.**

#### Descriptor key and field set

- **D-01:** ONE descriptor per **vendor**, carrying a capability list inside — *not* one descriptor
  per `(vendor, market, frequency)` triple. Vendor-level facts (credentials, quota, rate limits)
  are stated once. Consequence the planner must handle: `market × frequency` is **not** a full
  cross-product (Alpaca `tick` is `us_equity`-only), so validity is expressed by the capability
  list itself, never by a cross-product of two flat tuples.
  — **Reversibility:** costly — re-keying the registry after the console consumes it changes every
  enumeration call site in a second repository.

- **D-02:** Capabilities are **small dataclasses**, not bare tuples and not nested dicts. Each
  capability names at least `market` / `frequency` / `data_type`, and is extensible (asset class,
  earliest available date, entitlement required). It must express: Alpaca = `us_equity` at `1d`,
  `1m`, and `tick`, where `tick` splits further into `quotes` and `trades`
  (`AlpacaAcquisition.TICK_DATA_TYPES`, each with its own `ENDPOINT_MAP` entry); Tiingo =
  `us_equity` at `1d` only.

- **D-03:** The descriptor points at its acquisition class and config factory by **direct class
  reference**, matching `UniverseCatalog.MEMBERSHIP_FETCHERS`. **Accepted cost, recorded
  deliberately:** importing the registry imports every vendor SDK, because
  `quantlab/acquisition/tiingo.py:4` is `from tiingo import TiingoClient` at module level and
  `alpaca.py` imports `requests`. Both are already hard quantlab dependencies, so this is an import
  cost, not a fragility. The alternative (dotted path + `utils/module.py:get_cls_from_path`, the
  idiom `Acquisition.import_path` already uses) was considered and rejected.

- **D-04:** Credentials — the descriptor declares env var **names** (e.g.
  `REQUIRED_ENV = ("TIINGO_API_KEY",)`); the registry provides ONE shared `is_configured` check
  reading `os.environ` for presence-and-non-empty. It never returns a value. This repository has a
  real leaked-key incident in its history (Phase 1), and the constraint is absolute.
  **Planner must add** a test pinning the descriptor-declared names against the acquisition class's
  own credential check, because the name now appears in two places.

#### Where descriptors live, and how they register

- **D-05:** Descriptors are **independent dataclass instances** held in a registry tuple — not
  class attributes on the `Acquisition` subclass. Rationale: those subclasses are already heavy
  (`RAW_SCHEMA`, `QUOTA_STATUS_CODES`, `LEGACY_WATERMARK_POLICIES`, `FIELD_MAP`, `TIMEFRAME_MAP`,
  `ENDPOINT_MAP`, `RAW_COLUMNS_BY_DATA_TYPE`, …), and separating "who I am" from "how I download"
  lets one acquisition class carry several descriptors later (e.g. alpaca paper vs live).

  **NOTE FOR PLAN-CHECKER — do not flag:** this is a tuple of *instances* where
  `UniverseCatalog.MEMBERSHIP_FETCHERS` is a tuple of *classes*. That difference in element type is
  deliberate and developer-approved. It is still ONE class-level registration tuple, not a second
  registry style, so it does not violate the ROADMAP's "do not invent a second registry style".

- **D-06:** Registration happens via a **decorator** (`@register_source`) applied at descriptor
  definition, so defining a source registers it and it cannot be forgotten. Chosen over a
  hand-maintained tuple even though the repo has **no decorator-registration precedent** today.
  Consequences the planner owns: test isolation for a global mutable registry, and enumeration
  order (import order vs sorted) — both have well-known correct answers and were left to planning.

- **D-07:** Enumeration completeness is guaranteed by `quantlab/acquisition/__init__.py` explicitly
  importing every vendor module. **This is the first non-empty `__init__.py` in the repo** — the
  established convention is empty `__init__.py` with full dotted imports and no re-exports — and is
  an accepted, deliberate exception, because a decorator-populated registry is only as complete as
  the set of modules that have been imported.

#### Read-side query surface

- **D-08:** The read surface is a **new read-only inspector class**. Hard constraint driving this:
  it must run on a machine with **no credentials**, because it only reads locally downloaded data.
  Evidence: `TiingoAcquisition(config)` raises `RuntimeError("TIINGO_API_KEY")` at construction
  (`tests/test_tiingo_acquisition.py:65`), so any surface that constructs an `Acquisition` is
  unusable for browsing on an unconfigured machine. Extending `Acquisition` and deferring the
  credential check was considered and rejected — it would turn a fail-fast safety behaviour into
  fail-late.

- **D-09:** **Binding constraint:** the ROADMAP explicitly values that `coverage_report()` SHARES
  `_partition_by_coverage` with the real run. The inspector MUST NOT re-implement coverage
  judgement. *That* the logic is shared is locked; *how* it is extracted is the planner's call.

- **D-10:** Row-level browsing returns a **lazy object** (`pl.scan_parquet` + hive pruning for the
  raw tier), not a materialised page. The caller decides when to collect.

  **DEVELOPER OVERRIDE — do not flag:** the ROADMAP says "any surface that can be asked for a whole
  tier at once is the wrong surface". A lazy object technically permits that. The developer chose
  lazy anyway and closed the risk from the other side, in D-11.

- **D-11:** `symbols` **and** a date range are **REQUIRED** arguments on the lazy read — not
  optional. This guarantees hive pruning happens and that the lazy object is already narrow when
  handed out; asking for a whole tier then requires deliberately passing the full roster.
  (`us_all` is ~15.4k symbols × ~5.2k trading days, ~30M rows.)

#### Write path — CONTRACT CHANGE

- **D-12:** **This supersedes the ROADMAP's locked 2026-09-07 boundary contract.** WRITES no longer
  go through a subprocess CLI invocation. The console calls quantlab **in-process** for writes as
  well as reads.
  — **Reversibility:** one-way — the ROADMAP's "exported command IS what the console runs"
  guarantee is destroyed by this change and cannot be recovered without reinstating a CLI the
  console spawns; a second repository will have been built against the in-process API by then.

  **ACTION REQUIRED OUTSIDE THIS DOCUMENT:** the ROADMAP 03.4 boundary-contract bullet still states
  the subprocess rule. It must be **rewritten**, not left standing in contradiction.

- **D-13:** Consequence the developer explicitly accepted: long-running-task isolation — keeping a
  multi-hour backfill from blocking the TUI — moves ENTIRELY to the `quantlab-console` repo (a
  thread/process pool or job queue there). It is out of this roadmap.

- **D-14:** This phase delivers a **programmatic write entry point** (e.g. a registry-level
  `run(descriptor, config)`) that the console calls directly in-process.

- **D-15:** The three ingest scripts (`ingest_tiingo.py`, `ingest_us_equity.py`,
  `ingest_alpaca.py`) are **reduced to thin shells** over that entry point — kept, not deleted, and
  not evolved further. They stop being a human-facing surface (the TUI becomes that) but remain:
  (a) the registry's in-repo consumer, which is exactly what the ROADMAP's anti-rot requirement
  demands ("so the registry has a first consumer IN THIS REPO and cannot rot into a console-only
  side table"), (b) live proof the programmatic entry point works, (c) a fallback for running a
  backfill on a machine with no TUI.

  **SUPERSEDED:** an earlier answer in this same discussion chose "merge into one
  `ingest.py --source`". The thin-shell decision replaces it. **Do not build a merged CLI.**

  **Planner must verify:** `ingest_tiingo.py` already supports `--universe us_all`, so
  `ingest_us_equity.py` may already be largely redundant. Check before preserving both shells.

#### Progress, cancellation, results, logging, concurrency

- **D-16:** Progress is delivered as **event objects through a pluggable reporter** — define a
  progress event type plus a reporter abstraction (a tqdm-backed reporter as the default, a
  callback reporter for the console). Today `_run` renders `tqdm(..., desc=f"{self.VENDOR} …")` to
  stderr and logs through loguru; neither is consumable by an in-process caller, and tqdm's cursor
  control fights a Textual screen.

- **D-17:** Cancellation is a **separate cancel token** (e.g. `threading.Event` / a `CancelToken`)
  checked at **batch boundaries** — not folded into the reporter's return value. Completed batches
  land normally and advance the watermark, then the run exits cleanly, so a cancelled run stays
  resumable. Rationale for keeping it separate: a reporter that only wants to log must not be able
  to stop an acquisition by forgetting to return `True`. This gap is created by D-12 — under the
  old subprocess contract, cancelling was `kill`.

- **D-18:** The programmatic entry point **returns a result object** (successes, failures, reasons,
  whether it was cancelled, resulting coverage) **and** keeps writing `_failures.json`
  (`FAILURE_MANIFEST_NAME`) as it does today. Two outputs on purpose: the in-process caller gets
  the outcome without reading disk, and the manifest survives a crash. `_failures.json` is also
  resume input today, so it is not removable. The planner must keep the two consistent.

  > **Researcher correction — see Landmine L-4.** The clause "`_failures.json` is also resume input
  > today" is **factually false about the current code**. Nothing in `quantlab/` reads it. The
  > decision to keep writing it still stands (crash-durable operator record, and the inspector's
  > "failure reasons" source per D-08), but the plan must not be built on the resume claim.

- **D-19:** Logging stays as it is — **the console installs its own loguru sink**; quantlab does not
  grow a scoped log handle for an out-of-repo consumer. Accepted cost: the console receives global
  logs including unrelated modules, and concurrent acquisitions interleave.

- **D-20:** Concurrency/re-entrancy is **the console's task queue's responsibility**. quantlab adds
  no lock on concurrent acquisition of the same source.
  — **Reversibility:** reversible — a file lock can be added later if corruption is observed.

  **Flagged risk, developer-accepted:** the guarantee lives in another repository while the
  data-corruption consequence lives in this one, and the thin-shell scripts (D-15) run outside any
  console task queue, so a shell and the console can still overlap. A pre-planning check of whether
  watermark/sidecar writes are already atomic (temp-file + rename) would tell us how much this
  actually matters.

  > **Researcher answer — see Landmine L-5.** They are **NOT** atomic. Measured below.

## Summary

This is an **internal refactor of a mature, heavily-documented layer**, not an integration. The
`Acquisition` ABC (`quantlab/base/acquisition.py`, 1832 lines) already owns everything the phase
needs to expose: concurrent batch orchestration, coverage partitioning, failure isolation, a global
abort event, watermark sidecars and a failure manifest. Two concrete vendors implement it. The work
is (a) putting a descriptor layer in front of those two classes, (b) extracting the *credential-free*
half of the coverage logic so a no-credential inspector can call it, (c) threading a reporter and a
cancel token through the existing `_run` → `_run_once` → `_attempt_batch` chain at the exact
positions the existing abort already uses, and (d) collapsing the three ingest scripts onto the new
entry point. **No new third-party package is required.**

Three findings materially change the plan shape versus what CONTEXT.md assumed:

1. **`_failures.json` is not resume input.** Nothing in `quantlab/` reads it — resume is driven
   entirely by the presence/absence of watermark sidecars. D-18's stated rationale is wrong; the
   decision to keep writing it is still right for a different reason.
2. **Watermark and failure-manifest writes are NOT atomic** (plain `open(path, "w") + json.dump`),
   while `PageLedger._flush` and `ChunkLedger._flush` *are* (temp-file + `fsync` + `os.replace`).
   The in-repo precedent to copy already exists, 30 lines away.
3. **D-07's letter has collateral damage its rationale does not intend.** A non-empty
   `quantlab/acquisition/__init__.py` runs on *every* `import quantlab.acquisition.<anything>`,
   including `quantlab.acquisition.universe` — the module whose entire structural guarantee
   (`tests/test_volume_guard.py`) is "no acquisition client can be constructed here, whatever the
   call order". The existing test stays green (it is an AST scan of `universe.py`'s own source), so
   this fails silently rather than loudly. The measured cost is negligible (~30-50 ms); the
   *property* is what erodes.

**Primary recommendation:** Build `quantlab/acquisition/registry.py` (descriptor dataclasses +
`@register_source` + `is_configured` + `run()`), extract a credential-free `CoverageLedger` that
both `Acquisition` and the new `quantlab/acquisition/inspector.py` compose, thread a
`ProgressReporter` + `CancelToken` through `_run`/`_run_once`/`_attempt_batch` reusing the
`_attempt_batch` first-statement check position, and keep all three ingest scripts — they are not
redundant (proven below). Make the vendor-module imports live at the **bottom of `registry.py`**,
not in `__init__.py`, unless the developer confirms the volume-guard erosion is acceptable.

| Capability | Primary Tier | Secondary Tier | Rationale |

| Batch orchestration / concurrency | `Acquisition` (`base/acquisition.py:1276 _run_once`) | joblib threading backend | Hoisted here by 03.2-03 D-02. Do not re-hoist upward. |

| Cancellation check | `Acquisition._attempt_batch` first statement (`:1635`) | `_run_once` input generator (`:1306`, optimisation only) | joblib cannot cancel queued work — the worker-side check is the guarantee, exactly as the quota abort already documents. |

| Zarr-tier row browsing | Inspector (`xarray` `.sel()`) | `XrBackend` | Zarr is the canonical transport format; use xarray, never Polars. |

### Pattern 1 — The descriptor and its capabilities (D-01, D-02)

```python
# quantlab/acquisition/registry.py
```

### Pattern 2 — Decorator registration with test isolation (D-06)

```python
class DataSourceRegistry:
    """Every acquirable data source, one descriptor per vendor.

    Populated by `@register_source` at descriptor-definition time, so defining a
    source registers it and it cannot be forgotten. This is the same ONE
    class-level registration tuple `UniverseCatalog.MEMBERSHIP_FETCHERS`
    (acquisition/universe.py:1249) establishes; the element type differs
    (instances, not classes) by deliberate decision 03.4-CONTEXT D-05.
    """

    SOURCES: tuple[SourceDescriptor, ...] = ()

    @classmethod
    def all(cls) -> tuple[SourceDescriptor, ...]:
        # SORTED by vendor, never import order: enumeration order becomes the
        # console's display order and must not depend on which module a caller
        # imported first.
        return tuple(sorted(cls.SOURCES, key=lambda d: d.vendor))

    @classmethod
    def get(cls, vendor: str) -> SourceDescriptor: ...


def register_source(descriptor: SourceDescriptor) -> SourceDescriptor:
    if any(d.vendor == descriptor.vendor for d in DataSourceRegistry.SOURCES):
        raise ValueError(
            f"vendor {descriptor.vendor!r} is already registered. One descriptor "
            f"per VENDOR (D-01) -- express a second market/frequency as another "
            f"Capability, not as a second descriptor."
        )
    DataSourceRegistry.SOURCES += (descriptor,)
    return descriptor
```

**Enumeration order — recommendation: `sorted` by vendor, not import order.** Import order is a
function of which module the caller touched first and is therefore not reproducible; the console
renders this list to a human. This also makes an assertion on `all()` a literal tuple comparison.

**Test isolation — the fixture the repo's own idiom implies.** `tests/conftest.py:39` already
carries an `autouse` fixture that snapshots and restores the process-level data-root override.
Mirror it:

```python
@pytest.fixture
def isolated_registry(monkeypatch):
    """Snapshot/restore DataSourceRegistry.SOURCES so a test may register a fake
    source without leaking it into every later test in the session."""
    from quantlab.acquisition.registry import DataSourceRegistry
    monkeypatch.setattr(
        DataSourceRegistry, "SOURCES", tuple(DataSourceRegistry.SOURCES), raising=True
    )
    yield DataSourceRegistry
```

`monkeypatch.setattr` on the class attribute is enough **because `SOURCES` is rebound (`+=` on a
tuple), never mutated in place** — which is itself the reason to keep it a tuple rather than a list.
Make that a stated invariant with a test, or the isolation silently stops working the day someone
switches to `list.append`.

### Pattern 3 — `is_configured`, the one shared credential check (D-04)

```python
def is_configured(descriptor: SourceDescriptor) -> bool:
    """Whether every env var this source NAMES is present and non-empty.

    Returns a BOOL. It never returns, logs, or embeds a credential VALUE, and it
    never requires one to be present in order to answer. This repository has a
    real leaked-key incident in its history (Phase 1) and an operator dashboard
    that prints an env var is how the next one happens.

    Presence-and-non-empty is exactly the predicate both vendors already enforce
    at construction -- `acquisition/tiingo.py:149` (`if not os.environ.get(KEY_ENV)`)
    and `acquisition/alpaca.py:97-99` (`if not key or not secret`) -- so a source
    this reports as configured is one whose client will construct.
    """
    return all(os.environ.get(name) for name in descriptor.required_env)


def credential_status(descriptor) -> dict[str, bool]:
    """Per-NAME presence, for an operator who needs to know WHICH one is missing.
    Values are booleans. There is no code path here that reads a value into a
    return, a log line, or an exception message."""
    return {name: bool(os.environ.get(name)) for name in descriptor.required_env}
```

### Pattern 4 — Progress events and the reporter (D-16)

```python
# quantlab/acquisition/progress.py
@dataclass(frozen=True)
class ProgressEvent:
    kind: str          # "run_started" | "coverage" | "batch_completed" |
                       # "batch_failed" | "quota_exhausted" | "cancelled" | "run_finished"
    vendor: str
    completed: int = 0
    total: int = 0
    symbols: tuple[str, ...] = ()
    message: str | None = None    # ALWAYS pre-scrubbed by Acquisition._scrub
    detail: dict = field(default_factory=dict)


class ProgressReporter(ABC):
    @abstractmethod
    def emit(self, event: ProgressEvent) -> None: ...
    def close(self) -> None: ...     # concrete no-op default; tqdm closes its bar


class TqdmProgressReporter(ProgressReporter):
    """The DEFAULT, byte-compatible with today's bar: same total, same
    `f"{vendor} {start}..{end}"` description, same `unit="batch"`, same
    `disable=not config.kwargs['progress']` honouring."""


class CallbackProgressReporter(ProgressReporter):
    """What the console passes: `emit` forwards to a caller-supplied callable."""


class NullProgressReporter(ProgressReporter):
    """Emits nothing. What `progress=False` resolves to, and what every test
    that is not testing progress should use."""
```

Threading it in (minimal diff at `base/acquisition.py:1327-1352`): `_run_once` constructs no `tqdm`
directly; it calls `reporter.emit(ProgressEvent("batch_completed", …))` inside the existing
`for result in stream:` loop, and `reporter.emit(ProgressEvent("quota_exhausted", …))` where
`bar.set_description(...)` is today. `TqdmProgressReporter` reproduces the current stderr rendering,
so the observable default behaviour is unchanged.

**Where the reporter is stored matters.** It must NOT go on `AcquisitionConfig` — `to_dict()` is
`asdict(self)` and lands in persisted configs (`base/config.py:132-138`). Pass it as a call argument
to `download()`/`refresh()`/`run()`, or set it on the instance (`self._reporter`) with a
`NullProgressReporter` default, matching how `_abort_event` and `_no_data_marks` are already
instance state.

**A reporter must never be able to raise into the run.** A console callback that throws would tear
down `_run_once`'s result loop and abort a multi-hour backfill for a UI bug. Wrap
`reporter.emit(...)` in a `try/except Exception: logger.warning(...)` at the call site, in exactly
the spirit of `_attempt_batch`'s "never raises" contract.

### Pattern 5 — Cancellation at a batch boundary (D-17)

```python
# In Acquisition, beside `_abort` (:478)

@property
def _cancel(self) -> threading.Event:
    """The CALLER's stop flag, distinct from `_abort`.

    Separate from the quota abort on purpose and in both directions:
    `_abort` means "the vendor stopped us", `_cancel` means "the operator
    stopped us". They demand opposite follow-ups -- `_run`'s resume loop
    WAITS on a quota abort (`wait_for_quota`) and must NOT wait on a cancel,
    and `_run_once` logs "Vendor request allocation exhausted" on the first,
    which would be a lie about the second.
    """


def _should_stop(self) -> bool:
    return self._abort.is_set() or self._cancel.is_set()
```

`_attempt_batch` (`:1635`) becomes `if self._should_stop(): return list(symbols), "skipped", None`
— **same first statement, same return arity, same `"skipped"` status**, so the two existing tests
that unpack the 3-tuple stay green. `_run_once`'s `inputs()` generator (`:1306`) likewise switches
to `_should_stop()` and stays an optimisation.

`_run_once` returns a 4th element (or a small dataclass) so `_run` can distinguish:

```python
if cancelled:
    logger.warning(
        f"Cancelled at a batch boundary. {completed} symbol(s) completed and "
        f"their watermarks are on disk; the remainder was never attempted and "
        f"has no watermark, so a re-run resumes exactly here and re-downloads "
        f"nothing."
    )
    break                    # NOT the quota branch: no wait, no resume attempt
```

**Why a cancelled run is resumable — the mechanism, stated precisely:**
1. `_attempt_batch` writes each symbol's watermark **only after** a successful `_fetch_batch`
   (`:1738-1770`), so a batch that never ran leaves no sidecar.
2. `_partition_by_coverage` (`:1519`) re-derives `pending` **from the sidecars on disk** on every
   pass and every subsequent run — there is no separate bookkeeping to drift.
3. Inside a batch, `PageLedger` records each completed page atomically **before** the next request
   (`base/pageledger.py:423-450` — temp file + `fsync` + `os.replace`), and shard names are
   deterministic (`_shard_path`, `:828`), so even an in-flight batch resumes at page granularity
   with an overwrite rather than a duplicate.
4. Batches already in flight when cancel is set **complete normally** (up to `max_workers` of them)
   — that is the definition of "at a batch boundary", and it is what makes their watermarks honest.

### Anti-Patterns to Avoid

- **A second coverage implementation.** Any `if last_date == end_date` or `start_date <=
  config.start_date` comparison written outside `_classify_coverage` is the D-09 violation. The
  four-state rule (`uncovered`/`covered`/`widened`/`legacy`) plus the orthogonal `no_data` count is
  subtle enough that a "simple" reimplementation will get `legacy` wrong.
- **A registry that carries a field only some members can populate.** `UniverseCatalog`'s own
  comment (`universe.py:1259-1270`) is the precedent: a roster has no `PIT_COVERAGE_START`, so it
  lives in a different registry. Here the equivalent is per-capability data (`data_type`,
  `earliest_available`) — put it on `Capability`, never on `SourceDescriptor`.
- **Reporter or cancel token on `AcquisitionConfig`.** `to_dict()` is `asdict(self)` and the result
  lands on disk beside model checkpoints. A `threading.Event` is not serialisable and a reporter is
  not reproducible config.
- **Reusing `_abort` for cancellation.** It would trigger the quota-wait branch and the "Vendor
  request allocation exhausted" log line, both lies about an operator cancel.
- **`extra_columns="ignore"` / `missing_columns="insert"` on any new `scan_parquet`.** The raising
  default is the structural half of the vendor-isolation guarantee (`dataset/stock.py:315-322`).
- **A merged `ingest.py --source` CLI.** Explicitly superseded by D-15.
- **Adding a `Vendor` literal.** Not needed — both vendors already exist. Adding one commits to an
  on-disk path segment (`enums/data.py:88-93`).

## Common Pitfalls

### Pitfall 1: Reusing `_abort` for cancellation
**What goes wrong:** cancel trips the quota path — `_run` logs "Vendor request allocation
exhausted", and with `wait_for_quota=True` it sleeps an hour and resumes the run the operator just
cancelled.
**Why it happens:** `_abort` is right there, already checked at the right place.
**How to avoid:** separate `threading.Event`, one `_should_stop()` helper, and a distinct return
signal from `_run_once` that `_run` handles with `break` and no wait.
**Warning sign:** a cancel test that asserts on watermarks but not on the absence of `_sleep` calls.

### Pitfall 2: Cancel check placed in the input generator only
**What goes wrong:** joblib has already queued every batch; the run keeps issuing vendor requests
until the queue drains.
**Why it happens:** the generator check reads like the natural place.
**How to avoid:** the guarantee is `_attempt_batch`'s FIRST statement (`:1635`). The code already
says so verbatim: "joblib cannot cancel work it has already queued, so this check -- not the input
generator -- is what actually stops the ~260 sym/s burn observed in the field."
**Warning sign:** a cancel test with `max_workers=1` or `batch_size` equal to the roster size —
neither can distinguish the two positions.

### Pitfall 3: The result object and `_failures.json` disagreeing
**What goes wrong:** D-18 demands both. `_run` merges failures across resume passes and pops
succeeded symbols (`:1229-1248`); a result object assembled from the last pass alone would report a
clean run that the manifest contradicts.
**How to avoid:** build the result from the SAME accumulated `failures` dict `_write_failure_manifest`
receives, at the same point (`:1273`), and add a test asserting `set(result.failures) ==
set(json.load(manifest))` after a multi-pass run.
**Warning sign:** the result assembled inside `_run_once` instead of `_run`.

### Pitfall 4: A cancelled run silently erasing the previous run's failure manifest
**What goes wrong:** `_write_failure_manifest` **overwrites**. `_run`'s `failures` starts empty each
call. A run cancelled before it reaches symbols that failed last time writes `{}` — and the
"an empty manifest means the last run was clean" contract in that method's docstring (`:1783`)
becomes false.
**Why it happens:** the merge logic protects against a *pass* erasing an earlier pass, not against a
*run* erasing an earlier run — which was fine while every run either completed or quota-aborted.
**How to avoid:** on the cancel path either (a) skip the manifest write entirely, or (b) merge the
existing on-disk manifest for symbols this run never attempted. Decide and state it; do not leave it
to whichever branch happens to execute.
**Impact bound:** correctness of *resume* is unaffected (see L-4) — this is a reporting defect only,
but it is a reporting defect in the file the console shows an operator.

### Pitfall 5: The inspector paying the roster cost on every call
**What goes wrong:** an inventory that reads every watermark sidecar takes **1.65 s for 7,756
sidecars** `[VERIFIED: measured this session on
data/downloads/us_equity/1d/us_all/_watermarks/tiingo]` — and a TUI that refreshes on every keypress
will feel broken.
**How to avoid:** decide caching deliberately (a CONTEXT discretion item). `du`-equivalent directory
traversal of the 26,584-file raw root cost **0.05 s warm** `[VERIFIED: measured]`, so disk footprint
is the *cheap* half and sidecar reading is the expensive half — the opposite of what CONTEXT
assumed. Recommend: no cache in quantlab (the console owns refresh policy), but *do* return the
figures from one traversal rather than one per field.
**Warning sign:** `inventory()` calling `_read_coverage` per symbol in a loop that a caller invokes
per symbol.

### Pitfall 6: `XrBackend.filter_by_date` / `filter_by_symbol` mutate in place
**What goes wrong:** they assign `self.data = self.data.sel(...)`
(`quantlab/dataset/backend.py:1038-1044`). An inspector holding one backend instance and answering
two queries narrows permanently — the exact class of bug quick task 260906-w3t fixed for
`FactorPolars` (recorded in STATE.md: "narrowing `data_backend.data` IN PLACE … made that narrowing
permanent").
**How to avoid:** the inspector opens the store per query (`xr.open_zarr` is 0.2 s and lazy), or
holds an unnarrowed dataset and applies `.sel()` to a local, never writing back.

### Pitfall 7: `.sel(symbol=[...])` raising on an unknown symbol
**What goes wrong:** `KeyError: "not all values found in index 'symbol'"`
`[VERIFIED: measured this session]`. An operator browsing a plausible ticker gets a traceback.
**How to avoid:** catch and re-raise with a message naming the store, the requested symbols and how
many the store carries — the house style everywhere else in this repo. Do **not** silently `reindex`
to NaN: a NaN column is indistinguishable from a genuinely empty history.

### Pitfall 8: Tick sidecars and tick scan roots are namespaced by `data_type`
**What goes wrong:** an inspector that ignores the namespacing reads quotes' watermarks while
browsing trades. STATE.md records this exact incident: "a completed quotes backfill told the trades
run every symbol was covered; it skipped the whole roster and reported success."
**How to avoid:** the inspector must reach `_watermark_root` (which applies `/{data_type}` when
`"data_type" in self._hive_keys`, `:147-166`) and `_scan_root` (which descends to
`data_type={quotes|trades}`, `dataset/stock.py:110-138`) through the shared code, not by
reconstructing paths.

### Pitfall 9: A reporter exception killing the run
**What goes wrong:** the console's callback raises; it propagates out of `_run_once`'s result loop
and tears down the fan-out — the failure mode `_attempt_batch`'s "Never raises" contract exists to
prevent, reintroduced one level up.
**How to avoid:** wrap every `reporter.emit(...)` in `try/except Exception: logger.warning(...)`.

### Pitfall 10: Unscrubbed messages reaching the result object or a progress event
**What goes wrong:** `_scrub` (`:530`) is the choke point that made the failure manifest safe to
paste into an issue. A result object or progress event carrying a raw exception string bypasses it —
and Tiingo's error text echoes back the full request URL, which carries the token as a query
parameter (that method's own docstring says so).
**How to avoid:** the result object's failure messages must be the SAME already-scrubbed strings
`_attempt_batch` produces (`:1676`). Add a test that sets a fake credential value in the environment,
forces a failure whose message contains it, and asserts the value appears in neither the result
object nor any emitted event.

### L-4 — Watermark and failure-manifest writes are **NOT** atomic; the ledgers **are**

| Writer | Anchor | Atomic? |
|--------|--------|---------|
| `Acquisition._write_watermark` | `base/acquisition.py:264-269` — `with open(path,"w") as f: json.dump(payload, f)` | **NO** |
| `Acquisition._write_failure_manifest` | `base/acquisition.py:1793-1796` — same shape | **NO** |
| `PageLedger._flush` | `base/pageledger.py:422-450` — `NamedTemporaryFile` in the same directory → `flush` → `os.fsync` → `os.replace`, with `unlink` on any exception | **YES** |
| `ChunkLedger._flush` | `base/chunking.py` — the original `PageLedger._flush` was copied from | **YES** |

This answers the ROADMAP's open question and D-20's flagged risk directly: **a shell and the console
overlapping on one source can leave a half-written `{symbol}.json`.** The blast radius is bounded —
`_read_sidecar` (`:171-192`) catches `json.JSONDecodeError`/`OSError` and returns `None`, which
degrades to "uncovered" and a wider-than-necessary re-fetch, not corruption. So this is a
*performance and noise* risk, not a data-integrity one.

**Recommendation:** make both writes atomic in this phase. It is a ~15-line change, the in-repo
precedent is 30 lines away and already argued in its own docstring, and it makes D-20's "no lock"
decision materially safer at essentially zero cost. Extract one shared `write_json_atomic(path,
payload)` helper rather than making a third copy.

### The programmatic write entry point (D-14, D-18)

```python
# quantlab/acquisition/registry.py

@dataclass(frozen=True)
class AcquisitionResult:
    """What one programmatic run did. The in-process caller's copy of the
    outcome, so the console never has to read disk to know what happened --
    while `_failures.json` still lands on disk, because a crashed process
    returns nothing (D-18).

    `failures` values are ALREADY SCRUBBED: they are the same strings
    `Acquisition._attempt_batch` produced through `_scrub`, never raw vendor
    exception text, which for Tiingo echoes back a URL carrying the API token.
    """

    vendor: str
    requested: tuple[str, ...]
    succeeded: tuple[str, ...]
    failures: dict[str, str]
    cancelled: bool
    quota_aborted: bool
    coverage: dict          # the post-run coverage_report() shape


def run(
    descriptor: SourceDescriptor,
    config: AcquisitionConfig,
    *,
    refresh: bool = False,
    reporter: ProgressReporter | None = None,
    cancel: threading.Event | None = None,
) -> AcquisitionResult:
    """Start an acquisition IN-PROCESS and return its outcome (D-12/D-14).

    Constructing `descriptor.acquisition_cls(config)` is the FIRST point a
    credential is demanded, and that is deliberate: it is the vendor class's
    own fail-fast guard (acquisition/tiingo.py:149), and moving it later would
    turn a fail-fast safety behaviour into fail-late (D-08).
    """
    acquisition = descriptor.acquisition_cls(config)
    acquisition.attach(reporter=reporter, cancel=cancel)
    acquisition.refresh() if refresh else acquisition.download()
    return acquisition.last_result
```

```python
@pytest.mark.parametrize("vendor", ["tiingo", "alpaca"])
def test_descriptor_env_names_are_exactly_what_gates_construction(
    vendor, monkeypatch, acquisition_config, mock_tiingo_client, mock_alpaca_client
):
    """D-04: the env var NAME now lives in two places -- the descriptor and the
    vendor's own credential check. Pinned in BOTH directions, because either
    half alone passes for the wrong reason.

    Direction 1 (no name is missing): with every declared name set, construction
    succeeds -- so the descriptor does not under-declare.
    Direction 2 (no name is extra): deleting ANY ONE declared name makes
    construction raise -- so the descriptor does not over-declare either.

    Issues zero requests: `TiingoClient` construction was verified to make no
    network call, and both mock fixtures replace the transport.

    descriptor = DataSourceRegistry.get(vendor)
    cfg = acquisition_config(vendor=vendor)

    for name in descriptor.required_env:
        monkeypatch.setenv(name, "not-a-real-credential")

    for name in descriptor.required_env:     # direction 2
        monkeypatch.delenv(name)
        assert is_configured(descriptor) is False

            descriptor.acquisition_cls(cfg)
        monkeypatch.setenv(name, "not-a-real-credential")

    # And the cheap structural half, which catches a rename in one place only.
    assert descriptor.required_env == descriptor.acquisition_cls.CREDENTIAL_ENV_VARS
```

### The inspector's coverage answer with NO credentials (SC-2, SC-3, D-08)

```python
class SourceInspector:
    """Every read-side question, answerable on a machine with NO credentials.

    Constructing an `Acquisition` is not an option here: `TiingoAcquisition`
    raises `RuntimeError("TIINGO_API_KEY …")` at construction
    (acquisition/tiingo.py:149), which is why `ingest_us_equity.py:186-195`
    today SKIPS its own coverage report when the key is absent -- printing
    "skipped (export TIINGO_API_KEY to see it; it still issues zero price
    requests)" for a computation that is nothing but local file reads. This
    class is what removes that absurdity.

    Issues ZERO vendor requests, by construction: it imports no client class
    and binds no `Acquisition` subclass.
    """

    def coverage(self, descriptor, config, symbols=None) -> dict:
        ledger = CoverageLedger(config, data_type=self._data_type_for(config))
        requested = ledger.validate_symbols(list(symbols or config.symbols))
        pending, counts = ledger.partition_by_coverage(requested, from_watermark=False)
        return {
            "requested": len(requested),
            "pending": len(pending),
            "skipped": len(requested) - len(pending),
            **counts,
        }
```

This is `Acquisition.coverage_report`'s body (`:1399-1423`) reading from the *same shared object*.
`ingest_us_equity.py:198` should then route through the inspector, deleting its no-key skip branch —
a visible, checkable SC-3 consequence in this repo.

### Known Threat Patterns for this stack

| Pattern | STRIDE | Standard mitigation |
|---------|--------|--------------------|
| Credential value leaked into a log, exception, manifest, **progress event**, or **result object** | Information Disclosure | `_scrub` on every message before it leaves `_attempt_batch`; a test asserting a planted env value appears nowhere in the result or events |
| Credential persisted via `asdict(config)` into a checkpoint JSON | Information Disclosure | `AcquisitionConfig` carries no credential field (documented at `base/config.py:132-144`); a test asserting `is_configured` is a `bool` and `credential_status` values are `bool` |
| Path traversal through a roster entry (`../../../etc/hosts`) | Tampering | `_validate_symbols` before any path construction (`:639`, and `_run`/`coverage_report` call it first for exactly this reason). `tests/test_acquisition_batching.py:1259` already exercises `coverage_report(["../../etc"])` — **the inspector needs the same test.** |
| An operator console rendering an env var name AND value side by side | Information Disclosure | Descriptors declare NAMES; the registry has no API that returns a value |
| Vendor base URL redirected via config, exfiltrating credentials | Information Disclosure | `_AlpacaMarketDataClient.BASE_URL` is PINNED (`alpaca.py:84-88`) with an explicit comment. Do **not** let a descriptor carry an overridable base URL. |
| A test double replacing the transport and silently disabling redaction | Tampering | `CREDENTIAL_ENV_VARS` sourced from module-level constants, never from the patchable client class (`alpaca.py:15-23`) — the descriptor must follow the same rule |
| Concurrent writers corrupting a sidecar | Tampering | Currently only partly mitigated — see L-4. `_read_sidecar` tolerates corruption; atomic writes would close it. |

## Open Questions

1. **Does `run(descriptor, config)` include the raw→Zarr conversion, or stop at raw?**
   - What we know: the three scripts disagree today. `ingest_tiingo.py:160` converts unconditionally
     with a whole-window `from_raw_data()`. `ingest_alpaca.py:353-380` converts for `1d`/`1m` and
     stops at raw for `tick` (D-18 of 03.2). `ingest_us_equity.py:487-499` converts only under
     `--to-zarr`, chunked, with `--chunk` and `--on-new-listing`. Each carries its own RAM guard
     sized differently.
   - What is unclear: what the console means by "start an acquisition".
   - **Recommendation:** `run()` is **acquisition-only** — it mirrors `Acquisition`'s own contract
     ("they never touch xarray/Zarr storage", `base/acquisition.py:76-82`), and the conversion has
     three genuinely different modes with three different guards. Expose conversion as a separate
     registry-level call if the console needs it. **Confirm with the developer before planning**,
     because it is a cross-repo contract.

2. **How is the config factory attached to the descriptor?** (CONTEXT discretion item.)
   - `functools.partial(stock_acquisition_config, vendor="tiingo")` is the minimal form and keeps the
     descriptor a pure frozen dataclass. But `ingest_us_equity.py` needs `subdir="us_all"` and
     `kwargs={...}`, and `ingest_alpaca.py` needs `frequency`/`kwargs` — all of which the partial
     passes through fine. **Recommend the partial.** The alternative (a `build_config(**kw)` method)
     buys nothing here since there is only one factory.

3. **Do `_report_coverage`'s four log lines (`:1554-1603`) become progress events, stay logging, or
   both?** D-19 says logging stays as-is; D-16 says progress becomes events. Coverage reporting is
   arguably progress ("what this run is about to do"). **Recommend: emit a `coverage` event AND keep
   the log lines** — the console gets structured counts, and a shell run's stderr is unchanged.

4. **Where are the descriptors defined — `registry.py`, or beside each vendor class?**
   - Beside the class is more cohesive and makes "adding a vendor is registering a descriptor" true
     within one file. It requires `tiingo.py`/`alpaca.py` to import `registry.py`, so `registry.py`
     must not import them at module top — its vendor imports go at the bottom, which is the same
     placement L-3 recommends anyway. **Recommend: descriptors beside their vendor class.**

5. **`supported universe categories` semantics** (CONTEXT discretion item.)
   - Both vendors are US-equity, and the roster comes from `UniverseCatalog`, not from the vendor.
     `us_all`/`nasdaq_all` are *Tiingo-derived* rosters (`TiingoRosterFetcher`), while `sp500_constituent`
     /`nasdaq100_constituent` are Wikipedia-derived and vendor-independent. So "which categories does
     this source support" is really "which categories can this vendor's tickers be resolved against"
     — which today is *all four* for both vendors, with the caveat that 89 of 876 `sp500_constituent`
     symbols have no `us_all` counterpart (STATE.md pending todo). **Recommend: make the field
     advisory and default it to all four**, or omit it in v1 rather than encode a distinction that
     does not exist yet.

6. **Does the inspector's `inventory()` traverse the raw tier, the Zarr tier, or both?** Disk
   footprint of the raw tier is cheap (0.05 s warm) but of the whole `us_all` tree it is 208 MB
   across 26,584 files; the Zarr store is a separate 5.3 MB path with its own config field. **Both,
   reported separately** — they are different artefacts with different lifecycles.
