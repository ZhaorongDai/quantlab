# Phase 03.10 Plan 04: CRSP reference tables — the `_reference/` whole-table pull Summary

**`CrspReferenceTables.pull()` COPYs the six small CRSP/Compustat/CCM tables into a vintage-stamped `_reference/` sibling of the raw root — counted before copied, ceiling-refused, written atomically with the manifest last, and scoped so an S&P-only pull never touches Compustat.**

- **Files modified:** 2 created, 0 modified

## Accomplishments

- **The reference tier can be filled.** `quantlab/dataset/crsp_reference.py` (plan 02) declared the six tables and read them back; this plan is the writer. One `pull()` call turns a `ReferenceTableSpec` into a typed `.parquet` beside a `manifest.json`, and `CrspReference` reads the result with no driver and no credential.
- **The tier is pulled once per CRSP vintage.** The skip is decided from `product_end` plus the files on disk, BEFORE entitlement and before any count, so a repeat pull costs zero round trips on the single shared WRDS session. `refresh=True` and a new `product_end` are the two ways past it, and a new vintage starts from an empty table map rather than mixing files.
- **Nothing over-claims and nothing runs away.** Every table is counted with the COPY's own WHERE and refused above `MAX_REFERENCE_ROWS` before any bytes move (T-03.10-14); the COPY must return exactly that count; each file lands via tmp + `os.replace`; the manifest is the LAST write (T-03.10-12).
- **The Nasdaq-100 side asks for exactly what it needs.** `comp.idxcst_his` is read for `gvkeyx '000208'` with the reserved `from` quoted by `sql.Identifier` (Pitfall 8), then `crsp_a_ccm.ccmxpf_lnkhist` for exactly the gvkeys that returned, carried as a `sql.Literal` list (T-03.10-13). An empty membership raises instead of writing two empty tables.
- **Nothing lands under the raw root.** Asserted after every pull by measuring the raw root, because one stray file there breaks `StockDataset._scan_raw` for conversions that never asked for the reference tier (D-03 prohibition).

## Decisions Made

See `key-decisions` in the frontmatter. The three that a later reader is most likely to trip over:

1. **The manifest's per-table entry is a dict, not a row count.** `tests/crsp_fixtures.py:write_reference_tables` (plan 02) writes `tables: {name: rows}`; this plan writes `tables: {name: {schema, table, rows, where}}`, which is what the plan's `<behavior>` specified. Both satisfy `CrspReference`, which reads only `product_end`. The richer entry exists so a credential-free reader can tell what was ASKED for, and `where` is a description rather than rendered SQL because rendering needs a connection's quoting context.
2. **The vintage skip precedes entitlement.** Ordering it the other way would have made a no-op pull cost a schema probe per schema — and on the single shared WRDS session every probe is a round trip that can push a Duo prompt.
3. **Test-local session subclass instead of editing the shared fixture.** See "Deviations" below.

**1. [Rule 3 - Blocking] The shared CRSP fake records and can fail only the DAILY COPY**

- **Found during:** Task 1 (writing the RED tests)
- **Issue:** `<environment_notes>` directs this plan to drive the fake through `FakeCrspSession.raise_on_copy` and to observe `crsp_copy_calls` / `crsp_count_calls`, and forbids editing `tests/crsp_fixtures.py` (two other wave-3 plans read it). The plan's `raise_on_copy = {2: RuntimeError("boom")}` "(third table)" therefore means exactly what it says.
- **Files modified:** `tests/test_crsp_reference_tables.py` (no change to `tests/crsp_fixtures.py`)
- **Verification:** 17/17 tests pass; `tests/crsp_fixtures.py` is unmodified in `git status` and in the plan's diff.
- **Committed in:** `d3ab55d` (Task 1 RED commit)

**2. [Rule 2 - Missing Critical] A `ccmxpf_lnkhist` pull with no membership in memory**

- **Found during:** Task 2
