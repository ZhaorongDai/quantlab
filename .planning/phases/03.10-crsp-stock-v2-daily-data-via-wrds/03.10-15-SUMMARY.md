# Phase 03.10 Plan 15: GAP-D and WR-01 — `--qqq` Alone Now Produces the Benchmark Store Summary

**`scripts/ingest_wrds_crsp.py` no longer runs the equity conversion when its roster is empty — it prints why and moves on — and `CrspDatasetConfig` can no longer express "no securities" and be read as "every security": `permnos=()` is refused at config assignment naming both meanings, and every read of the field is an explicit `is not None`. `--qqq --to-zarr` alone now exits 0 and writes a one-symbol `wrds_crsp_qqq_1d.zarr` over a planted stale `custom` store whose sidecar comes back byte-unchanged.**

## Accomplishments

- **GAP-D closed, and the command that has never worked now works.** With `--qqq` and no `--permnos`/`--universe`, `equity_permnos` is the empty tuple. The script used to build an equity `ds_config` anyway, fall back to the store name `custom`, collide with whatever earlier run had written that name, and die on the anchor gate **before** the QQQ block — which is why truths 08-T6 and 10-T6 both claim a benchmark store that is not on disk. The whole equity path (config, probe, raw-data refusal, the `Converting N PERMNO(s)` line, `convert()`, the three sidecar prints) now sits behind a non-empty roster, and the else branch prints one line beginning `Skipping the equity conversion:`.
- **The QQQ and membership blocks are now independent outputs, which is the whole point.** They were already textually after the equity conversion; they were not *reachable* past a failure in it. They reference neither `ds_config` nor `probe_dataset`, verified by reading, so lifting nothing out of the guarded region was sufficient. `test_a_universe_with_qqq_writes_all_three_stores` pins that all three still appear together.
- **WR-01 disarmed — the landmine, not just its symptom.** `_derivation` gated the roster filter with `if self.config.permnos:`, a truthiness test, so `permnos=()` converted the **entire** raw tier. The two readings of `()` — "no security" and "every security" — were indistinguishable, and the wrong one was free. The config setter now **refuses** the empty tuple with a message that names both, and all three reads of the field (`_derivation`, `_roster_sources`, `_roster_exemption`) test `is not None`. The comment-stripped source holds zero truthiness gates on it.
- **The `is not None` change is pinned by a test the plan did not prescribe, because the prescribed pair could not fail on it.** Once the setter refuses `()`, no constructor path reaches `_derivation`'s gate with an empty tuple — so a refusal test plus a `permnos=None` guard leaves the gate entirely unpinned. The added test reaches `_derivation` through the path the plan's own comment names: the field assigned on the **config object**, not through the dataset's `config` property, exactly as `dataclasses.replace` / a JSON round trip / a changed default would. It fails `assert 10 == 0` against the defect.
- **"No equity store was written" is proved in bytes.** The end-to-end test **plants** the trap the live run hit — a `wrds_crsp_custom_1d.zarr` directory plus a `.crsp_adjustment.json` recording a different window, its name taken from the production `adjustment_sidecar_path` classmethod rather than a literal — records the sidecar's bytes and the directory listing, and asserts both unchanged afterwards. A conversion that ran and merely failed cannot pass this test either.
- **IN-06 taken in passing.** `replace(ds_config, symbols=None)` was a no-op (`symbols` is already `None` on that config) and each construction re-runs the config setter and re-resolves the security filter; `probe_dataset` is now built from `ds_config` directly. `filter_report_path`/`symbology_report_path` were deliberately left as instance methods — the instance is still needed for `refuse_conversion_without_raw_data`.
- **`example/wrds_crsp.md`'s GAP-2 section is now a record of delivered behaviour.** Title and live evidence preserved (D-18), status line added, the 「在修好之前怎么办」 workaround replaced by an 已交付的行为 block covering both layers and stating that **no store rebuild is required** — what changed is which conversions run and what an empty roster means, not any column's numbers. The QQQ section no longer says the store is unavailable, the command-example warning is replaced by what the run now prints, and the 已知问题 preamble records that the section has no open gap left.
