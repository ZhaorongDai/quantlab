### 1. Plan 14 的 backstop —— Blackstone 的 listed-partnership 时期不被截断

命令（需要 live WRDS 连接，会触发 Duo 推送）：

```
uv run python scripts/ingest_wrds_crsp.py --universe crsp_sp500 \
  --start-date 2007-01-01 --end-date 2019-12-31 --to-zarr
```

然后从生成的面板里读出 PERMNO 92108，并读该 store 的 `.crsp_filter_report.json`。

expected: Blackstone 在 2007-06-22..2019-06-30 全程历史完整——它的 `UG`（listed partnership）时期
存在而非被截断；`roster_overrides` 点名 PERMNO 92108，带该日期区间与被拒绝的 type 组合。

why_human: plan 14 把它标记为 `verification: backstop`，它需要本机没有的 vendor 行——本地 raw tier
只有 2019-01 起、539 个 PERMNO，而 92108 在其中只有 2024 年的行且全是 `NS`。取 2007-2019 的行需要
live WRDS session，而 D-13 禁止 agent 开连接（每次连接可能推 Duo）。

**机制本身已在真实数据上验证**：verifier 用等价案例 Carnival（`CCL`, PERMNO 75154, 同样的 `UG` 规则）
在 2024 全量 tier 上证明了 roster-beats-filter——原本被 filter 丢弃的 252 行现在全部保留且在
`roster_overrides` 中被点名，同时未指定总体仍被正常筛选（`AD` 756 行、QQQ 252 行 ETF 仍被丢弃）。
所以本项是**确认**，不是怀疑：未跑的只是这一只证券在这一个窗口上的复现。
