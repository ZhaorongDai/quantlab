# Phase 03.10: Code Review Report

**Reviewed:** 2026-09-20
**Depth:** standard (per-file, language-aware, grounded against the on-disk live artifacts)
**Files Reviewed:** 15
**Status:** issues_found

## Summary

The phase's SQL surface is clean: every statement is built with `psycopg2.sql`
composables, `--permnos` is `isdigit()`-gated and `int()`-coerced before it can
become a literal, no credential reaches argv, a log line or an exception
message, and the entitlement/product-end/vintage gates all fire before the
first `COPY`. Injection, credential leakage and path traversal turned up
nothing.

The correctness surface did not fare as well. **Two BLOCKERs, both in
`quantlab/dataset/crsp.py`'s adjustment arithmetic, are reproducible on the
store this phase already shipped** (`data/data/us_equity/1d/wrds_crsp_sp500_1d.zarr`):
every security that delists inside the conversion window has its **entire**
`adjClose/adjOpen/adjHigh/adjLow` history written as **identically 0.0** and its
**entire** `adjVolume` history written as **NaN**. Four of the 522 symbols in
that 2024 store (WRK, CTLT, PXD, MRO — all real S&P 500 removals) are affected,
and the mechanism scales with window length, not with a rare data shape: all
5 of 5 delisting rows in the pulled raw tier carry it.

The root cause is a CRSP sentinel the phase's evidence base never contained.
`03.10-RESEARCH`/D-19 characterised delisting rows from Lehman 2008
(`dlyprcflg='DP'`, `dlyprc=0.052` — a *real* price), and `tests/crsp_fixtures.py`
encodes exactly that one shape. Modern CIZ delistings use `dlyprcflg='DA'` with
`dlyprc = 0.0` and `dlyclose/dlyvol/dlycumfacpr/dlycumfacshr` all NULL. The
anchor-selection guard tests `close.is_not_null()`, which `0.0` passes, so the
delisting row becomes the anchor with `close_A = 0`.

These are distinct from the two recorded gaps (GAP-1 security filter, GAP-2
`--qqq` alone) and are not mentioned in any of the eleven SUMMARY files: the
live smoke verified AAPL's split ratio and the S&P store's row counts, but
never opened a delisted security's column.

Eight Warnings follow, most of them the same theme the phase's own docstrings
warn against — a filter or a default that silently widens or narrows the panel
instead of failing loudly.

## Critical Issues

### CR-01: A delisted security's ENTIRE adjusted price history is written as 0.0, and its raw `close` publishes a fabricated $0.00

**File:** `quantlab/dataset/crsp.py:418-450` (the `close` definition and the anchor
`group_by`), with the consequence spreading through `:451-455` and `:726-729`

**Issue:** CRSP CIZ writes a delisting row with `dlyprcflg = 'DA'` and
`dlyprc = 0.0` — a *sentinel for "no price, a delisting amount was paid"*, not a
price. `_derivation()` computes `close = abs(dlyprc)` (line 419), so that
sentinel becomes a real close of `0.0`. The anchor guard on line 431 only
excludes NULL closes (`filter(pl.col("close").is_not_null())`), and `0.0` is not
null, so the delisting row IS the anchor: `_close_anchor = 0.0`. Every adjusted
value is then

```
adjClose_t = _close_anchor * _G_t / _G_anchor = 0.0 * anything = 0.0
_factor_t  = adjClose_t / close_t             = 0.0
adjOpen/High/Low_t = raw * _factor_t          = 0.0
```

for **every day of that PERMNO's history**, not just the delisting day. The
module docstring's stated defence ("the anchor is the LAST row with a non-null
close, not simply the last row: a PERMNO whose final row has no price would
otherwise anchor the entire series on a null and make every adjusted value
NaN") guards against NULL and not against the zero sentinel that CRSP actually
uses.

Separately, the same sentinel lands in the panel's **raw** `close` as a genuine
$0.00, which contradicts `ret` on the same row and contradicts the module
docstring's own justification for preferring `dlyprc` over `dlyclose` ("using
`dlyclose` would put a return chain and a price series that disagree into one
panel"). `prc_is_bidask` is `0.0` on that row (only `'BA'` sets it), so the
panel positively asserts "this was a trade at $0.00".

**Concrete failure scenario (reproduced read-only on the shipped store):**

Raw tier `data/downloads/us_equity/1d/wrds_crsp/wrds/`, PERMNO 21186 (WestRock,
WRK), pulled by the live smoke:

| dlycaldt | dlyprc | dlyprcflg | dlyret | dlycumfacpr | dlycumfacshr | dlyvol |
|---|---|---|---|---|---|---|
| 2024-07-03 | 49.75 | TR | 0.019676 | 1.0 | 1.0 | 4,435,075 |
| 2024-07-05 | 51.51 | TR | 0.035377 | 1.0 | 1.0 | 11,862,010 |
| 2024-07-08 | **0.00** | **DA** | -0.005630 | **null** | **null** | **null** |

`data/data/us_equity/1d/wrds_crsp_sp500_1d.zarr`, `sel(symbol="WRK")`:

| timestamp | close | open | adjClose | ret | is_delisting |
|---|---|---|---|---|---|
| 2024-07-03 | 49.75 | 49.55 | **0.0** | 0.019676 | 0.0 |
| 2024-07-05 | 51.51 | 50.78 | **0.0** | 0.035377 | 0.0 |
| 2024-07-08 | **0.00** | NaN | **0.0** | -0.005630 | 1.0 |

`np.unique(adjClose)` over the whole column is `[0.]`. The same holds for
PERMNO 14763 (CTLT), 75241 (PXD) and 15069 (MRO) — 4 of 522 symbols in a
**single-year** store; the ratio grows with the window.

Downstream, `quantlab/factor/alpha158.py` and `quantlab/label/fret.py` read
`adjOpen/adjHigh/adjLow/adjClose/adjVolume` only. A whole column of `0.0` does
not raise: it produces `0/0 -> NaN` returns, `x/0 -> inf` ratios, and a
cross-sectional rank in which the security sits at the bottom of every
price-level factor on every day it existed. A backtest reading raw `close`
sees a **-100% move** on the delisting day where CRSP says **-0.56%**.

**Fix:** treat the delisting-amount sentinel as "no price" rather than as a
price, in both places.

```python
# quantlab/dataset/crsp.py, inside _derivation()

#: `dlyprcflg` values that mean "this row carries no market price". `DA` is
#: the delisting-AMOUNT row: CRSP writes dlyprc = 0.0 there as a sentinel,
#: not as a close. `DP` (delisting PRICE) is a real price and stays.
_NO_PRICE_FLAGS = ("DA",)

derived = frame.with_columns(
    pl.when(
        pl.col("dlyprcflg").is_in(list(_NO_PRICE_FLAGS))
        | (pl.col("dlyprc") == 0.0)
    )
    .then(None)
    .otherwise(pl.col("dlyprc").abs())
    .alias("close"),
    (1.0 + pl.col("dlyret").fill_null(0.0))
    .cum_prod().over("permno").alias("_G"),
)
```

and harden the anchor so a zero can never be one:

```python
anchor = (
    derived.filter(
        pl.col("close").is_not_null()
        & (pl.col("close") > 0.0)
        & pl.col("dlycumfacshr").is_not_null()   # see CR-02
    )
    .group_by("permno")
    .agg(...)
)
```

Add a loud guard so this class of failure cannot be silent again — after the
anchor join, refuse (naming the PERMNOs) when any `_close_anchor` is null,
zero or non-finite, rather than publishing a zeroed column. The `-0.56%`
delisting return stays in `ret` and in `_G`, so the total-return chain is
unaffected by the fix; only the *level* the chain is anchored to changes, from
`0.0` to the last real close (51.51).

### CR-02: A delisted security's ENTIRE `adjVolume` history is written as NaN

**File:** `quantlab/dataset/crsp.py:431-434` (`_cumfacshr_anchor`), `:453-454`
(`_volume_factor`), `:729` (`adjVolume`)

**Issue:** The anchor row is selected purely on `close`, and the aggregation
then reads `pl.col("dlycumfacshr").last()` off that row. On the `DA` delisting
row `dlycumfacshr` is **NULL** (verified on all 5 delisting rows in the pulled
tier). So `_cumfacshr_anchor` is null, `_volume_factor = dlycumfacshr / null`
is null for every row of that PERMNO, and `adjVolume = dlyvol * null` is NaN
for the security's whole history.

This is a *separate* mechanism from CR-01 — fixing `close` alone does not fix
it, because a security whose last priced day legitimately lacks a
`dlycumfacshr` would still zero out — which is why it is filed separately.

**Concrete failure scenario:** same store, same four symbols. `adjVolume`
NaN fraction over the symbol's observed rows is **1.000** for WRK, CTLT, PXD
and MRO, while raw `volume` is fully populated (4.4M and 11.9M shares on
WRK's last two trading days). Any liquidity filter, turnover factor or
volume-weighted signal built on `adjVolume` silently excludes every security
that ever delisted — i.e. it reintroduces exactly the survivorship bias D-10
exists to remove, through a different door than the one D-10 guards.

**Fix:** make the anchor row satisfy every quantity read off it, and fail
loudly when none does.

```python
priced = derived.filter(
    pl.col("close").is_not_null()
    & (pl.col("close") > 0.0)
    & pl.col("dlycumfacshr").is_not_null()
)
anchor = priced.group_by("permno").agg(
    pl.col("close").last().alias("_close_anchor"),
    pl.col("_G").last().alias("_G_anchor"),
    pl.col("dlycumfacshr").last().alias("_cumfacshr_anchor"),
)
derived = derived.join(anchor, on="permno", how="left")

orphans = (
    derived.filter(pl.col("_close_anchor").is_null())
    .get_column("permno").unique().sort().to_list()
)
if orphans:
    raise ValueError(
        f"{self.class_name}: {len(orphans)} PERMNO(s) have no usable "
        f"adjustment anchor (no row with a positive close and a "
        f"dlycumfacshr) in [{self.config.start_date}, "
        f"{self.config.end_date}]: {orphans[:10]}. Refusing rather than "
        f"publishing an all-zero adjusted price series."
    )
```

Also guard `_G_anchor == 0.0` while you are here: a `dlyret = -1.0` total-loss
delisting makes the cumulative product zero, and `close_A * G_t / 0.0` yields
`inf` for the whole series under IEEE float semantics. No such row exists in
the pulled data, but nothing in the code prevents it and nothing would report
it.

## Warnings

### WR-01: `permnos=()` silently means "every PERMNO in the raw tier", not "none"

**File:** `quantlab/dataset/crsp.py:399-402`; `quantlab/base/config.py` (the
`permnos` docstring); `scripts/ingest_wrds_crsp.py:475-490`

**Issue:** `_derivation()` gates the roster filter with `if self.config.permnos:`
— a *truthiness* test. An empty tuple is falsy, so a config carrying
`permnos=()` converts the **entire** raw tier instead of nothing. The config
field documents only `None` as "every PERMNO"; `()` is undocumented and gets
the same meaning by accident. The config setter (`:343-353`) happily accepts and
normalises `()`.

This is the mechanism underneath recorded GAP-2, but it is a distinct defect
that outlives GAP-2's symptom: GAP-2 is "the conversion collides with a stale
store", whereas this is "an empty roster silently widens the panel to every
security on disk". Fixing GAP-2 by skipping the conversion when the roster is
empty leaves this landmine armed for every other caller of
`CrspDatasetConfig`.

**Concrete failure scenario:** a user with a populated S&P raw tier constructs
`CrspDatasetConfig(..., permnos=(), zarr_file_path=".../my_two_stocks.zarr")`
intending an empty (or later-filled) roster. The conversion writes all 522
S&P PERMNOs plus QQQ into a store named for two of them, with an anchor and
filter report describing the whole tier. Nothing warns.

**Fix:** test for `None` explicitly and refuse the empty tuple at config
assignment.

```python
# quantlab/dataset/crsp.py, _derivation()
if self.config.permnos is not None:
    frame = frame.filter(pl.col("symbol").is_in(list(self.config.permnos)))

# quantlab/dataset/crsp.py, config setter, beside the digit check
if config.permnos is not None and not permnos:
    raise ValueError(
        f"{self.class_name}: config.permnos is an EMPTY tuple, which selects "
        f"no security and would otherwise be read as 'every PERMNO in the raw "
        f"tier'. Pass None to mean 'everything', or a non-empty roster."
    )
```

### WR-02: `from_raw_data()` bypasses the anchor gate and writes a store with no sidecars, which then permanently refuses every later chunked conversion

**File:** `quantlab/dataset/crsp.py:1002-1005` (`_raw_data_to_xr`), against
`:912-946` (`_raw_axes_in_range`)

**Issue:** The anchor gate (`_assert_anchor_unchanged`), the anchor sidecar
(`_write_adjustment_record`) and both identity reports (`_write_identity_reports`)
are all wired into `_raw_axes_in_range`, which **only the chunked path calls**.
`CrspStockDataset._raw_data_to_xr()` calls `_raw_data_to_xr_window()` directly,
so `BaseDataset.from_raw_data().save()` produces a Zarr store with no
`.crsp_adjustment.json`, no `.crsp_filter_report.json` and no
`.crsp_symbology_report.json`.

The failure is latched: `_assert_anchor_unchanged` (`:857-868`) refuses any
store that exists without a sidecar, so the user's next
`from_raw_data_chunked()` (and therefore `registry.convert()`) on that path
raises "the store exists but its adjustment sidecar is missing" and can never
succeed without deleting the store by hand.

**Concrete failure scenario:** a notebook user does
`CrspStockDataset(cfg).from_raw_data().save()` (the idiom every other dataset
in this repo supports and the one `dataset/constituent.py` itself uses four
lines away in `scripts/ingest_wrds_crsp.py:546`). They then run the CLI with
`--to-zarr` pointed at the same `zarr_file_path` and get a permanent refusal
about a sidecar they have never heard of.

**Fix:** move the gate into `_derivation()` (which both paths call) or
override `from_raw_data` on this class:

```python
def _derivation(self) -> pl.DataFrame:
    cached = getattr(self, "_derivation_cache", None)
    if cached is not None:
        return cached
    record = self._adjustment_record()
    self._assert_anchor_unchanged(record)
    ...
```

and have `_raw_axes_in_range` keep only the *write* half, which is already
once-per-run.

### WR-03: A failed conversion overwrites the surviving store's filter and symbology sidecars

**File:** `quantlab/dataset/crsp.py:944` / `:948-969`

**Issue:** `_write_identity_reports()` writes both JSON sidecars unconditionally
— there is no "only if the store does not exist" guard like
`_write_adjustment_record` has (`:901-902`). It runs inside
`_raw_axes_in_range`, i.e. *before* `ChunkLedger.assert_consistent()`, before
`_reconcile_new_listings`' `on_new_listing='refuse'` arm, and before the
per-window `actual != symbols` axis check — all three of which can still abort
the conversion.

**Concrete failure scenario:** an existing `wrds_crsp_sp500_1d.zarr` is
re-converted with a wider roster under the default
`on_new_listing='refuse'`. `_raw_axes_in_range` overwrites
`.crsp_filter_report.json` and `.crsp_symbology_report.json` with the *new*
roster's numbers, then `_reconcile_new_listings` refuses and nothing is
appended. The store on disk is unchanged; its two provenance sidecars now
describe a panel that was never written, and the ones that described the real
store are gone. The filter report is the D-17 audit artifact whose whole
purpose is to say what the store dropped.

**Fix:** write the reports to a temp name and `os.replace` them only after the
append loop reports success, or (cheaper) skip the write when the store
already exists and the ledger is not about to be extended — mirroring
`_write_adjustment_record`'s existing guard.

### WR-04: An interrupted cross-vintage reference pull leaves a mixed-vintage `_reference/` that reports the OLD vintage

**File:** `quantlab/acquisition/wrds_crsp_reference.py:169-224`

**Issue:** `pull()` writes the manifest **last** (correct, and documented), but
when the probed `product_end` differs from the manifest on disk it starts
overwriting the parquet files in place while the **old manifest stays**. If the
pull is interrupted between two tables — a dropped WRDS connection, Ctrl-C, the
`MAX_REFERENCE_ROWS` refusal on a later table — the directory holds a mixture of
two annual vintages, and `CrspReference.product_end` (`crsp_reference.py:328-331`)
reports the *old* one, because it reads the stale manifest.

The consequence is not confined to the reference tier:
`CrspStockDataset._adjustment_record()` (`:824-830`) stamps
`"product_end": str(reference.product_end)` into `.crsp_adjustment.json`, so a
panel built from mixed-vintage symbology records a vintage it was not built
from — defeating exactly the check `CrspVintageError` and the anchor sidecar
exist to provide.

**Concrete failure scenario:** the 2025 tier exists. The 2026 CRSP refresh
lands. A user runs `--universe crsp_sp500`; `stksecurityinfohist.parquet` and
`stkdelists.parquet` are rewritten as 2026, then the session drops during
`stkdistributions`. `manifest.json` still says `product_end: 2025-12-31`. The
next conversion reads 2026 symbology, 2025 distributions, stamps `2025-12-31`,
and the anchor gate can never detect it.

**Fix:** invalidate the manifest before the first write of a different vintage.

```python
if existing is not None and not same_vintage:
    logger.warning(
        f"{type(self).__name__}: {str(self.reference_dir)!r} holds the "
        f"{existing.get('product_end')} vintage and this pull is for "
        f"{product_end.isoformat()}; removing the manifest before the first "
        f"write so an interruption cannot leave a tier that claims a vintage "
        f"it is not."
    )
    self.manifest_path.unlink(missing_ok=True)
    self._manifest = None
```

A stronger form writes the new vintage into a sibling directory and
`os.replace`s the directory at the end.

### WR-05: Ticker reuse on the delisting day DROPS the delisting return row, reintroducing survivorship bias

**File:** `quantlab/dataset/crsp_symbology.py:517-551` (`active_over_delisting`)

**Issue:** `resolve_collisions`' first rule keeps the PERMNO that is still
trading and **discards the other PERMNO's rows on that cell** (`discard.update(...)`,
`:547-551`). The docstring names the exact case it is aimed at — "the old
security's delisting row and the new one's first row share a day" — so the row
it throws away is, by construction, the `dlydelflg='Y'` row that carries the
delisting return. That is the single row D-10, the `label_rows` delisting carry
(`crsp_symbology.py:382-404`) and the security-filter carry
(`crsp.py:604-617`) all exist to preserve.

The loss is recorded in `report["collisions"]` but is invisible in the panel:
the symbol column simply stops at the previous day and the new company starts,
and the `_seam` NaN (`crsp.py:542-560`) then also NaNs the incoming row — so
the delisting loss is neither shown nor flagged in the data itself.

**Concrete failure scenario:** company A delists 2020-03-16 under ticker `XYZ`
with `dlyret = -0.72`; company B is assigned `XYZ` and its first trading day is
also 2020-03-16. `active_over_delisting` keeps B, drops A's row. A's panel
history ends 2020-03-13 at its last *pre*-delisting price, and the -72% never
enters `ret`, never enters the adjusted chain (A's anchor moves back to
2020-03-13) and never reaches a label. Survivorship bias, in the flattering
direction, with a well-formed panel.

**Fix:** do not resolve a collision by discarding a delisting row. Either
refuse the cell (forcing `symbol_overrides` to separate them), or route the
delisting PERMNO to a distinct column (e.g. `XYZ.DELIST` / a class suffix) so
the return survives, and record which was done. At minimum, raise the report
entry to a `logger.warning` naming the dropped delisting rows, and add a
`rows_dropped_carrying_delisting` count to the symbology report so the loss is
countable.

### WR-06: "Tolerated" CCM link gaps punch a real hole of up to 4 TRADING days in the Nasdaq-100 universe

**File:** `quantlab/dataset/crsp_membership.py:483-500`, with
`LINK_GAP_TOLERANCE_DAYS = 4` at `:163`

**Issue:** A membership stretch of `<= 4` calendar days that no CCM link covers
is moved to `report["tolerated_gaps"]` and then **dropped from `uncovered`** —
so it never reaches the unlinked refusal. But nothing bridges it either:
`_merge_intervals` (`:93`) only merges when `start <= previous.end + 1 day`, so
a 2-, 3- or 4-day gap stays two intervals with a genuine hole between them. The
resulting `symbol_intervals` frame feeds `IndexConstituentDataset._densify`,
which writes `is_member = False` for those days.

The justifying comment — "a long weekend plus a holiday is four days and no
trading happens in it" — is only true for a gap anchored on a weekend. A gap
running Tuesday→Friday is 4 calendar days and **4 trading days**.

**Concrete failure scenario:** a gvkey whose CCM link ends 2015-06-08 (Monday)
and whose successor link starts 2015-06-13 leaves 2015-06-09..2015-06-12
uncovered — 4 calendar days, 4 trading days. The Nasdaq-100 mask reads False for
that member across a full trading week; a strategy masked by it holds nothing
in that name and the backtest attributes the absence to the universe rather
than to a link-table seam. `allow_unlinked` has no effect, because the gap was
never classified as unlinked.

**Fix:** either bridge the gap (which is what "tolerated" should mean) by
extending the preceding piece's end to `gap_end` before merging, or narrow the
tolerance to gaps that contain no weekday:

```python
weekdays = sum(
    1
    for offset in range((gap_end - gap_start).days + 1)
    if (gap_start + timedelta(days=offset)).weekday() < 5
)
if matched and weekdays == 0:
    self.report["tolerated_gaps"].append(...)
else:
    uncovered.append((gap_start, gap_end))
```

### WR-07: With `config.symbols` set, the pinned timestamp axis is taken from the UNFILTERED derivation

**File:** `quantlab/dataset/crsp.py:930-946`

**Issue:** `_raw_axes_in_range()` filters `symbols` by `config.symbols`
(`:935-937`) but takes `timestamps` from the whole derivation (`:938`),
*before* any symbol restriction. `from_raw_data_chunked` then plans its windows
from that unrestricted axis and passes `len(timestamps)` to
`_reconcile_new_listings(append_dim_size=...)`, while
`_raw_data_to_xr_window` (`:985-990`) *does* apply the `config.symbols` filter.

**Concrete failure scenario:** a config with `symbols=("AAPL",)` over a raw
tier holding 500 PERMNOs. The planner is handed every trading day any of the
500 traded; a window covering a stretch in which AAPL has no rows (a trading
halt, or a window before AAPL's first row) densifies to a frame with zero rows,
whose `to_xarray()` has a zero-length `timestamp` dim, and the append
contributes nothing. The store's timestamp axis then has fewer entries than the
`append_dim_size` reconciliation was told to expect, and a later `widen` rewrite
pins a chunk grid against a size that does not exist on disk.

**Fix:** derive both axes from the same filtered frame.

```python
derivation = self._derivation()
if self.config.symbols:
    wanted = {str(symbol) for symbol in self.config.symbols}
    derivation = derivation.filter(pl.col("symbol").is_in(list(wanted)))
symbols = sorted(str(v) for v in derivation.get_column("symbol").unique().to_list())
timestamps = derivation.get_column("timestamp").unique().to_list()
```

### WR-08: The delisting fixture encodes only the `DP` shape, which is why CR-01 and CR-02 shipped

**File:** `tests/crsp_fixtures.py:274-300` (the Lehman delisting rows),
`:184-212` (the `dsf_v2` row defaults)

**Issue:** Every `dlyprcflg` value in the fixture file is `TR` (4 rows) or `DP`
(1 row, Lehman 2008-09-18 `dlyprc="0.052000"` — a real price). There is no
fixture anywhere with `dlyprcflg='DA'`, no fixture with `dlyprc = 0`, and no
fixture with a NULL `dlycumfacshr`/`dlycumfacpr`/`dlyvol`. The default row
builder always supplies `dlycumfacshr="1.000000000000"`.

That is precisely the shape **5 of 5** real delisting rows in the pulled tier
have, so `tests/test_crsp_dataset.py`'s delisting assertions pass against a
case that no longer occurs in the data while the case that does occur is
untested. This is the test-quality defect that let two BLOCKERs through a
1,100-line test file and a live smoke run.

**Fix:** add a modern-delisting fixture alongside the Lehman one and assert the
invariants CR-01/CR-02 violate.

```python
#: A MODERN CIZ delisting row (verified against WRK / PERMNO 21186,
#: 2024-07-08): dlyprcflg 'DA' with dlyprc = 0.0 as a NO-PRICE sentinel and
```

## Info

### IN-01: A bare expression statement is the eager config validation

**File:** `quantlab/acquisition/wrds_crsp.py:447`

`self._data_type  # resolves and validates, or raises` is a no-op expression
whose only effect is the property's side effect. `ruff --select B` flags it
(`B018 Found useless expression`), and any autofix or "remove dead code" pass
deletes the eager guard silently. Prefer an explicit binding:
`_ = self._data_type` with the comment kept, or better,
`self._validate_data_type()`.

### IN-02: Dead local and a redundant second `.select()`

**File:** `quantlab/dataset/crsp.py:796-804`

`columns` is built, then `frame.select(timestamp, symbol, *casts).select(columns)`
re-selects the exact column set the first `select` already produced in the
exact order. Drop the second `.select(columns)` and the `columns` local.

### IN-03: Function-scope `import json` duplicating a module-level idiom

**File:** `quantlab/dataset/crsp.py:851`

`_assert_anchor_unchanged` imports `json` inside the function body while
`crsp_reference.py` and `wrds_crsp.py` both import it at module scope. There is
no import-cycle or cost reason to defer it here (the module already imports
polars and xarray eagerly), and a deferred import hides the dependency from a
reader scanning the header. Same shape, one file over, at
`wrds_crsp_reference.py:115`.

### IN-04: Five f-strings with no placeholders

**File:** `quantlab/dataset/crsp_membership.py:618-622`

`ruff F541`. Harmless, but they sit inside the most-read refusal message in the
module, so the noise is where it is most likely to be copied.

### IN-05: The whole-dict anchor comparison makes any future sidecar key invalidate every existing store

**File:** `quantlab/dataset/crsp.py:882` (`if recorded != record:`)

Adding one key to `_adjustment_record()` (a filter fingerprint, a schema
version) makes every store written before that change fail the comparison, and
the refusal message will blame `end_date` — the only field it names. Compare the
anchor-determining keys explicitly (`start_date`, `end_date`, `product_end`,
`rule`) and treat unknown keys as informational, or carry a `version` field
that the comparison switches on.

### IN-06: `probe_dataset` builds a full dataset to print two pure-function paths

**File:** `scripts/ingest_wrds_crsp.py:491`, `:511-512`

`replace(ds_config, symbols=None)` is a no-op — `symbols` is already `None` on
that config — and the instance exists only for `refuse_conversion_without_raw_data`
plus two path prints. Both `filter_report_path()` and
`symbology_report_path()` are pure functions of `config.zarr_file_path` and
could be classmethods like `adjustment_sidecar_path` already is, which would
let the script print all three the same way and construct one fewer dataset
(each construction re-runs the config setter and re-resolves the security
filter).
