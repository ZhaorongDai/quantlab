# Phase 03.10 Plan 03: CRSP daily provider hardening Summary

**The CRSP daily provider now refuses or explicitly clips a window past the annual product end, stamps its vintage so two CRSP releases can never share one raw tier, fails a malformed page loudly and resumably, and prices a pull per year with the exact WHERE the pull will run.**

## Accomplishments

- **The vintage stamp (D-01).** `CrspVintageError`, `VINTAGE_DIR_NAME` and `vintage_path_for()` put a `{"product_end": "..."}` JSON at `.../{subdir}/_vintage/wrds.json` — a sibling of *both* roots. The first run writes it with `write_json_atomically`; a later run that probes a different annual release is refused before any COPY, with a message naming both vintages and both cures (a fresh `subdir`, or deleting the raw root with its `_watermarks/wrds` and `_vintage` siblings).
- **One probe per run.** `resolve_window` was split into the probing classmethod and the pure `window_for_product_end`, so `_run` issues a single `max(dlycaldt)` and reuses the answer for the window arithmetic *and* the vintage comparison. The refusals now say `ANNUAL UPDATE` and explain why clipping cannot rescue a window whose *start* is past the edge.
- **Preflight ordering.** `_run` is now roster → entitlement → product-end probe → vintage, all before the base runner dispatches a batch. The roster check (`_assert_permnos`) is first because it costs nothing; entitlement is before the probe because the probe is itself a query against the schema the account may not be able to read.
- **`year_pages()` as the one page definition.** `_fetch_page` derives its bounds and next token from it, and `CrspVolumeProbe` prices exactly those bounds. Two inline copies would be two definitions that can drift, and the drift is invisible in the dangerous direction — an estimate quoted against slightly different bounds silently understates the disk.
- **Bounded refusals.** `SAMPLE_LIMIT = 10` caps what a duplicate/stranger/off-window refusal enumerates, and each message now states the consequence (which year the next run re-fetches; that an off-window row would land under a `month=` partition this page does not own).
- **`CrspVolumeProbe`.** `count_rows_by_year()` issues one `count(*)` per (year page, PERMNO batch) using `year_pages` and `CrspQueries.daily_where` — the pull's own two functions — keyed by the ISO page end, so `SqlVolumeGuard`'s `fitting_end_date` and its `--end-date` suggestion are a date a re-run can be handed verbatim. The guard itself is reused unchanged (D-03).
- **28 new tests**, all offline, all through `mock_crsp_session` except the one that installs `fake_connect` inside its body to prove the username scrub through the REAL session.

## Decisions Made

See `key-decisions` in the frontmatter. The two with the widest blast radius:

- **The vintage stamp is a sibling of both roots.** Parking it beside the watermarks would have made `wrds.json` a phantom PERMNO in every coverage report (`CoverageLedger.iter_watermark_symbols` reads every `*.json` stem there as a symbol); parking it under the raw root would have put a non-parquet file in a tree `StockDataset._scan_raw` walks.
- **The probe's bucket is a YEAR.** `WrdsNbboVolumeProbe` counts per trading day because a TAQ page *is* a day table. A CRSP page is a calendar year, so a day-keyed CRSP estimate would let the guard suggest `--end-date 2019-06-14` — a boundary no page has and no re-run can honour.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] The PERMNO check had to move to `_run`, not only `_fetch_page`**
- **Found during:** Task 1 (while implementing the preflight order)
- **Issue:** The plan's task-2 behaviour requires `download(["AAPL"])` to raise "before any `fetch_rows`/`copy_csv` call". Plan 02 checked PERMNO-shape inside `_fetch_page`, which runs *after* the product-end probe and inside a batch — so a ticker roster was recorded as a per-symbol failure, i.e. as if WRDS had rejected those securities, and it cost a network probe first.
- **Fix:** Extracted `_assert_permnos()` and called it as the first statement of `_run` (over `_validate_symbols(symbols or config.symbols)`), keeping the `_fetch_page` call as the guard for a direct page fetch.
- **Files modified:** `quantlab/acquisition/wrds_crsp.py`
- **Verification:** `test_a_ticker_roster_is_refused_because_crsp_symbols_are_permnos` asserts `fetch_calls == []` and `crsp_copy_calls == []`.
- **Committed in:** `358bd3f` (Task 1 commit)

**2. [Rule 1 - Bug] `_run` probed `max(dlycaldt)` once for the window and would have probed it again for the vintage**
- **Found during:** Task 1
- **Issue:** `resolve_window(session, ...)` performs its own probe. Adding the vintage check naively would have issued a *second* full-table aggregate per run for a value that cannot change mid-run.
- **Fix:** Split into the probing `resolve_window` (unchanged public signature and 3-tuple contract, still used by callers and tests) and the pure `window_for_product_end`, which `_run` calls with the single probed value.
- **Files modified:** `quantlab/acquisition/wrds_crsp.py`
- **Verification:** `test_entitlement_is_checked_before_the_product_end_probe` asserts no `max(` query survives an entitlement failure; the tracer's single-COPY/single-connection assertions still hold.
- **Committed in:** `358bd3f` (Task 1 commit)
