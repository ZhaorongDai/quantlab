## Summary

The phase adds three pieces:

1. A PERMNO-keyed WRDS CRSP provider that writes a complete raw daily tier. It reuses the `Acquisition` base: one batch = a set of PERMNOs, one page = one calendar year.
2. A small set of whole-table "reference" pulls: security-info history, delistings, distributions, S&P 500 membership, the Compustat Nasdaq-100 constituent history and CCM links.
3. A `CrspStockDataset` that turns PERMNO rows into the period-correct-ticker panel and emits Tiingo's exact variable set.

**Keying acquisition on PERMNO is the key design move.** Each raw shard's `symbol` column holds the PERMNO string, which `TRADEABLE_TICKER_PATTERN` admits. Tickers are assigned only at conversion time from `stksecurityinfohist`. So renames, share classes and ticker reuse never touch the watermark/resume machinery, and the open todo about ticker renames is sidestepped for this vendor.

**Correctness findings the plan must honour:**

- **Delisting returns are already in the daily series.** CIZ stores the delisting return as its own `StkDlySecurityData` row dated `DelDlyDt`, the trading day after the delisting date, with `DlyDelFlg='Y'`, `DlyPrcFlg='DP'` and `DlyRet` equal to the delisting return. Chaining `dlyret` therefore already includes delisting losses. Compounding `stkdelists.delret` on top would double count. [CITED: WRDS CIZ webinar p.13; CRSP DB Guide 2.0, `DelDlyDt`]
- **CIZ prices are always positive.** CIZ reports the bid/ask midpoint as a positive `dlyprc` flagged `dlyprcflg='BA'`. The legacy SIZ convention was a negative price. [VERIFIED: live check AAPL 1980-12-12: `dlyprc` 28.8125, `dlybid` 28.75, `dlyask` 28.875, `dlyprcflg` `BA`; CITED: WRDS webinar p.8]
- **`dsf_v2` lacks `shareclass` and `tradingsymbol`.** Those columns are needed to spell `BRK.B`: CRSP's `ticker` is `BRK` for both Berkshire classes. So symbology has to come from `stksecurityinfohist` whichever daily table is pulled.
- **The adjustment must be computed over the whole configured range before chunking.** Otherwise each year-window gets its own anchor and the stored `adjClose` jumps at every window seam.

**Primary recommendation:** Pull `crsp_a_stock.dsf_v2`, gated on live check L1 confirming `(permno, dlycaldt)` is unique. The fallback is `stkdlysecuritydata` plus `stkdlycumulativeadjfactor`. Use PERMNO batches × one-year pages and a per-page uniqueness assertion. Pull the small reference tables whole into a sibling `_reference/` directory outside the raw root. Build `CrspStockDataset(StockDataset)` with a `CrspDatasetConfig` that computes adjustment factors per PERMNO over the full configured range. Store QQQ in a separate benchmark store (same raw tier, different dataset config). Register CRSP as a second `Capability` on vendor `"wrds"`. That needs one small registry extension: an optional per-capability `acquisition_cls` / `config_factory`.

## Key Findings by Question

### Q1 — Table choice (D-02)

- **Live facts** [VERIFIED: 03.10-LIVE-CHECK.json, `C2_tables` / `C3_columns` / `C4_*`]:
  - `crsp_a_stock.dsf_v2`, `stkdlysecuritydata` and `wrds_dsfv2_query` are all `BASE TABLE`.
  - Catalog row estimates (`pg_class.reltuples`) are 110,257,376 / 110,162,368 / 110,261,760. These are ANALYZE-sampled estimates, and the 0.09% spread is inside sampling noise, so they **prove nothing about duplication**.
  - All three cover `1925-12-31`..`2025-12-31`.
  - `dsf_v2` has 50 columns, verbatim from `C3_columns`: `permno:integer, hdrcusip:character varying, permco:integer, siccd:integer, nasdissuno:integer, yyyymmdd:integer, sharetype:character varying, securitytype:character varying, securitysubtype:character varying, usincflg:character varying, issuertype:character varying, primaryexch:character varying, conditionaltype:character varying, tradingstatusflg:character varying, dlycaldt:date, dlydelflg:character varying, dlyprc:numeric, dlyprcflg:character varying, dlycap:numeric, dlycapflg:character varying, dlyprevprc:numeric, dlyprevprcflg:character varying, dlyprevdt:date, dlyprevcap:numeric, dlyprevcapflg:character varying, dlyret:numeric, dlyretx:numeric, dlyreti:numeric, dlyretmissflg:character varying, dlyretdurflg:character varying, dlyorddivamt:numeric, dlynonorddivamt:numeric, dlyfacprc:numeric, dlydistretflg:character varying, dlyvol:numeric, dlyclose:numeric, dlylow:numeric, dlyhigh:numeric, dlybid:numeric, dlyask:numeric, dlyopen:numeric, dlynumtrd:integer, dlymmcnt:smallint, dlyprcvol:numeric, dlycumfacpr:numeric, dlycumfacshr:numeric, cusip:character varying, ticker:character varying, exchangetier:character varying, shrout:integer`.
- **`dsf_v2` has no `shareclass` and no `tradingsymbol`.** It cannot spell `BRK.B` on its own: live `stksecurityinfohist` rows for permno 83443 carry `ticker='BRK'`, `shareclass='B'`, `tradingsymbol='BRKB'`. So `stksecurityinfohist` is required for symbology (D-04) and for the universes (D-05/D-14) whichever daily table is used.
- **`wrds_dsfv2_query` is rejected.** Its 98 columns include one distribution's fields (`disexdt, disseqnbr, ...`) and one shares interval's fields (`shrstartdt, shrenddt`). Such a join repeats a `(permno, dlycaldt)` on any day with more than one distribution [ASSUMED: inferred from the column set]. Distributions are pulled separately anyway.
- **Recommendation: `dsf_v2`**, gated on live check L1 (`count(*) = count(DISTINCT (permno, dlycaldt))` and equal to `stkdlysecuritydata`'s count over the same window). One pull per page gives CRSP's own `dlycumfacpr`/`dlycumfacshr`/`shrout` and the per-day type columns (D-06 filter inputs).
  - Put the table name in a class constant (`DAILY_TABLE = "dsf_v2"`) so the fallback is a one-line switch.
  - **Always** assert per page that `(permno, dlycaldt)` is unique and fail the batch on a duplicate. Never silently dedup.
- **Pull cost:**
  - An S&P 500 member set is about 500 PERMNOs per day. Across 2000–2025 that is about 1,100 distinct PERMNOs and ~6M rows when each member's full window is pulled (needed for factor warm-up) [ASSUMED: arithmetic from 500 × 252 × 26 plus non-member days].
  - With 200-PERMNO batches × 26 yearly pages that is about 150 COPYs. The min/max probe over the whole table returned in 0.03–0.17 s [VERIFIED: `C4_range_*` `secs`], so filtered queries are expected to be fast; the live smoke should measure it.

### Q2 — CIZ return / price semantics (D-08/D-09/D-10)

| Field | Meaning | Evidence |
|---|---|---|

| `DlyPrcFlg` | Price-flag family PC: "Most values are BA (Bid/Ask Average) or TR (Closing Trade)"; `DP` appears on delisting rows | [CITED: guide flag table; webinar p.13]; live `BA`, `TR` [VERIFIED] |

**Consequences:**
- **D-10:** do not add `stkdelists.delret`. The chained `dlyret` already carries it on the `DlyDelFlg='Y'` row. Keep `stkdelists` as raw event data only. Test: a Lehman-style fixture gives cumulative loss (1+0.428571)(1−0.566667)(1−0.6)−1, not an extra ×(1−0.6).
- **D-09:** `abs(dlyprc)` is a harmless no-op on CIZ (it only guards against a legacy-style negative). The flag variable should come from `dlyprcflg == 'BA'` (bid/ask midpoint), not from the sign. `dlyret` null means NaN whatever `dlyretmissflg` says. Never fill with 0.
- **`close` should be `abs(dlyprc)`, not `dlyclose`.** `dlyclose` is null on bid/ask days, the whole pre-1992 Nasdaq era and delisting rows, while `dlyret` is computed from `dlyprc`. Using `dlyprc` keeps `adjClose` consistent with the return chain and puts the delisting value (`DP` price) into the panel. Keep `dlyclose` as a separate extra (`close_trade`) if wanted. This is a planner call; the D-07 text allows either.

### Q3 — Common-stock filter codes (D-06)

- **Legacy `shrcd in (10, 11)` in CIZ** is `sharetype='NS' AND securitytype='EQTY' AND securitysubtype='COM' AND usincflg='Y' AND issuertype IN ('ACOR','CORP')`. The exchange part (`exchcd 1,2,3,31,32,33`) is a separate triple: `primaryexch IN ('N','A','Q') AND conditionaltype IN ('RW','NW') AND tradingstatusflg='A'`. [CITED: tidy-finance.org/chapters/wrds-crsp-and-compustat.html, SQL verbatim and footnote 2]
- **Code families** [CITED: CRSP guide flag table]:
  - ShareType: `NS` "No Special designation", `AD` ADR, `UG` Units.
  - SecurityType: `EQTY`, `FUND`, `UNIT`, `N/A`.
  - SecuritySubType: `COM`, `ETF`, `CEF`, ...
  - IssuerType: `CORP`, `ACOR`, `REIT`.
  - USIncFlg: `Y`/`N`/`X`.

### Q4 — Ticker mapping (D-04)

**Live rows** [VERIFIED: `C5_ticker_hist_crsp_a_stock.stksecurityinfohist`]:

| permno | period | ticker | tradingsymbol | shareclass | wanted symbol |
|---|---|---|---|---|---|
| 13407 | 2012-05-18..2022-06-08 | FB | FB | A | FB |
| 13407 | 2022-06-09..2025-12-31 | META | META | A | META |
| 83443 | 1996-05-09..2002-01-01 | BRK | `None` | B | BRK.B (collision-driven) |
| 83443 | 2002-01-02..2025-12-31 | BRK | BRKB | B | BRK.B |
| 90319 | 2004-08-19..2014-04-02 | GOOG | GOOG | A | GOOG |
| 90319 | 2014-04-03..2025-12-31 | GOOGL | GOOGL | A | GOOGL |
| 14593 | 1980-12-12..2025-12-31 | AAPL | None → AAPL (from 1982-11-01) | None | AAPL |

**Rule, in order (deterministic):**
1. `cls = shareclass` unless it is null, empty or `'NONE'`. `base = ticker.strip().upper()`.
2. If `cls` is set and `tradingsymbol == base + cls`, then `symbol = base + '.' + cls` (BRK+B → `BRK.B`; the delimiter is the constituent-universe `.`, the same as TAQ's `SUFFIX_DELIMITER = "."` at `quantlab/acquisition/wrds_taq.py:278`).
3. Otherwise `symbol = base` (GOOGL, META, FB, FOXA).
4. **Collision pass over interval overlaps.** When two PERMNOs map to the same symbol on overlapping dates and both carry distinct `cls`, suffix both with their class. This covers BRK 1996–2002, where `tradingsymbol` is null.
5. **Row-level collisions left on a given date:**
   - (a) prefer the active row (`dlydelflg='N'`) over a delisting row (`'Y'`);
   - (b) then prefer the PERMNO that is a universe member on that date, if a universe is configured;
   - (c) otherwise **refuse**, with a `ValueError` listing `(date, symbol, permnos)`.
   - Every resolution in (a)/(b) is written to a sidecar `{zarr}.crsp_symbols.json`, so nothing is silently merged.
6. `symbol_overrides` (config) maps a PERMNO to a fixed symbol **before** all of this. QQQ (86755) becomes `QQQ` for the whole history, including the QQQQ 2004-12-01..2011-03-22 span [VERIFIED: NDX-QQQ `C1_qqq_names`].

**Other mapping facts:**
- **Renames** (FB→META, same permno 13407) become two symbol columns, `FB` ending 2022-06-08 and `META` starting 2022-06-09. This is expected by D-04. A backtester holding FB sees the column end, which is a rename-as-delist event; call it out in docs.
- **How often collisions happen** is L5 [ASSUMED: rare outside NYSE share classes and ticker reuse].
- **Delisting rows can fall outside every `stksecurityinfohist` interval.** `DelDlyDt` is the trading day *after* the delisting date, while the last `secinfoenddt` may be the delisting date. The as-of join must carry the last interval's label forward for `dlydelflg='Y'` rows up to the PERMNO's last daily row. Otherwise the delisting return silently loses its symbol (L3 verifies this).

### Q6 — Drop-in target (D-07)

- **Tiingo variables**, verbatim `TiingoColumns.EOD` at `quantlab/enums/data.py:110-111`: `"open,high,low,close,volume,adjOpen,adjHigh,adjLow,adjClose," "adjVolume,divCash,splitFactor"`. The timestamp dtype is `"timestamp": pl.Datetime("us")` (`tiingo.py:149`), and every EOD column is `pl.Float64`.
- **`StockDataset` emits every raw column** minus `vendor` and the hive keys (`_scan_raw`), and dedups on `(timestamp, symbol)` (`quantlab/dataset/stock.py:487`: `return dedup_raw_frame(data, keep="last")`). `clean_market_data` requires `REQUIRED_COLUMNS = ("open", "high", "low", "close", "volume")` (`quantlab/dataset/cleaning.py:41`).
- **Consumers:**
  - `Alpha158Stock` reads `adjClose`, `adjLow`, `adjHigh`, `adjOpen` and `adjVolume` (read in `quantlab/factor/alpha158.py`, `_get_func_names`).
  - `Return`/`BinaryReturn` read `Input("adjClose")` (`quantlab/label/fret.py`).
  - The backtester values positions at `adjClose` and fills at `adjOpen` (`example/backtest.md:165,179`).
- **Recommended CRSP panel variables:**
  - **Drop-in:** `open` (`dlyopen`), `high`, `low`, `close` (= `abs(dlyprc)`), `volume` (`dlyvol`), `adjOpen`, `adjHigh`, `adjLow`, `adjClose`, `adjVolume`, `divCash` (= `dlyorddivamt + dlynonorddivamt`, on the ex-date), and `splitFactor` (= `dlycumfacpr[prev obs] / dlycumfacpr[t]`, which is 1.0 on ordinary days and derivable offline).
  - **Extras** (float64 only; see Pitfall 7): `permno`, `permco`, `ret`, `retx`, `shrout` (shares = thousands × 1000), `market_cap` (USD = `dlycap` × 1000), `bid`, `ask`, `prc_is_bidask` (1.0/0.0), `is_delisting` (1.0/0.0 from `dlydelflg`), `numtrd`, `cumfacpr`, `cumfacshr`.
- **Adjustment (D-08)**, per PERMNO over the whole configured range, sorted by date:
  - Let `A` = the last row with a non-null `close`, and `G_t = Π_{s≤t}(1 + ret_s)`, where a null ret contributes 1.
  - `adjClose_t = close_A · G_t / G_A` and `factor_t = adjClose_t / close_t`.
  - `adjOpen/High/Low = raw × factor_t`.
  - `adjVolume_t = volume_t · cumfacshr_t / cumfacshr_A`.
  - Null returns contribute 1 because CIZ returns span gaps to `DlyPrevDt` (see `DlyRetDurFlg`), so the next valid return covers the missing day. The snippet was run this session (see Code Examples).
- **Anchor movement and incremental refresh:**
  - The anchor is the PERMNO's last date in the configured window. Extending `end_date` (e.g. the 2026 vintage) rescales every earlier `adj*` value of every still-listed PERMNO by a per-PERMNO constant. Ratios within a series are unchanged; levels change.
  - The Zarr chunk ledger appends windows and never rewrites finished ones. An append after an anchor move would therefore splice two anchors into one column, which makes a fake return at the seam.
  - **Prescription:** write the anchor (`config.end_date` and raw product-end vintage) to a sidecar `{zarr}.crsp_adjustment.json` on the first write. Refuse any later conversion into that store whose anchor differs, naming both anchors, and require a rebuild (new store path or delete). A full rebuild of the S&P daily panel is cheap, and CRSP updates once a year.
- **Tiingo does the same thing** — the vendor restates adjusted history as of fetch time [ASSUMED]. Its `refresh()` appends rows without re-pulling history, so the existing Tiingo store has the same latent seam issue. Record this as an observation, not in scope.

### Pattern 1: Reuse the session through the module attribute
**What:** `wrds_crsp.py` does `from quantlab.acquisition import wrds_taq as _wrds` and calls `_wrds.WrdsSession.shared()` at call time.
**Why:** `tests/conftest.py:mock_wrds_session` patches `"quantlab.acquisition.wrds_taq.WrdsSession"` (conftest lines 1196-1216). A `from ... import WrdsSession` binding would escape the patch. The tripwire would then fire in tests, and a real run would still work, so the bug would be hidden. `_close_shared_wrds_sessions` also only consults the `wrds_taq` module (conftest lines 129-142).

### Pattern 2: PERMNO batch × year page on the base `_fetch_batch`
Implement only `_fetch_page(symbols, start, end, page_token)` → `(frame, next_token)`. Everything else (ledger, shard write before ledger record, resume, failure manifest, abort) is inherited. `test_acquisition_batching.py` walks every concrete `Acquisition` subclass and forbids placeholder bodies (`"not implemented"`, `"not finished"`).

### Pattern 3: Reference tables are not an `Acquisition`
They are whole small tables, not symbol time series. Write them atomically (tmp + `os.replace`) as `.parquet`, not `.pqt`, into the sibling `_reference/`, with `manifest.json` = `{product_end, pulled_at, rows per table, sql_text per table}`. Readers (`CrspStockDataset`, constituent datasets, `CrspUniverse`) take `reference_dir` from config.

### Pattern 4: Global adjustment before chunked windows
`from_raw_data_chunked` calls `_raw_axes_in_range()` once, then `_raw_data_to_xr_window(start, end, symbols)` per window (`quantlab/base/data.py:358-...`). The CRSP dataset computes `(permno, timestamp) → factor, cumfacshr_anchor` from ONE scan over `[config.start_date, config.end_date]`, caches it on the instance, and joins it inside each window. Test: `granularity="year"` and `"month"` produce byte-identical stores.

### Anti-Patterns to Avoid
- **Computing the adjustment inside `_raw_data_to_xr_window` from only that window's rows.** This gives a per-year anchor and a seam every January.
- **Keying raw or watermarks on tickers.** Renames and reuse corrupt resume.
- **Compounding `stkdelists.delret` into returns.** It double counts (Q2).
- **Filtering the raw pull by security type.** This breaks D-06 configurability and the future CRSP-native dataset.
- **Using `dlyclose` as `close`.** It loses bid/ask days and the delisting price.
- **Null `end_date` in CRSP membership intervals.** `_densify` would extend the panel to wall-clock today.
- **Importing `WrdsSession` by name** (Pattern 1).

## Don't Hand-Roll

## Common Pitfalls

### Pitfall 1: Per-window adjustment anchor
**What goes wrong:** `adjClose` jumps at every chunk boundary.
**Why:** the factor is computed from window rows only.
**How to avoid:** compute it globally (Pattern 4).
**Warning signs:** the `year` vs `month` granularity stores differ.

### Pitfall 2: Anchor moves when the store is extended
**What goes wrong:** appending the 2026 vintage to a 2025-anchored store splices two anchors.
**How to avoid:** use the adjustment sidecar and refuse (Q6).
**Warning signs:** a return seam at the old end date for every long-lived PERMNO.

### Pitfall 3: Delisting row loses its symbol
**What goes wrong:** the `DelDlyDt` row lies after the last `secinfoenddt`, the as-of join yields a null ticker, and the row is dropped. The delisting loss disappears, bringing survivorship bias back in.
**How to avoid:** carry the last label forward for `dlydelflg='Y'` rows, and test it with the Lehman fixture.

### Pitfall 4: Ticker seams between different PERMNOs
**What goes wrong:** a ticker is reused, or a holdco reorganisation assigns a new PERMNO under the same ticker. The symbol column then concatenates two securities, each with its own per-PERMNO anchor, and the ratio across the seam is a fabricated return. Rolling features and forward labels spanning the seam are contaminated.
**How to avoid:**
- Keep `permno` in the panel.
- Report every seam (date, symbol, old → new PERMNO) in `{zarr}.crsp_symbols.json`.
- Consider setting `adj*` to NaN on the first day of an incoming PERMNO, so return windows break there. This is an open question for the user; see OQ-2.

This is inherent to D-04's ticker-keyed panel.

### Pitfall 5: Filter defaults silently shrink the index universe
**What goes wrong:** a shrcd-10/11 replication drops REITs and non-US-incorporated S&P/NDX members, and an ADR exclusion drops Nasdaq-100 ADR members.
**How to avoid:** make the default preset a user decision (A3), and write a filter-drop report per run.

### Pitfall 6: `dsf_v2` duplicates, if any
**What goes wrong:** duplicate `(permno, dlycaldt)` rows would be collapsed silently by `dedup_raw_frame(keep="last")`.
**How to avoid:** assert uniqueness per page in the provider and fail the batch.

### Pitfall 7: Non-numeric panel variables
**What goes wrong:** a bool or string column with missing cells becomes `object` dtype after `to_xarray()` reindexing, and Zarr/KunQuant choke on it.
**How to avoid:** encode flags as float64 1.0/0.0/NaN in the panel. Keep CRSP string flags in raw only.

### Pitfall 8: `"from"` is reserved SQL
**How to avoid:** always use `sql.Identifier("from")` for `comp.idxcst_his`.

### Pitfall 9: The session fixture doesn't cover the new module
**What goes wrong:** a by-name import escapes the `mock_wrds_session` patch (Pattern 1).
**How to avoid:** import through the module attribute. The CRSP fakes should live in `tests/crsp_fixtures.py` (a subclass of `FakeWrdsSession` with CRSP methods), with their own fixture patching the same target, so 03.9's in-flight edits to `tests/wrds_fixtures.py` don't conflict.

### Pitfall 10: Editing `wrds_taq.py` while 03.9 is executing
**What goes wrong:** plan 04 is rewriting the session (pgpass pre-check, broken-session semantics, `assert_entitled`, `count_rows`), so 03.10 edits there risk merge conflicts.
**How to avoid:** sequence 03.10's session changes after 03.9 plans 04–08 merge. Then add only generic methods: `schema_usable(schema) -> bool`, `copy_csv(query: sql.Composed) -> bytes` (factoring out the body of `copy_nbbo_csv`), and `fetch_rows(query) -> list[tuple]`. Keep `APPLICATION_NAME` as it is; it is cosmetic.

### Pitfall 11: Pre-1992 Nasdaq rows have no OHLC/volume
**What goes wrong:** `adjOpen/High/Low` and volume are NaN (live AAPL 1980), and `validate_schema` warns.
**How to avoid:** nothing — this is expected. Document it. Factor windows over those years are NaN.

```python
def interval_symbol(ticker, tradingsymbol, shareclass):
    base = (ticker or "").strip().upper()
    cls = None if shareclass in (None, "", "None", "NONE") else shareclass.strip().upper()
    if cls and tradingsymbol and tradingsymbol.strip().upper() == base + cls:
        return f"{base}.{cls}", False          # BRK + BRKB + B -> BRK.B
    return base, bool(cls and not tradingsymbol)  # (symbol, class_ambiguous -> collision pass may suffix)
```
