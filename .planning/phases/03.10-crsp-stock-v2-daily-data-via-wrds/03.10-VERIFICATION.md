## Verdict, stated plainly

**The panel is now drop-in, and I proved it on the vendor's own rows rather than on fixtures.**

The first-stage report refused this phase for one reason: four of 522 symbols in the shipped store —
CTLT, MRO, PXD, WRK, every one a real 2024 S&P 500 removal — had their entire `adjClose/adjOpen/
adjHigh/adjLow` history written as identically `0.0` and their entire `adjVolume` written as `NaN`,
and those five columns are the only ones `alpha158.py` and `fret.py` read. Two further defects
(a mid-history truncation of real index constituents; a `--qqq`-alone run that could never write its
store) sat beside it.

I did not take the gap set's word for any of that. Working from the same shipped raw tier
(`data/downloads/us_equity/1d/wrds_crsp/`, 138,893 rows / 539 PERMNOs / 2019-01-02..2025-12-31, read
only, no WRDS connection), I re-converted through the current code into scratch stores under `/tmp`
and measured the result:

| Symbol | adjClose, shipped store | adjClose, current code (same raw rows) | adjVolume NaN fraction, shipped → current |
|---|---|---|---|
| CTLT | `unique == [0.]` | min positive 42.5602, max 63.4800, **no zero cells** | 1.000 → 0.0041 |
| MRO | `unique == [0.]` | 21.7834 … 29.3374 | 1.000 → 0.0738 |
| PXD | `unique == [0.]` | 214.1795 … 275.5200 | 1.000 → 0.6516 |
| WRK | `unique == [0.]` | 37.8766 … 54.7400 | 1.000 → 0.4754 |

Across that four-security panel: **0** cells where raw `volume` is finite and `adjVolume` is `NaN`;
**0** cells where raw `close` is finite and `adjClose` is not finite-and-positive; **0** zero-valued
`adjClose` cells. The residual NaN fractions are post-delisting absence (PXD stops in May 2024, WRK
in July), not the defect. WRK reproduces the hand-computed arithmetic exactly: `adjClose`
2024-07-05 = 51.510000000000005 (its last real close), 2024-07-03 = 49.749994446467326, and
51.51/1.035377 = 49.749994446467326 to the last digit; the 2024-07-08 delisting row is `close` NaN
and `adjClose` NaN, **not** a fabricated $0.00 trade, while `ret` on that row is still -0.00563 —
the loss stays in the chain, only the level it anchors to moved, exactly as plan 13 promised.

GAP-C got the same treatment, and this is the check no fixture can make: converting the **whole**
2024 tier with `collision_universe='crsp_sp500'` and the default `equity_common` preset, the 252
Carnival (`CCL`, PERMNO 75154, `UG/EQTY/COM/CORP/N`) rows that the shipped store's filter report
records as **dropped** are now kept — 252 of 252 finite close days — and named in the new
`roster_overrides` section with symbol, type, row count and date range, while the unspecified
population is still screened (756 `AD` rows and QQQ's 252 ETF rows still go). That is the
roster-beats-filter rule working on the real vendor rows it was written for, and it is reported
rather than silent.

The QQQ store, which had never existed, now converts from the same local tier: 502 timestamps,
exactly one symbol `QQQ`, and `close` on 2025-12-31 = **614.31** — the operator's live-smoke number
to the cent, reproduced offline.

Ten CRSP suites: **199 passed**, 0 failed, run by this verification in the main tree.

What keeps this from `passed` is not a defect. Plan 14 declared one `verification: backstop` truth —
Blackstone's unbroken 2007-2019 history through a live pull — and the rows it needs are not on this
machine (the local tier is 2019+; PERMNO 92108's rows in it are 2024-only, all `NS`). An agent may
not open a WRDS session (D-13), so that single item goes to the operator. One command, one check.

One thing the operator should keep in view, recorded as advisory rather than as a gap: the repaired
`adj*` columns restore the delisted security's **level**, but for the modern `DA` shape the
delisting day itself has no adjusted price (correctly — CRSP publishes none), so an `adjClose`-based
label still cannot see the final move. Small here (-0.563% on WRK, 5 such rows in the tier), not
small in principle. The vendor doc has already narrowed its guarantee to match the code.
