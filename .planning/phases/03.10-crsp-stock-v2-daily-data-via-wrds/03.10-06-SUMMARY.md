## Accomplishments

- **The panel's vocabulary is complete and documented at its definition.** `CRSP_EXTRA_VARIABLES` names 15 extras, each with a comment giving its CRSP source column and the unit the panel states it in — `shrout` x1000 (CRSP stores thousands of shares), `market_cap` = `dlycap` x1000 (thousands of USD -> USD), `close_trade` = `dlyclose` kept beside `close = abs(dlyprc)`. Every variable but `anomaly_flag` is float64, including `permno` and the two indicators, because a dense cartesian panel needs a NaN to say "this symbol did not exist yet" (RESEARCH Pitfall 7).
- **The two indicators read CRSP's FLAG columns, not values.** `prc_is_bidask` comes from `dlyprcflg == "BA"`, never from the sign of `dlyprc`: the live check counted ZERO negative prices against 122,471 `BA` rows in 2000 (`L10_1`), so a sign test would have flagged no no-trade day at all. `abs()` survives as a guard against a legacy-shaped row, and the module docstring now says so in those words. A NULL flag produces NaN rather than 0.0 — "unknown" is not "was a trade".
- **The delisting loss is in the series exactly once.** `is_delisting` marks Lehman's 2008-09-18 row and nothing multiplies by it; `dlyret` already carries the -0.6, so `stkdelists.delret` stays event data. The test pins the three-day product `(1+0.428571)(1-0.566667)(1-0.6)` and, separately, that the `Return` label on 2008-09-17 IS -0.6 — the same fact in the vocabulary a model trains on.
- **A missing return is NaN, never 0, in both directions.** `ret` keeps CRSP's null; the only `fill_null(0.0)` in the module is inside the cumulative product, where a gap-spanning return already covers the missing day. The test asserts the consequence rather than the code: across a Missing-Price day, `adjClose` moves by exactly the next day's own return.
- **The drop-in promise is now proved rather than asserted.** `Alpha158Stock` (KMID/ROC5/STD5) and `Return` are built through the SAME `FactorConfig` a Tiingo store uses, with only the `Dataset` subclass swapped, over a 40-day synthetic panel containing a 2:1 split. The label equals the next day's CRSP `ret` for all 39 consecutive pairs, split day included — which holds only if the total-return adjustment reproduces the return chain exactly. The acceptance criterion is an EMPTY `git diff --stat` of `quantlab/factor` and `quantlab/label`, and it is empty.
- **The adjustment anchor is now protected, not merely global.** `{zarr}.crsp_adjustment.json` sits beside the store (like `ChunkLedger`'s `.chunks.json`) recording `start_date`, `end_date`, `product_end` and `rule`. `_raw_axes_in_range` — called exactly once, before `ChunkLedger.assert_consistent` and before any append — compares it first and writes it last. Extending `end_date` into an existing store now raises, naming both anchors, the sidecar, WHY (an append-only ledger plus a moving anchor equals two anchors in one column) and the remedy; the test proves the store and its chunk ledger come out byte-identical.
- **`adjClose` is NaN on a priceless day.** The chain is defined there (a null return contributes 1), so the previous behaviour published the anchor's level as that day's adjusted price — inventing a price that a return series would then diff against.
- **Chunking is invisible in the output, measured.** Eleven months of daily rows converted at `granularity="year"` (2 windows) and `granularity="month"` (11 windows) produce stores that pass `xr.testing.assert_identical` — Pitfall 1's own warning sign, turned into a test.

## Decisions Made

Recorded in the frontmatter `key-decisions`. The three a later plan will meet:

- **The indicators read flags, not values.** `prc_is_bidask` from `dlyprcflg`, `is_delisting` from `dlydelflg`, both NaN when the flag itself is null. Inferring "no trade" from a negative price would have been silently vacuous on CIZ.
- **Check first, write last.** The anchor comparison runs before the derivation (so a refusal is cheap and total); the record is written after it succeeds (so a run that dies on a symbology collision leaves no record for a store that was never created). A store can never exist without its record; a record can exist without a store only if a previous run was deleted by hand, and the next matching run simply overwrites it.
- **Refuse rather than rescale.** Rescaling on an extended window is what Tiingo does and is arithmetically fine. It is wrong HERE because the chunk ledger appends and never rewrites, so the old windows would keep the old anchor. The remedy is a rebuild, which is cheap because CRSP publishes once a year.
