# Phase 03.10 Plan 08: CRSP Panel Identity — Filter, Collisions, Seams and the QQQ Store Summary

**The CRSP equity panel now states WHO is in it and WHY: a per-date common-stock filter whose verdict a delisting row inherits rather than dies of, a ticker-ownership pass that resolves a contested day by stated rule or refuses naming both PERMNOs, a NaN break wherever a symbol column changes company so no return spans two businesses, and a separate `qqq_benchmark` store that is data only — every one of those four decisions written to a JSON sidecar beside the store.**

## Accomplishments

- **The common-stock filter exists, and the D-17 reading it implements is written down at the constant that implements it.** D-17 states the predicate `securitytype='EQTY' AND securitysubtype='COM'` *and* states that the filter drops ADRs and units. On the live S&P rows those two goals disagree: an ADR reads `AD/EQTY/COM/CORP/N` and a unit reads `UG/EQTY/COM/CORP/N`, so both **satisfy** the stated predicate. `equity_common` therefore also carries `sharetype in (NS, SB, CE)` — every ShareType code CRSP's flag dictionary defines except `AD` and `UG` — which delivers exactly the drops and exactly the keeps D-17 lists: REITs stay (the eight `SB` ones included), non-US-incorporated common stays, ADRs/units/funds/ETFs/unknown types go. The reading is reversible at zero cost: the literal two-column predicate is one `security_filter` dict away, and the report shows the difference either way.
- **The verdict is per DATE, and the one row whose own evidence is blank inherits.** The filter reads `dsf_v2`'s own per-day type columns, so a security that stopped being common stock keeps precisely the era in which it was. The exception is load-bearing: a `dlydelflg='Y'` row is where CRSP's type columns go blank, and it is the row carrying the delisting **return**. Judging it on its own blanks would have dropped Lehman's −60% day and let survivorship bias back in through the filter, one row at a time, immediately after plan 05's carry rule had just rescued that same row from a NULL ticker.
- **Rows are dropped after the adjustment chain, not before.** Filtering first would have let the next kept day's adjusted move span a return the panel no longer shows — a fabricated number with no visible cause. The chain runs on the PERMNO's full series; only then does the filter cut.
- **Silent universe shrinkage is now impossible.** `{zarr}.crsp_filter_report.json` records the filter **as requested and as resolved** (so a preset name is not the only trace of what ran), `rows_total == rows_kept + rows_dropped`, a count per dropped type combination, and one line per dropped PERMNO with its last symbol, its types, its row count and its first/last date. "The S&P panel lost its ADR member" is now a line in a file rather than a column nobody notices is missing.
- **A contested ticker is resolved by rule or refused — never merged.** `_resolve_identity` runs `CrspSymbology.resolve_collisions` over the whole derivation, feeding it `CrspMembership.permno_intervals(collision_universe)` when one is configured. Two *active* PERMNOs under one ticker resolve to the universe member; a delisting row against an active row resolves to the active one with no universe needed (which is the shape ordinary ticker reuse actually takes). Anything still tied raises, naming the date, the symbol and both PERMNOs, from the once-per-run axes hook — so the store does not exist afterwards.
- **A ticker column that changes company breaks there; a rename does not.** The seam test is `permno != permno.shift(1).over(symbol)`, a **PERMNO** test rather than a ticker test — the only formulation that tells reuse (two companies) from a rename (FB → META, PERMNO 13407 on both sides, where the ratio across the two columns is a real return). On a seam the incoming row's `adjOpen/adjHigh/adjLow/adjClose/adjVolume` are all NaN, which required nulling `adjClose` **and** both factors, since `adjClose` comes straight from the anchor while the other four come from `_factor`/`_volume_factor`. Raw prices and `permno` are untouched: the break removes the fabricated quantity, not the observation.
- **The opt-out removes the correction, never the record.** `nan_adj_at_permno_seam=False` gives a continuous column to anyone who wants to study the ticker rather than the company — and still writes the seam to the sidecar, so the panel can never hide that a column changed hands.
- **QQQ has its own correctly-labelled store, and D-16 is locked by a test rather than by a promise.** `CrspDatasetConfig.qqq_benchmark()` states all three settings at once because getting any one wrong is silent — most sharply `security_filter="none"`, since QQQ is `FUND`/`ETF` and a benchmark store built with the equity default would come out **empty** rather than merely wrong. The override pins `QQQ` across the 2004–2011 `QQQQ` spell, so one instrument is one column. The scope prohibition is enforced two ways, because either alone would pass while the promise was broken: an identifier scan proves no CRSP module reaches for `benchmark_dataset`, and an AST check proves `quantlab/base/backtest.py` still refuses the slot with `NotImplementedError`.
- **Every new config field survives a JSON round trip.** The filter is validated at assignment but `config.security_filter` is left as the user wrote it — a preset name stays a name, a dict has its value lists frozen to tuples — which is what makes `load_dataset_from_config(json.loads(json.dumps(...)))` compare equal for both spellings.

## Deviations from Plan

None — the plan executed as written. Two notes that are readings rather than deviations:

- **The filter is validated in the config setter but `config.security_filter` is not rewritten.** The plan says "resolve the config value in the setter". Resolution happens there (and refuses there); the resolved mapping is held on the dataset as `_security_filter` while the config keeps the user's spelling. Rewriting a preset name into its dict would have made Task 3's round-trip assertion pass for the wrong reason and would have hidden which preset a saved config asked for. A dict value **is** normalised in place (lists → tuples), which is what the round trip needs.
- **Plan 02's duplicate check in `_raw_data_to_xr_window` was kept, not removed.** The plan allowed removal "only if the collision step now guarantees uniqueness". It guarantees uniqueness across *different* PERMNOs, which is what it resolves; it does not speak to two rows of the *same* PERMNO on one day. The assertion is therefore kept and redocumented as the backstop the plan asks for in the same sentence.
