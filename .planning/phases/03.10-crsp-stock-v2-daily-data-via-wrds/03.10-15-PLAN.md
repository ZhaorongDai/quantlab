<objective>
**GAP-D, and WR-01, the landmine underneath it.** `scripts/ingest_wrds_crsp.py` runs the equity
conversion unconditionally. With `--qqq` and no `--permnos`/`--universe` the roster is exactly the
QQQ PERMNO, so `equity_permnos` is the EMPTY tuple — and `CrspStockDataset._derivation` gates its
roster filter with a truthiness test, so `()` silently means "every PERMNO in the raw tier" rather
than "none". The store name falls back to `custom`, collides with a pre-existing
`wrds_crsp_custom_1d.zarr` written under a different anchor, and the anchor gate raises before the
QQQ block is ever reached. No `wrds_crsp_qqq_1d.zarr` has ever been produced.

The anchor gate behaved correctly. Two things are wrong above it, and they must be fixed
separately: the CLI should not convert an empty roster, and an empty roster should not mean
"everything" to any caller of `CrspDatasetConfig`. Fixing only the symptom leaves the landmine armed
for the next caller — a user who writes `permnos=()` intending an empty roster gets all 522 S&P
PERMNOs written into a store named for two of them, with an anchor and a filter report describing
the whole tier, and nothing warns.

Purpose: truths 08-T6 and 10-T6 both claim the QQQ benchmark store exists. Neither is true on disk.

Output: the empty-roster refusal in the config setter, the `is not None` test in `_derivation`, the
CLI skip with a stdout line, and an end-to-end CLI test that plants the stale store the live run
tripped on.
</objective>
