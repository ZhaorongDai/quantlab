<objective>
Prepare the WRDS vendor seam that the CRSP tracer (plan 02) needs, as its own
wave-1 plan (split from the tracer per plan-checker iteration 1). No CRSP code is
written here. This plan settles, in code, the two structural questions that PATTERNS.md
left open.

- **Registry shape (D-12).** WRDS stays one descriptor.
  - `Capability` gains two OPTIONAL fields, `acquisition_cls` and `config_factory`.
  - `SourceDescriptor.acquisition_cls_for` / `config_factory_for` resolve per capability, fall back to the descriptor, and refuse ambiguity.
  - `run()` uses the resolver.
- **Import cycle.** The `WRDS_SOURCE` descriptor MOVES from `wrds_taq.py` into a new neutral module, `quantlab/acquisition/wrds.py`, which imports the provider modules.
  - `wrds_taq.py` then imports nothing from the registry.
  - When plan 02 adds `wrds_crsp.py`, that module imports the `wrds_taq` module object (for the shared session), and only `wrds.py` imports both. Neither import order can cycle.

It also adds three generic, provider-neutral methods to the one `WrdsSession`: `schema_usable`, `fetch_rows` and `copy_csv`. The CRSP provider uses them instead of adding CRSP-shaped methods to a TAQ module. TAQ's own methods delegate to them without changing their SQL.

**Sequencing:** execute only after phase 03.9 is fully merged (plans 06, 07, 08). This
plan edits `wrds_taq.py`, `registry.py`, `tests/test_source_registry.py` and
`tests/test_nbbo_dataset.py`, all of which 03.9 touched.

Purpose: plan 02 can add the CRSP capability as one row on an existing descriptor, with
the registry already able to hold two acquisition classes under one vendor.

Output: the resolver, the neutral descriptor module, the generic session helpers, and
the tests that lock them.
</objective>

phase: the `wrds` vendor gains a SECOND acquisition class, while `run()` assumed one
class per vendor (`descriptor.acquisition_cls(config)`).
- Primary noun: the `Capability` `(market, frequency, data_type)` becomes the unit that
  may own an acquisition class and a config factory; the descriptor-level
  `acquisition_cls` / `config_factory` become the vendor DEFAULT.
- Decision: `add-alongside`, i.e. optional per-capability fields plus one resolver. The
  reason: three ingest shells read `SourceDescriptor.acquisition_cls` directly
  (`SOURCE.acquisition_cls.DEFAULT_BATCH_SIZE`, ...), and making it optional would ripple
  through them for no behavioural gain.
- Accepted debt: a third vendor with several acquisition classes, or a console that must
  enumerate classes per capability, should promote the capability fields to required and
  retire the descriptor default.
- The raw-identity decision of this phase is a `promote`: the CRSP raw tier is keyed by
  PERMNO and the ticker is derived at conversion time. It is implemented by plan 02.
- Invariant lock (Task 1): for every registered descriptor and every capability,
  `acquisition_cls_for(c.market, c.frequency, c.data_type)` returns the capability's class
  or the descriptor default; an ambiguous request raises.
