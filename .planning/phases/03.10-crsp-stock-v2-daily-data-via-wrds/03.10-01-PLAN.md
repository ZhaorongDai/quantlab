<objective>
**This is the phase tracer.** Prove the whole architecture on ONE PERMNO-month before
anything is built sideways: a fake WRDS session serves Apple's (PERMNO 14593) real
`crsp_a_stock.dsf_v2` rows around the 2020-08-31 4:1 split, a new CRSP provider lands
them as raw daily shards keyed by PERMNO, the registry resolves the CRSP capability of
the existing `wrds` vendor, and a new `CrspStockDataset` turns the shards into a
drop-in `[timestamp, symbol]` panel with hand-checked total-return `adjClose`.

It also settles, in code, the two structural questions PATTERNS.md left open:
- **Registry shape (D-12):** WRDS stays one descriptor. `Capability` gains two OPTIONAL
  fields, `acquisition_cls` and `config_factory`; `SourceDescriptor.acquisition_cls_for`
  / `config_factory_for` resolve per capability, fall back to the descriptor, and refuse
  ambiguity; `run()` uses the resolver.
- **Import cycle:** the `WRDS_SOURCE` descriptor MOVES from `wrds_taq.py` into a new
  neutral module `quantlab/acquisition/wrds.py` that imports both provider modules.
  `wrds_crsp.py` imports the `wrds_taq` module object (for the shared session and error
  types); `wrds_taq.py` imports nothing CRSP. So there is no cycle in either import order.

**Sequencing:** execute only after phase 03.9 is fully merged (plans 06, 07, 08). This
plan edits `wrds_taq.py`, `registry.py` and `tests/conftest.py`, which 03.9 also touched.

Purpose: every later plan (acquisition hardening, reference tables, symbology,
membership universes, dataset semantics, CLI) expands a path that already works end to
end.

Output: the neutral WRDS descriptor, the CRSP provider and dataset skeletons with real
happy-path behaviour, the CRSP test fixtures, and the existing registry / subclass-walk
suites taught about the second WRDS capability.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired (kind `pluralization`). The real plurality in this
phase: the `wrds` vendor gains a SECOND acquisition class, while `run()` assumed one
class per vendor (`descriptor.acquisition_cls(config)`).
- Primary noun: the `Capability` `(market, frequency, data_type)` becomes the unit that
  may own an acquisition class and a config factory; the descriptor-level
  `acquisition_cls` / `config_factory` become the vendor DEFAULT.
- Decision: `add-alongside` — optional per-capability fields plus one resolver, because
  `SourceDescriptor.acquisition_cls` is read directly by three ingest shells
  (`SOURCE.acquisition_cls.DEFAULT_BATCH_SIZE`, ...) and making it optional would ripple
  through them for no behavioural gain.
- Accepted debt: a third vendor with several acquisition classes, or a console that must
  enumerate classes per capability, should promote the capability fields to required and
  retire the descriptor default.
- Second identity change, promoted: the raw tier is keyed by PERMNO (the stable CRSP
  security id), and the ticker is derived at conversion time. Ticker renames therefore
  never touch watermarks or resume state.
- Invariant lock (Task 2): for every registered descriptor and every capability,
  `acquisition_cls_for(c.market, c.frequency, c.data_type)` returns the capability's class
  or the descriptor default; an ambiguous request raises.
</assumption_delta_decision>
