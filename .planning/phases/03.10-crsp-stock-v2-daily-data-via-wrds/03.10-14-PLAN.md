<objective>
**GAP-C — the security filter screens an unspecified population; it must not overrule an explicit
roster.** This is a specification defect, not an implementation one: truth 08-T1 was met exactly as
written, and what was written was wrong.

`SECURITY_FILTER_PRESETS['equity_common']` is `securitytype EQTY` + `securitysubtype COM` +
`sharetype in (NS, SB, CE)`, and `_apply_security_filter` evaluates it per row against `dsf_v2`'s
own type columns with no roster exemption of any kind — `config.permnos` and
`config.collision_universe` never enter the predicate. So the `UG` (listed-partnership era) and
`AD` rows of REAL index constituents are dropped MID-SECURITY: Blackstone loses 2007-2019, KKR
2010-2018, Carnival everything from 2003, Royal Dutch Petroleum its entire life. Seven of the 1,956
historical S&P 500 member PERMNOs are hit, and a truncated series is downstream-indistinguishable
from a late IPO.

The operator decided the direction on 2026-09-20, recorded verbatim in `03.10-11-SUMMARY.md`:
「优先保证成分股不缺」. A `--universe` run means the index provider already decided membership, so a
member is never dropped during its membership spell. A `--permnos` run means the user named the
securities, so they are not dropped. A broad screen with no explicit roster keeps today's behaviour,
because excluding ADRs and units is meaningful there. And the override must be REPORTABLE.

Purpose: the phase's own reason for being is that constituents must not go missing. A filter that
can silently truncate twelve years of a real S&P 500 member defeats it through a different door
than the delisting one plan 03.10-13 closed.

Output: the roster exemption in `_apply_security_filter`, a `roster_overrides` section in the filter
report, the WR-07 axis fix, and the corrected `example/wrds_crsp.md` sections.
</objective>

<assumption_delta_decision>
The detector fired `pluralization` on this phase's scope, and the real delta is in this plan's
scope rather than in the sentence it matched.

**What changed.** `CrspDatasetConfig.collision_universe` was introduced as "the universe that
breaks a same-day ticker collision" — a tie-break input, one narrow use. This plan gives it a
second, larger responsibility: it is also the explicit roster that exempts its members from the
security filter. A field whose meaning was "which index arbitrates a rare tie" becomes "which index
this conversion is scoped to".

**The noun that is now primary:** *the explicit roster this conversion is scoped to*. Collision
tie-breaking is demoted to one of that roster's two uses.

**Decision: `promote`, with the field NAME retained.** The responsibility is promoted in the
docstring, the report and the doc; the identifier stays `collision_universe`. Rationale: every
store this phase already shipped carries a serialized `config.json` that
`quantlab/utils/module.py:load_backtester_from_config` and the dataset rebuild path read back by
key, so renaming the field breaks the round trip for stores that exist on disk today. Adding a
SECOND field naming the same universe would be worse — two fields carrying one fact can disagree,
and nothing at runtime would notice, which is exactly the failure the single shared symbology was
built to avoid.

**Accepted debt, and what would force a rename.** The identifier now lags its responsibility. A
rename becomes forced the first time a conversion legitimately needs a roster universe DIFFERENT
from its collision tie-break universe; at that point the field splits and both names become
accurate. Recorded here so a later reader sees it was decided rather than overlooked.

**Companion invariant test (accepted, authored in Task 2):** for every preset, a PERMNO that is a
member on a date survives the filter on that date. It goes red the instant a future change
reintroduces the unconditional filter.
</assumption_delta_decision>
