# Phase 03.10 Plan 01: WRDS Vendor Seam Summary

**The registry now resolves an acquisition class and config factory per `Capability` (descriptor value as the vendor default, explicit refusal on disagreement), and the `wrds` descriptor moved into a neutral `quantlab/acquisition/wrds.py` whose shared `WrdsSession` exposes provider-neutral `schema_usable` / `fetch_rows` / `copy_csv` — so plan 02's CRSP provider is one capability row, not a registry rewrite.**

## Accomplishments

- `Capability` gained two OPTIONAL fields, `acquisition_cls` and `config_factory`, placed after `dataset_cls` so no positional construction changes meaning. `None` means "the descriptor's default", which is what makes the change purely additive.
- `SourceDescriptor._resolve_capability_field` states the resolution rule ONCE — no match → the descriptor's own field (today's behaviour, unchanged for every existing caller); matches that agree → the value; matches that disagree → `ValueError` naming the descriptor, the request tuple and the matched `data_type`s, in the style `convert()` already uses one axis over. `acquisition_cls_for` / `config_factory_for` sit on top of it.
- `registry.run()` constructs `descriptor.acquisition_cls_for(config.market, config.frequency, (config.kwargs or {}).get("data_type"))(config)` — `Capability`'s own key. Every Tiingo, Alpaca and WRDS call resolves exactly the class it constructed before.
- `WRDS_SOURCE` moved from `wrds_taq.py` to the new neutral `quantlab/acquisition/wrds.py`, which imports the provider module object plus `NbboPanelDataset`. The nbbo capability now carries its own class/factory; the descriptor default is the same pair; `required_env` is still the literal `("WRDS_USERNAME",)`.
- `wrds_taq.py` calls no `register_source` and imports nothing from `quantlab.acquisition.registry` or `.wrds` — so when plan 02 adds `wrds_crsp.py`, only `wrds.py` imports both providers and no import order can cycle.
- `WrdsSession` gained `schema_usable(schema)`, `fetch_rows(query)` and `copy_csv(query)`, all through `_query`. `has_schema_usage(year)` is now `self.schema_usable(f"taqm_{int(year)}")` and `copy_nbbo_csv` is `self.copy_csv(self.copy_query(...))`; both issue byte-identical SQL, pinned against literals captured from the pre-change module.

## Decisions Made

- **`add-alongside`, not `promote`** (the plan's recorded assumption-delta decision, implemented as written). The descriptor-level `acquisition_cls` / `config_factory` stay REQUIRED and act as the vendor default. Accepted debt, unchanged from the plan: a third vendor with several acquisition classes, or a console that must enumerate classes per capability, should promote the capability fields to required and retire the descriptor default.
- **Agreement is tested identity-then-equality** (`value is not first and value != first`). A class reference compares by identity; a `functools.partial` config factory does not. Testing identity alone would make Tiingo's and Alpaca's partial-based factories look like disagreement the moment two capabilities shared one.
- **The SQL pins are literals, not rebuilds.** `test_taq_methods_delegate_without_changing_their_sql` compares against strings captured from the pre-change module. Both already passed in the RED run — which is the evidence that they are pre-change text rather than a tautology against the delegation. The COPY assertion is then restated as the property (`== render_composed(copy_query(...))`) so a future re-render cannot drift from the builder either.
- **`display_name` unchanged.** The plan anticipated widening it when CRSP joins; until that capability exists, a widened name would advertise something the descriptor cannot serve.
