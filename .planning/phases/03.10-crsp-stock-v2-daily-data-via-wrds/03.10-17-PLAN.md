  <context>
    VERIFICATION lists WR-05 and WR-06 among the anti-patterns but deliberately does NOT file them
    as gaps: both are "design decisions a human should make rather than defects to patch". Each has
    a real cost, each has more than one defensible answer, and each changes what downstream phases
    04, 05 and 06 will consume. Deciding them silently in code is the failure mode this checkpoint
    exists to prevent.

    **WR-05 — `quantlab/dataset/crsp_symbology.py`, `resolve_collisions` / `active_over_delisting`.**
    When two PERMNOs claim one ticker on one day, the first rule keeps the PERMNO still trading and
    DISCARDS the other's rows on that cell. By the docstring's own account the case it targets is
    "the old security's delisting row and the new one's first row share a day" — so the row thrown
    away is, by construction, the `dlydelflg='Y'` row carrying the delisting return. That is the one
    row D-10, the symbology delisting carry and the security-filter carry all exist to preserve. The
    loss is recorded in the symbology report but is invisible in the panel: the column simply stops
    a day early and the new company starts. Concretely: company A delists with `dlyret = -0.72` on
    the same day company B takes its ticker; A's history ends at its last pre-delisting price and
    the -72% reaches no return series, no adjusted chain and no label. Survivorship bias, in the
    flattering direction, with a well-formed panel.

    Options: (a) keep the current behaviour and accept the bias, with a louder warning and a
    `rows_dropped_carrying_delisting` count in the symbology report so it is at least countable;
    (b) refuse the cell, forcing the operator to separate the two with `symbol_overrides`;
    (c) route the delisting PERMNO to a distinct column (a suffixed symbol) so the return survives,
    and record which was done. (a) is cheapest and keeps every current store valid; (b) is safest
    and will stop conversions that work today; (c) preserves the data but adds a symbol the
    universe panels do not know about.

    **WR-06 — `quantlab/dataset/crsp_membership.py`, `LINK_GAP_TOLERANCE_DAYS = 4`.** A membership
    stretch of four or fewer calendar days that no CCM link covers is moved to `tolerated_gaps` and
    dropped from `uncovered`, so it never reaches the unlinked refusal — but nothing bridges it
    either, because `_merge_intervals` only merges when the next start is within one day. The
    justifying comment ("a long weekend plus a holiday is four days and no trading happens in it")
    is true only for a gap anchored on a weekend; a gap running Tuesday to Friday is four calendar
    days and four TRADING days, and the Nasdaq-100 mask reads `is_member=False` across a full
    trading week for a real member. `allow_unlinked` has no effect, because the gap was never
    classified as unlinked.

    Options: (a) bridge the gap — extend the preceding interval's end to the gap end before merging,
    which is what "tolerated" ought to mean; (b) narrow the tolerance to gaps containing no weekday,
    so a Tuesday-to-Friday gap reaches the refusal; (c) keep it and document the up-to-four-trading-day
    hole as known. (a) invents membership the link table does not attest; (b) will start refusing
    pulls that succeed today; (c) leaves a silent hole in a universe mask.

    Both affect data that phases 04, 05 and 06 consume, so a decision now is cheaper than a decision
    after a model has trained on it.
  </context>
