# Phase 03.10 Plan 10: The CRSP daily ingest CLI Summary

**One command — `scripts/ingest_wrds_crsp.py` — entitles, clips the window to the CRSP annual product end, pulls the reference tables, resolves a point-in-time roster to PERMNOs, prices the pull per YEAR and refuses over the ceilings, pulls the daily tier and converts the equity panel, the QQQ benchmark and the universe mask, all on ONE WRDS connection; with nine structural locks holding that order in place.**

## Accomplishments

- **The operator surface exists (D-12).** One command replaces the sequence a user would otherwise have to compose by hand out of `CrspQueries`, `CrspReferenceTables`, `CrspMembership`, `CrspVolumeProbe`, `registry.run` and three separate `convert` calls — and, more importantly, replaces it *in the right order*. Every protective check fires before any daily row moves.

- **The guard now says what it is counting, without touching the TAQ path.** `SqlVolumeGuard` prices two different pulls: a TAQ page IS a trading day, a CRSP page is a calendar YEAR. The fix is a `unit` **word** (`estimate(..., unit="year bucket")`), stored in the estimate and used where the bucket count is rendered — *not* renamed fields. The dict key stays `trading_days` because it is the bucket COUNT, and the 03.9 caller that reads it is correct as it stands. An estimate with no `unit` key renders `trading days:` exactly as before, which is right by construction: such a dict can only come from a pre-03.10-10 caller, and every one of those is a TAQ caller.

- **Entitlement is scoped, and it is first.** The schemas probed are exactly the ones this invocation reads: `crsp_a_stock` always, `crsp_a_indexes` only for `crsp_sp500`, `comp` + `crsp_a_ccm` only for `comp_nasdaq100`. Most CRSP subscriptions do not include Compustat, so probing it for an S&P run would produce a "no" that nothing in that run needs. Probing happens before the product-end probe and before the reference pull, so an unentitled run leaves **no** `_reference/` directory behind — asserted, not assumed.

- **The roster reaches the config already resolved to PERMNOs.** Plan 03 moved `_assert_permnos` to the top of `_run` and left a forward note: any future roster source must be resolved to PERMNOs *before* it reaches the acquisition config. This is that source, and the rule is now a structural lock rather than a note — `pull(` < `permnos_in_range(` < `count_rows_by_year(` by line number.

- **The clip is printed verbatim (T-03.10-37).** `clipped end 2026-06-30 -> 2025-12-31 (crsp_a_stock annual product end)`, and the test asserts the last daily COPY's upper bound really is the product end. A start past the edge exits non-zero with zero daily COPY, because clipping cannot rescue a window that is entirely past it.

- **QQQ leaves the equity panel by ROSTER, not only by filter.** `--security-filter none` is a legitimate choice a user will make, and a benchmark that re-entered the cross section the moment someone widened the filter would defeat D-15 silently. The equity config's `permnos` therefore excludes the `--qqq`-added PERMNO outright, and the benchmark gets its own store through `CrspDatasetConfig.qqq_benchmark()`.

- **Nine structural locks, one of them mutation-checked.** An end-to-end test against a fake session cannot see a guard that moved below the pull — the fake always admits. So the ordering, the single session, the absent credential argument, the absent config factory and the resolved-never-named vendor class are asserted on the SOURCE, with every failure message naming the line numbers it compared.

## Decisions Made

See `key-decisions` in the frontmatter. The three most likely to be revisited:

1. **A unit WORD, not renamed guard fields.** The alternative — renaming `trading_days` to `buckets` — would have forced an edit on `scripts/ingest_wrds_taq.py` and `tests/test_ingest_wrds_taq.py` to fix something that is not broken there. Plan 03's forward note said exactly this, and it is followed.
2. **`include_sp500` follows `--universe` rather than defaulting True.** `CrspReferenceTables.pull` defaults it to True, which is right for a library caller with no opinion. A CLI *has* an opinion: a `--permnos` run has no index to answer, so pulling `dsp500list_v2` for it would ask `crsp_a_indexes` a question that run never needs — and, with entitlement scoped the same way, would have made an S&P-unentitled account unable to run a plain PERMNO pull.
3. **The explicit-roster store is `wrds_crsp_custom_1d.zarr`.** Naming it after whatever index the caller's PERMNOs happen to resemble would put a claim in a filename that nothing downstream can check.
