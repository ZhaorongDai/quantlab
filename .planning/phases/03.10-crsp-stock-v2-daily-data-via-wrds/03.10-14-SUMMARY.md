# Phase 03.10 Plan 14: GAP-C — the Security Filter No Longer Overrules an Explicit Roster Summary

**`config.permnos` and `config.collision_universe` now reach `_apply_security_filter`, so an S&P 500 member's listed-partnership (`UG`) era survives its membership spell instead of being truncated mid-security — the rescue is recorded under `roster_overrides` with row counts and date ranges, a broad screen with no roster still drops `AD`/`UG` exactly as before, and `_raw_axes_in_range` now pins both axes from one `config.symbols`-filtered frame (WR-07).**

## Accomplishments

- **GAP-C closed.** `_roster_exemption` gives the filter three behaviours instead of one: a PERMNO named in `config.permnos` is exempt on **every** date (the user named the security, not a window of it); a PERMNO that `collision_universe`'s membership spells cover is exempt **on the dates inside a spell** and nowhere else; with neither set the exemption is a literal `False` and the filter is byte-for-byte the screen it was. That is the operator's 2026-09-20 decision — 「优先保证成分股不缺」 — expressed as code rather than as a doc warning plus a workaround.
- **The override is auditable, which the decision explicitly required.** `roster_overrides` carries `sources` (which rosters are in play, with member and spell counts), `rows_rescued` and a per-PERMNO breakdown (`symbol`, the rejected type combination, `rows`, `first`, `last`). It is present **with zero counts when no roster is configured**, so a reader can tell "no override happened" from "this store predates the feature" by the key's presence. A non-zero rescue also emits a `logger.warning` naming the counts and the report key.
- **`rows_rescued` means exactly "would have been dropped and was not."** The exemption is OR-ed in **after** the delisting carry, so a row the carry already rescued is not counted as a roster rescue, a rescued delisting row is still rescued, and a rescued ordinary row does not become its PERMNO's carried verdict for the next day. `rows_kept + rows_dropped == rows_total` still holds with rescued rows counted as kept — asserted in two tests.
- **One membership read, one opinion.** `_member_intervals` memoises `permno_intervals` on the instance, and `_resolve_identity` now calls it instead of building its own. The IO saving is the smaller reason: two independent reads of the reference tier could disagree under a long conversion, and a filter verdict that disagreed with a collision verdict about who is a member would produce a panel built from two rosters with nothing noticing.
- **The exemption is pinned as SCOPED, not just as working.** `test_without_a_roster_the_filter_still_truncates_the_rejected_era` runs over the **same fixture** as the two positive tests and asserts the opposite, so a future blanket widening (T-03.10-48) fails the suite. `test_every_member_survives_every_preset_on_its_member_dates` is the durable invariant, parametrised over both presets and quantified over `CrspMembership.permno_intervals` itself, so it goes red the instant the unconditional filter returns.
- **WR-07 closed.** `_raw_axes_in_range` applies the `config.symbols` restriction to the derivation once and reads **both** axes off that frame. The consequence of separating them is written beside the code, because the bug is invisible in the store and visible only in the pinned axis and the ledger.
- **`example/wrds_crsp.md` now states the rule as delivered behaviour** in the surrounding file's Chinese: the 名册优先 rule above the preset table, the three cases, a `roster_overrides` key table, the operator's phrasing as the reason, the `equity_common` row pointing at the rule instead of at an open defect, and a GAP-1 section that keeps its seven-PERMNO evidence and loses its 修复方向 and its workaround. GAP-2 is byte-identical.

**1. [Rule 1 - Bug] The plan's fixture recipe could not produce the truncation it describes**

- **Found during:** Task 2 (writing the RED tests)
- **Issue:** the plan says to give the scenario "two `secinfo_row` intervals over one window: the earlier with the partnership `sharetype` the preset rejects". `_apply_security_filter` evaluates the preset against `dsf_v2`'s per-day columns and never reads `stksecurityinfohist`, so a secinfo-only era leaves all ten daily rows `NS/EQTY/COM/CORP/Y`. **2. [Rule 1 - Bug] The plan's WR-07 assertion passes with the defect present**

- **Found during:** Task 3
- **Issue:** the plan says to "assert the store's timestamp axis equals that symbol's own observed days rather than the union". Measured on the pre-fix code with a two-PERMNO / three-year fixture: the planner logged `7 observed timestamp(s)` and appended a `(0 row(s))` window, and the **store's** axis came out as the symbol's 5 days anyway — an empty window appends nothing. - **Fix:** the test asserts (a) the PINNED axis `_raw_axes_in_range` returns, which is the D-02 once-resolved axis the `append_dim_size` caller reads, and (b) the chunk ledger's window list, which persists a completed window over a year the requested symbol never traded. - **Files modified:** `tests/test_crsp_identity.py`

**3. [Rule 2 - Missing critical] `_roster_exemption` returns a two-tuple only because the membership test is materialised**

- **Found during:** Task 1
- **Issue:** the plan requires `_roster_exemption` to return "a two-tuple of the boolean polars expression naming the exempt rows and a short description of the roster sources". A per-date interval membership test is a JOIN, and the join-free ways to express it as a pure expression are both unacceptable at real scale — O(spells) passes over the frame for a disjunction, or millions of `(permno, date)` pairs for a set membership.
- **Fix:** the join runs inside `_member_days` and its boolean result is returned as `pl.lit(series)`, which IS a polars expression, so the plan's contract holds literally. The row-order coupling it introduces (the expression must be evaluated against the frame it was built from) is stated in the docstring, and the caller obeys it.
- **Files modified:** `quantlab/dataset/crsp.py`
- **Verification:** the six roster tests plus all ten CRSP/WRDS suites green.
- **Committed in:** `fa2bac5`
