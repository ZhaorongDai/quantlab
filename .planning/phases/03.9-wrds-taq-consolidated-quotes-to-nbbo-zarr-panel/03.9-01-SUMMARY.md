# Phase 03.9 Plan 01: WRDS TAQ NBBO tracer Summary

One AAPL symbol-day (2024-01-24) now goes the whole way offline. A fake WRDS session serves the rows, `registry.run(WRDS_SOURCE)` lands every record as raw tick shards with an arrival ordinal, and `registry.convert(..., granularity="day")` produces a 390-bar right-closed 1m NBBO Zarr panel. The panel values match the hand-computed ones. A D-28 tripwire in the tests blocks any real `psycopg2`/`wrds` connection.

## What was built

- **`WrdsSession`**: uses `psycopg2` directly and never imports the `wrds` package. The host, port and database are pinned class constants. The connection is opened lazily, is read-only with autocommit, and is shared once per username. There is no password parameter; libpq reads `~/.pgpass`. The SQL builders are pure `psycopg2.sql` objects: `table_identifier`, `where_clause` (`sym_root = ANY(...) AND (sym_root, coalesce(sym_suffix,'')) IN (...)`) and `copy_query`. The network methods are `trading_days` (via `information_schema`), `table_columns` and `copy_nbbo_csv`.
- **`WrdsTaqNbboAcquisition`**: one page is one day table queried for one symbol batch, and the page token is the next trading day's ISO date. `wrds_row_ord` is assigned before any other frame operation. `time_m` is parsed with or without a fractional part. `time_m_nano` becomes a typed null before 2018. The timestamp is the ET wall clock plus nanoseconds, converted to naive UTC as `Datetime("ns")`. Records are never sorted, deduplicated or filtered. The class refuses `max_workers != 1`, and `build_config` is the descriptor's `config_factory` (D-27).
- **`NbboResampler`** (the thin slice): a stable total order `(symbol, date, timestamp, wrds_row_ord)`, then the pre-open seed moved to the open, records after the close dropped, and right-closed labels at bar end. It also computes `n_updates`, an as-of backward join with both sides sorted just before it, time-weighted spread and sizes from cumulative integrals, and mid, spread, spread_bps and imbalance. Every output column is Float64.
- **`NbboPanelDataset(StockDataset)`**: the scan filters on the `date` hive key, so the seed survives. The window densifier builds a dense labels × symbols grid with an object-dtype `str` symbol coordinate, `_clean` calls `clean_nbbo_panel`, and `_widen_fill_values` returns `{}`.
- **Registry**: `wrds` is registered through a module-object import at the bottom of `registry.py`, so a cold import enumerates `['alpaca', 'tiingo', 'wrds']`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Tracer compared a nanosecond timestamp through a polars scalar**
- **Found during:** Task 1 (GREEN)
- **Issue:** `raw["timestamp"][4]` returns a Python `datetime`, which drops the 500 ns, so the assertion could never hold. The stored data was correct.
- **Fix:** the test now compares through pandas (`raw["timestamp"].to_pandas().iloc[4]`).
- **Files:** tests/test_nbbo_dataset.py. **Commit:** c90bc17

**2. [Rule 3 - Blocking] The subclass walk asserted a watermark path that tick vendors do not use**
- **Found during:** Task 2
- **Issue:** the walk checked `Path(cfg.watermark_path) / f"{symbol}.json"`. `CoverageLedger.watermark_root` namespaces tick sidecars by data type (`.../_watermarks/wrds/nbbo/AAPL.json`), so WRDS could never satisfy that path.
- **Fix:** the walk now asserts `acq._watermark_path(symbol).exists()` plus containment under `cfg.watermark_path`. This is byte-identical for the `1d` vendors, so nothing was weakened.
- **Files:** tests/test_acquisition_batching.py. **Commit:** 2da2a71

**3. [Rule 3 - Blocking] `test_the_no_credentials_fixture_empties_every_declared_name` pinned the old three-name tuple**
- **Issue:** the plan adds `WRDS_USERNAME` to `_CREDENTIAL_ENV_NAMES`, and this pin still listed only the three older names.
- **Fix:** added `WRDS_USERNAME` to the expected tuple and changed "three names" to "declared names" in its docstring.
- **Files:** tests/test_source_registry.py. **Commit:** 2da2a71

**4. [Rule 1] Silenced two polars warnings in the resampler**
- `explode(..., empty_as_null=False)` replaces the deprecated default behaviour.
- `join_asof(check_sortedness=False)` is used because both sides are explicitly sorted immediately before the join (Pitfall 8). Polars cannot verify sortedness itself when `by=` is given.
- **Commit:** c90bc17

**Total deviations:** 4 auto-fixed (2 Rule 1, 2 Rule 3). **Impact:** none on scope. Every fix keeps or strengthens the original assertion.
