# Phase 03.9 Plan 07: WRDS TAQ ingest CLI and docs Summary

`scripts/ingest_wrds_taq.py` is the single command for WRDS NBBO. It resolves the `wrds` source from the registry, resolves the roster by interval overlap, and opens one shared WRDS session. Before the first COPY it checks entitlement and counts rows with `count(*)` per (trading day, symbol batch), and `SqlVolumeGuard` prices those counts. It then pulls through `registry.run`. With `--to-zarr` it also resamples through `registry.convert` and prints the path of the filter-stats sidecar. `example/wrds_taq.md` documents the contract in Chinese.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] The store name carries the session window**
- **Found during:** Task 1
- **Issue:** The plan's template `wrds_nbbo_{bar_interval}.zarr` would give two runs with different `--session-start/--session-end` the same store. `ChunkLedger` fingerprints only the symbol axis, so the second run would skip already-written days without a word and keep the first window's bars.
- **Fix:** `DEFAULT_STORE_TEMPLATE = "wrds_nbbo_{bar_interval}_{session_start}-{session_end}.zarr"`, with the HHMM edges normalised by the calendar. Tests assert `wrds_nbbo_5m_0930-1600.zarr` and `wrds_nbbo_30m_0400-2000.zarr`.
- **Files modified:** scripts/ingest_wrds_taq.py, tests/test_ingest_wrds_taq.py
- **Commit:** f1eeef7

**2. [Rule 2] More argument refusals**
- `--batch-size < 1` and a roster that resolves to no symbols are now parser errors, so neither reaches the probe.
- **Commit:** f1eeef7
