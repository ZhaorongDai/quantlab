# Phase 03.9: WRDS TAQ Consolidated Quotes to NBBO Zarr Panel - Context

**Gathered:** 2026-09-19
**Status:** Ready for planning

<domain>
## Phase Boundary

WRDS NYSE TAQ (millisecond product) **NBBO records** are acquired verbatim into resumable raw parquet
shards through a new `quantlab/acquisition/` vendor provider, and a new Dataset class **resamples them
locally** into the canonical dense `[timestamp, symbol]` Zarr panel at a caller-chosen frequency.

In scope: the WRDS provider (PostgreSQL via the `wrds` library), the raw NBBO shard layout, a SQL-shaped
volume guard, the local resampler + NBBO Dataset writing Zarr, registry registration, a CLI entry.

Out of scope: storing raw records on a non-dense event axis in Zarr (Phase 03.3), full per-exchange
`cqm` quotes, TAQ trades, CRSP permno linking.

Note: the phase title says "Consolidated Quotes"; per D-01 the acquired table is WRDS's NBBO table
from the same millisecond TAQ product, not the per-exchange `cqm_*` table. The title is kept for
roadmap stability.

</domain>

<decisions>
## Implementation Decisions

### Source & raw layer
- **D-01:** Acquire WRDS's **NBBO record table** (the millisecond TAQ product's NBBO tables — e.g.
  `taqm_YYYY.nbbom_YYYYMMDD` / `complete_nbbo_YYYYMMDD`; researcher must confirm which table carries
  the full NBBO state per row and its exact schema on WRDS PostgreSQL). Each row is the national best
  bid/offer at that instant. Not the per-exchange `cqm_*` quotes (an order of magnitude larger).
  — **Reversibility:** costly — switching tables changes the raw schema, the shard layout and every
  test fixture; data already pulled would have to be re-pulled.
- **D-02:** Raw records land in parquet **as-is, one row per NBBO record**, including every ordering
  field WRDS provides (`time_m`, `time_m_nano`, and the sequence-number field such as `qu_seqnum`),
  plus the original `sym_root` / `sym_suffix`. No server-side resampling or aggregation.
- **D-03 (ordering, from the WRDS PROC SQL note):** Server-side SQL is `SELECT ... WHERE` only —
  **no `GROUP BY`, no `SELECT DISTINCT`, no reliance on physical row order**. On PostgreSQL there is
  no order guarantee at all without `ORDER BY`, so the SAS-era "plain select preserves order" result
  does NOT carry over. Record order is re-established **locally** by a total order key
  `(date, symbol, time_m, time_m_nano, <seqnum>)`. Researcher must verify on WRDS that this key is
  unique per symbol-day; if it is not, the plan must name the tie-breaker and lock it with a test.
  "Last NBBO in a bar" is always defined by this key, never by arrival order.
- **D-04:** Collection covers the **full day** (pre-market through after-hours) — session trimming
  happens only in the resampler (D-09).
- **D-05:** Anomalous records (crossed bid>ask, locked bid=ask, zero price/size, abnormal condition
  codes) are **kept in raw**; filtering happens only in the resampler (D-10).
- **D-06:** Batching follows WRDS's access pattern: one **daily table × a batch of symbols**
  (`WHERE sym_root IN (...)`), since TAQ tables are indexed/sorted by symbol. Raw hive layout reuses
  the existing intraday conventions (`date=` = US/Eastern session date, `SESSION_TIME_ZONE =
  "America/New_York"`, timestamps naive UTC `Datetime("ns")`), with a `data_type` value for NBBO.

### Credentials
- **D-07:** Username from env var `WRDS_USERNAME`; password from `~/.pgpass` (the `wrds` library's
  standard mechanism). No credential ever in `AcquisitionConfig`, logs, or exception messages
  (`CREDENTIAL_ENV_VARS` + `_scrub`). The provider must never trigger `wrds`'s interactive
  password prompt or offer to create `.pgpass` — missing credentials fail fast with an actionable
  message.

### Local resampling & Zarr panel
- **D-08:** Resample **frequency is a parameter** (e.g. `1s`, `5s`, `1m`, `5m`), not hard-coded 1m.
  This requires extending the locked `Frequency` literal (`quantlab/enums/data.py`) and every table
  keyed on it (`RAW_HIVE_KEYS`, `HIVE_SCHEMA_BY_FREQUENCY`, `BARS_PER_DAY_BY_FREQUENCY`, chunking docs).
  The planner decides whether the resample frequency is a new token family or a separate
  "panel frequency" parameter distinct from the raw acquisition frequency (raw NBBO is event data,
  i.e. `tick`-like). — **Reversibility:** costly — `Frequency` is a shared locked literal consumed by
  config, acquisition, dataset and registry.
- **D-09:** Panel defaults to **regular trading hours 09:30–16:00 ET**; the session window is
  configurable. Bars are built on a regular grid within the session.
- **D-10:** Resampler filtering is **configurable**; default drops crossed quotes and zero/missing
  prices, keeps locked quotes. Counts of dropped records are recorded (per run, and inspectable).
- **D-11:** Bar semantics — **both**:
  - point-in-time snapshot = the last valid NBBO at or before bar end (by the D-03 order key; no
    look-ahead),
  - time-weighted averages over the bar of spread and depth (record duration = time until next
    record; tied timestamps have zero duration, so only the last record of a tie carries weight).
- **D-12:** Panel variables: `bid`, `ask`, `bid_size`, `ask_size`, `mid`, `spread`, relative spread in
  bps, **NBBO update count** per bar, **order imbalance** `(bid_size-ask_size)/(bid_size+ask_size)`,
  plus the time-weighted spread/depth of D-11. Exact variable names are the planner's choice
  (consistent style with existing Dataset variables).
- **D-13:** Empty bars (no NBBO update) **carry forward** the previous NBBO, update count = 0;
  **never carry across trading days**; bars before the day's first valid NBBO are NaN.
- **D-14:** The NBBO Dataset overrides `_clean` (the default `clean_market_data` requires OHLCV
  columns — `quantlab/dataset/cleaning.py:38`), following the `clean_membership_panel` precedent.

### Symbols & universe
- **D-15:** Symbol = `sym_root` + `sym_suffix` joined in the **universe's notation** (e.g. `BRK.B`),
  with raw `sym_root`/`sym_suffix` columns retained. Universe = existing point-in-time
  `sp500_constituent` / `nasdaq100_constituent` via `UniverseCatalog.get_symbols_in_range`; date range
  via CLI arguments. Membership tickers are period-correct, matching TAQ's period-correct symbols.

### Volume guard
- **D-16:** SQL-shaped guard: before pulling, run `count(*)` per daily table for the requested
  symbols, estimate total rows and disk bytes, refuse above ceilings unless `--force-volume` (same
  flag contract as the existing guard, `tests/test_volume_guard.py`). The REST requests/min model
  does not apply to WRDS. Must respect the rule that `universe.py` imports no acquisition module.

### Integration
- **D-17:** Register a `SourceDescriptor` (vendor `"wrds"`, `required_env=("WRDS_USERNAME",)`,
  capability with the NBBO dataset class) in `quantlab/acquisition/registry.py`, and add a CLI entry
  `scripts/ingest_wrds_taq.py` following `scripts/ingest_alpaca.py`.

### Post-research decisions (2026-09-19, after live WRDS checks — evidence in `03.9-LIVE-CHECK-{1,2}.json`)
- **D-18 (table, supersedes the open part of D-01):** `taqm_{YYYY}.complete_nbbo_{YYYYMMDD}`
  (BASE TABLE; `taqmsec.*` are views of the same). Verified columns (identical 2012/2016/2024 except
  nano): `date, time_m, [time_m_nano], sym_root, sym_suffix, qu_cond, natbbo_ind, qu_source,
  nbbo_qu_cond, best_bid, best_bidsizeshares, best_ask, best_asksizeshares`. **No `qu_seqnum`.**
  `time_m_nano` exists only from **2018-01-02**; 2003–2017 tables have microsecond `time_m` only.
- **D-19 (ordering, refines D-03):** total order key = `(date, symbol, time_m, time_m_nano, wrds_row_ord)`.
  - 2018+: `(symbol, time_m, time_m_nano)` was verified unique (2,065,354/2,065,354 rows on
    2024-01-24 for AAPL/MSFT/BRK), so order is fully determined.
  - Pre-2018: ~5% of rows share a (symbol, µs) with a *different* NBBO state (2016-12-07, 5 names:
    1,999,275 rows, 1,897,424 distinct timestamps, only 786 fully identical rows). No sequence field
    exists, so the **physical order** is the only tie-breaker. The provider pulls with
    `COPY (SELECT … WHERE …) TO STDOUT` **without ORDER BY / GROUP BY / DISTINCT** (the WRDS note's
    empirically safe form) and records the **arrival ordinal within each (date, symbol-batch)
    query** as `wrds_row_ord` in raw. The local sort must be stable on that ordinal.
  - The panel carries a per-bar **ambiguous-tie count** (records sharing their timestamp with a
    differently-valued record), so downstream users can filter pre-2018 bars. — **Reversibility:**
    costly — `wrds_row_ord` is part of the raw schema; dropping it later forces a re-pull.
- **D-20 (connection):** do not use `wrds.Connection` (its `raw_sql` breaks under pandas 3 and it
  prompts interactively). Connect with `psycopg2` to host `wrds-pgdata.wharton.upenn.edu:9737`,
  db `wrds`, `sslmode=require`, user from `WRDS_USERNAME`, password from `~/.pgpass` via libpq;
  read-only session; `COPY` verified allowed. **One connection per run** (each connection can
  trigger a Duo push; role connection limit is 7), `max_workers=1`.
- **D-21 (entitlement):** probe `has_schema_privilege('taqm_YYYY','USAGE')` per requested year
  before pulling (the user's subscription covers 2016 and 2024 but NOT 2012). Unentitled dates fail
  the run fast with a clear message; they are a global condition, never per-symbol failures.
- **D-22 (bar labels):** bars are **right-closed and labelled at bar end** — a `09:31` bar is the
  state over `(09:30, 09:31]`; label time = information-available time (no look-ahead).
- **D-23 (calendar):** add the `exchange_calendars` dependency (XNYS) for session open/close incl.
  historical half days; adding the package is a human-verify checkpoint (confirm name/version).
- **D-24 (volume):** keep the default 20 GiB ceiling; large backfills run as several date
  segments, each guarded separately; `--force-volume` remains the override. Calibration from
  live data: 2024-01-24 full market = 313,568,856 rows / 9,703 roots; AAPL 1.24M, XOM 0.76M,
  MSFT 0.67M, JNJ 0.16M, BRK 0.15M rows/day. Per-symbol filtered `count(*)` is < 1 s (columnar
  chunk-group filters on `sym_root`, not a B-tree index); a full-table count takes ~76 s, so the
  guard counts **per symbol batch**, never the whole table.
- **D-25 (data facts for the resampler):** rows with one or both sides NULL exist (202 of 2.98M on
  2024-01-24, 158 in RTH) — treat a NULL side as "no quote on that side" (NaN, not zero); crossed
  545, locked 130,164 (4.4%, kept by default per D-10). `qu_cond` observed: `R` (regular), `O`
  (opening); `qu_source` `N`/`C` (two SIPs); `natbbo_ind` `2`/`4`/`U`/`G`. Suffix spelling:
  `BRK`+`B` → `BRK.B`, `BF`+`B` → `BF.B`.
- **D-26 (panel frequency):** the "arbitrary frequency" choice is realised as a `bar_interval`
  parameter on the NBBO dataset config; raw acquisition uses the existing `frequency="tick"` +
  `data_type="nbbo"` machinery, so the locked `Frequency` literal is NOT extended (this is the
  D-08 option "separate panel frequency parameter").
- **D-27 (config factory):** `SourceDescriptor.config_factory` is satisfied by a classmethod on
  the provider (e.g. `build_config(...)`), not a new function in `quantlab/config` (user memory:
  no config factories).
- **D-28 (test safety):** an autouse test tripwire makes any `psycopg2.connect` to WRDS fail in
  the test suite (an existing test walks every `Acquisition` subclass and calls `download()`).
  Phase gate = "no new failures vs the 55 pre-existing ones", not "suite green".
- **D-29 (session window range, user decision 2026-09-19 after plan check; supersedes the planner's
  earlier RTH-only restriction):** the panel session window (`session_start`/`session_end`, D-09)
  may be configured anywhere inside the extended window **04:00–20:00 ET**; edges outside it, or
  start >= end, are refused. The default stays **09:30–16:00 (RTH)**. On an XNYS early-close day
  only the **regular close** is capped (e.g. 13:00): an edge that lies inside regular hours
  (09:30–16:00) is clipped to that session's actual exchange open/close, while an edge in extended
  hours (before 09:30 or after 16:00) is wall-clock and unchanged. So RTH on 2024-11-29 is
  09:30–13:00, a 04:00–20:00 window on that day stays 04:00–20:00 (continuous through the early
  close; bars after 13:00 carry post-close NBBO state exactly as bars after 16:00 do on a normal
  day), and a window whose capped span is empty (e.g. 13:30–16:00 on a half day) yields no bars
  for that date. The resampler seeds each window from the last valid NBBO at or before the window
  start, for extended windows exactly as for RTH.

## Existing Code Insights

### Reusable Assets
- `Acquisition` ABC: only `_fetch_page` is abstract; returning `None` as the page token is a complete
  implementation for a non-paginated vendor. Watermarks, PageLedger, deterministic shard names,
  per-batch failure isolation, and scrubbing come for free.
- Tick hive keys `(data_type, date, symbol)` and `_clear_superseded_shards` already exist for
  per-symbol tick partitions.
- `from_raw_data_chunked` + `TimeChunkPlanner` + `ChunkLedger` handle windowed, resumable Zarr appends.
- `UniverseCatalog.get_symbols_in_range` supplies sorted period-correct tickers.
- `wrds>=3.1.6` is already in `pyproject.toml`.

### Established Patterns
- Layer boundary: acquisition never touches xarray/Zarr; Dataset never calls vendors.
- Everything class-based and config-driven (user memory: encapsulate new components; no config
  factories — construct configs directly).
- `_raw_data_to_xr_window` builds the timestamp axis from observed timestamps (no calendar grid);
  the NBBO resampler must build its own regular session grid instead (D-09/D-13).
- There is no trading-calendar library; session handling is the ET session-date hive key only.

### Integration Points
- `quantlab/enums/data.py` (Frequency extension, D-08), `registry.py` (D-17), `universe.py` guard
  (D-16), new `quantlab/acquisition/wrds_taq.py`-style module, new NBBO Dataset under
  `quantlab/dataset/`, new `scripts/ingest_wrds_taq.py`, docs under `example/`.

  raw NBBO records means frequency/fields can change later without re-pulling from WRDS.

  correctness risk of this phase.
