# Phase 03.9 Plan 05: NBBO resampler semantics Summary

The resampler now implements the full semantics, each locked by a hand-computed fixture. Filtering is configurable, and every dropped record is counted per (date, symbol). A NULL side is NaN, and each time-weighted average divides by the time its own variable was defined. Ties are ordered by the D-19 key and collapsed, and a per-bar ambiguous-tie count shows where that order was ambiguous. Bars are right-closed and a ragged grid is rejected. State never carries from one date to the next.

## What was built

- **`NbboFilterPolicy`**: a frozen dataclass whose defaults are the D-10 defaults (`drop_crossed=True`, `drop_locked=False`, `drop_nonpositive_price=True`, `keep_qu_cond=None`). `from_config(config)` builds it from the config. `reason()` returns one expression that gives each record its drop reason, taking the first match in precedence order. Crossed and locked are only evaluated when both sides are present.
- **`NbboDatasetConfig`**: gains the same four fields, so a rebuild from `config.json` reproduces the filter.
- **`NbboResampler.resample_with_stats(records, sessions) -> (panel, stats)`** runs in this order:
  1. Normalise the input, nulling the size of a NULL side.
  2. Take the input (symbol, date) pairs.
  3. Filter, and build the stats.
  4. Apply the stable total order and join the sessions.
  5. Count ambiguity per instant.
  6. Aggregate `n_updates` and `n_ambiguous_ties` per bar.
  7. Collapse ties with `unique(keep="last", maintain_order=True)`.
  8. Seed.
  9. Build the per-variable value and coverage integrals.
  10. Do the as-of join on a grid built from the pre-filter pairs.
  11. Compute the TW values as ΔF/ΔG, null when ΔG is 0.

  `resample()` keeps its plan-01 signature and returns the panel only.
- **Stats frame**: `date, symbol, records_in, dropped_nonpositive_price, dropped_condition, dropped_crossed, dropped_locked, one_sided_kept, both_null_kept`. Every count is Int64. It is ready for plan 06's sidecar.
- **Grid**: `_edges` raises `ValueError` for a session that is not a whole, positive number of `bar_interval` bars. The error names the date and the interval.
- **Docstrings**: the module docstring covers filter-first, NULL-side-as-NaN and carry-as-state. The class docstring covers the D-19 order, tie collapse and the ambiguity facts (2018+ unique per L-4; about 5% ambiguous in 2016).

`quantlab/dataset/nbbo.py` was not touched, as the plan requires. `cleaning.py` also needed no change. Its module docstring already listed `clean_nbbo_panel` as the fourth entry point, and it already met every validation test.

## Deviations from Plan

**1. [Rule 2 - Correctness] A NULL side's size is nulled**
- **Found during:** Task 1.
- **Issue:** the plan says a NULL side's price and size are NaN. The input can carry a 0 size beside a NULL price.
- **Fix:** `_normalise` nulls the size whenever its price is null or NaN, so the TW size coverage stays correct.
- **Commit:** 0c301db

**2. [Rule 2] `keep_qu_cond` guard**
- **Issue:** a bare string like `"R"` would silently be iterated as characters.
- **Fix:** the policy raises on a bare string, and it normalises a JSON-round-tripped list to a tuple.
- **Commit:** 0c301db

**3. [Rule 1/key link] One variable definition**
- **Issue:** `PANEL_VARIABLES` in the resampler duplicated `NBBO_PANEL_VARIABLES`, and the plan's key link requires one definition.
- **Fix:** it is now imported from `cleaning.py`.
- **Commit:** 0a5703c

**4. The all-dropped-pair grid was built from pre-filter pairs in Task 1, not Task 3**
- **Issue:** `resample_with_stats` needed the input pairs for its stats anyway.
- **Effect:** Task 3's test for this passed on first run.

**Total deviations:** 4 (2 Rule 2, 1 Rule 1, and 1 change of order). **Impact:** none on scope.
