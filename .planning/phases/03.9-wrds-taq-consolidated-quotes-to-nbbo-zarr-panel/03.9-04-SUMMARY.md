# Phase 03.9 Plan 04: WRDS provider hardening Summary

**The WRDS TAQ NBBO provider now reads its password only through libpq's pgpass file and checks that file before connecting. It also refuses env vars that could redirect the connection and connects once per session, never again after a break. An unentitled year fails before any COPY. Raw pages keep the same schema across eras and preserve arrival order, each page's rows are checked against a count(*) with the same WHERE, and a per-(day, batch) count probe feeds the volume guard.**

## Accomplishments

- **Task 1: credentials and connection (D-07, D-20, D-21).**
  - `WrdsSession._assert_pgpass_entry` checks that `$PGPASSFILE` or `~/.pgpass` exists, is a regular file and has mode `& 0o077 == 0`. It also needs one line matching host:port:db:user, with `*` wildcards and `\:` escapes allowed.
  - Only fields 1-4 are parsed (`_pgpass_fields` stops at the 4th colon), so the password is never bound to a name. Messages refer to `$WRDS_USERNAME` and never contain the password or the username value.
  - `REFUSED_ENV` (PGHOSTADDR, PGSERVICE, PGSERVICEFILE) is refused before connecting. PGHOST is ignored because the pinned host is always passed explicitly.
  - `_connect_attempted` is set before `psycopg2.connect`, and any `psycopg2.Error` marks the session broken and becomes `WrdsSessionError`. After that, calls fail without reconnecting.
  - `_classify_error` returns "quota" (a global stop) for session, entitlement, OperationalError and InterfaceError.
- **Task 2: raw schema, SQL shape and symbols (D-02/03/05/15/18/19/25).**
  - The SELECT follows `TAQ_COLUMNS` order, taking only the columns the server has. If a required column is missing, the page raises ValueError.
  - Pages from 2016 and 2024 have identical schemas, with `time_m_nano` as a typed-null Int16 before 2018.
  - `symbol_to_pair` refuses hyphens (and says to use dot notation), more than one dot, and an empty root or suffix. The check runs before any query.
  - `_assert_page_belongs` fails the page when a row belongs to an unrequested (root, suffix) pair, or when its `date` or ET session date differs from the table's day.
  - NULL bid/ask sides stay null. Crossed and locked records, and ties within the same microsecond, are all kept in arrival order.
- **Task 3: resume, entitlement and probe (D-06, D-21, D-24).**
  - `has_schema_usage`, `assert_entitled`, `count_query` and `count_rows` are added to the session.
  - The `_run` override checks entitlement for every year of the window before any batch is dispatched. An unentitled year raises `WrdsEntitlementError` naming `taqm_YYYY` and the subscription; no COPY runs and nothing is written to the manifest.
  - `verify_page_counts` (default True) runs a count(*) with the same WHERE before each COPY. A mismatch raises a per-batch ValueError that names the day and both numbers, and the next run re-fetches that day.
  - `WrdsNbboVolumeProbe.count_rows_by_day` checks entitlement first. It then counts each (trading day, batch), using the same chunking as `Acquisition._batches` and the same WHERE as the COPY, and refuses an empty batch.
  - Resume works at day-page granularity: a per-batch failure on day k resumes at day k, and a `WrdsSessionError` sets `quota_aborted`, writes no manifest entry, and also resumes at day k.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Credential/env pre-check failures raise `WrdsSessionError`, not plain `RuntimeError`**
- **Found during:** Task 1
- **Issue:** A plain RuntimeError would be classified "failed", so a missing pgpass reached inside a batch would put every symbol in the manifest.
- **Fix:** `WrdsSessionError` subclasses RuntimeError, so the plan's `pytest.raises(RuntimeError)` contract still holds and the failure is a global stop.
- **Files modified:** quantlab/acquisition/wrds_taq.py
- **Commit:** 18d8f84

**2. [Rule 1 - Bug] `has_schema_usage` does not use the name form of `has_schema_privilege`**
- **Found during:** Task 3
- **Issue:** `has_schema_privilege('taqm_YYYY','USAGE')` raises for a schema that does not exist. That driver error would break the single session, so "a missing schema counts as not entitled" could not hold.
- **Fix:** The query is `SELECT has_schema_privilege(oid, 'USAGE') FROM pg_namespace WHERE nspname = %s`. When no row comes back, the year counts as not entitled.
- **Commit:** 2ae53ef

**3. [Rule 3 - Blocking] `copy_expert` receives the Composable, not `as_string(conn)`**
- **Found during:** Task 1
- **Issue:** `as_string` needs a real connection's quoting context, so it cannot run against a `FakeConnection`.
- **Fix:** Since psycopg2 2.7, `copy_expert` accepts a Composable and renders it against the cursor's own connection (the C extension carries `as_string`/`Composable` handling). Live behaviour is the same.
- **Commit:** 18d8f84

**4. [Rule 2] The COPY's CSV header must equal the requested columns**
- **Found during:** Task 2
- **Fix:** A cheap guard in `_fetch_page` against a server answering with a different column list.
- **Commit:** a091d3f
