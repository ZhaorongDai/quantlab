# Phase 03.9: WRDS TAQ Consolidated Quotes to NBBO Zarr Panel - Research

**Researched:** 2026-09-19
**Domain:** WRDS PostgreSQL (NYSE Daily TAQ millisecond product) acquisition, NBBO event-to-bar resampling, dense xarray/Zarr panel
**Confidence:** MEDIUM overall. The codebase integration is HIGH (read in full this session). The WRDS table schema is MEDIUM: it rests on third-party code that ran against WRDS, and no live probe was possible. The tie-breaker is LOW until the live checks run.

## Summary

WRDS serves TAQ millisecond data on PostgreSQL in per-year schemas `taqm_YYYY` (2003-2026). Each schema holds daily tables. The unified `taqmsec` schema holds the same tables. For NBBO there are two per-day tables: `nbbom_YYYYMMDD` (the SIP's NBBO file) and `complete_nbbo_YYYYMMDD` (WRDS's "Official Complete NBBO"). **Both carry the full NBBO state (best bid, best ask and both sizes) on every row. The difference is completeness, not "one side vs both".** `nbbom` misses every instant where a single exchange's quote became both the NBB and the NBO, because the SIP flags that case only in the quote file (`cqm`). `complete_nbbo` merges those quote-file records back in, following Holden & Jacobsen (2014). **Use `complete_nbbo_YYYYMMDD`** (D-01, Claude's discretion). Its columns as observed in working third-party queries: `date, time_m, time_m_nano, sym_root, sym_suffix, qu_cond, best_bid, best_bidsizeshares, best_ask, best_asksizeshares`. **Whether it also carries `qu_seqnum` is unverified**, and that is the phase's central open question (D-03).

Two findings change how the provider has to be built:
1. **`wrds.Connection.raw_sql()` is broken in this environment.** `pandas 3.0.5` plus `SQLAlchemy 1.4.54` (which `wrds 3.1.6` pins as `<2`) raises `AttributeError: 'Connection' object has no attribute 'cursor'`. This was reproduced offline this session.
2. **`wrds.Connection.connect()` falls back to `input()`/`getpass()`** and then offers to write `.pgpass`, which D-07 forbids.

The provider should therefore **use the `wrds` package only for its pinned host/port/db/SSL constants and connect with `psycopg2` directly.** `psycopg2` is already installed as a `wrds` dependency, reads `~/.pgpass` through libpq, and never prompts. Each WRDS connection can trigger a Duo push, so the design needs **one long-lived session per run and `max_workers=1`**.

On the quantlab side the phase fits the existing machinery **without extending the locked `Frequency` literal**:
- Raw NBBO lands as `frequency="tick"`, `kwargs["data_type"]="nbbo"`. It reuses the tick hive layout `data_type=/date=/symbol=`, the per-data-type watermark namespacing, `_clear_superseded_shards`, and a registry `Capability(market="us_equity", frequency="tick", data_type="nbbo", dataset_cls=<NBBO dataset>)`. That makes `registry.convert()` work with zero changes.
- The panel frequency (D-08) is a **separate `bar_interval` parameter** on a new `DatasetConfig` subclass, validated against a new small literal. It is not a new `Frequency` token.
- One `_fetch_page` call = one trading day's `complete_nbbo_YYYYMMDD` table for one symbol batch. `page_token` is the next trading day's ISO date, so `PageLedger` resumes by day for free.
- The resampler is vectorised polars: a total-order sort, tie collapse, an as-of join of grid edges, and cumulative integrals for the time-weighted averages. It was prototyped and hand-verified this session.

**Primary recommendation:**
- Build `WrdsTaqNbboAcquisition` (tick, data_type `nbbo`, one psycopg2 session, one page per trading day, `COPY (SELECT ...) TO STDOUT` into polars).
- Build `NbboPanelDataset(StockDataset)`. It reads raw by session date and resamples in polars onto a per-day session grid from a `SessionCalendar` seam.
- Keep `Frequency` untouched.
- Before any code, gate the phase on a **live WRDS schema/uniqueness checkpoint** run by the user (the checklist is at the end of this document).

## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Source & raw layer
- **D-01:** Acquire WRDS's **NBBO record table** (the millisecond TAQ product's NBBO tables — e.g.
  `taqm_YYYY.nbbom_YYYYMMDD` / `complete_nbbo_YYYYMMDD`; researcher must confirm which table carries
  the full NBBO state per row and its exact schema on WRDS PostgreSQL). Each row is the national best
  bid/offer at that instant. Not the per-exchange `cqm_*` quotes (an order of magnitude larger).
  — **Reversibility:** costly — switching tables changes the raw schema, the shard layout and every
  test fixture; data already pulled would have to be re-pulled.
- **D-02:** Raw records land in parquet **as-is, one row per NBBO record**, including every ordering
  field WRDS provides (`time_m`, `time_m_nano`, and the sequence-number field such as `qu_seqnum`),
  plus the original `sym_root` / `sym_suffix`. No server-side resampling or aggregation.
- **D-03 (ordering, from the WRDS PROC SQL note):** Server-side SQL is `SELECT ... WHERE` only —
  **no `GROUP BY`, no `SELECT DISTINCT`, no reliance on physical row order**. On PostgreSQL there is
  no order guarantee at all without `ORDER BY`, so the SAS-era "plain select preserves order" result
  does NOT carry over. Record order is re-established **locally** by a total order key
  `(date, symbol, time_m, time_m_nano, <seqnum>)`. Researcher must verify on WRDS that this key is
  unique per symbol-day; if it is not, the plan must name the tie-breaker and lock it with a test.
  "Last NBBO in a bar" is always defined by this key, never by arrival order.
- **D-04:** Collection covers the **full day** (pre-market through after-hours) — session trimming
  happens only in the resampler (D-09).
- **D-05:** Anomalous records (crossed bid>ask, locked bid=ask, zero price/size, abnormal condition
  codes) are **kept in raw**; filtering happens only in the resampler (D-10).
- **D-06:** Batching follows WRDS's access pattern: one **daily table × a batch of symbols**
  (`WHERE sym_root IN (...)`), since TAQ tables are indexed/sorted by symbol. Raw hive layout reuses
  the existing intraday conventions (`date=` = US/Eastern session date, `SESSION_TIME_ZONE =
  "America/New_York"`, timestamps naive UTC `Datetime("ns")`), with a `data_type` value for NBBO.

#### Credentials
- **D-07:** Username from env var `WRDS_USERNAME`; password from `~/.pgpass` (the `wrds` library's
  standard mechanism). No credential ever in `AcquisitionConfig`, logs, or exception messages
  (`CREDENTIAL_ENV_VARS` + `_scrub`). The provider must never trigger `wrds`'s interactive
  password prompt or offer to create `.pgpass` — missing credentials fail fast with an actionable
  message.

#### Local resampling & Zarr panel
- **D-08:** Resample **frequency is a parameter** (e.g. `1s`, `5s`, `1m`, `5m`), not hard-coded 1m.
  This requires extending the locked `Frequency` literal (`quantlab/enums/data.py`) and every table
  keyed on it (`RAW_HIVE_KEYS`, `HIVE_SCHEMA_BY_FREQUENCY`, `BARS_PER_DAY_BY_FREQUENCY`, chunking docs).
  The planner decides whether the resample frequency is a new token family or a separate
  "panel frequency" parameter distinct from the raw acquisition frequency (raw NBBO is event data,
  i.e. `tick`-like). — **Reversibility:** costly — `Frequency` is a shared locked literal consumed by
  config, acquisition, dataset and registry.
- **D-09:** Panel defaults to **regular trading hours 09:30–16:00 ET**; the session window is
  configurable. Bars are built on a regular grid within the session.
- **D-10:** Resampler filtering is **configurable**; default drops crossed quotes and zero/missing
  prices, keeps locked quotes. Counts of dropped records are recorded (per run, and inspectable).
- **D-11:** Bar semantics — **both**:
  - point-in-time snapshot = the last valid NBBO at or before bar end (by the D-03 order key; no
    look-ahead),
  - time-weighted averages over the bar of spread and depth (record duration = time until next
    record; tied timestamps have zero duration, so only the last record of a tie carries weight).
- **D-12:** Panel variables: `bid`, `ask`, `bid_size`, `ask_size`, `mid`, `spread`, relative spread in
  bps, **NBBO update count** per bar, **order imbalance** `(bid_size-ask_size)/(bid_size+ask_size)`,
  plus the time-weighted spread/depth of D-11. Exact variable names are the planner's choice
  (consistent style with existing Dataset variables).
- **D-13:** Empty bars (no NBBO update) **carry forward** the previous NBBO, update count = 0;
  **never carry across trading days**; bars before the day's first valid NBBO are NaN.
- **D-14:** The NBBO Dataset overrides `_clean` (the default `clean_market_data` requires OHLCV
  columns — `quantlab/dataset/cleaning.py:38`), following the `clean_membership_panel` precedent.

#### Symbols & universe
- **D-15:** Symbol = `sym_root` + `sym_suffix` joined in the **universe's notation** (e.g. `BRK.B`),
  with raw `sym_root`/`sym_suffix` columns retained. Universe = existing point-in-time
  `sp500_constituent` / `nasdaq100_constituent` via `UniverseCatalog.get_symbols_in_range`; date range
  via CLI arguments. Membership tickers are period-correct, matching TAQ's period-correct symbols.

#### Volume guard
- **D-16:** SQL-shaped guard: before pulling, run `count(*)` per daily table for the requested
  symbols, estimate total rows and disk bytes, refuse above ceilings unless `--force-volume` (same
  flag contract as the existing guard, `tests/test_volume_guard.py`). The REST requests/min model
  does not apply to WRDS. Must respect the rule that `universe.py` imports no acquisition module.

#### Integration
- **D-17:** Register a `SourceDescriptor` (vendor `"wrds"`, `required_env=("WRDS_USERNAME",)`,
  capability with the NBBO dataset class) in `quantlab/acquisition/registry.py`, and add a CLI entry
  `scripts/ingest_wrds_taq.py` following `scripts/ingest_alpaca.py`.

**Decision (D-01 discretion): use `taqm_{YYYY}.complete_nbbo_{YYYYMMDD}`.**
- Reason: it is the only NBBO table that contains every NBBO state change. Resampling `nbbom` would silently hold a stale NBBO whenever a single venue set both sides. That case is not rare (Mengjie Xu measured 37.63% of their sample's pre-trade NBBO records as quote-only).
- The per-year schema is preferred over `taqmsec` because it is what every observed working query uses. Make the schema pattern a class constant so the live check can flip it.
- If live check L-2 shows `complete_nbbo` has **no** sequence number, see §Ordering fallback. Do not switch to `nbbom` for its `qu_seqnum`: the completeness loss is worse than an unresolvable tie.

### Pattern 1: One page = one trading day's table for one symbol batch
**What:** `_fetch_page(symbols, start, end, page_token)` resolves the ordered list of trading days in `[start, end]` (cached per instance). It fetches `page_token or days[0]` and returns `(frame, next_day_iso or None)`.
**Why:** the base `_fetch_batch` loop already provides:
- shard-before-ledger ordering;
- deterministic names `part-{batch_key}-{page_index:05d}.pqt`;
- resume at `PageLedger.resume_point()`, which returns the recorded `next_token` verbatim [VERIFIED: quantlab/base/pageledger.py:226-238];
- the repeated-token guard.

A crash mid-backfill resumes at the interrupted day. Watermarks are written per symbol only after the whole batch completes (base behaviour).
**Trading days:** `SELECT table_name FROM information_schema.tables WHERE table_schema = %s AND table_name ~ '^complete_nbbo_[0-9]{8}$'`, once per year schema in the window. Do not iterate calendar days and catch `UndefinedTable`: a missing table then looks the same as a holiday.
**Batch size / workers:** `DEFAULT_BATCH_SIZE = 25` [ASSUMED: working value, sized so one page is a few million rows], overridable via `kwargs["batch_size"]`. `DEFAULT_MAX_WORKERS = 1`, because one session means one Duo push (see Pattern 2). The base default is 8 [VERIFIED: base/acquisition.py:466].

### Pattern 2: `WrdsSession`: never prompt, never a second connection
**What:** a transport class, the analog of `_AlpacaMarketDataClient` (alpaca.py:71-145). Its behaviour:
1. `__init__` makes no network call. It reads `WRDS_USERNAME` (missing → `RuntimeError` naming the variable).
2. It pre-checks the password file: `$PGPASSFILE` or `~/.pgpass` must exist, have mode `& 0o077 == 0` (libpq ignores group/world-readable files on Unix [ASSUMED: libpq behaviour, documented in the PostgreSQL manual]), and contain a line matching `host:port:db:user` with `*` wildcards and `\:` escapes. On failure it raises an actionable message **without reading the password into any string that could be logged**. Parse only the first four fields.
3. It connects lazily on first use: `psycopg2.connect(host=WRDS_POSTGRES_HOST, port=WRDS_POSTGRES_PORT, dbname=WRDS_POSTGRES_DB, user=user, sslmode="require", application_name=..., connect_timeout=...)`. There is **no `password=` argument**, so libpq uses .pgpass. The host is **pinned**: it is not read from config and `PGHOST` is not honored. `wrds.Connection` honors `PGHOST` (`wrds/sql.py:66-68`), which would turn an env var into a place credentials get sent.
4. `fetch_nbbo_day` runs `COPY (SELECT …) TO STDOUT WITH (FORMAT csv, HEADER true)` via `cursor.copy_expert` into a `tempfile.SpooledTemporaryFile`, then `pl.read_csv(..., schema_overrides=...)`. Identifiers are built with `psycopg2.sql.Identifier(schema, table)` and values with `psycopg2.sql.Literal(list_of_roots)` (verified offline: composition works without a connection).
5. **Process-level reuse:** the CLI builds one session, and the probe and the acquisition share it. Otherwise the volume probe and `registry.run` would each connect, meaning two Duo pushes. `registry.run` constructs `acquisition_cls(config)` itself, so provide `WrdsSession.shared(user)`, a process-level cache keyed by username, and have the acquisition use it.

Facts from the source read this session:
- `wrds.Connection.connect()` → on failure `__get_user_credentials()` → `input("Enter your WRDS username …")` + `getpass.getpass(...)`; after success it asks `input("Create .pgpass file now [y/n]?: ")` [VERIFIED: .venv/.../wrds/sql.py:111-135, 198-215]. **Never instantiate `wrds.Connection`.**
- Duo: "the user will receive a push request when attempting to connect to PostgreSQL … This includes using the WRDS Python module". Non-push users: "This username/IP combination will be valid for 30 days after a successful MFA" [CITED: wrds-www.wharton.upenn.edu/pages/about/log-in-to-wrds-using-two-factor-authentication/multi-factor-authentication-for-sasconnect-and-postgresql/].
- Per-user concurrent connection limit: **not published** (no public doc found). Treat it as unknown and read it live (L-7).

### Pattern 3: Raw schema: a pinned superset with typed nulls
`RAW_COLUMNS` must be identical for every shard (base contract, base/acquisition.py:436-447 docstring). The `complete_nbbo` column set varies by year (no `time_m_nano` before ~2015-16). So:
- Introspect once per table: `SELECT column_name, data_type FROM information_schema.columns WHERE table_schema=%s AND table_name=%s`. Cache per schema-year, since the columns of one year's daily tables are presumably uniform [ASSUMED].
- SELECT only the columns that exist. Add the absent ones as typed nulls locally.
- **Do not name any raw column `date` or `data_type`.** `_write_shard` derives the hive keys with `with_columns(... .alias(key))` and then `group.drop(keys)` [VERIFIED: base/acquisition.py:990-1000, 1104-1115]. A raw `date` column would be silently overwritten by the session date and then dropped. Rename TAQ `date` → `taq_date`, or drop it and assert equality (see the next paragraph).

Proposed projection [ASSUMED until L-1/L-2]: `timestamp` (Datetime ns, naive UTC), `symbol`, `vendor`, `taq_date` (Date), `sym_root`, `sym_suffix` (String, nullable), `time_m` (Time), `time_m_nano` (Int16, nullable), `qu_seqnum` (Int64, nullable), `best_bid`, `best_ask` (Float64), `best_bidsizeshares`, `best_asksizeshares` (Float64, matching Alpaca quotes' float sizes), `qu_cond`, `nbbo_qu_cond`, `natbbo_ind` (String, nullable). `symbol` is written as a path segment only (tick layout drops it from the file; `StockDataset.DERIVED_HIVE_KEYS = ("month", "date", "data_type")` keeps `symbol` [VERIFIED: dataset/stock.py:51]).

**Timestamp reconstruction:** `ts_et = taq_date + time_m + time_m_nano ns` → `replace_time_zone("America/New_York", ambiguous="raise", non_existent="raise")` → `convert_time_zone("UTC")` → `replace_time_zone(None)`. Add a per-row guard that the derived session date equals the table date. That catches a unit or timezone bug at write time. `time_m_nano` is assumed to be the 0-999 ns remainder beyond `time_m`'s microseconds [ASSUMED from pytaq's description; live check L-3].

### Pattern 4: The resampler: total order, tie collapse, as-of snapshot, cumulative integrals
Prototyped and hand-checked this session on polars 1.44.1. The prototype is in the scratchpad and is not committed; its algorithm is reproduced below. It exercised:
- a tie at one instant (the last row by seq wins);
- a pre-open seed;
- a record exactly on a bar edge (right-closed);
- a symbol with no NBBO until mid-bar (NaN, then partial coverage);
- carry-forward over an empty bar.

The asserted values all matched: `tw_spread` 0.225, updates `[3,1,0]`, and NaN then 0.5 for the late symbol.

Per `(symbol, session_date)`, never across dates (D-13):
1. **Filter** (D-10), counting drops per reason. Defaults: drop `bid > ask` (crossed); drop null or `<= 0` price on either side; keep `bid == ask` (locked). Optional knobs off by default: `keep_qu_cond` allow-list (Holden–Jacobsen use `["A","B","H","O","R","W"]` [CITED: pytaq/hj_defaults.py]), `max_spread` ($5 with a $2.50 quote-change rule in H&J), `drop_locked`. A dropped record leaves the previous valid NBBO standing, which is the same as H&J's "deleting leaves the venue's previous quote standing".
2. **Total order:** sort by `(symbol, session_date, timestamp_ns, qu_seqnum)` with `maintain_order=True` (see §Ordering for the fallback when `qu_seqnum` is null). **Never rely on `StockDataset._scan_raw`'s order.** It sorts `["timestamp","symbol"]` only, and polars `sort` is not stable by default [VERIFIED: dataset/stock.py:473].
3. **Update counts** per bar come from the post-filter rows before collapse. Every tied message is one update.
4. **Tie collapse:** `unique(subset=[symbol, date, timestamp], keep="last", maintain_order=True)`. The last row by the total key is the NBBO after that instant, and its predecessors in the tie have zero duration (D-11).
5. **Seed:** the last record at or before `session_open` is moved to `session_open`. This is the true NBBO state at the open (full-day collection, D-04). Records after `session_close` are dropped.
6. **Cumulative integrals:** `dur_i = next_ts - ts_i` (last: `session_close - ts_i`). `C_x = exclusive cum_sum(x * dur)` for x in {spread, bid_size, ask_size, spread_bps}, and `C_t = exclusive cum_sum(dur)`.
7. **Grid edges** `e_0 = open, e_1..e_N` (right-closed bars `(e_{k-1}, e_k]`, labelled at `e_k`). `join_asof(strategy="backward", by=[symbol, date])` onto records: snapshot = matched row; `F_x(e) = C_x + x*(e - ts)`; `G(e) = C_t + (e - ts)`.
8. **TW average of bar k** = `ΔF_x / ΔG`. Dividing by covered time rather than bar length is what makes a bar where the first NBBO arrives mid-bar correct. Bars with no record at or before `e_k` are NaN (D-13). Empty bars carry forward automatically and get `n_updates = 0`.
9. **Derived snapshot variables:** `mid`, `spread`, `spread_bps = 1e4*spread/mid`, `imbalance = (bid_size-ask_size)/(bid_size+ask_size)`, and optionally `quote_age` (seconds since the matched record: a staleness signal for carried-forward bars).

```python
# Source: prototype verified this session (polars 1.44.1); abbreviated
r = recs.sort(["symbol", "date", "ts", "seq"], maintain_order=True)
r = r.unique(subset=["symbol", "date", "ts"], keep="last", maintain_order=True)
nxt = pl.col("ts").shift(-1).over(["symbol", "date"]).fill_null(session_close)
r = r.with_columns(dur=(nxt - pl.col("ts")).dt.total_nanoseconds().cast(pl.Float64))
r = r.with_columns(
    (pl.col("spread") * pl.col("dur")).cum_sum().shift(1, fill_value=0.0).over(["symbol", "date"]).alias("C_spread"),
    pl.col("dur").cum_sum().shift(1, fill_value=0.0).over(["symbol", "date"]).alias("C_t"),
)
j = grid.sort(["symbol", "date", "edge"]).join_asof(
    r.rename({"ts": "rec_ts"}), left_on="edge", right_on="rec_ts",
    by=["symbol", "date"], strategy="backward")
el = (pl.col("edge") - pl.col("rec_ts")).dt.total_nanoseconds().cast(pl.Float64)
j = j.with_columns(F=pl.col("C_spread") + pl.col("spread") * el, G=pl.col("C_t") + el)
d = lambda c: pl.col(c) - pl.col(c).shift(1).over(["symbol", "date"]).fill_null(0.0)
j = j.with_columns(tw_spread=d("F") / d("G"))
```
Numerical note: `F` reaches ~2e13 for a 6.5 h session in ns. At float64 precision, the error after `/ΔG` is below 1e-11 for 1 s bars. This is acceptable [VERIFIED by arithmetic; exact in the prototype].

**Session grid:** the `SessionCalendar` seam returns `(open_utc, close_utc)` per session date. It localizes `date + 09:30` and `date + 16:00` in `America/New_York`, so DST is correct per date, and uses the calendar's early close on half days. The grid label set for the store = the concatenation over the session dates present in raw. `D-09` configurability: `session_start`/`session_end` on the config. The calendar's early close caps `session_end`.

**Why a calendar is required:** raw collection runs to 20:00 ET (D-04). On a 13:00-close half day, a fixed 16:00 grid would treat 13:00-16:00 **after-hours** quotes as in-session state. The result is a plausible but wrong panel.

### Ordering (D-03): key, fallback, and the lock test
- **Primary total key:** `(taq_date, sym_root, sym_suffix, time_m, time_m_nano, qu_seqnum)`. Locally this is `(symbol, date, timestamp_ns, qu_seqnum)`.
  - The NBBO/quote files are "sorted by symbol, time, and message sequence number" [CITED: NYSE spec v4.3 §4, §6], so (time, seqnum) reproduces file order.
  - Sequence numbers are per SIP: "For Tape C symbols (published by the UTP SIP) … incrementing by 1 with every message. For Tape A and B symbols (published by the CTA SIP) … (CTA Block Sequence Number * 100) + CTA Message ID", which "do not increase continuously" [CITED: NYSE spec v4.3 §1.5.3].
  - A symbol belongs to one tape, so within a symbol-day all seqnums come from one SIP. Cross-tape collisions are therefore irrelevant for a per-symbol key [ASSUMED: CTA line reassignment mid-day would break monotonicity; this is exactly what L-4 measures].
- **Evidence on ties:** at microsecond precision, 0.67% of AAPL NBBO rows (2020-01-02) share an instant. "Nanoseconds resolve every one" [CITED: pytaq TO_VERIFY.md]. In 2016 (pre-ns), WRDS `complete_nbbo` had 20,926 of 569,448 AAPL rows sharing a timestamp (3.7%) [CITED: same]. **Ties are real for pre-Oct-2016 data. The tie-breaker matters there, and nanoseconds alone suffice after.** [the "after" part is a single symbol-day; ASSUMED in general]
- **Fallback when `qu_seqnum` is absent or null, or when `(…, qu_seqnum)` is still not unique:** order the remaining ties deterministically by `(best_bid, best_ask, best_bidsizeshares, best_asksizeshares)`. Record the number of ambiguous tie groups per symbol-day in the filter-stats sidecar as `ambiguous_ties`. Do **not** use PostgreSQL `ctid`: it is physical placement, and WRDS may serve these as views or foreign tables (the `wrds` library enumerates foreign tables, `wrds/sql.py:398-403`). The deterministic fallback only affects the snapshot when two different NBBOs share one timestamp **and** that timestamp is the bar's last. TW averages are unaffected, because tied rows have zero duration except the last one.
- **Lock test** (offline): a fixture with a 3-row tie where the rows arrive in a shuffled physical order. It asserts the snapshot and `C_x` take the max-`qu_seqnum` row, and that the result is invariant to 20 random input permutations. A second fixture with `qu_seqnum` null asserts the deterministic fallback plus an `ambiguous_ties` count of 1.

### Anti-Patterns to Avoid
- **Instantiating `wrds.Connection`.** It can prompt, offer to write `.pgpass`, honor `PGHOST`, and its `raw_sql` is broken under pandas 3.
- **One connection per batch or per worker.** Each connect may push Duo to the user's phone.
- **Server-side `ORDER BY`, `GROUP BY`, `DISTINCT`, or window functions** (D-03). Also, never sort locally by timestamp alone.
- **Iterating calendar days and catching `UndefinedTable`.** A missing table (permission, not-yet-loaded) becomes an indistinguishable "holiday".
- **Using `_scan_raw(start, end)` for NBBO windows.** It drops the pre-open seed and cuts the session at the window edges.
- **A raw column named `date`**, which is silently replaced by the hive key.
- **A fixed 16:00 close on half days.**
- **Filling NBBO in `cleaning.py`.** Carry-forward is resampler semantics only.
- **Any automated test that can reach `psycopg2.connect`** (see the guard fixture below).

## Common Pitfalls

### Pitfall 1: Automated tests reach WRDS
**What goes wrong:** `tests/test_acquisition_batching.py::_concrete_acquisition_subclasses` imports **every** module in `quantlab/acquisition` and walks every concrete `Acquisition` subclass. `test_every_concrete_acquisition_subclass_reaches_the_vendor_via_fetch_batch` then constructs each one and calls `download()`, mocking only Tiingo and Alpaca [VERIFIED: tests/test_acquisition_batching.py:356-457]. The new WRDS class will be picked up automatically.
**How to avoid:**
- Add an **autouse** conftest fixture that monkeypatches `psycopg2.connect` (and `wrds.Connection`) to raise `AssertionError("network to WRDS in a test")`.
- Add a `mock_wrds_session` fixture (a `FakeWrdsSession` serving polars frames per `(day, roots)`, plus a fake trading-day list and counts).
- Extend those tests and the `acquisition_config` fixture to the `wrds` vendor with `frequency="tick", kwargs={"data_type":"nbbo"}`.
- Add `"WRDS_USERNAME"` to `_CREDENTIAL_ENV_NAMES` (tests/conftest.py:133-137) and `_CHILD_CREDENTIALS` (tests/test_source_registry.py). Point `PGPASSFILE` at a tmp file in tests.
**Warning signs:** a test run that hangs at connect, or a Duo push during `pytest`.

### Pitfall 2: The `wrds` library's own connection path
**What goes wrong:** interactive prompts or a `.pgpass` write offer (D-07 violation). `raw_sql` crashes under pandas 3.
**How to avoid:** use psycopg2 only. Add an AST test asserting `wrds_taq.py` never references `Connection` from `wrds` and imports only `wrds.sql` constants.

### Pitfall 3: `complete_nbbo` schema drift across years
**What goes wrong:** pre-2015/16 tables lack `time_m_nano`, and possibly other columns. A pinned `RAW_COLUMNS` then fails, or a shard lands with a different schema and makes the whole root unreadable.
**How to avoid:** use per-table column introspection plus typed nulls. Fixture tests cover a "2012-shaped" table without `time_m_nano`.

### Pitfall 4: numeric/Decimal and `time` types
**What goes wrong:** prices arrive as `Decimal`/object and `time_m` as `datetime.time` or text.
**How to avoid:** use COPY CSV text with explicit polars parsing (`Float64` prices, `str.to_time("%H:%M:%S%.f")`). CSV of numeric is exact decimal text, so the Float64 conversion is the only rounding, which matches the rest of the raw tier.

### Pitfall 5: Session-date vs window mismatch
**What goes wrong:** the planner's windows are UTC timestamps. The pre-open seed rows lie before the window start. With a custom session reaching 20:00 ET, the labels cross into the next UTC date.
**How to avoid:** resample whole session dates, then slice labels. Scan by the `date` hive key.

### Pitfall 6: Default ceilings refuse any realistic pull
**What goes wrong:** at 20 GiB, S&P 500 NBBO fits roughly 1-3 weeks. The first user run is refused.
**How to avoid:** print the estimate (the `print_volume_estimate`-style shape) and make the ceilings `config.kwargs` knobs. Document expected sizes in `example/wrds_taq.md`.

### Pitfall 7: Pre-existing red tests mask regressions
**What goes wrong:** the baseline suite has **55 failures before this phase** (1250 passed, 1 skipped; `uv run pytest -q --ignore=tests/test_factor_hierarchy.py`, measured this session). They are concentrated in `test_ingest_shells.py` (14), `test_ingest_tiingo_universe_wiring.py` (11), `test_ingest_conversion_gate.py` (6), `test_volume_guard.py` (5), `test_spot_dataset.py` (2) and `test_universe.py` (1). The cause is commit `d07f06e` moving `ingest_*.py` into `scripts/` while the tests still open `"ingest_tiingo.py"` etc. relative to the repo root. For example, `INGEST_SCRIPTS = ("ingest_tiingo.py", "ingest_us_equity.py", "ingest_alpaca.py")` [VERIFIED: tests/test_volume_guard.py:913] fails with `FileNotFoundError: [Errno 2] No such file or directory: 'ingest_tiingo.py'` (observed).
**How to avoid:** the phase gate is "no new failures vs. the 55-failure baseline", not "suite green". Alternatively, a Wave-0 task fixes the script paths first (ask the user; it is outside the phase scope). The new script's structural tests should use `scripts/ingest_wrds_taq.py` paths directly.

### Pitfall 8: `join_asof` sortedness
**What goes wrong:** with `by=` groups, polars cannot verify sortedness ("UserWarning: Sortedness of columns cannot be checked when 'by' groups provided", observed) and silently returns wrong matches on unsorted input.
**How to avoid:** always sort both sides by `(by…, on)` immediately before the join. A test shuffles input rows.

### .pgpass pre-check without touching the password
```python
# Source: libpq .pgpass format host:port:database:username:password (PostgreSQL docs) [ASSUMED format details]
def _pgpass_has_entry(path, host, port, db, user) -> bool:
    st = path.stat()
    if st.st_mode & 0o077:
        raise RuntimeError(f"{path} is group/world-accessible; libpq ignores it. chmod 600 {path}")
    for raw in path.read_text().splitlines():
        if not raw or raw.startswith("#"):
            continue
        fields = re.split(r"(?<!\\):", raw, maxsplit=4)[:4]   # never keep field 5
        if len(fields) == 4 and all(f in ("*", want) for f, want in zip(fields, (host, str(port), db, user))):
            return True
    return False
```
