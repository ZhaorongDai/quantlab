# Phase 03.2 Plan 03: Shared Orchestration with Per-Vendor Error Classification Summary

**One concurrent, resumable, failure-isolated orchestration on `Acquisition` now drives both vendors, with a three-outcome `_classify_error` seam that lets the same HTTP 429 mean "stop the world" to Tiingo and "wait five seconds" to Alpaca — `ConcurrentTiingoAcquisition` deleted outright, and the abort-first and no-placeholder invariants locked by AST introspection.**

## Accomplishments

- **The mechanism moved; the classification did not.** ~460 lines of orchestration — the `joblib` threading fan-out, the bounded quota wait/resume loop, coverage partitioning and reporting, the failure manifest, the global abort `Event`, the `_sleep` seam and the `_scrub` choke point — now live once on `Acquisition`. `QUOTA_STATUS_CODES` and `QUOTA_MESSAGE_TOKEN` stayed on `TiingoAcquisition`, and their absence from the base is asserted mechanically rather than trusted.
- **The 429 asymmetry is real and proved in both directions.** Tiingo's 429 trips the global abort and stays out of the manifest; Alpaca's backs off inside the worker, retries the same batch, leaves the abort unset and the manifest empty, and after a bounded number of attempts degrades to `failed`. Each direction is asserted by that vendor's own tests, and mutation confirms reversing either is caught.
- **A retired name was retired.** `ConcurrentTiingoAcquisition` and all 85 of its references — 33 in `test_tiingo_quota.py`, 37 in `test_tiingo_acquisition.py`, 15 in `ingest_us_equity.py` — went in one commit. No alias, no parameterisation over both names.
- **Two invariants are now unlosable quietly.** `abort_is_first` parses `_attempt_batch`'s AST and asserts the abort guard is the first executable statement — a comment or docstring mentioning it cannot satisfy the assertion. The subclass walk imports every module in the `acquisition` package and iterates `Acquisition.__subclasses__()`, naming neither vendor, so a third vendor added later is covered without editing the test.
- **D-02 held at every commit.** The Tiingo suites were run before each of the four commits and after every intermediate edit — never at the end only. The RED commit was deliberately scoped to exclude `test_tiingo_quota.py` precisely so that gate was never violated.
- **Twelve mutations, one escape, one new test.** The escape is the interesting result: the watermark grouping was proved as a function but never proved to be *wired*, and the only vendor whose refresh is covered end to end has `batch_size = 1`, where grouping cannot fail.

## Decisions Made

- **Grouping, not `min(watermark)`, for refresh request packing** (RESEARCH Open Question 4). Most symbols in a routine refresh share one watermark, so grouping is near-free; issuing the earliest start for a mixed batch is correct but re-fetches history nobody asked for and makes 03.2-04's volume guard systematically wrong. `_attempt_batch` still takes `min(...)` over a batch as a *defensive* reading of the grouping invariant — over-fetching a shared window is an overwrite thanks to deterministic shard names, while under-fetching silently loses rows.
- **`_vendor_response`/`_status_of` hoisted in Task 3, not Task 1.** Task 1's instruction was to prefer leaving them over a speculative generalisation. Once Alpaca needed to read a status off an exception chain the generalisation stopped being speculative, and two independent walks of the same exception shape would eventually disagree — with a misclassified status as the failure mode, which is this module's most expensive bug.
- **The base declares an empty `RATE_LIMIT_STATUS_CODES`,** mirroring `QUOTA_STATUS_CODES` not existing there at all. A vendor with no per-minute ceiling says so by leaving it empty rather than by inheriting someone else's numbers.
- **`X-RateLimit-*` headers are read for logging only, and an absent header contributes no entry.** Alpaca does not guarantee them on every response, so the backoff stays a configured interval and never a computed reset instant — the same reasoning 260906-26o applied to Tiingo's unpublished reset semantics.
- **The RED commit excludes `tests/test_tiingo_quota.py`.** D-02 requires that file green at *every* commit of this plan, and a genuine RED commit containing its three failing seam tests would have violated that must-have verbatim. The Tiingo mirror tests were verified red against the pre-implementation tree, parked, and landed with GREEN. Recorded rather than papered over.
