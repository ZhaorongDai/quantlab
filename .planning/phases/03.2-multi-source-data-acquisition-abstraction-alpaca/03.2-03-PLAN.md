<objective>
Move the orchestration MECHANISM up into `Acquisition` so one implementation drives both vendors, and
keep error CLASSIFICATION per-vendor so the same status code can mean opposite things to Tiingo and
Alpaca.

Purpose: D-02 is the decision that makes this a multi-source abstraction rather than a second copy.
It is also the riskiest change in the phase — a relocation whose failure mode is silent behavioural
drift, not a crash — which is why the 43-test Tiingo suite is the gate on every commit rather than on
the plan.

Output: batched concurrent `download()`/`refresh()` on the base class, `ConcurrentTiingoAcquisition`
collapsed out of existence, a three-outcome `_classify_error` policy seam, and source-introspection
tests that make the two most easily-lost invariants impossible to lose quietly.
</objective>

<planner_decisions>
Two questions RESEARCH left open that this plan answers rather than leaves floating:

- **Open Question 4 — does `refresh()` still mean one request per symbol once batching exists?**
  Decision: **group pending symbols by identical recorded `last_date`, then chunk each group into
  batches.** Most symbols in a routine refresh share one watermark, so grouping is near-free and
  avoids re-fetching history the volume guard would otherwise have to size. The alternative —
  issuing `min(watermark)` for a mixed batch and letting `dedup_raw_frame` absorb the overlap — is
  correct but wasteful and would make the guard's estimate systematically wrong. **D-06's window rule
  is unchanged either way: this is about request packing, not window semantics.**

- **The staging question CONTEXT.md left to Claude's discretion** (whether the lift lands as one
  refactor or is staged). Decision: **staged across three commits within this plan**, because the
  non-regression constraint is per-commit. Task 1 hoists the mechanism while
  `ConcurrentTiingoAcquisition` still exists as a thin subclass; Task 2 collapses it; Task 3 adds the
  classification seam and the introspection guards. No commit leaves the 43 tests red.
</planner_decisions>
