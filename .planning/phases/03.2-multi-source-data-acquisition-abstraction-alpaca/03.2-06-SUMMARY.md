## Decisions Made

Beyond the frontmatter `key-decisions`, two are worth their reasoning here:

- **`_session_date` raises on an undeclared time zone rather than truncating.** The plan's wording allowed either a truncating default or a raising one. A truncating default would mean the exact bug A8 exists to prevent — a naive-UTC vendor silently filing the last four hours of every session under the following day — reaches disk for any vendor whose author never thought about the boundary. A vendor whose timestamps are genuinely session-local states so by overriding the method, which makes the convention a deliberate statement instead of an unnoticed default. Only intraday frequencies reach it, so `TiingoAcquisition` (daily-only) is unaffected.
- **The intraday reader widens by a day rather than encoding the session time zone.** The reader deliberately does not know the writer's `SESSION_TIME_ZONE`; duplicating it would put one fact in two places and let them drift. One day of slack is correct for any session zone within ±24h of UTC, over-includes at most two partitions, and the `timestamp` predicate trims them exactly. Measured cost on the test tree: still 2 of 5 sources.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] A field map that stops matching the envelope wrote null columns instead of raising**

- **Found during:** Task 2 (post-GREEN mutation pass)
- **Issue:** `_fetch_page` gained a convenience that fills any `RAW_COLUMNS` entry absent from a page with a typed null, so a sparse `conditions` would not fail a whole batch. Mutation M6 — substituting `QUOTE_FIELD_MAP` for `TRADE_FIELD_MAP` — then left the suite fully green: a trade's `x/p/s/i` simply stop mapping, and the shard gains an all-null `price`, `size`, `trade_id` and `exchange`. That is indistinguishable from a stretch of untraded symbols and would stay that way forever. It is the same class of silent-wrongness as a swapped `o`/`c`, which the `FIELD_MAP` pinning exists to prevent — the convenience had quietly reopened it.
- **Fix:** Added `OPTIONAL_COLUMNS_BY_DATA_TYPE` (only `conditions`, and nothing at all for bars). Any other absent column raises, naming what went missing, what is allowed to be absent, and the vendor fields the map expected. Added `test_the_quote_and_trade_field_maps_are_pinned_and_map_nothing_twice` (direct equality, like the bars map), `test_quote_and_trade_values_survive_the_field_map_onto_the_shard` (round-tripped VALUES on disk, which is what M6 actually broke), and `test_a_field_map_that_stops_matching_the_envelope_raises_not_nulls`.
- **Files modified:** `acquisition/alpaca.py`, `tests/test_alpaca_acquisition.py`
- **Verification:** Re-ran M6 → 6 tests red. Added M12 (null-fill instead of raise) → red.
- **Committed in:** `a697e31`

**2. [Rule 1 - Bug] A `data_type` predicate cannot isolate a tick data type; only root scoping can**

- **Found during:** Task 2 (GREEN)
- **Issue:** The plan specified `_hive_window_predicate` filtering on `data_type`. Implemented that way, `test_a_tick_scan_filtered_to_one_data_type_reads_only_that_data_type` failed with `SchemaError: extra column in file outside of expected schema: price`. Measured against polars 1.44.1: `pl.scan_parquet` fixes its expected schema from the FIRST file it discovers and enforces it against every file it opens — including the files a predicate has already pruned the scan down to. `.explain()` shows the plan correctly listing only the trades shard and `.collect()` still raises. Filtering to `quotes` "works" only because `quotes` sorts before `trades`, so the bug is ordering-dependent and would read as intermittent.
- **Fix:** `StockDataset._scan_root()` roots a tick scan at `{vendor_root}/data_type={quotes|trades}`, with `_scanned_hive_keys` / `_scanned_hive_schema` narrowing the hive schema and predicate to the keys still below that root. This is D-11's vendor-segment lesson one level deeper: a distinction only a predicate enforces is not isolation. The measurement is recorded in `_scan_root`'s docstring and pinned by `test_an_unfiltered_tick_scan_of_a_mixed_root_raises_rather_than_blending`, which now asserts both that the plan prunes correctly and that the collect still raises.
- **Files modified:** `dataset/stock.py`, `tests/test_raw_hive_layout.py`
- **Verification:** Mutation M8 (remove root scoping) → 4 tests red.
- **Committed in:** `a697e31`

**3. [Rule 2 - Missing Critical] A quotes backfill's watermarks marked the subsequent trades run covered**

- **Found during:** Task 2 (GREEN — `test_tick_shards_land_under_data_type_then_session_date_then_symbol` reported the trades shard missing)
- **Issue:** Quotes and trades share one vendor raw root, separated only by the leading `data_type=` hive key. Their bookkeeping sidecars have no such key — they are `{symbol}.json`, `_failures.json`, `{batch_key}.pages.json` — so after a quotes backfill, a trades run's coverage check found every symbol already covered, skipped the entire roster, wrote nothing, and reported success. The plan did not anticipate this because it is a consequence of the tick layout sharing a root, which only became concrete at implementation.
- **Fix:** `Acquisition._watermark_root` appends the data type when (and only when) the frequency's `RAW_HIVE_KEYS` include `data_type`. `1d` and `1m` sidecar paths are byte-identical to before, so no existing watermark tree moves. Locked by `test_a_quotes_backfills_watermarks_do_not_mark_the_trades_run_covered` (asserts both runs issue a request AND the sidecars live in separate directories) and `test_the_daily_watermark_layout_is_unchanged_by_the_tick_namespacing`.
- **Files modified:** `base/acquisition.py`, `tests/test_alpaca_acquisition.py`
- **Verification:** Mutation M9 (un-namespace the root) → 2 tests red. D-02 Tiingo gate stayed at 48 passed.
- **Committed in:** `a697e31`

**4. [Rule 1 - Bug] `_scan_raw` deduped tick rows on `(timestamp, symbol)`, destroying D-16 resolution**

- **Found during:** Task 2 (GREEN)
- **Issue:** `_scan_raw` unconditionally ends with `dedup_raw_frame(keep="last")`. Many genuine quotes and trades share one `(timestamp, symbol)` — that is what a tick stream is — so every read of a tick root would have silently collapsed them, discarding exactly the resolution D-16 says must be preserved. The dedup is not general hygiene: it exists because `.to_xarray()` raises on a non-unique MultiIndex, a dense-panel requirement that tick has no path to this phase (D-18).
- **Fix:** `_scan_raw` returns before the dedup for `tick`, with the reasoning at the branch. Locked by `test_a_tick_scan_does_not_dedup_rows_sharing_a_timestamp_and_symbol`.
- **Files modified:** `dataset/stock.py`, `tests/test_raw_hive_layout.py`
- **Verification:** Mutation M7 (re-enable dedup for tick) → red.
- **Committed in:** `a697e31`
