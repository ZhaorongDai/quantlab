## Fixed Issues

### CR-01: `asof` never reached the wire — the survivorship-bias guard was a no-op

**Commit:** `0e297f5`
**Files:** `acquisition/alpaca.py`, `tests/test_alpaca_acquisition.py`

`requests` drops `None`-valued params before building the query string, so
`"asof": None` was documented, threaded and asserted — and never sent. Alpaca
applied its current-day default and mapped every delisted ticker onto whatever
entity holds the symbol now.

- `ASOF_NO_MAPPING = "-"` is sent when the knob is unset.
- `_ASOF_UNSET` separates "never set" from an explicit `kwargs={"asof": None}`.
  `_knob` cannot tell them apart, and collapsing them is how the harmful default
  became the effective default. The explicit `None` is the only path that omits
  the key, and it must now be typed deliberately.
- Tests moved to the **prepared URL**. The new
  `test_asof_survives_query_string_encoding_at_the_transport` does **not** patch
  `_AlpacaMarketDataClient` — it uses the real transport and patches
  `requests.Session.send`, which receives the fully prepared request. That is
  the one boundary at which the claim is falsifiable, and the reason the defect
  survived two green tests.

**Sentinel value is UNVERIFIED and labelled as such in the code.** This project
has no Alpaca credential, so `"-"` could not be probed; the constant carries a
comment saying so and points at the same 03.2-07 one-request probe that settles
the `feed` question. The failure mode if it is wrong is a 4xx per batch —
**loud**, isolated, recorded in the failure manifest — versus the silent,
plausible-looking, biased data it replaces. This is the direction to be wrong
in, and it does not swap one silent unverified claim for another.

**Mutation:** reverted `params["asof"]` to `None`. The transport test went red
**while every dict-level assertion stayed green** — reproducing the exact
failure shape the review recorded.

### CR-02: polars inferred the page schema from 100 rows, silently dropping later fields

**Commit:** `df12153`
**Files:** `acquisition/alpaca.py`, `tests/test_alpaca_acquisition.py`

`pl.DataFrame(rows, infer_schema_length=None)` infers over the whole page. A
page carries up to `limit=10_000` rows in symbol-major order and Alpaca omits an
absent field per row, so a field first seen at row 101 vanished with no error.

**Mutation:** removed `infer_schema_length=None`. The test went red — and did so
*as a spurious whole-batch failure with a manifest entry blaming the field map*,
which is finding CR-02's second predicted symptom reproducing itself.

The regression test puts a **required** field (`trade_id`) and an **optional**
one (`conditions`) only after row 110 of a 120-row page and asserts both survive
with their real values — covering both halves of the finding (silent null-fill
and spurious batch failure).

### CR-03: densification with no dense-panel guard in front of it

**Commit:** `5b5d19d`
**Files:** `acquisition/universe.py`, `utils/cli.py`, `ingest_alpaca.py`,
`ingest_tiingo.py`, `tests/test_volume_guard.py`, `tests/test_universe.py`

- `estimate_dense_panel` / `assert_dense_panel_fits` gained `bars_per_day`
  (default `1`, so every existing daily caller is byte-identical). The guard
  sizes the **timestamp axis**; at `1m` a session is 390 rows, so left at the
  default it would admit the very fetch it exists to refuse — the review flagged
  this explicitly and it is the easiest half to get wrong.
  `_ExplicitSymbolCatalog` mirrors the signature, since `--symbols` is the path
  that matters most.
- `ingest_alpaca.py` calls the guard before the fetch for `1d`/`1m`, sized on
  Alpaca's own 7-variable bar width rather than the 12-column Tiingo default (a
  guard that overstates refuses valid fetches, which is how a guard gets
  deleted). Tick skips it — D-18 fences that conversion out.
- `ingest_tiingo.py` **had the same gap**, in front of an unconditional
  `from_raw_data()`. Not named by the review; surfaced because the new test is
  scoped by *reachability* rather than by script name — which is exactly what
  `test_the_chunked_panel_guard_keeps_both_of_its_call_sites` got wrong by
  pinning itself to `ingest_us_equity.py`.

`acquisition/universe.py` still imports no acquisition module: `bars_per_day` is
a plain int, and `ingest_alpaca.py` reads `BARS_PER_DAY_BY_FREQUENCY` off the
catalog it already holds. The refuse-before-construct ordering is unchanged and
is now asserted (`min(ram_guards) < min(densify_sites)`).

`tests/test_universe.py::test_the_whole_range_guard_survives_beside_the_chunked_one`
pinned the exact signature. It was updated, not weakened: the original
parameters must still be present **in their original order**, and every appended
parameter must default to the pre-existing behaviour, with `bars_per_day == 1`
asserted by name.

**Mutations:** (1) removed the `ingest_alpaca.py` call site → the wiring test
red; (2) made `estimate_dense_panel` ignore `bars_per_day` → the arithmetic test
red.

**One correction to the review's own numbers, recorded rather than silently
absorbed:** CR-03 states S&P-500 minute for a year densifies to "~4 TB". The
arithmetic is 500 × 98,280 × 7 × 8 ≈ **2.75 GB** — under the 4 GiB budget, not
three orders of magnitude over it. The guard is still necessary and the finding
still stands (two years is ~5.5 GiB and is refused; `us_all` minute is refused
by orders of magnitude), but the test asserts over a window that is
unambiguously over budget rather than one sitting on its edge, and says so in a
comment.

### CR-04: tick rows duplicated across runs

**Commit:** `caae2c7`
**Files:** `base/acquisition.py`, `tests/test_alpaca_acquisition.py`

`_write_shard` now clears shards written by a **different** batch key before
writing, gated on the partition being per-symbol.

- The window is part of `batch_key`, so a re-fetch over a different window wrote
  a second file rather than overwriting the first. `refresh()` does this every
  run — `last_date` is inclusive.
- **The gate is load-bearing in both directions and both are tested.** A `1d`
  (`month=`) or `1m` (`date=`) directory is shared by concurrently-running
  batches, so clearing there would destroy a sibling batch's data. A tick
  directory is `data_type=/date=/symbol=` and one symbol belongs to exactly one
  batch per run, so the only removable files are earlier runs' shards for a
  session this run is re-fetching in full.
- **Within the D-19 contract-4 filename**: no timestamp, no uuid, no counter was
  added. What changed is that a superseded name is *removed* rather than left
  beside its successor. `_shard_path`'s docstring now states the scope its
  determinism actually has, which is the undocumented assumption the review
  identified.

**Mutations:** (1) disabled the cleanup → the new
download-then-refresh-over-an-overlap test red (the session doubles to 6 rows);
(2) forced the gate always-true → **three Tiingo tests red**, confirming the
gate is not decoration.

### WR-01: tick timestamps truncated from nanoseconds to microseconds

**Commit:** `b39a531` · **Files:** `acquisition/alpaca.py`, `tests/test_alpaca_acquisition.py`

`RAW_SCHEMA_BY_DATA_TYPE` declares the unit per data type (`us` bars, `ns`
quotes/trades) and `_fetch_page` parses with the declared unit. Asserted on the
**ninth fractional digit through the parquet round trip** — `.item()` would hide
it, since Python's `datetime` stops at microseconds — plus three trades inside
one microsecond staying three distinct timestamps, which is the property that
matters in a tier that never dedups. Bars are pinned at `us` so "just make
everything ns" stays a visible change.

**Mutation:** dropped `time_unit=` → red.

### WR-08: a pages-carrying ledger with no fingerprint was resumed onto

**Commit:** `e547c25` · **Files:** `base/pageledger.py`, `tests/test_page_ledger.py`

Two halves that cover each other:

- `_load` treats a **missing** fingerprint on a ledger that **has pages** as a
  mismatch. A ledger with no pages is left alone — nothing to resume onto, and
  emptying it would discard forward-compatible keys a newer writer put there,
  which would break the additive-in-both-directions guarantee (constraint 6).
  A caller supplying no roster still reads the file as-is: the guard is about a
  mismatch, and there is nothing to mismatch.
- `describe()` now flushes, closing the path that produced the state from this
  code.

**Mutations:** (1) skip the missing-fingerprint refusal → red; (2) remove the
flush → red.

### WR-09: bare dates sent for intraday while the watermark claimed the whole day

**Commit:** `8433811` · **Files:** `acquisition/alpaca.py`, `tests/test_alpaca_acquisition.py`

`_window_bounds` widens intraday edges to `T00:00:00Z` /
`T23:59:59.999999999Z`; `1d` keeps bare dates; a bound that already carries a
time passes through untouched. Nine fractional digits, matching the vendor's own
resolution and the now-nanosecond tick schema, so no genuine trade in the final
microsecond is dropped.

The review's real point was that **nothing recorded which reading was assumed**.
The assumption is now sent explicitly, asserted at the prepared URL, and
documented on `INTRADAY_END_SUFFIX` together with the watermark coupling: with
the window provably covering the session, `last_date = end_date` is a true
statement about what was queried, and the `no_data` marker carries the separate
"asked and got nothing" case. The unconditional stamping is therefore left as
it is — deliberately, and now for a stated reason rather than an unexamined one.

**Mutations:** (1) widening disabled → red; (2) `INTRADAY_END_SUFFIX` truncated
to midnight → red.
