## Decisions Made

- **`mock_alpaca_client` probes with `importlib.util.find_spec` before patching.** `monkeypatch.setattr` on a dotted string imports the module; `raising=False` only tolerates a missing *attribute*. See Deviations. The guard is deliberately narrow (`find_spec is not None`, never `except Exception`) so a genuine `ImportError` from a broken `acquisition/alpaca.py` still surfaces instead of leaving the fixture silently unpatched.
- **`acquisition_config` expresses the vendor purely through its paths.** The plan offered two options; the preferred one was taken — `AcquisitionConfig.vendor` is introduced in 03.2-02 Task 1, in the same commit as the dataclass field, rather than being faked here behind a guarded `dict` splat.
- **`alpaca_bars_page` raises on a project column name.** A fixture that accepted `close` would let a test be written against a shape the vendor never emits, and would hide the vendor→project field mapping that is the most likely place for `AlpacaAcquisition` to be quietly wrong (a swapped `o`/`c` reads as plausible data forever).
- **`test_raw_hive_layout.py` asserts the bug as well as the shape.** `test_a_scan_rooted_above_both_vendors_merges_them_silently` reproduces RESEARCH's measured merge (two vendors, same schema, duplicate `(timestamp, symbol)` rows with different `close` values). Its failure message routes a future reader to re-derive SC-7 against new polars behaviour rather than deleting the test.
- **Hive-key derivation lives in a module-level `_hive_partition_value` helper**, covering `month`/`date`/`symbol` — the three keys Pattern 5 assigns to `1d`/`1m`/`tick` — so the fixture can serve all three frequencies without 03.2-05 rewriting it.
- **Self-test names were chosen so the phase's `-k` selectors already match** where the self-test genuinely covers that ground: `..._vendor_isolation_must_prevent` matches `-k vendor_isolation`, `..._support_a_midway_resume` matches `-k resume`. Selectors the self-tests do not honestly cover (`abort_is_first`, `no_data`, `rate_limit`, `idempotent`, `fingerprint`, `prun`) were deliberately NOT forced onto a self-test name — a name that matches a selector without testing that behaviour is the same green-but-empty lie this plan exists to prevent.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `monkeypatch.setattr` on a dotted string imports the module, so `raising=False` was not enough**

- **Found during:** Task 2 (first run of the five new files)
- **Issue:** The plan specified `monkeypatch.setattr("acquisition.alpaca._AlpacaMarketDataClient", FakeAlpacaClient, raising=False)`, mirroring `mock_tiingo_client`. That pattern works for `acquisition.tiingo` only because that module now exists. `raising=False` tolerates a missing *attribute*, not a missing *module* — every test using `mock_alpaca_client` errored with `ImportError: import error in acquisition.alpaca: No module named 'acquisition.alpaca'`. Collection succeeded (the plan's `--collect-only` criterion passed), so the defect was invisible until the fixture was actually used; four tests errored.
- **Fix:** Probe the target with `importlib.util.find_spec("acquisition.alpaca")` and patch only when it resolves. While the module is absent there is nothing to patch **and** nothing that could issue a real request, because `_AlpacaMarketDataClient` does not exist for any caller to construct. The moment 03.2-06 lands it, the patch becomes real with no change to the fixture. Documented in-place with an explicit prohibition on widening the guard to `except Exception`.
- **Files modified:** `tests/conftest.py`
- **Verification:** `uv run pytest tests/test_page_ledger.py tests/test_alpaca_acquisition.py -q` went from 4 errors to green; full suite 237 passed.
- **Committed in:** `cf20e20` (Task 2 commit)
