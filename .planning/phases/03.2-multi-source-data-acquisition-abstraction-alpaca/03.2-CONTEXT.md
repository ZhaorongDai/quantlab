# Phase 03.2: Multi-Source Data Acquisition Abstraction (Alpaca) - Context

**Gathered:** 2026-09-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Generalize `base/acquisition.py:Acquisition` from a one-symbol-per-call
abstraction into one that can drive vendors whose APIs are **batched
(multi-symbol per request) and paginated**, and add Alpaca source classes on
top of it covering daily bars, minute bars, and high-frequency quotes/trades —
with a pre-flight volume guard.

**In scope:** the acquisition layer only — network fetch → raw local files,
plus the batching/pagination/resume/guard machinery that makes a multi-hour
full-market job survivable, plus the path-convention change that lets two
vendors coexist.

**Out of scope (explicit fences):**
- **The raw → xarray/Zarr conversion for tick data.** Acquisition writes raw
  files; `Dataset._raw_data_to_xr()` converts. A tick Dataset subclass and its
  new (non-dense) storage shape are deferred to a follow-up phase 03.3 (D-18).
- **Alpaca's trading/broker API.** Market-data endpoints only (D-15).
- **Corporate actions.** Abstraction must not preclude it; no implementation
  this phase (D-07).
- **Cross-vendor reconciliation** (comparing Tiingo vs Alpaca bars). Discussed
  and rejected as a separate concern.

### Scope deviation from REQUIREMENTS.md — recorded, user-accepted

`REQUIREMENTS.md` places **DATA-V2-01** (full production tick ingestion) and
**DATA-V2-02** (full minute-frequency historical backfill) in v2 / Out of
Scope; `PROJECT.md` words it as "架构需要支持，但完整实现留待后续". D-07 selects
minute bars and quotes/trades for this phase, which crosses that line.

**The line this phase does NOT cross:** what is being delivered is **接入能力打通**
— the code path can fetch, resume, guard, and land these frequencies — **not** a
full-market full-history backfill of 15.4k symbols at minute or tick
resolution. Do not plan a mass backfill run. The volume guard (D-09) is the
mechanism that keeps that distinction enforceable rather than merely stated.

</domain>

<decisions>
## Implementation Decisions

### Abstraction shape — batching and pagination

- **D-01:** **Invert the primitive.** `_fetch_batch(symbols, start_date,
  end_date)` becomes the single abstract fetch method on `Acquisition`; a
  single-symbol vendor is the degenerate case (Tiingo's implementation loops
  its own per-symbol call internally). Rejected: adding `_fetch_batch`
  alongside `_fetch_and_write` with a looping default (leaves two adjacent
  abstractions and a "which do I override?" trap), and a separate
  `BatchedAcquisition` sibling base (forks `download`/`refresh` into two
  parallel implementations). — **Reversibility:** costly — undoing means
  re-splitting the abstraction and re-touching `acquisition/tiingo.py` (674
  lines, currently in production use) plus every source written against it.

- **D-02:** **Unify orchestration in the base class.** Concurrency
  (`joblib.Parallel(backend="threading")`), resume/skip-already-covered,
  failure isolation, and the global quota abort move UP out of
  `ConcurrentTiingoAcquisition` into the base's batched
  `download()`/`refresh()`, so Tiingo and Alpaca share one implementation.
  This deliberately overrides `ConcurrentTiingoAcquisition`'s own docstring
  claim that "a shared seam is not worth introducing for one subclass" — there
  is now a second subclass, which is exactly the condition that claim was
  conditioned on. — **Reversibility:** costly — undo means re-forking
  orchestration and re-verifying the quota-abort / legacy-watermark behaviour
  that quick task 260906-26o only just landed.

  **Hard non-regression constraint:** every behaviour 260906-26o locked must
  survive the lift, specifically: `QUOTA_STATUS_CODES == frozenset({429})`
  (403 deliberately excluded), the abort `threading.Event` checked as
  `_attempt`'s FIRST statement with the result generator drained rather than
  abandoned, un-stamped legacy watermarks SKIPPED-but-loudly-reported with the
  exact stamping command, and `refresh()`'s end-date-only rule (D-06).

- **D-03:** **Page-level resume.** Pagination is checkpointed: fetched pages
  are written to disk as shards and the vendor's `next_page_token` is
  recorded, so an interrupted multi-hour job resumes at the failed page rather
  than at page 1 or at the top of the batch. Rejected: batch-atomic
  (accumulate all pages in memory, discard the whole batch on any failure —
  burns quota and makes peak memory unbounded) and write-what-you-have +
  narrowed-watermark (requires pages to arrive in strict time order, which is
  not established). — **Reversibility:** costly — the shard-plus-token model
  is what the raw layout (D-08) and the ledger (D-05) are both shaped around.

  **Open for research:** `next_page_token` lifetime/expiry semantics, and
  whether Alpaca returns pages in a stable order. If tokens expire, the ledger
  must record enough to re-derive a resume point without one.

### Watermark and failure semantics under batching

- **D-04:** **A symbol absent from a batch response gets a third state.** Not
  "failure" (a full-market run would accumulate thousands of permanent
  retries against delisted tickers and the failure report would lose all
  signal) and not a bare successful advance (which would launder a silent
  vendor fault into "confirmed no data"). The sidecar records an explicit
  "queried, no data" marker alongside the coverage range, the watermark
  advances, and the state stays distinguishable at read time. This follows
  260906-26o D-04's principle directly: an unknown is represented explicitly
  and never guessed. — **Reversibility:** costly — the marker lands in
  on-disk sidecars; removing it later makes no-data symbols indistinguishable
  from never-fetched ones and triggers a re-fetch storm across ~15.4k symbols.

  Schema extension must stay **additive**, same as 260906-26o: old readers
  must tolerate new files and new readers must tolerate old ones.

- **D-05:** **Two layers of state, separate responsibilities.** The per-symbol
  watermark sidecar keeps its exact current semantics (`{start_date,
  last_date}`, unknown start = key ABSENT, never invented) and gains nothing
  about pagination. Pagination progress goes into a **task-level ledger**,
  built in the same shape as the already-proven `base/chunking.py:ChunkLedger`.
  Rejected: cramming page tokens into the per-symbol sidecar, and collapsing
  15.4k sidecars into one manifest (which would force a real data migration of
  `stamp_watermarks()`'s legacy path and every sidecar already on disk).
  — **Reversibility:** reversible — the ledger is a new sidecar; deleting it
  costs one re-run, and the coverage sidecars are untouched.

- **D-06:** **`refresh()`'s end-date-only rule carries over verbatim to the
  batch path.** `refresh` fetches `[symbol watermark, config.end_date]` and
  does NOT honour a widened `config.start_date`; back-filling earlier history
  is `download()`'s job. Rationale is 260906-26o's, unchanged: judging refresh
  against a widened start re-fetches endlessly without ever closing the gap.
  — **Reversibility:** reversible — a rule in one method.

### Alpaca scope, raw layout, and the volume guard

- **D-07:** **Delivered this phase:** daily bars, minute bars, quotes/trades.
  **Abstraction-only, not implemented:** corporate actions. (Note for
  planning: `02-08-RESEARCH.md` already established that Alpaca's Corporate
  Actions API explicitly excludes delistings/reorganizations, so the eventual
  implementation cannot be treated as a replacement for the Tiingo
  `supported_tickers.csv` delisting signal.) — **Reversibility:** reversible.

- **D-08 (REVISED during discussion):** **Raw data lands in a hive-partitioned
  layout**, e.g. `.../{market}/{frequency}/{vendor}/date=YYYY-MM-DD/symbol=XXX/*.pqt`
  (exact partition keys and their order are the researcher's call). Read via
  `pl.scan_parquet(..., hive_partitioning=True)` so date and symbol predicates
  prune at the directory level.

  **This decision was reversed mid-discussion and the reversal is the
  load-bearing part.** It was first set to `raw/{symbol}/{part}.pqt`
  (symbol directory + shards) at a point when tick data had not yet been
  scoped in. Once D-16/D-18 fixed "raw tick, undownsampled, stops at the raw
  layer", the raw tier became the largest-volume tier in the phase, and a
  symbol-only directory tree cannot prune by date: "give me one day across the
  market" would open every shard under every symbol directory. Do NOT
  "restore" the simpler layout. — **Reversibility:** one-way — the raw
  directory layout is an on-disk contract consumed by `_scan_raw`, the ingest
  scripts, and every already-fetched file; changing it later means physically
  relaying the entire raw tier.

  **Consequence to plan for:** `dataset/stock.py:_scan_raw` currently does
  `get_pqt_files` → per-file `pl.scan_parquet` → `pl.concat(how="diagonal_relaxed")`
  → filter. It must be reworked onto hive scanning. The `diagonal_relaxed`
  concat is also the exact mechanism by which two vendors' differently-shaped
  parquet would merge *without erroring* — which is why D-11's vendor
  partition is structural rather than conventional.

- **D-09:** **The volume guard is a pre-flight estimate that refuses, with an
  explicit override.** Before issuing requests, estimate volume from
  symbol count × date span × frequency; over threshold it raises with a
  concrete narrowing suggestion. Same shape as the project's existing
  `assert_dense_panel_fits` / `MAX_DENSE_PANEL_BYTES`. Failing before spending
  quota and wall-clock is the point. Rejected: unconditional chunk-and-stream
  with no ceiling (a mistyped parameter would quietly run for tens of hours
  and fill the disk with nothing stopping it). — **Reversibility:** reversible
  — threshold and override are config.

  This guard is also the enforcement mechanism for the scope fence in
  `<domain>`: it is what keeps "接入能力打通" from silently becoming a
  full-market tick backfill.

### Multi-vendor coexistence

- **D-10:** **Alpaca and Tiingo coexist as parallel alternative sources,
  selected by config.** Not a replacement (which would leave the "multi-source
  abstraction" with only one real caller and therefore unvalidated), and not
  cross-validation/reconciliation (a separate concern, deferred).
  — **Reversibility:** costly — undo touches the config factories and CLI
  surface that every ingest entry point reads.

- **D-11:** **The path convention gains a vendor segment:**
  `data/{market}/{frequency}/{vendor}/…`, for both `raw_data_dir_path` and
  `watermark_path`. Structural isolation, not conventional: with
  `diagonal_relaxed` concat in `_scan_raw`, two vendors sharing a directory
  would merge into one xarray *without raising*. Every factory function in
  `config/__init__.py` must derive the vendor segment rather than have it
  passed in ad hoc. — **Reversibility:** one-way — the path convention is
  consumed by every config factory and every on-disk store; changing it later
  requires exactly the migration D-13 is choosing to avoid now.

- **D-12:** **Alpaca subscription tier is undecided.** Design the feed level
  (SIP vs IEX) as a **config parameter**, so upgrading is a config change and
  not a code change. — **Reversibility:** reversible.

  **Required of research:** enumerate concretely what differs between the free
  (IEX) and paid (SIP) tiers for the three delivered data types — historical
  depth, rate limits, available fields, and any delay — so the user can decide
  with numbers. If quotes/trades on the free tier are IEX-only (a small
  fraction of consolidated volume), that limitation must be documented on the
  class itself, not just in research.

- **D-13:** **Existing Tiingo raw data and watermarks are NOT migrated and NOT
  read via a fallback path — they are re-fetched under the new vendor path.**
  Chosen for a clean code path with no dual-path branch that would outlive its
  purpose. — **Reversibility:** one-way — the existing per-symbol coverage
  records are discarded and cannot be reconstructed.

  **Accepted risk, stated at decision time and confirmed:** this re-burns
  Tiingo quota, and the account's allocation was observed to run out after
  ~4,600 requests on 2026-09-06. Plan the re-fetch as a resumable run that
  respects the quota-abort path, not as a fire-and-forget step. It is also
  worth planning it as an *optional/separate* invocation so a failed re-fetch
  does not block the rest of the phase from verifying.

### Entry points, credentials, sequencing

- **D-14:** **One top-level script per source** — add `ingest_alpaca.py`,
  matching the existing `ingest_tiingo.py` / `ingest_us_equity.py` /
  `ingest_binance_spot.py` / `refresh_us_equity_universe.py` shape. Rejected:
  adding `--vendor` to `ingest_us_equity.py`, and a unified
  `ingest.py --market --frequency --vendor`. — **Reversibility:** reversible.

  **Constraint carried from the discussion:** do not copy-paste a third
  implementation of the shared `--universe` / `--as-of-date` / `--chunk`
  argument parsing. Factor it into something both scripts call.

- **D-15:** **Market-data endpoints only. No trading/broker API this phase.**
  Alpaca's market-data API does not distinguish paper from live, so no
  paper/live switch exists in this phase's surface. Credentials are
  market-data credentials only, read from environment variables in
  `__init__` and never assigned to a config dataclass — the exact pattern
  `TiingoAcquisition` already uses for `TIINGO_API_KEY`. — **Reversibility:**
  reversible.

- **D-16:** **Raw tick is not downsampled.** Quotes/trades are fetched and
  landed at full resolution; no resampling or aggregation step in this phase.
  — **Reversibility:** reversible.

- **D-17:** **Run 03.2 before closing Phase 3's outstanding gaps.** Continues
  the sequencing 03.1-CONTEXT D-06 already chose. — **Reversibility:**
  reversible.

  **Known conflict, larger than 03.1's:** `03-07-PLAN.md` modifies
  `dataset/stock.py` and `config/__init__.py`; D-08 and D-11 modify **both of
  those same files**, more invasively than 03.1 did. `03-07` was written
  against a pre-03.1 state that this phase will move further still. The 03.2
  plans MUST record this overlap explicitly. Before running
  `/gsd-execute-phase 3 --gaps-only`, `03-06`/`03-07`'s `read_first` lists and
  file expectations must be re-derived against the post-03.2 state.

  Also still live: Phase 3 sits at `gaps_found`, so US-equity KunQuant factors
  compute `VWAP0 ≡ 1.0`. Do not use US-equity factor output as a correctness
  signal while verifying this phase.

- **D-18:** **The tick → Zarr conversion is a separate follow-up phase
  (03.3).** This phase stops at raw. A tick Dataset subclass needs a storage
  shape that the existing dense `[timestamp, symbol]` panel convention cannot
  express (an irregular event axis), which is a genuine second data-model
  branch — and the project already hit a 16 GiB dense-panel OOM in quick task
  260906-13w. Splitting keeps each phase independently verifiable.
  — **Reversibility:** reversible — a scope boundary, not a code commitment.

  rather than a new invention.
- `base/chunking.py:TimeChunkPlanner` — window planning from either an observed

  a second vendor's overlapping rows flow through it unchanged.

### Established Patterns
- **Acquisition never touches xarray/Zarr.** Stated in `Acquisition`'s own
  docstring and preserved by D-18's scope fence.
- **Credentials read from `os.environ` in `__init__`, never stored on the
  config dataclass** (`TiingoAcquisition.__init__`). `AcquisitionConfig` is
  `asdict`-serialized, so a key on it would leak into any persisted config.

- **Unknown state is represented by absence and never guessed** (260906-26o

- **Config factories in `config/__init__.py`, not inline construction at call

## Execution-Time Decisions (confirmed during 03.2-02)

### D-19: The one-way on-disk contracts, confirmed `as-proposed` (2026-09-06)

03.2-02-PLAN.md Task 1 was a `gate="blocking-human"` `checkpoint:decision`
asking the developer to confirm the raw-tier on-disk contracts BEFORE any code
wrote them, because D-08 (hive layout), D-11 (vendor path segment) and D-13
(no migration) are each rated one-way: undoing one after data has landed means
physically relaying the raw tier and re-burning vendor quota.

**Answer: `as-proposed`.** All nine contracts below are confirmed exactly as
03.2-02-PLAN.md proposes them, and are not to be re-opened or re-derived:

1. **Raw hive root** — `downloads/{market}/{frequency}/{subdir}/{vendor}/`.
   The basename IS the vendor, which is what makes `_scan_raw`'s
   `Path(raw_data_dir_path).name == config.vendor` assertion expressible.
2. **Watermark root** — `downloads/{market}/{frequency}/{subdir}/_watermarks/{vendor}/`,
   a SIBLING of the vendor directory and never a child. A polars directory scan
   walks every file beneath the root it is given, so a `.json` sidecar inside
   the raw tree breaks `pl.scan_parquet` outright.
3. **Page ledger** — `{watermark_path}/_pages/{batch_key}.pages.json`, where
   `batch_key` is the sha256 of `vendor|frequency|start|end|sorted(symbols)`
   truncated to 16 hex characters. Per-key `setdefault` on load keeps the
   schema additive in both directions.
4. **Shard filename** — `part-{batch_key}-{page_index:05d}.pqt`, fully
   deterministic: no timestamp, no uuid, no counter. Determinism is what makes
   the crash window between shard-write and ledger-record cheap, because a
   re-fetched page overwrites instead of duplicating.
5. **Hive keys by frequency** — `1d` -> `month=YYYY-MM`; `1m` ->
   `date=YYYY-MM-DD`; `tick` -> `data_type=quotes|trades/date=/symbol=`.
   Declared ONCE as `RAW_HIVE_KEYS` in `enums/data.py` and imported by both the
   writer and the reader, never duplicated.
6. **The leading `data_type=` key for tick** is expressed as a hive key, NOT as
   new `Frequency` tokens, so `enums/data.py`'s locked literal set stays
   untouched (02-RESEARCH.md Assumptions Log A2).
7. **The intraday `date=` key derives from the US/Eastern SESSION date.**
   Timestamp VALUES stay naive UTC and unchanged; only the derived partition
   key converts. A UTC-derived key files the last ~4 hours of each session
   (20:00-24:00 UTC) under the FOLLOWING day.
8. **`no_data` marker** — one additive boolean on the existing watermark
   sidecar, written ONLY when true and omitted when false, so every sidecar
   written before this phase reads back as not-no-data.
9. **No migration (D-13)** — no dual-path fallback reader is written. Existing
   Tiingo raw parquet and watermarks become unreadable by the new hive-aware
   `_scan_raw` and are re-fetched under the new paths as a separate, resumable,
   optional invocation.

**Rejected on the record** (recorded so the rejections are durable, not so they
are revisited):

- **`date-key-for-daily`** — `date=YYYY-MM-DD` for `1d` means ~2,690
  directories x ~155 batches, i.e. ~417,000 files of ~90 rows each for a
  full-market daily backfill. Survivable but pathological, and `month=` was
  measured to prune correctly.
- **`utc-day-key`** — a naive-UTC intraday day key makes a one-trading-day
  query wrong at BOTH edges, and the wrongness presents as sparse data rather
  than as a bug (03.2-RESEARCH.md Assumption A8).
- **`watermarks-inside-vendor-dir`** — a polars scan of the raw root walks into
  `_watermarks/` and fails on the `.json` files; every scan would then need a
  glob rather than the directory form that auto-enables hive partitioning.
