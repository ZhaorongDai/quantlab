<planner_decisions>
**Assumption A8 resolved: the intraday `date=` hive key is the US/Eastern SESSION date.**
RESEARCH flagged this for an explicit plan-review decision rather than resolving it. The decision is
session date, because every timestamp in this codebase is a naive `pl.Datetime` carrying UTC wall
time, and a UTC-derived day key would put the last ~4 hours of each US session (20:00-24:00 UTC) into
the following day's partition. A "give me one trading day" query would then be silently wrong at both
edges — the failure would look like missing data at the close and phantom data at the open. The
timestamp VALUES stay naive UTC, unchanged and consistent with Tiingo's; only the derived partition
key is converted. The conversion is stated in the class docstring and asserted by a test that fetches
a bar at 20:30 UTC and asserts it lands in that day's partition, not the next.

**Data type is a `config.kwargs` knob, not a new `Frequency` token.** `Frequency` is a locked literal
set whose extension requires revisiting 02-RESEARCH.md Assumptions Log A2. `tick` plus
`kwargs["data_type"]` covers quotes and trades without touching it, and the leading `data_type=` hive
key keeps their differing schemas from meeting inside one directory scan.
</planner_decisions>
