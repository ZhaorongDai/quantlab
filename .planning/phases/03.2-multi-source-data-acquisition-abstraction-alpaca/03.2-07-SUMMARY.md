# Phase 03.2 Plan 07: Shared ingest CLI, the Alpaca front door, and the volume guard wired everywhere Summary

**`utils/cli.py` holds the ingest argument groups and a two-mode roster resolver with no default; `ingest_alpaca.py` is the second vendor's front door with credentials from the environment only; and `assert_acquisition_volume_fits` — which had no call site at all — now refuses an over-budget fetch in all three entry points before any client is constructed.**

## Accomplishments

- **The shared ingest arguments exist once.** `utils/cli.py` owns `UNIVERSE_CATEGORY_MAP`, `add_window_args`, `add_universe_args`, `add_chunk_args`, `add_concurrency_args`, `add_volume_guard_args`, `validate_roster_args`, `roster_category` and `resolve_symbols`. `ingest_tiingo.py` and `ingest_us_equity.py` call them; the flags, defaults, help text and `parser.error(...)` messages are byte-identical after the relocation.
- **Both roster modes stayed reachable and neither became a default.** `resolve_symbols`'s `mode` is keyword-only with no default; `"as_of"` and `"in_range"` dispatch to different catalog methods, and a call that omits `mode` gets a `TypeError` rather than a quiet survivorship bias.
- **`ingest_alpaca.py` exists.** Vendor selected by config through the `config/__init__.py` factories (locked by an AST assertion that neither config dataclass is called by name), credentials from `APCA_API_KEY_ID` / `APCA_API_SECRET_KEY` only, `--data-type` required for tick and rejected otherwise, and a tick run that stops at raw and names 03.3 as where the conversion arrives.
- **The volume guard has call sites.** It previously had none — 03.2-04 proved it as a function while nothing invoked it. All three doors now call it before the fetching client is constructed, with `--force-volume` as the explicit, visible, per-run override.
- **An explicit `--symbols` list is priced, not exempted.** A `UniverseCatalog` subclass overriding exactly one method (`estimate_dense_panel`) prices a hand-named list or a `--limit`-truncated category, so every ceiling, refusal message and re-estimated narrowing stays the catalog's own code.
- **The three credential-dependent questions left the phase visibly open**, with no `feed` default written into code to answer one of them by habit.

## Decisions Made

See `key-decisions` in the frontmatter. The two worth restating:

- **The guard is named at each call site, not hidden behind a wrapper.** The shared part is which object prices the fetch and how the estimate is reported; the refusal itself is written where the decision to fetch is made, so a reader of any single ingest script sees it and a grep across the entry points finds all three.
- **`ingest_alpaca.py` writes to `stock_alpaca.zarr`, not `stock.zarr`.** D-11 puts the vendor segment on `raw_data_dir_path` and `watermark_path`; `zarr_file_path` has none. Sharing the factory's default store name would have let an Alpaca conversion overwrite the Tiingo store in place — the same silent cross-vendor merge D-11 exists to prevent, one layer up. Found while writing the script, not by a failing test.

## Open Verifications (credential-dependent — NOT resolved)

All three are recorded as OPEN. None was answered by inference, and none was defaulted in code.

**A. The free-tier SIP question (RESEARCH A7 / open question O-1).** Alpaca's documentation self-conflicts: three sources say the Basic tier reaches historical SIP data older than 15 minutes, one says IEX is the only usable feed without a subscription. With credentials exported, one request settles it:

```
export APCA_API_KEY_ID=... APCA_API_SECRET_KEY=...
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "APCA-API-KEY-ID: $APCA_API_KEY_ID" -H "APCA-API-SECRET-KEY: $APCA_API_SECRET_KEY" \
  'https://data.alpaca.markets/v2/stocks/trades?symbols=AAPL&start=2024-01-02T14:30:00Z&end=2024-01-02T14:31:00Z&feed=sip&limit=10'
```

`200` means the Basic tier reaches historical SIP. `403` with a subscription message means the IEX-only reading holds and free-tier tick data is ~2.5% of consolidated volume. Until then `feed` stays a `config.kwargs` parameter with no in-code default and no CLI flag — verified by `test_no_feed_default_reaches_the_alpaca_config`.

**B. A real vendor round-trip (SC-5's manual half).** No Alpaca credentials exist on this machine; every other SC-5 behaviour was proved against the mocked transport. With credentials:

```
uv run python ingest_alpaca.py --symbols AAPL --start-date <one trading day> --end-date <same day>
```

Confirm a `.pqt` shard under `downloads/us_equity/1d/<subdir>/alpaca/month=YYYY-MM/`, a page-ledger and a watermark sidecar under `downloads/us_equity/1d/<subdir>/_watermarks/alpaca/`, and that neither the console output nor `_failures.json` contains either credential value.

**C. The real symbol-per-request ceiling (RESEARCH A2 / O-2).** `AlpacaAcquisition.DEFAULT_BATCH_SIZE` is 100, chosen under the 200 a single forum post about an older API cites; the v2 reference documents no cap and 200 was deliberately not encoded as a constant. If 100 is far below the real ceiling the default is worth raising; if the vendor errors at 150 the default was right and the finding belongs on the class.
