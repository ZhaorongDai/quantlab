<objective>
Add the pre-flight volume guard: an estimate that costs zero vendor requests, a refusal that names the
numbers and the cure, and an explicit override.

Purpose: this is the mechanism that keeps CONTEXT.md's "接入能力打通" distinction enforceable rather
than merely stated. A mistyped `--frequency 1m --universe us_all` would otherwise run for ~50 hours
and write ~358 GB against ~120 GiB of free disk, with nothing stopping it. Failing before spending
quota and wall clock is the entire point.

Output: an `estimate_acquisition_volume` / `assert_acquisition_volume_fits` pair on `UniverseCatalog`,
built as the sibling of the dense-panel guard that already exists in that file.
</objective>

Computation:

- `symbols` and `trading_days` come from the same derivation `estimate_dense_panel` uses, so the two
  estimators cannot disagree about the roster.
- `rows` for `1d` is `estimate_dense_panel`'s `observed_cells` (the measured 0.368 density is the
  whole reason a dense count would be wrong here). For `1m` it is that figure multiplied by

- `wall_clock_hours = requests / rate_limit_per_min / 60`, with `rate_limit_per_min` defaulting to
  `DEFAULT_RATE_LIMIT_PER_MIN` when not passed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments -> volume estimate -> refusal | An unvalidated `--frequency` / `--universe` / date window decides how much disk and wall clock a run will consume |
| local disk capacity -> the guard's byte ceiling | The guard is the only thing between a mistyped parameter and a filled volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.2-07 | Denial of Service | unbounded fetch fills the disk or runs for tens of hours | high | mitigate | `assert_acquisition_volume_fits` refuses before the client is constructed and before a single request, on bytes, request count AND wall clock — three independent ceilings, so a scenario that slips past one is caught by another |
| T-03.2-20 | Denial of Service | a guessed `tick` row count admitting a fetch orders of magnitude larger than estimated | high | mitigate | `rows_per_symbol_day` is REQUIRED for `tick`; the estimator raises rather than defaulting. RESEARCH Assumption A4 flags the underlying figure as order-of-magnitude only and unmeasured against Alpaca, which is exactly why it is not encoded as a default |
| T-03.2-21 | Tampering | the override becoming a silent bypass | medium | mitigate | `force` is an explicit named parameter with a `False` default; there is no environment-variable escape hatch and no config key that disables the guard wholesale. Every threshold is individually raisable, which is the deliberate path |
| T-03.2-22 | Repudiation | a refusal a user works around by deleting the guard | medium | mitigate | The message names a concrete narrowing computed from the estimate itself, following the `assert_dense_panel_fits` / `STAMP_COMMAND_HINT` idiom already proven in this repo. A refusal with a named cure is actionable; one without is an obstacle |
| T-03.2-15 | Elevation of Privilege | — | low | accept | Single-user local research pipeline with no authorization surface (ASVS V4 not applicable) |
