<objective>
Give "the vendor was asked and returned nothing" its own explicit, additive, on-disk representation —
and make sure it can only be written about a batch that actually finished.

Purpose: without a third state, a full-market run either accumulates thousands of permanent retries
against delisted tickers until the failure report loses all signal, or launders a silent vendor fault
into "confirmed no data" by advancing the watermark bare. D-04 refuses both. The trap is Pitfall 4:
Alpaca is symbol-major, so page 1 of a 100-symbol batch legitimately contains one symbol — computing
the marker per page would stamp 99 symbols "no data", advance their watermarks and skip them forever,
as a silent 99% data loss that looks like a successful run.

Output: one additive boolean key on the existing watermark sidecar, a `_read_coverage` that returns
it, a `_coverage_status` that skips on it, and a write gate that fires only on batch completion.
</objective>
