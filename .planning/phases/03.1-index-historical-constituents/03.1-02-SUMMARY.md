## Decisions Made

**Nasdaq-100 anchor source.** `https://stockanalysis.com/list/nasdaq-100-stocks/` is `ANCHOR_URL`. `https://www.slickcharts.com/nasdaq100` (also 102 rows, columns `# / Company / Symbol / Weight / Price / Chg / % Chg`) is recorded in the class docstring as the documented alternative if that source dies — **deliberately not implemented as a second code path**, per the plan. Wikipedia's own `Nasdaq-100` page has no parseable constituents table (its components render through a navbox template), which is why a commercial scraped source was needed at all.

**102 rows, not 100.** The live anchor probed at 102 constituents because the index carries multiple share classes for some issuers (GOOGL/GOOG, FOX/FOXA). An `== 100` assertion is therefore *wrong against correct data*, and the fixture mirrors the real 102-row shape with an inline `assert len(symbols) == 102` so the count is visible in the source rather than implied.

**The two message strings that were parameterised.** Exactly two, both in the hoisted envelope:

1. `fetch_changes()`'s fallback `logger.error`: `"Failed to fetch/parse S&P 500 changes from Wikipedia ..."` → `f"Failed to fetch/parse {self.INDEX_LABEL} changes from Wikipedia ..."`.
2. `_load_cache()`'s `RuntimeError`: `"No cached S&P 500 changes snapshot available ... cannot build sp500_constituent intervals."` → `f"No cached {self.INDEX_LABEL} changes snapshot available ... cannot build {self.CATEGORY} intervals."`

With `INDEX_LABEL = "S&P 500"` and `CATEGORY = "sp500_constituent"` these render byte-identical to the pre-extraction text for the S&P path. The two `ValueError` guard messages (missing-columns and row-count monotonicity) were **not** touched — they stayed word-for-word, including the "memberships only close, they don't retroactively vanish" reasoning.

**`MIN_ANCHOR_ROWS = 50` as a Nasdaq-only class constant.** The threshold is deliberately far below the real 102 so a legitimate index resize never trips it, while a markup drift that yields a handful of rows fails loudly. It is Nasdaq-specific because the S&P anchor is a hosted CSV with no equivalent failure mode.

**`UniverseCatalog` is deliberately NOT wired to `nasdaq100_constituent` in this plan.** `build()` still hardcodes the two Phase-2 fetchers and `get_symbols_as_of()` still guards only `sp500_constituent`'s pre-coverage boundary. That wiring — including the second, later left edge at 2007-02-01 — is 03.1-04's Task 2, which owns the same file in a later wave. This plan's scope fence (`git diff --stat base/ dataset/ config/` empty) held.

## Deviations from Plan

**1. [Rule 2 - Missing Critical] Named `MIN_ANCHOR_ROWS` constant instead of an inline literal 50**
- **Found during:** Task 1 (Nasdaq-100 `fetch_anchor()` shape guard)
- **Issue:** The plan specified the guard as "fewer than 50 rows"; an inline magic number in a security-relevant guard is unreviewable and invites a silent tightening/loosening.
- **Fix:** Declared `MIN_ANCHOR_ROWS = 50` as a `Nasdaq100MembershipFetcher` class constant with a comment explaining why 50 is far below 102, and interpolated it into the error message.
- **Files modified:** `acquisition/universe.py`
- **Verification:** `test_nasdaq100_anchor_rejects_a_structurally_drifted_page` passes; the acceptance-criteria introspection checks are unaffected (they assert on method sets, not constants).
- **Committed in:** `0c1a088`

**2. [Rule 2 - Missing Critical] Split the anchor guard into two distinct errors**
- **Found during:** Task 1
- **Issue:** The plan asked for one `ValueError` covering both "too few rows" and "lacks the symbol column". Collapsing them means the error cannot say which drift occurred, and the row-count check would crash on a table with no `Symbol` column before it could report anything useful.
- **Fix:** Two guards — a missing-`Symbol`-column check that runs first (selecting the table by column presence across all parsed tables), then the row-count check. Both name `ANCHOR_URL`; the row-count one also names the observed count, as specified.
- **Files modified:** `acquisition/universe.py`
- **Verification:** `test_nasdaq100_anchor_rejects_a_structurally_drifted_page` (which exercises the row-count branch) passes; both raise `ValueError`, so the plan's contract is unchanged.
- **Committed in:** `0c1a088`

**3. [Rule 3 - Blocking] `TEMP1` is not in the anchor fixture, producing an expected stale-anchor WARNING**
- **Found during:** Task 1 (fixture design)
- **Issue:** The plan's change-log fixture adds `TEMP1` on 2018-03-02 but its anchor fixture row list does not include `TEMP1`, so `reconstruct_intervals()` takes the "open interval but not in current anchor set" branch and closes it at `last_eff`.
- **Fix:** Left as-is — this is the plan's own row list and it exercises a real, already-tested reconstruction branch (stale anchor relative to the change log). No assertion depends on `TEMP1`.
- **Files modified:** `tests/conftest.py` (documented in the fixture docstring)
- **Verification:** 14/14 tests in the file pass; the warning is informational.
- **Committed in:** `0c1a088`
