<objective>
**As a** quant researcher, **I want to** obtain a daily point-in-time S&P 500 membership panel as
an `xarray.Dataset`, **so that** any downstream layer can mask its universe per day without
survivorship bias.

This is the phase's core slice and the one piece with no in-repo precedent: converting
`acquisition/universe.py`'s `(symbol, start_date, end_date)` interval table into a dense
`(timestamp, symbol) -> bool` panel, persisted to Zarr per D-04. 03.1-RESEARCH.md Finding 6 lists
six ways that conversion goes silently wrong; every one of them gets an explicit, hand-checkable
test here rather than a plausible-looking panel nobody audits.

Purpose: DATA-05 for the S&P 500 and the first of D-01's two concrete daily constituent
dataset classes (date + ticker), and it establishes the `IndexConstituentDataset` base that
03.1-04 adds the Nasdaq-100 to with zero edits under `base/`.
Output: `base/constituent.py`, `dataset/constituent.py`, `clean_membership_panel()`, the config
factory, and the densification correctness suite.

**The densification contract — write it exactly as specified; this is where correctness is decided.**

`IndexConstituentDataset._densify(intervals: pl.DataFrame) -> xr.Dataset`:

- **Symbol axis:** `sorted(set(intervals["symbol"]))`, the ALL-TIME union, computed before any
  date filtering. A symbol whose entire membership predates the panel window still gets a column
  (all False). This is the survivorship-bias guarantee and it is also what makes
  `XrBackend.filter_by_symbol`'s `.sel(symbol=[...])` safe — a requested symbol that was never a
  member raises `KeyError` loudly instead of silently vanishing.
- **Left edge:** `max(self.config.start_date, self._pit_coverage_start())`, ISO-string comparison.
  `enums/constant.py:Date.START_DATE` is `"1900-01-01"`, 76 years before the S&P's coverage, so
  without this clamp the panel gains a huge all-False region that reads as "nobody was a member"
  rather than "unknown" (CONFLICT 5).
- **Right edge:** `min(self.config.end_date, horizon)` where `horizon` is the maximum of every
  `start_date` and every non-null `end_date` in the interval table — the latest date the source
  data can speak to. `Date.END_DATE` is `"2100-01-01"`, so without this clamp the default config
  would materialise a 45,000-day panel of fabricated future membership. When
  `config.end_date` exceeds `horizon`, emit a `logger.warning` naming both dates so the truncation
  is visible; do not extend the panel past the last observation.
- **Guard:** if the resolved right edge is earlier than the resolved left edge, raise `ValueError`
  naming both edges and the index's coverage start. An empty panel is never a valid answer.
- **Axis:** `pd.date_range(left, right, freq="D")` — CALENDAR days, not trading days. State this in
  the class docstring together with its one real consequence: a downstream join against OHLCV data
  that only has trading days must reindex/`sel` onto the price panel's timestamps, since the
  membership panel carries weekend and holiday rows whose value is the last trading day's
  membership carried forward. A trading-day axis would need a session calendar this repository
  does not have.
- **Fill:** for each interval row, `mask = (ts >= start) & (ts <= (end if end is not None else right))`
  then `values[mask, column_of[symbol]] = True`. Both comparisons are inclusive. This is
  deliberately the same convention as `acquisition/universe.py:305`'s
  `(pl.col("end_date").is_null() | (pl.col("end_date") >= as_of_date))` combined with
  `pl.col("start_date") <= as_of_date`: the removal's effective date IS a membership day. A
  divergence here would make the panel and `get_symbols_as_of()` disagree by one day for every
  removal in history, and nothing at runtime would notice.
- **Return:** `xr.Dataset({"is_member": (["timestamp", "symbol"], values)}, coords={"timestamp": ts, "symbol": symbols})`
  with `values` a `numpy` array of dtype `bool`. This shape is verified to round-trip through
  `XrBackend.write`/`read` with dtype preserved, and `sel(timestamp=slice(...))` /
  `sel(symbol=[...])` both work on it. Sort the timestamp axis (`pd.date_range` already is) —
  `XrBackend.filter_by_date` uses `.sel(timestamp=slice(...))`, which silently returns wrong
  results on an unsorted index.

**The PIT left-edge clamp runs at config-assignment time, via a property-setter override.**
`IndexConstituentDataset` redefines the `config` property and its setter; the setter calls
`BaseDataset.config.fset(self, config)` to run the whole shared lifecycle first, then clamps
`self._config.start_date` up to `self._pit_coverage_start()` if it is earlier. This mechanism was
verified working at plan time. It makes the clamp assertable on the config object itself
(`SP500ConstituentDataset(cfg).config.start_date == "1976-07-01"`) rather than only observable in
the panel, and it also makes the inherited `_filter()` consistent with the panel on `read()`.

**`_reset_symbols()` is overridden to a no-op (CONFLICT 1).** Docstring must state all three
reasons the inherited body is wrong here, from 03.1-PATTERNS.md §9: the symbol axis is derived
from the interval table rather than from a store so overwriting `config.symbols` with the store's
symbols is meaningless; the inherited `FileNotFoundError` fallback calls `from_raw_data()`, which
for this class reaches a remote fetch, so merely constructing the object on a fresh clone would
perform an unannounced HTTP request; and only `FileNotFoundError` is caught, so a network or parse
error would escape `__init__` and the object could not be constructed offline at all. Never solve
this with an `isinstance` check or a config flag.
