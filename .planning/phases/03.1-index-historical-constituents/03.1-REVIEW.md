# Phase 03.1: Code Review Report

**Reviewed:** 2026-09-05
**Depth:** standard
**Files Reviewed:** 20
**Status:** issues_found

## Summary

The phase delivers a clean structural split (`BaseDataset` / `MarketDataset`,
`IndexMembershipFetcher` base + data-only subclasses) and the 46 tests in scope all pass.
The abstraction boundaries are genuinely good and the densification layer
(`base/constituent.py`) is close to correct.

The problems are concentrated in `acquisition/universe.py`, and they share one shape: **the
module's stated safety philosophy — "never silently answer with an incomplete/wrong answer" —
is not what the code actually does.** Several defences that the docstrings describe as
"load-bearing SAFETY properties ... by construction" are provably vacuous, and four distinct
paths return a wrong-but-plausible roster with no error and no warning. In a survivorship-bias-
free universe table, a silently-wrong roster is exactly the failure the whole module exists to
prevent, and it is undetectable downstream.

Every Critical finding below was reproduced against the real code, not inferred from reading.

## Critical Issues

### CR-01: A current index constituent is silently reconstructed as a *former* member

**File:** `acquisition/universe.py:242-260`

**Issue:** `reconstruct_intervals()` reconciles the anchor against the change log in only two
directions:

1. open interval, symbol **not** in anchor → close it (with a warning);
2. symbol in anchor, **never seen** in the change log → open an interval at
   `date_added or PIT_COVERAGE_START`.

The third case is unhandled: a symbol whose **last change-log event was a removal but which the
anchor lists as a current constituent**. `seen_symbols = {c[0] for c in closed}` contains it, so
the anchor-only loop at line 258 skips it, and no open interval is ever created. It is recorded
as a former member, with no warning — the mirror-image inconsistency at line 245 *does* warn.

This is not hypothetical for these sources: the docstrings themselves record that the live
Nasdaq-100 log has 16 drop-only rows and is known to be asymmetric, so a re-addition missing
from the log is precisely the drift the anchor is there to correct.

Reproduced:

```python
anchor  = pl.DataFrame({"symbol": ["CURR"], "date_added": [None]}, schema={"symbol": pl.String, "date_added": pl.String})
changes = pl.DataFrame({"effective_date": ["1990-01-01", "2005-01-01"],
                        "added_ticker":   ["CURR", None],
                        "removed_ticker": [None, "CURR"]})
SP500MembershipFetcher(cache_dir="/tmp/x").reconstruct_intervals(anchor, changes)
# -> {'symbol': 'CURR', 'start_date': '1990-01-01', 'end_date': '2005-01-01'}   (no warning)
```

Consequence: `get_symbols_as_of(category, today)` omits a current constituent, and
`IndexConstituentDataset` densifies `is_member = False` for it at the live edge — the panel is
wrong exactly where a universe mask is consumed.

**Fix:** reconcile all three directions, and make the anchor authoritative for "is a member
today":

```python
closed_by_symbol: dict[str, list[int]] = {}
for i, (sym, _s, _e) in enumerate(closed):
    closed_by_symbol.setdefault(sym, []).append(i)

for sym in anchor_symbols - set(open_intervals):
    idxs = closed_by_symbol.get(sym)
    if not idxs:
        continue  # handled by the never-seen loop below
    last = max(idxs, key=lambda i: closed[i][2] or "")
    logger.warning(
        f"{sym}: change log's last event is a removal at {closed[last][2]}, but the "
        f"current anchor still lists it as a constituent -- the change log is missing a "
        f"re-addition. Re-opening membership from that removal date."
    )
    closed.append((sym, closed[last][2], None))
```

Whatever policy is chosen (re-open, or hard-fail), it must not stay silent.

### CR-02: `pd.read_html`'s default NA coercion silently deletes real tickers and fabricates a `"nan"` symbol

**File:** `acquisition/universe.py:300-317` (S&P 500), `372-404` and `406-423` (Nasdaq-100)

**Issue:** Every `pd.read_html(...)` call in this module uses pandas' default NA handling, which
converts the cell strings `NA`, `N/A`, `NULL`, `NaN`, `None`, `nan`, `-`, `1.#IND` … to `NaN`.
Ticker symbols collide with that set (`NA` is a real, historically-listed US equity ticker).

Two distinct corruptions follow, both reproduced:

*Change log* — `NaN` is the exact sentinel `reconstruct_intervals()` uses for "no change on this
side" (`row["added_ticker"] is not None`, lines 218/230), so an add or remove event for such a
ticker is **silently discarded**:

```
<td>NA</td> in the Added column  ->  added_ticker = NaN  ->  event dropped entirely
```

*Nasdaq-100 anchor* — line 400 does `str(sym)`, so the same `NaN` becomes the literal string
`"nan"` and enters the anchor set as a fabricated permanent constituent:

```
anchor["symbol"] -> ["nan", "NDX001", ...]     # real ticker "NA" is gone
```

The fabricated `"nan"` symbol then becomes a real, always-True column in the densified panel
(`base/constituent.py:_densify`), and the real ticker is missing from a table whose entire
purpose is to contain every symbol that was ever a member.

**Fix:** disable NA inference on every `read_html` call and use an explicit blank sentinel:

```python
tables = pd.read_html(
    io.StringIO(html_text), attrs={"id": "changes"}, flavor="lxml",
    keep_default_na=False, na_values=[],
)
...
for col in ("added_ticker", "removed_ticker"):
    changes[col] = changes[col].astype(str).str.strip()
    changes.loc[changes[col].isin({"", "—", "-", "–"}), col] = None
```

and in `fetch_anchor()` drop blanks rather than `str()`-ing them:

```python
raw = anchor["Symbol"].astype(str).str.strip()
symbols = [s for s in raw.tolist() if s and s.lower() != "nan"]
```

Add a test asserting a `NA`-tickered add/remove row survives parsing.

### CR-03: The base class's "required column" guard can never fire; a header reorder silently inverts add/remove

**File:** `acquisition/universe.py:168-173` (guard), `305-317` and `412-423` (subclass parses)

**Issue:** `IndexMembershipFetcher`'s docstring (lines 107-117) declares the required-column
check a "load-bearing SAFETY property ... every subclass gets [it] BY CONSTRUCTION". It is dead
code. Both `_parse_changes_table()` implementations **assign** column names positionally
(`changes.columns = [...]`) and then return exactly
`changes[["effective_date", "added_ticker", "removed_ticker"]]`, so
`required_columns.issubset(set(changes.columns))` at line 169 is unconditionally `True`. Nothing
validates the *source* headers at all.

The real guard is the implicit `Length mismatch` raised when the column *count* differs — which
means the one drift the source is most likely to produce (a header **reorder**, same count) is
accepted and silently mislabelled. Reproduced against `Nasdaq100MembershipFetcher`, with the
page's `Added`/`Removed` groups swapped:

```
  effective_date added_ticker removed_ticker
0     2007-02-01         CMVT           LOGI     <- LOGI now recorded as REMOVED in 2007
1     2018-03-02         LOGI          TEMP1     <- and ADDED in 2018 — exactly inverted
base-class required-column check passes: True
```

Aggravating factor: `Nasdaq100MembershipFetcher._parse_changes_table` takes `tables[0]` with no
selector at all (line 408), unlike the S&P 500's `attrs={"id": "changes"}` — so any table
Wikipedia inserts ahead of the change log is parsed as the change log.

**Fix:** validate the source headers before renaming, and select the table by identity:

```python
EXPECTED_HEADER = ("Date", "Added Ticker", "Added Security",
                   "Removed Ticker", "Removed Security", "Reason")

def _parse_changes_table(self, html_text: str) -> pd.DataFrame:
    tables = pd.read_html(io.StringIO(html_text), flavor="lxml", keep_default_na=False, na_values=[])
    changes = next(
        (t for t in tables if tuple(" ".join(map(str, c)).split()[-2:] for c in t.columns) == ...),
        None,
    )
    if changes is None:
        raise ValueError(f"{self.INDEX_LABEL}: no table matching the expected change-log header ...")
```

At minimum: assert the flattened source header matches an expected tuple before assigning names,
and move that assertion onto the base so it actually is by-construction.

### CR-04: `get_symbols_as_of()` answers an unknown category or a malformed date with a silent empty roster

**File:** `acquisition/universe.py:492-515`

**Issue:** `category` and `as_of_date` are typed `str` (not `UniverseCategory`) and are never
validated. Three wrong inputs all produce `[]` — a *legitimate* return value that
`tests/test_universe.py:test_nasdaq_all_has_no_coverage_boundary` explicitly asserts — so the
caller has no way to distinguish "no members" from "you asked wrong". Reproduced against a built
and reloaded catalog:

```
typo'd category "sp500"        -> []
non-ISO date "01/01/2024"      -> []      # string comparison "1980-12-12" <= "01/01/2024" is False
```

`as_of_date` reaches this function straight from the `--as-of-date` CLI argument in
`ingest_tiingo.py:44` with no format validation, so a mistyped date silently ingests **nothing**
instead of the S&P 500. That is the same class of silent-wrong-answer the coverage-start guard
three lines above raises a `ValueError` to prevent.

**Fix:**

```python
def get_symbols_as_of(self, category: str, as_of_date: str) -> list[str]:
    known = {"nasdaq_all"} | {f.CATEGORY for f in self.MEMBERSHIP_FETCHERS}
    if category not in known:
        raise ValueError(f"Unknown universe category {category!r}; known: {sorted(known)}")
    try:
        datetime.date.fromisoformat(as_of_date)
    except ValueError as exc:
        raise ValueError(
            f"as_of_date must be an ISO YYYY-MM-DD string, got {as_of_date!r}; "
            f"the table stores ISO strings and compares them lexicographically."
        ) from exc
    ...
```

### CR-05: `NasdaqUniverseFetcher` has no shape guard and no cache fallback — a silently-empty `nasdaq_all` overwrites the good `universe.parquet`

**File:** `acquisition/universe.py:68-84`, `463-484`

**Issue:** The file applies two safety envelopes to index membership — `MIN_ANCHOR_ROWS` (line
370, with a comment explaining that a truncated roster "silently reintroduces survivorship
bias") and the row-count monotonicity guard (line 174) — and applies **neither** to the
full-exchange roster, which is the largest category in the table.

`fetch()` filters on exact-match literals (`"NASDAQ"`, `"Stock"`, `"USD"`, lines 76-80). If
Tiingo changes a token's casing or spelling, or renames a column value, the filter yields zero
rows without raising. `build()` (line 475) concatenates that empty frame happily, and
`refresh_us_equity_universe.py:17`'s `UniverseCatalog(config).build().save()` then writes the
result **over** the previous good `universe.parquet`. Reproduced: an empty NASDAQ frame produces
a persisted catalog for which `get_symbols_as_of("nasdaq_all", "2024-01-01")` returns `[]`, with
no error anywhere in the pipeline.

Data-loss risk: the previous 10,000+-symbol roster is destroyed, and the only warning is that
downstream ingestion quietly does nothing.

**Fix:** give the roster the same guard the NDX anchor already has, and make `save()` refuse to
overwrite with a degenerate table:

```python
MIN_ROSTER_ROWS = 1000  # far below the real ~10k, so a legitimate shrink never trips it

def fetch(self) -> pl.DataFrame:
    ...
    data = data.select(["symbol", "start_date", "end_date"])
    if len(data) < self.MIN_ROSTER_ROWS:
        raise ValueError(
            f"Tiingo supported_tickers filtered to only {len(data)} rows "
            f"(exchange={self.EXCHANGE_FILTER}, assetType={self.ASSET_TYPE}, "
            f"priceCurrency={self.PRICE_CURRENCY}) -- the source's token vocabulary has "
            f"drifted. Refusing to continue rather than overwriting the reference table "
            f"with an empty roster."
        )
    return data
```

and in `save()`, assert every category in `MEMBERSHIP_FETCHERS` plus `nasdaq_all` is non-empty
before writing.

## Warnings

### WR-01: A stale cache fallback is written to `universe.parquet` with no staleness marker

**File:** `acquisition/universe.py:184-202`, `463-479`
**Issue:** On any fetch/parse failure `fetch_changes()` returns `_load_cache()` — correct and
deliberate — but `build()`/`save()` then persist that stale reconstruction into
`universe.parquet` indistinguishably from a fresh one. A permanently-broken source (see WR-11)
freezes the universe at the cache date; only a `logger.error` line, easily lost in a cron log,
records it.
**Fix:** have `fetch_changes()` record provenance (e.g. return `(frame, is_stale, cache_mtime)`
or set an attribute), and have `UniverseCatalog.build()` either add a `source_asof` column to the
persisted table or raise unless an explicit `allow_stale=True` is passed.

### WR-02: A corrupt cache silently disables the row-count monotonicity guard, and the cache write can create exactly that corruption

**File:** `acquisition/universe.py:150-156` (guard disable), `192-193` (non-atomic write)
**Issue:** `except Exception: cached_row_count = 0` swallows the read failure without logging,
after which `len(changes) < 0` can never be true — the monotonicity guard the class docstring
calls a load-bearing safety property is off. `parsed.write_parquet(self._cache_path)` writes in
place with no temp-file-and-rename, so an interrupted run leaves a truncated parquet that
produces precisely this state.
**Fix:** log the corrupt-cache read at `logger.error`, and write atomically:

```python
tmp = self._cache_path.with_suffix(".parquet.tmp")
parsed.write_parquet(tmp)
tmp.replace(self._cache_path)
```

### WR-03: Tests write a persistent cache file into the repository working directory

**File:** `tests/test_universe.py:42`, `tests/test_universe.py:60`
**Issue:** `SP500MembershipFetcher(cache_dir="unused")` makes `_cache_path` a **CWD-relative**
path, and `fetch_changes()` does `mkdir(parents=True)` + `write_parquet`. Running the suite
creates `unused/sp500_changes_snapshot.parquet` in the repo root — it exists there right now,
and is only kept out of `git status` by an incidental `*.parquet` rule
(`.gitignore:212`), not by an intentional ignore. Worse, that file persists **across runs** and
feeds `cached_row_count`, so the monotonicity guard these tests exercise carries hidden state
from previous invocations; shrinking a fixture would fail or pass depending on run history.
**Fix:** use `tmp_path` in both tests (`cache_dir=str(tmp_path)`), matching every other test in
the module, and delete the stray `unused/` directory.

### WR-07: The panel's right edge depends on wall-clock `today`, making the artifact non-reproducible

**File:** `base/constituent.py:210-213`
**Issue:** `horizon = max(observed, pd.Timestamp.today().normalize())` when any membership is
open. Rebuilding the same config on two days produces two differently-shaped Zarr stores, and
`save()` overwrites with `mode="w"`. That conflicts with CLAUDE.md's 可复现性 constraint ("全流程参数尽量通过配置文件驱动") — the single most

### WR-11: `pd.to_datetime` is called with no `format=` and no `errors=`, so one bad row aborts the whole fetch

**File:** `acquisition/universe.py:314-316`, `420-422`
**Issue:** Both parses emit `UserWarning: Could not infer format, so each element will be parsed
individually, falling back to dateutil` (observed). Beyond the noise, a single unparseable cell —
Wikipedia routinely carries footnote markers and ranges in date columns — raises
`DateParseError`, which the broad `except Exception` at line 184 converts into a permanent,
silent fallback to the stale cache (WR-01).
**Fix:** parse with an explicit format and surface the offending rows instead of failing the
whole table:

```python
parsed_dates = pd.to_datetime(changes["effective_date"], format="mixed", errors="coerce")
bad = changes.loc[parsed_dates.isna(), "effective_date"]
if len(bad):
    raise ValueError(f"{self.INDEX_LABEL}: unparseable effective_date rows: {bad.tolist()}")
changes["effective_date"] = parsed_dates.dt.strftime("%Y-%m-%d")
```

### WR-12: Date comparisons are lexicographic on unvalidated strings

**File:** `base/constituent.py:105`, `base/constituent.py:196-197`, `acquisition/universe.py:501`
**Issue:** `requested >= coverage_start`, `max(self.config.start_date, self._pit_coverage_start())`
and `as_of_date < coverage_start` all rely on the caller supplying zero-padded ISO strings. A
non-ISO or non-padded value (`"2007-2-1"`, `"01/01/2005"`) compares wrong and silently skips the
clamp or the coverage guard. Nothing in `BaseDatasetConfig`/`UniverseConfig` validates date
format.
**Fix:** normalize once at the config boundary — `datetime.date.fromisoformat(...).isoformat()`
in the `BaseDatasetConfig` setter and in `get_symbols_as_of` (see CR-04) — and keep the
comparisons lexicographic afterwards.

### WR-13: A null `start_date` in the interval table poisons the horizon computation

**File:** `base/constituent.py:200-209`, `240`
**Issue:** `max(pd.Timestamp(row["start_date"]) for row in rows)` — `pd.Timestamp(None)` is `NaT`,
and every comparison against `NaT` is `False`, so `max()` returns whatever it happened to hold
first rather than raising. `start_date` can legitimately be null today: it comes from
`effective_date`, which becomes null if `pd.to_datetime` ever yields `NaT` (WR-11) or if a
change-log row lacks a date. The same null then reaches line 240 and silently produces an
all-False mask row.
**Fix:** reject nulls explicitly before densifying:

```python
missing = [r["symbol"] for r in rows if r["start_date"] is None]
if missing:
    raise ValueError(
        f"{self.class_name}: interval rows with a null start_date cannot be densified: {missing}"
    )
```

### WR-14: `symbols` type contract is inconsistent across the constituent path

**File:** `config/__init__.py:128,164` (`symbols: list | None`), `base/config.py:36`
(`symbols: tuple | None`), `base/constituent.py:118-141` (no-op `_reset_symbols`)
**Issue:** `BaseDatasetConfig.symbols` is declared `tuple | None` and `MarketDataset` normalizes
it to a tuple inside `_reset_symbols()`. `IndexConstituentDataset` overrides that to a no-op

both) but the declared contract is now false for one branch of the hierarchy.
**Fix:** normalize in the `BaseDatasetConfig` setter rather than in `_reset_symbols()`:
`self._config.symbols = tuple(self._config.symbols) if self._config.symbols is not None else None`,
then drop the two `# type: ignore[arg-type]` comments.

**Issue:** `dict(zip(anchor["symbol"], anchor["date_added"]))` silently truncates if a future
`fetch_anchor()` returns mismatched column lengths.
**Fix:** `zip(..., strict=True)`.

### IN-04: Every config path resolves under a doubled `data/data/` segment

**File:** `config/__init__.py:31-38`
**Issue:** `_data_root()` already ends in `data/`, and `_market_data_root()`/`_market_downloads_root()`
append another `"data"`/`"downloads"`, so `sp500_constituent_config().zarr_file_path` resolves to
`<repo>/data/data/us_equity/1d/sp500_constituent.zarr`. Pre-existing and asserted by
`tests/test_config_paths.py`, but it will confuse anyone setting `QUANTLAB_DATA_DIR`.
**Fix:** either rename `_data_root()` to `_storage_root()` and drop its `data` suffix, or document
the layout explicitly in the `_data_root()` docstring.

### IN-05: Anchor symbols are not stripped, upper-cased or deduplicated

**File:** `acquisition/universe.py:398-404`, `293-298`
**Issue:** `str(sym)` on a scraped commercial page preserves any stray whitespace or NBSP, and
`set(anchor["symbol"])` would then treat `"AAPL "` and `"AAPL"` as different constituents.
**Fix:** `.str.strip().str.upper()` before constructing the frame (see CR-02's fix, which touches
the same lines).

### IN-06: `enums/data.py` `UniverseCategory` comment block duplicates the fetcher docstrings

also live on `Nasdaq100MembershipFetcher` and in `README.md`. Three copies of one fact will drift.
**Fix:** keep the "these are different universes" warning here (that part is genuinely useful at
