<objective>
**As a** quant researcher, **I want to** persist and reload a dataset that is not OHLCV market
data through the same storage contract every pipeline layer already uses, **so that** an index
membership panel becomes a first-class dataset instead of a market dataset with two meaningless
`raise NotImplementedError` stubs bolted on.

Deliver D-03's dataset-side abstraction: split `base/data.py:Dataset` into a shared
`BaseDataset(ABC)` and a `MarketDataset(BaseDataset)` that owns every nautilus/KunQuant member,
and split `DatasetConfig` the same way `BaseFactorConfig`/`FactorConfig` were split in 03-02.
This is a **refactor, not a rewrite** — every hoisted body is moved verbatim, behaviour must not
change for `SpotKlineDataset` or `StockDataset`, and `base/factor.py`/`base/factor_polars.py`/
`base/model.py` must require zero edits.

Purpose: DATA-06, and it unblocks 03.1-02's `IndexConstituentDataset(BaseDataset)`.
Output: the two-class dataset hierarchy, the three-way config split, and a guard-test file that
fails loudly if a later change re-couples the shared base to nautilus/KunQuant or reverses the
`__init__` assignment order.
</objective>

**CONFLICT 1 — `_reset_symbols()` must become a named overridable seam.** `base/data.py:78-90`:
the config setter calls `_reset_symbols()` whenever `config.symbols is not None`, and that method
does `self.read()`, falls back to `self.from_raw_data()` on `FileNotFoundError`, then overwrites
`self._config.symbols` with whatever the store holds. For a market dataset this is merely
surprising. For 03.1-02's constituent dataset it is fatal three times over: the symbol axis comes
from a membership-interval table rather than a store; `from_raw_data()` there means a live HTTP
fetch, so merely constructing the object would hit the network; and only `FileNotFoundError` is
caught, so a network/parse error escapes `__init__`. Hoist the method to `BaseDataset` with its
body byte-identical, and give it a docstring declaring it an overridable seam — the same
treatment `base/factor.py:79-92`'s `_maybe_resolve_factor_names()` got in 03-02 and that
`base/factor_polars.py:56` overrides to a no-op. Do NOT solve this with an `isinstance` check or
a config boolean flag; 03-02 explicitly rejected both. Do NOT push `_reset_symbols()` down to
`MarketDataset` — it is called from the shared config setter, so the setter would have to be
split too, which is strictly messier.

**CONFLICT 2 — the two hierarchies hold OPPOSITE `__init__` invariants and both are correct.**

`tests/test_factor_hierarchy.py:test_factor_init_assigns_config_before_the_storage_backend`)
