<objective>
**As a** quant researcher, **I want to** reconstruct point-in-time Nasdaq-100 membership intervals
the same way S&P 500 intervals are already reconstructed, **so that** a second index becomes a data
change rather than a code change and the daily panel layer can consume both identically.

Extract `IndexMembershipFetcher` out of `SP500MembershipFetcher` — 03.1-RESEARCH.md Finding 4
verified that `reconstruct_intervals()` is already 100% generic — and add
`Nasdaq100MembershipFetcher` as a data-only sibling. The two behaviours that must survive the
extraction are not incidental: the row-count monotonicity guard that treats a shrunken table as a
parse failure, and the cached-snapshot fallback that does NOT overwrite the cache on failure. Both
matter MORE for the Nasdaq-100 than for the S&P, because its anchor comes from a commercial scraped
site rather than a GitHub-hosted CSV.

Purpose: DATA-05's Nasdaq-100 half at the source layer. It is independent of the dataset-hierarchy
split, so it runs in wave 1 alongside 03.1-01 on a disjoint file set.
Output: the fetcher base, the Nasdaq-100 fetcher, the third `UniverseCategory` value, and the
offline fixtures every later Nasdaq-100 test depends on.
</objective>

2026-09-05, MultiIndex columns `Date | Added(Ticker, Security) | Removed(Ticker, Security) | Reason`
— **six** flat columns after `pd.read_html`. The parse hook therefore assigns six names
(`effective_date`, `added_ticker`, `added_security`, `removed_ticker`, `removed_security`,
`reason`), normalises `effective_date` with `pd.to_datetime(...).dt.strftime("%Y-%m-%d")`, and
selects the same three columns the base's required-column check expects. Verified at plan time
that this exact sequence produces `None` (not `NaN`) in the polars frame for a blank cell, so
`reconstruct_intervals()`'s `row["removed_ticker"] is not None` guard works unchanged.

lets the base's required-column check reject anything else.

**Nasdaq-100 anchor (RESEARCH Finding 5).** Wikipedia's `Nasdaq-100` page has no parseable
constituents table — its components render through a navbox template — so the anchor comes from
`https://stockanalysis.com/list/nasdaq-100-stocks/`, which probed at 102 rows with columns
`No. / Symbol / Company Name / Market Cap / Stock Price / % Change / Revenue`.
`https://www.slickcharts.com/nasdaq100` is the documented alternative if that source dies; record it
in the class docstring, do not implement both. **102, not 100, is correct** — the index carries

`date_added` column, so `fetch_anchor()` must synthesise an explicit all-null `date_added` column,
which is what makes `reconstruct_intervals()`'s existing
`anchor_date_added.get(sym) or self.PIT_COVERAGE_START` fallback fire as written instead of raising
`KeyError`.
