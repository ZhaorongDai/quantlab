## Accomplishments

- `BaseDataset(ABC)` now carries the entire storage lifecycle — the `config` property/setter, `_filter`, `read`/`save`, `from_raw_data()` with its `_clean()` hook, the xarray/polars accessors — and exactly one abstract method, `_raw_data_to_xr()`. `MarketDataset(BaseDataset)` adds `_write_catalog`, `to_nautilus`/`_to_nautilus`, `to_kunquant`/`_to_kunquant` and nothing else. Every hoisted body was moved verbatim, Chinese inline comment and all.
- `_reset_symbols()` became a named overridable seam with a docstring in the shape of `Factor._maybe_resolve_factor_names()`. `tests/test_dataset_hierarchy.py::test_reset_symbols_seam_suppresses_construction_time_io` proves an override to a no-op suppresses **both** the store read and the `from_raw_data()` fallback — the exact suppression 03.1-02's constituent dataset needs so that merely constructing it does not fire an HTTP fetch.
- `DatasetConfig` split three ways under `kw_only=True`. `catalog_path` is now unreachable from a non-market config, so a membership panel cannot be handed a nautilus write destination at all; `ConstituentDatasetConfig` adds only `cache_dir`.
- `tests/test_dataset_hierarchy.py` (7 tests) locks the shape: abstractness/subclassing, the five-member allocation, the positive config-field delta, the inverse `__init__` ordering, the seam, the non-market end-to-end round trip, and the retirement of the old `Dataset` name.
- The interchangeability proof holds: `base/factor.py`, `base/factor_polars.py` and `base/model.py` are byte-for-byte unchanged across all three commits. The split reached the factor layer through a single annotation edit (`"Dataset"` -> `"MarketDataset"`).

## Decisions Made

- **`BaseFactorConfig.dataset` is `"MarketDataset"`, not `"BaseDataset"`.** `FactorKunQuant` calls `dataset.to_kunquant()`, which only exists on `MarketDataset`. Widening the annotation to `BaseDataset` would type-check while being false about what today's two factor backends require. A future consumer that masks factor output with a membership panel takes a `BaseDataset` of its own; the annotation was deliberately **not** pre-widened.
- **The old `Dataset` name is retired, not aliased.** A transitional `Dataset = MarketDataset` existed for exactly one commit (Task 2) so the `base/data.py` split could land with a green suite instead of leaving `dataset/spot.py`'s import broken between two commits. Test 7 makes reintroducing it a test failure.
- **`MarketDataset` carries a bare `config: DatasetConfig` class annotation.** The plan mandated importing `DatasetConfig` into `base/data.py` for `MarketDataset`; a bare annotation is the honest reference (it records that `_write_catalog` legitimately reads the market-only `catalog_path`) and, having no assignment, does not shadow the inherited `BaseDataset.config` property. See Deviations.
- **No `BaseDataset.config_cls` ClassVar.** `utils/module.py:13`'s hardcoded `DatasetConfig(**config)` was left alone, matching 03-02's identical refusal for factors.
