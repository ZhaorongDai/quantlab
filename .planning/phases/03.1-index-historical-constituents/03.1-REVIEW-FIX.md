## Fixed Issues

### CR-01: A current index constituent is silently reconstructed as a *former* member

**Files modified:** `acquisition/universe.py`, `tests/test_universe.py`, `tests/conftest.py`
**Commit:** `5f5d938`
**Applied fix:** Added the missing third reconciliation direction — symbol whose last
change-log event is a removal but which the anchor still lists as current. The anchor is
authoritative for "is a member today", so membership is re-opened from the removal date
with a warning. All three directions are now documented on the method.

**Note — a fixture contradiction this surfaced.** The NDX anchor fixture listed `LOGI`
while the change log removes it in 2018. An anchor is a *current-constituent snapshot*, so
that asserted "LOGI is a member today" and "LOGI stopped being a member in 2018"
simultaneously. `LOGI` was dropped from the anchor (replaced by a generated row to hold the
102-row shape); it still reaches the panel's symbol axis via its closed interval, which is
the survivorship-bias guarantee.

### CR-02: `pd.read_html`'s NA coercion silently deletes real tickers and fabricates `"nan"`

**Files modified:** `acquisition/universe.py`, `tests/test_universe.py`
**Commit:** `f215824`
**Applied fix:** `keep_default_na=False, na_values=[]` on both reads; the "no change on
this side" sentinel is re-derived explicitly from a named blank-cell set. The anchor drops
absent cells **by nullness** rather than by comparing against the string `"nan"` — the
review's suggested string check would have dropped a ticker named `NAN`, reintroducing the
same class of bug. `MIN_ANCHOR_ROWS` now counts cleaned symbols, so a page rendering 102
rows of which three carry a ticker is also caught.

### CR-03: The base class's "required column" guard can never fire

**Files modified:** `acquisition/universe.py`, `tests/test_universe.py`, `README.md`
**Commit:** `04adc55`
**Applied fix:** `_parse_changes_table()` is now **concrete on the base**. It selects the
change-log table by matching its flattened header against a subclass-declared
`EXPECTED_SOURCE_HEADER`, then reads the three consumed columns *by name* off that verified
header. Subclasses supply header constants, not a parse body, so no index can ship a parse
that skips validation — the docstring's "BY CONSTRUCTION" claim is now true of the code.
This also removed the `tables[0]` positional pick (the aggravating factor). The surviving
required-column check is re-documented honestly as a post-condition backstop rather than as
source validation. **Also closes WR-06** (the README recipe was rewritten as a 6-step list
naming the enum and CLI steps the test suite enforces).

## Notes for the verifier

Three items warrant a human eye, all of them deliberate decisions rather than mechanical
applications:

1. **CR-01 changed a test fixture, not just source.** The NDX anchor fixture encoded a
   contradiction (a removed ticker listed as a current constituent). Confirm the reading
   that an anchor is a current-constituent snapshot — if the fixture's `LOGI` row was
   intentionally modelling a real quirk of the live stockanalysis.com page, the fix belongs
   in `reconstruct_intervals()`'s policy instead.

2. **WR-08 changed the persisted parquet schema** (`end_date_is_inferred`). Nothing
   downstream reads the universe table positionally today, and `_densify()` selects its
   three columns by name, but any external consumer of `universe.parquet` will see a new
   column.

3. **WR-12 rejects nearly-ISO dates rather than repairing them.** Loud by design; if any
   operator workflow passes non-padded dates, it will now fail fast instead of silently
   computing the wrong window.

Two behavioural defaults also became stricter and could surface in ops rather than in
tests: `UniverseCatalog.build()` now **refuses** stale cached snapshots without
`allow_stale=True` (WR-01), and `NasdaqUniverseFetcher.fetch()` **raises** below 1000 rows
(CR-05). Both are the intended safety posture, but a scheduled refresh that was quietly
degrading will now fail visibly.
