## Decisions Made

**Raise, not warn-and-clamp. Reversibility: `reversible`.** `.planning/REQUIREMENTS.md` DATA-05 says 显式报错 literally, and a raise is that; a log line is not. Symmetry was the gap itself — the class exposes two membership queries and resolving the sibling differently would leave two contracts, which is the condition that produced this gap. No caller in this repository needs an unbounded-left sweep on a membership category (all four in-repo call sites pass a boundary-free category or an in-coverage date). And clamping would buy nothing: every membership interval already starts at or after its own coverage start, so raising `1900-01-01` to `1976-07-01` leaves the overlap predicate's result set identical — the caller would get the same truncated roster plus a warning, which is the exact "the caller cannot tell" failure DATA-05 names, only noisier. Undo cost is one deleted call in one method; there is no persisted format, no wire format, and no contract published outside this repository, so this is not a one-way door.

**Inclusive boundary (strict `<`).** The coverage start is the earliest date the change log actually covers, so it is answerable; membership intervals are closed on both ends everywhere else in this layer; and a `<=` would make the two membership queries disagree on the boundary day.

**Only `start_date` is checked on the interval query.** It is the window's left edge — the only end that can reach left-censored territory.

**The panel keeps clamping.** `IndexConstituentDataset._clamp_coverage_start()` processes a framework-supplied config default (`enums/constant.py:Date.START_DATE`) that nobody typed, so raising there would make every default construction explode. A query date is one somebody actually asked. Both docs now state this contrast explicitly so a future reader does not "align" the two by deleting one.
