## SC-3 in depth: verifying the PROPERTY, not one date format

The phase context is explicit that must-haves phrased entirely in dashed-date form must not be allowed to stand in for SC-3's general claim. So SC-3 was probed as a property across **three distinct ISO input forms**, both queries, both categories, and the CLI path — all against the live `data/data/reference/universe.parquet`.

|---|---|---|
| `get_symbols_as_of('nasdaq100_constituent','20070115')` | 103 symbols returned | **raises** — `as_of_date='2007-01-15' precedes it` |
| `get_symbols_in_range('nasdaq100_constituent','20070101','2020-01-01')` | 204 symbols returned | **raises** — `start_date='2007-01-01' precedes it` |

Note the error messages quote the **normalised** date (`'2007-01-15'`, not `'20070115'`), which is the observable signature that the parse is no longer discarded.

### Probes beyond the review's cases

The fixer's correction to CR-01's stated mechanism was taken seriously: the index-4 discriminator only bites when the basic-form date shares a year with the compared date, so a naive same-year-only probe could pass for the wrong reason. ### Why no un-normalised value can reach a comparison

`_normalize_iso_date` (`acquisition/universe.py:1428`) now `return datetime.date.fromisoformat(value).isoformat()` — anything `fromisoformat` accepts leaves as canonical dashed; anything it rejects raises. The verifier enumerated **all 9 call sites** and confirmed every one **rebinds** the return: `acquisition/universe.py:1574,1575` (`get_symbols_in_range`), `:1655,1656` (`estimate_dense_panel`), `:1829,1830` (`assert_chunked_panel_fits`), `:2340` (`get_symbols_as_of`), and `utils/cli.py:457,458` (`_ExplicitSymbolCatalog` override). Every lexicographic date comparison in the module (`:1580,1585,1676,1677,1682,1685,2352,2353` and the `<` in `_assert_within_coverage`) is downstream of one of those rebindings. The only raw-string use that remains is `datetime.date.fromisoformat(start_date)` arithmetic inside an error-message f-string at `:2307`, which parses rather than compares.

The rename from `_validate_*` to `_normalize_*` is load-bearing in itself: a caller that ignores a `_normalize_*` return reads as obviously wrong, which is the structural half of the fix.

### Residual on SC-3

`estimate_dense_panel` still bypasses `_assert_within_coverage` (WR-02, deliberately deferred). It returns **counts, not a roster** — `symbols=766, trading_days=30240` for the window `get_symbols_in_range` refuses — so it does not falsify SC-3's "returning a silently incomplete roster". Recorded as advisory + routed to human decision, not as an SC-3 failure.
