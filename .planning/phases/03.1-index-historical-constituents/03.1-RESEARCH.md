# Phase 03.1 Research — Index Historical Constituents

Every finding below was produced by an actual fetch+parse run, not from memory.
Probe scripts were throwaway (scratchpad, not committed). Where a number is
quoted it was observed on 2026-09-05.

## Finding 1 — The NDX-100 change log exists and is structurally identical to the S&P 500 one

The initial risk assessment was that Nasdaq-100 historical membership would be
scattered across per-year Wikipedia sections and much weaker than the S&P 500's.
**That was wrong.** There is a dedicated page with a single structured table:

- URL: `https://en.wikipedia.org/wiki/Historical_components_of_the_Nasdaq-100`
- One table, **226 rows**
- Columns (MultiIndex): `Date` / `Added(Ticker, Security)` / `Removed(Ticker, Security)` / `Reason`
- All 226 dates parse cleanly with `pd.to_datetime` (0 failures)

This is the same shape `SP500MembershipFetcher.fetch_changes()` already parses
from `Historical_components_of_the_S%26P_500` (which uses `attrs={"id":"changes"}`).

**Parser note:** call `pd.read_html(..., flavor="lxml")` explicitly. Passing
`attrs=` without a flavor made pandas fall back to `html5lib`, which is not
installed and raised `ImportError: Import html5lib failed`. `lxml>=6.1.3` is
already a declared dependency — no new package is needed for this phase.

## Finding 2 — NDX point-in-time coverage starts 2007-02-01 (HARD BOUNDARY)

Earliest row in the change table:

```
February 1, 2007 | LOGI Logitech | CMVT Comverse Technology | Comverse did not meet the minimum monthly weighting requirements.
```

Latest observed row: `August 4, 2026`.

So NDX membership **cannot be correctly answered before 2007-02-01**, versus
1976-07-01 for the S&P 500. This must be an explicit, enforced boundary, exactly
as `SP500MembershipFetcher` already does:

```python
PIT_COVERAGE_START = "2007-02-01"   # NDX
```

and `get_symbols_as_of` must **raise** for earlier dates rather than silently
return an incomplete roster. The existing S&P implementation and its comment
(which notes the Wikipedia page's own prose claim of 1963 coverage is NOT what
the table actually contains) is the precedent to follow.

## Finding 3 — One-sided change rows are common; existing reconstruction already handles them

Of the 226 NDX rows:

| shape | count |
|---|---|
| both added and removed present | 192 |
| add-only (`removed_ticker` is NaN) | 18 |
| drop-only (`added_ticker` is NaN) | 16 |

`SP500MembershipFetcher.reconstruct_intervals()` already guards each side
independently (`if row["removed_ticker"] is not None:` / `if row["added_ticker"]
is not None:`), so one-sided rows need no new logic.

## Finding 4 — `reconstruct_intervals()` is already generic; extract it

Read `acquisition/universe.py:180-243`. The algorithm depends only on:

- `self.PIT_COVERAGE_START` (a class attribute)
- an `anchor` frame with `symbol` + `date_added` columns
- a `changes` frame with `effective_date` / `added_ticker` / `removed_ticker`

Nothing in it is S&P-specific. It already handles left-censored removals
(warn + start at `PIT_COVERAGE_START`), duplicate adds (warn + keep earlier),
open intervals absent from the anchor (warn + close at last effective date), and
anchor members never mentioned in the log
(`anchor_date_added.get(sym) or self.PIT_COVERAGE_START`).

**Recommendation:** extract `IndexMembershipFetcher` carrying
`reconstruct_intervals()` + `build_intervals()` + the cache-fallback pattern;
`SP500MembershipFetcher` and `Nasdaq100MembershipFetcher` then differ only in
`ANCHOR_URL`, `CHANGES_URL`, `PIT_COVERAGE_START`, and their table-specific
parse step. This mirrors D-03's `BaseDataset` extraction at the fetcher layer.

Preserve the two existing safety behaviours when extracting — they are not
incidental:
1. the row-count monotonicity check ("memberships only close, they don't
   retroactively vanish") that treats a shrunken table as parse failure;
2. the cached-snapshot fallback that does NOT overwrite the cache on failure.

## Finding 5 — NDX current-constituent anchor needs a new source

Wikipedia's `Nasdaq-100` page has **no parseable constituents table** — probing
it returned 18 tables, none of them a ~100-row ticker list (the components are
rendered through a navbox template). The S&P anchor
(`raw.githubusercontent.com/datasets/s-and-p-500-companies`) has no NDX analogue.

Two working candidates, both probed successfully:

| source | rows | columns |
|---|---|---|
| `https://stockanalysis.com/list/nasdaq-100-stocks/` | 102 | `No. / Symbol / Company Name / Market Cap / Stock Price / % Change / Revenue` |
| `https://www.slickcharts.com/nasdaq100` | 102 | `# / Company / Symbol / Weight / Price / Chg / % Chg` |

**102, not 100, is correct** — NDX includes multiple share classes for some
issuers (GOOGL/GOOG, FOX/FOXA). A plan that asserts exactly 100 will fail
against correct data.

**Neither source carries a `date_added` column.** That is tolerable without new
logic: `reconstruct_intervals()` falls back via
`anchor_date_added.get(sym) or self.PIT_COVERAGE_START`, so anchor members with
no event in the change log start at 2007-02-01. Supply the anchor frame with an
explicit null `date_added` column so the existing code path is exercised as
written rather than KeyError-ing.

**Pitfall:** both are commercial scraped sites, less stable than the S&P
anchor's GitHub CSV. The cached-snapshot fallback from Finding 4 matters more
here than it does for the S&P, not less.

## Finding 6 — Interval table to daily panel is the new conversion, and it is where correctness is decided

The existing `UniverseCatalog` produces `(symbol, start_date, end_date)` rows
with `end_date = None` for still-open memberships. The panel this phase adds is
the densification of that into `(timestamp, symbol) -> bool`.

Points a plan must pin down explicitly, because each is a silent-wrongness
opportunity:

- **Interval half-openness.** `reconstruct_intervals()` closes an interval AT the
  removal's `effective_date`. Whether the removal date itself counts as a
  membership day must be stated and tested, not left to whichever comparison
  operator gets typed.
- **Open intervals.** `end_date is None` means "still a member" — it must
  densify to True through the panel's right edge, not be dropped as null.
- **Calendar.** Daily over what — calendar days, or trading days? Change
  effective dates are trading days, but the panel's `timestamp` axis needs a
  stated rule. A calendar-day axis is simpler and self-consistent; a
  trading-day axis requires a session source this repo does not yet have.
- **Left edge.** The panel must not start before the category's
  `PIT_COVERAGE_START` (1976-07-01 for S&P, 2007-02-01 for NDX). Two categories
  with different left edges must not be silently unioned onto one axis that
  implies coverage neither has.
- **Symbol axis.** All-time union of every symbol ever in the category, so a
  delisted member is a real column of mostly-False rather than absent.
