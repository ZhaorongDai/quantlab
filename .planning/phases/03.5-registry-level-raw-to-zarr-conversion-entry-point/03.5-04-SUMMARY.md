# Phase 03.5 Plan 04: Abstract the Windowed-Densify Seam Summary

**`_raw_data_to_xr_window` is now `@abstractmethod` on `MarketDataset`, so a market data source with no windowed densify fails to construct instead of silently degrading to a whole-range densify announced by a `logger.warning` nobody reads.**

## Accomplishments

- **The single entrance ticket to chunked conversion can no longer be satisfied by accident.** `MarketDataset` re-declares `_raw_data_to_xr_window` abstract (D-08). A new source that omits it raises `TypeError` naming the missing method at construction, which is the author's first test run — not an OOM at production roster size months later.
- **`BaseDataset` keeps its concrete default, and the assertion that forbids the other placement was left untouched.** `BaseDataset.__abstractmethods__` is still exactly `{"_raw_data_to_xr"}`. `IndexConstituentDataset` subclasses `BaseDataset` directly (verified before proceeding, per the plan's stop-and-report instruction), so the membership panel still inherits a working densify-then-slice.
- **The warn-and-degrade block is deleted, not softened.** For a market dataset the identity check is now unreachable; for a non-market dataset the default is the intended behaviour, not a degradation worth a warning about. The 11 lines are gone from `from_raw_data_chunked`, and nothing else in that method changed.
- **`SpotKlineDataset` gains the seam explicitly with behaviour verbatim, and says out loud what that buys (D-09):** nothing, in memory terms. The docstring states it is a known non-memory-bounded implementation, names `quantlab/utils/file.py:file_date_filter` as the pending pushdown mechanism, points at `StockDataset._raw_data_to_xr_window` as the shape a bounded version takes, and records why crypto spot stays out of the registry conversion entry point.
- **`ingest_binance_spot.py` is untouched and pinned as such** by an AST check that it names no `convert(` call and still reaches `from_raw_data` — the fourth converting shell the roadmap never names stays out of the entry point deliberately.

## Decisions Made

- **The `_raw_axes_in_range` docstring was amended too, beyond the two the plan named.** Its closing sentence — a subclass that cannot push the filter down "inherits a working, slower default and is warned about it at run time" — is the literal text the plan attributed to the default seam's docstring, and `_raw_data_to_xr_window`'s docstring incorporates it by reference ("the same caveat as `_raw_axes_in_range()` applies"). Deleting the warning falsifies it verbatim, so it was corrected in the same edit rather than left as a false promise one hop away from the seam it describes.
- **`MarketDataset`'s class docstring gained a separate paragraph rather than a sixth item in the existing list.** The existing five are "nautilus- and KunQuant-specific" members kept OFF `BaseDataset`; the new one is neither market-specific nor kept off the base. Folding it into that sentence would have made the sentence false while making the count right.
- **`MARKET_ONLY_CONFIG_FIELDS` already contained `"market"`** — Plan 01 restored it, as the plan's "check first, doing it twice is a conflict" instruction anticipated. No action taken.
