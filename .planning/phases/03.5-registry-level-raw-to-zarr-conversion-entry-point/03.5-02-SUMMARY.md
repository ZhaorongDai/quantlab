# Phase 03.5 Plan 02: Split "ask" from "refuse" for the chunked RAM guard Summary

**`estimate_chunked_panel()` now completes its loop and returns every planned window with its own `fits` verdict and remedy, `assert_chunked_panel_fits()` is the thin wrapper over it, both size the timestamp axis through a keyword-only `bars_per_day: int = 1`, and the report's rendering moved into `quantlab/utils/cli.py` while `--to-zarr` collapsed to one flag with one help text.**

## Accomplishments

### Task 1 — the estimate/assert split (TDD: RED `9dfba1f` → GREEN `6c6c0be`)

`assert_chunked_panel_fits` used to raise INSIDE its per-chunk loop, above `chunks.append`, so the chunk list was truncated at the first refusal: a caller whose second of five windows overflowed was told about window one and nothing else. That is precisely the case SC-4's "ask what peak it predicts, without starting" exists for.

The whole body moved into a new `estimate_chunked_panel()` with exactly the changes the plan specified and no others:

- The loop runs to completion. `chunks.append` happens for every window, in ascending order, before any budget comparison.
- Each chunk gains `fits: bool` and `remedy: str | None`. The remedy is per CHUNK because DATA-08 asks for the remedy per over-budget window, not one remedy per run.
- A keyword-only `bars_per_day: int = 1` (D-10 as amended 2026-09-11), forwarded to the whole-range advisory by keyword and multiplied into each chunk's timestamp axis. The trading-day derivation — 252/365.25, half-to-even `round()`, `max(..., 1)` floor — is untouched; `bars_per_day` is a factor of the axis, never a replacement for the day count.
- The return dict gains a top-level `"bars_per_day"` key beside `"granularity"`, which is what lets the refusal and the renderer print a decomposition that multiplies out to the byte count beside it.

`assert_chunked_panel_fits` is now: call the estimator, find the first chunk whose `fits` is false in window order, return the report if there is none, otherwise raise. The message is byte-identical to today's at the default `bars_per_day`; above it, it gains only ` x N row(s)/day` spliced after the trading-days term, worded exactly as `assert_dense_panel_fits` words it.

The tie-break is now stated rather than incidental: `max()` returns the first maximal element, so tied windows resolve to the earliest, and a test pins it (January and March 2023 are both 31 calendar days and tie exactly).

### Task 2 — the renderer hoist (`0a3811b`)

`_print_chunk_report` moved from `ingest_us_equity.py` into `quantlab/utils/cli.py` as `print_chunk_report`, taking `print_volume_estimate`'s shape: `print_fn=print` injected last, and the input dict returned so both call sites still compose as a wrapper around the guard call — a refusal still prints nothing, and the AST ordering assertions in `tests/test_volume_guard.py` still read a guard line number below every densify line number.

This is the mechanism behind SC-4's "the estimate is a value the caller renders" (D-13): `quantlab/acquisition/` produces the report object, every print of it lives in one module, and the out-of-repo console renders the same dict its own way.

`ingest_us_equity._GIB` was NOT deleted — `_print_estimate` still uses it for six of its own lines, as the pattern map flagged.

### Task 3 — one flag, one help text (`fcb64c9`)

`ConversionMode` and the two-armed `_TO_ZARR_HELP` dict are gone from `quantlab/utils/cli.py`, along with `add_to_zarr_arg`'s keyword-only `mode` parameter. There is no second conversion shape to select (D-06), so the machinery that existed to distinguish two of them went with the mode itself; the surviving help text is the chunked arm's word for word. `Literal` stays imported — `RosterMode` and `WindowSemantics` still use it — and the D-14 paragraph about the three front doors having disagreed stays, because that is still why the flag is defined once here.

`quantlab/enums/data.py` grew nothing: D-07's sub-decision to relocate the mode `Literal` beside `Market`/`Frequency`/`Vendor` is moot, since the type ceases to exist rather than moving.

## Deviations from Plan

### 1. [Rule 3 — Blocker] The plan's `--help` verify command cannot pass as written: argparse hard-wraps help text

- **Found during:** Task 3
- **Issue:** Task 3's third `<verify>` command asserts `'resumes at the first unwritten window' in t` against raw `--help` stdout. argparse's `HelpFormatter` wraps the help string to the terminal width, so the rendered text contains `resumes at the first\n                        unwritten window`. The substring can never appear contiguously in `--help` output at any realistic width, regardless of the implementation. This is a defect in the check, not in the code — the acceptance criterion it serves is "All three shells respond to `--help` with exit 0 and carry the identical `--to-zarr` help sentence", which is a property of the SENTENCE, not of argparse's line breaking.
- **Fix:** Ran the same command with whitespace collapsed (`re.sub(r'\s+', ' ', o.stdout)`) before the substring test. All three shells exit 0 and carry the identical sentence. Nothing in the implementation was changed to accommodate the check.
- **Files modified:** none (verification-command adjustment only)
- **Verification:** `help ok` printed; the wrapped text was read directly out of `ingest_tiingo.py --help` to confirm the sentence is present and identical.
- **Commit:** `fcb64c9`

### 2. [Rule 3 — Blocker] The empty-chunks case is unreachable from valid input, so it is injected rather than driven

- **Found during:** Task 1
- **Issue:** Task 1's action says "For the empty case, drive the estimator over a window that plans to zero chunks rather than mocking the planner." No such window exists. `TimeChunkPlanner.plan_calendar` raises when `end_date` precedes `start_date`, and otherwise builds `pd.date_range(start, end, freq="D")`, which always yields at least one day and therefore at least one window. A single-day window plans to exactly one chunk, not zero. Verified by reading `chunking.py:124-157` and `_group_by_period` directly.
- **Fix:** The branch still has to exist — `max()` over an empty sequence raises, and `print_chunk_report` indexes `max_chunk` — so `test_a_window_that_plans_no_chunks_reports_nothing_rather_than_raising` monkeypatches `TimeChunkPlanner.plan_calendar` to return `[]`. The test's docstring states plainly why the result is injected rather than reached, so a later reader does not mistake it for a lazily written mock. The renderer's own empty case (Task 2) needs no injection at all: it is driven by a hand-built empty report dict, which is exactly what an external caller could hand it.
- **Files modified:** `tests/test_chunked_panel_estimate.py`
- **Verification:** `uv run pytest tests/test_chunked_panel_estimate.py -q` — 15 passed
- **Commit:** `6c6c0be`

### 3. [Rule 3 — Blocker] No reachable window produces an exact `round()` half-to-even tie

- **Found during:** Task 1
- **Issue:** Task 1's behaviour list asks the precision test to include "a `window_days` value whose `round()` lands on a `.5` tie (half-to-even)". Searching every `window_days` from 1 to 4,000, `window_days * 252 / 365.25` never lands on a half — the closest is 1,640 days at 1131.4990. The tie is not expressible.
- **Fix:** `_longhand_dense_bytes` in the test calls the same `round()` on the same expression, so the tie-breaking is inherited BY CONSTRUCTION rather than exercised by a hand-picked window; a re-derivation that changed the tie-breaking or dropped the `max(..., 1)` floor is still caught. The test docstring records the search and its result so the gap is visible rather than silently absent.
- **Files modified:** `tests/test_chunked_panel_estimate.py`
- **Verification:** `test_each_chunks_dense_bytes_matches_the_longhand_arithmetic` passes against all five windows of a 2020-12-31..2024-12-31 year plan.
- **Commit:** `6c6c0be`

### 4. [Rule 2 — Missing critical] `print_chunk_report` takes `budget_bytes` rather than importing `UniverseCatalog` at module scope

- **Found during:** Task 2
- **Issue:** The hoisted body read `UniverseCatalog.MAX_DENSE_PANEL_BYTES` directly. `quantlab/utils/cli.py`'s module docstring pins its module-scope project dependency surface at `quantlab.base.chunking` / `quantlab.base.data`, and `_explicit_symbol_catalog` in the same file defers its own `UniverseCatalog` import to call time for exactly that reason. Naming the class at import time would have widened that surface.
- **Fix:** Took the route the plan authorises: a keyword-only `budget_bytes: int | None = None`, resolved through the same call-time import when omitted, so no caller has to know the number and a caller sizing against a different budget can say so. `print_fn` remains the last parameter, as the plan's `<verify>` requires.
- **Files modified:** `quantlab/utils/cli.py`
- **Verification:** `renderer ok`; `uv run pytest tests/test_data_dir_cli.py -q` (which holds the module-scope import contract) passes.
- **Commit:** `0a3811b`
