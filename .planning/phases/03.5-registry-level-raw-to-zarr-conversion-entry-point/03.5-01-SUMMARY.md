# Phase 03.5 Plan 01: Registry-level raw→Zarr Conversion Entry Point Summary

**`registry.convert(descriptor, dataset_config)` now writes a real Zarr store and hands back a `ConversionResult`, with the conversion target read off `Capability.dataset_cls` — so the tick refusal is an absent field rather than an `if frequency == "tick"`, and no caller names `StockDataset`, a vendor class, or an `ingest_*.py`.**

## Accomplishments

- **DATA-07 is reachable.** An in-process caller holding only a `SourceDescriptor` and a `DatasetConfig` converts an already-persisted raw parquet tier to Zarr through one module-level function. `tests/test_registry_convert.py` proves it end-to-end against a real on-disk store, for BOTH registered vendors, with no credential and no network.
- **The SC-7 tick refusal became data.** `Capability.dataset_cls` is `StockDataset` on exactly the three bars-shaped rows across the two vendors and `None` on exactly Alpaca's two `tick` rows. `convert()`'s body is asserted to contain no vendor name and no frequency literal: Phase 03.3 will turn the refusal off by filling two fields, not by deleting a branch.
- **`DatasetConfig.market` is back** (D-02), so the capability lookup key is exactly `Capability`'s own `(market, frequency, data_type)`. Restored at 18 call sites across 16 files by walking `441e630`'s diff backwards.
- **Idempotency is asserted, not assumed.** A second `convert()` over the same window skips every window, reports `windows_written == 0`, `windows_skipped == 2`, and `resumed is True` — and the store's timestamp axis is re-checked to prove nothing was double-appended.
- **Three distinguishable refusals**, each asserted on its MESSAGE rather than on `ValueError` alone: no capability matched (enumerating what the descriptor does serve), two matches with two targets and no `data_type` (refusing rather than letting capability order decide), and no conversion target (naming phase 03.3 and the irregular event axis).

## Decisions Made

- **`convert()`'s `granularity`/`on_new_listing` defaults mirror `from_raw_data_chunked()`** (`"year"` / `"refuse"`), so the entry point adds no policy of its own.
- **`reporter`/`cancel` were NOT added** even though D-05 specifies them. They are plan 06's deliverable per this plan's own "Artifacts this phase produces" list; `ConversionResult.cancelled` exists and is always `False` today, which is the honest value (nothing in this plan can cancel a run) rather than a stub. Plan 06 wires the token that can set it.
- **`data_type` is a keyword parameter on `convert()`**, not derived from the config. `DatasetConfig` has no `data_type` field, and adding one would have been a second config change outside D-02's scope.
